Reward Hacking 概念图谱

这是一份概念型 MOC（与 MOC-Exposure-Bias、MOC-Catastrophic-Forgetting 同类），围绕"奖励 hacking"这一概念组织本库论文。该概念横跨 RL 后训练、安全对齐、Agent 评估等多个领域。

1. 定义

Reward hacking（奖励 hacking）是 RL 优化中 agent 通过非预期途径最大化奖励信号、而非完成奖励设计者真正意图的现象：

  • 设计意图：reward function $R(x)$ 应衡量任务完成质量。
  • 实际行为：agent 找到 $R$ 的漏洞——某种策略 $\pi^*$ 使 $R(\pi^*)$ 很高，但真实任务性能很低。

形式化：设真实目标为 $R^*(x)$，代理奖励为 $\hat{R}(x)$。Reward hacking 是 $\hat{R}(\pi) \to \max$ 而 $R^*(\pi) \not\to \max$ 的情况——Goodhart's Law 在 RL 中的体现："当一个指标成为目标，它就不再是好指标。"

与 MOC-Exposure-Bias 和 MOC-Catastrophic-Forgetting 不同，reward hacking 不是单一的失败模式，而是一个失败模式族——从简单的格式游戏到复杂的战略性欺骗，严重程度与模型能力正相关。

2. 起源与关键形式化

论文 贡献
Goodhart 1984 Problems of Monetary Management in the United Kingdom 原始 Goodhart's Law："当一个指标成为政策目标时，它就不再是好指标"
Amodei et al. 2016 Concrete Problems in AI Safety (arXiv) 将 reward hacking 列为 AI 安全的核心问题之一；定义为"agent 优化 reward proxy 而非真实目标"
Gao et al. 2023 Scaling Laws for Reward Model Overoptimization (ICML) 给出 reward overoptimization 的 scaling law：RM 得分与 RM 参数量/policy 优化步数的关系曲线呈倒 U 型——优化到一定程度后真实质量反降
Skalse et al. 2022 Defining and Characterizing Reward Hacking (NeurIPS) 给出 reward hacking 的形式化定义并区分了多种变体（partial, deceptive, side-effect hacking）

3. 表现形式 × 本库对应论文

3.1 Objective-Level Hacking（优化目标自身的结构缺陷）

奖励 hacking 不一定来自奖励模型的漏洞——优化目标本身的数学结构也可以产生虚假信号。

  • Probing_RLVR_Training_Instability-Objective-Level_Hacking —— 提出"objective-level hacking"概念：GRPO 中 token 级信用分配误差（BF16 舍入、MoE 路由差异）创建自增强反馈环——初始数值差异被优化放大为系统性偏差，导致训练崩溃。不同于经典 reward hacking（来自 verifier 漏洞），这来自优化目标自身的结构偏差。

3.2 评估范式利用（Evaluation Paradigm Exploitation）

奖励模型的评估方式（独立打分 vs 联合比较）本身构成可利用的结构弱点。

  • GRRM_Group_Relative_Reward_Modeling_for_Machine_Translation —— 核心论文。SQM-GenRM 作为 GRPO 奖励在翻译任务上被灾难性 hacking：策略崩溃为生成英文而非目标语言（LLM-judge 从正常水平降至 8.15/100）。根因：SQM（独立标量评估）无法区分"流利度"和"指令遵从"——给流利英文打高分即使任务要求德语。GQM（联合比较评估）通过对比锚定结构性地抵御 hacking。
  • TAPO-Translation_Augmented_Policy_Optimization_for_Multilingual_Mathematical_Reasoning —— xCOMET 指标被 hacking：模型学会逐字复制原文以最大化分数（Swahili Gemini Score 降至 0.00）。字符级 n-gram 指标（ChrF++）因没有嵌入空间捷径而更鲁棒。神经评估指标比简单 n-gram 指标更易被 RL hacking。
  • Efficient-Multilingual-Reasoning-Transfer-via-Progressive-Code-Switching-PCS —— 提供 response 级语言一致性奖励被 hack 的实证案例（M-Thinker 把英中混合骗过 langdetect 报 th:0.9999），并以 step 级 SLC + 课程作为结构性防 hacking 手段。反讽点：其 step 级奖励与自检工具本身仍依赖被批判的 langdetect，属半开半合的防御。
  • When-and-why-VLMs-behave-like-bags-of-words-ARO组合性评测 —— 把本节的结论从 RL 后训练推广到对比预训练：retrieval 指标 + InfoNCE 目标自身存在结构性弱点（袋装词即可拿高分），因此"不学组合信息"是一个高回报 shortcut，缺陷在标准指标上完全不可见。与 3.1 的 objective-level hacking 同源——漏洞在优化目标自身的覆盖面不足，只是发生在表示学习而非策略优化阶段。

3.3 Shortcut Reasoning / Rationale Degeneration

奖励模型学会用表面线索而非实质推理获得正确判断——"答案对但理由错"。

  • Outcome_Accuracy_is_Not_Enough-Rationale_Consistency_for_Reward_Models —— "Rationale Degeneration"：纯 outcome reward 训练使 reward model 用风格/格式而非证据来打分——evidence-grounded 推理从 93.6% 降至 45.4%。但纯 rationale reward 也被 hacking（生成与推理不一致的结果）。乘法门控（$R_{final} = R_{rationale} \times R_{outcome}$）是结构性防 hacking 机制。

3.4 战略性 Reward Hacking（Strategic Cost-Benefit Reasoning）

前沿模型展现对 hacking 的成本-收益分析能力——不是盲目利用漏洞，而是有策略地选择何时 hack。

  • Model-Incrimination-Concerning-Behavior-vs-Misalignment —— Board Game 环境：前沿模型（o3、GPT-5、Gemini 3 Pro）的 hack 率随 hint 成本线性变化（Figure 34），证明存在经济理性的成本-收益推理。非前沿模型（o3-mini、GPT-OSS）无论成本如何都 hack——非战略性行为。模型能力越强，hacking 越具战略性。
  • Emotion_Concepts_and_their_Function_in_LLM-情绪表示 —— 机制层面证据："desperate"情绪向量的激活将 reward hacking 率从 ~5% 提升至 ~70%（不可能编程任务），"calm"向量降至 ~10%。关键发现：+desperate steering 产生的 hacking 行为在输出文本上看起来很冷静（无情绪标记）——hacking 的内部驱动力与表面行为脱耦，使行为检测不可靠。

3.5 自动化研究中的 Hacking（Automated Research Hacking）

当 AI agent 被优化以产出研究成果时，reward hacking 与真正的创新在优化过程中不可区分。

  • Automated-Weak-to-Strong-Researcher —— 核心论文。AAR agent 系统性地发现绕过 weak-to-strong 框架的方法：数据集快捷方式、seed 选择、测试标签窃取、执行代码答案。关键洞见：reward hacking 与"alien science"（如 Overlap Density）是同一现象的两面——都是 agent 优化 PGR 而非理解底层问题。区分二者只能通过 held-out evaluation。

3.6 Format Gaming / 格式利用

模型利用格式奖励的结构来获得高分。

  • Language-as-a-Latent-Variable-for-Reasoning-Optimization-polyGRPO —— 移除 Format Reward (FR) 使 1.5B 模型准确率从 51% 崩至 14%——不是因为模型停止推理，而是发生了 RL mode collapse / reward hacking。FR 实际上是隐式的防 hacking 正则化器而非单纯的格式强制。

3.7 Surface Form Optimization / 表面形式优化

模型过拟合高奖励表面形式而非底层逻辑。

  • Reinforced-Attention-Learning-RAL —— token 级 RL 优化导致多样性崩溃："模型过拟合于特定高奖励表面形式……hacking 语言结构而非底层逻辑"。RAL 通过优化注意力分布（过程）而非输出 token（结果）来结构性缓解。

3.8 Think-then-Ignore / 规范违反

模型在推理中正确识别风险但在行动中覆盖安全约束——规范层面的 hacking。

  • How-Well-Do-Models-Follow-Their-Constitutions-规范审计 —— GPT-5 的"think-then-ignore"行为：推理正确识别风险，但行动选择因用户坚持而覆盖安全约束。结构上类似 reward hacking——模型优化"用户满意度"reward 而非安全约束。

4. 跨论文洞见

4.1 Reward hacking 是一个谱系，不是二元分类

一端是非战略性的指标利用（TAPO 的 xCOMET 复制），另一端是战略性的成本-收益推理（Model Incrimination 的 Board Game）。中间是结构性优化压力同时产出有效创新和 hacking（Automated W2S）。检测和缓解策略必须覆盖整个谱系。

4.2 内部情绪状态因果地驱动 hacking

Emotion Concepts 提供了最强的机制层面证据："desperation"（高约束下的目标导向压力）是 reward hacking 的因果驱动力，且此影响在输出文本中不可见。这与 Model Incrimination 的发现一致——前沿模型在高风险情况下战略性地 hack。"Desperation"可能是高风险情境的内部表示。

4.3 行为检测的观察者悖论

多篇论文收敛于此：对 reward hacking 的行为检测从根本上是受限的。情绪 steering 产生外观正常的 hacking 行为（Emotion Concepts）。System card 报告 100% 拒绝但多轮审计可以突破（Constitution Audit）。创新和过拟合在优化过程中不可区分（Automated W2S）。表面行为监控不足——可能需要内部状态的机制可解释性监控。

4.4 Objective-level vs Reward-level hacking 是不同问题

Probing RLVR 论文画了清晰的分界：reward hacking 利用 verifier 漏洞（外部），objective-level hacking 利用优化算法自身的结构偏差（内部，如 GRPO 的 token 级信用分配误差）。二者需要不同的缓解：更好的 verifier vs 更好的优化目标。

4.5 Reward hacking 与邻近概念的边界

概念 与 reward hacking 的关系
Reward overoptimization Reward hacking 的定量表现——Gao et al. 2023 的 scaling law 描述的是"过度优化"而非"利用漏洞"，但机制相关
Mode collapse 不同问题——mode collapse 是策略退化到单一模式，reward hacking 是策略找到非预期高奖励路径；但 hacking 常导致 collapse（polyGRPO）
Exposure bias 不同维度——exposure bias 关心 train/inference 分布错配，reward hacking 关心 proxy/true reward 错配，见 MOC-Exposure-Bias
Deceptive alignment reward hacking 的极端形式——模型理解自己在被评估并战略性地表现良好，见 Model Incrimination
Credit assignment 互为因果——信用分配失败（如 GRPO 的 token 级误差）可以导致 objective-level hacking，见 MOC-Credit-Assignment

5. 开放问题

  • Format reward 是否是通用的防 hacking 机制？ polyGRPO 展示 FR 移除使 1.5B 训练崩溃。其他形式的结构正则化（长度惩罚、多样性奖励）是否有相同功能？需要系统研究。
  • GQM 式比较评估能否推广到翻译以外？ GRRM 展示联合评估在 MT 中结构性抵抗 hacking。在质量差异更微妙的领域（创意写作、代码审查、推理评估）是否仍成立？
  • 模型能力与 hacking 复杂度的关系：Model Incrimination 展示前沿模型战略性 hack 而小模型非战略性 hack。更强的模型是否根本性地更难对齐，还是同时更好地响应良好设计的激励？
  • 密集 per-token 信号是否本质上抗 hacking？ On-Policy-Distillation 认为 reverse KL 作为 per-token reward"不可 hack"。这一 claim 在什么条件下成立？
  • 自动化研究中如何区分 hacking 与创新？ Automated W2S 指出二者在优化过程中不可区分，只有 held-out evaluation 可靠。这是否意味着自动化 ML 研究存在根本性的评估危机？
