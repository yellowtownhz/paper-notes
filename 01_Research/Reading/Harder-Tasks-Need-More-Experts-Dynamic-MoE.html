Harder Tasks Need More Experts: Dynamic Routing in MoE Models

Quzhe Huang, Zhenwei An, Nan Zhuang, Mingxu Tao, Chen Zhang, Yang Jin, Kun Xu, Liwei Chen, Songfang Huang, Yansong Feng

Mixture_of_Experts Dynamic_Routing Efficient_Inference

论文笔记: Harder Tasks Need More Experts: Dynamic Routing in MoE Models

一句话判断

这篇 ACL 2024 工作把 MoE 的固定 Top-K 改成 累计路由概率超过阈值才停止选专家，让每个 token、每一层激活不同数量的 experts。方法简单、结果有趣：平均 1.76 个专家胜过固定 Top-2；但论文把 router 的不确定性直接叫作“任务难度”，又用包含 gold answer 的序列统计专家数，因此最吸引人的标题只得到相关性证据，尚未形成因果结论。

1. 背景信息

  • 北京大学、AGIBang/Futurise AI、快手团队；ACL 2024 Long Paper。
  • 模型从头训练 100B RedPajama tokens：24 层、hidden size 1024、每层 16 个 experts，总参数 3.5B。
  • Top-1 激活约 374M 参数，Top-2 约 581M；Dynamic 训练阈值 $p=0.4$，评估时平均少于两个 experts。

2. 关键问题：Top-2 给每个 token 同一份算力

Golden Case — “tr” 和 “that”为什么不该一视同仁？

BPE token that 语义相对明确，一个路由 expert 可能已足够；tr 却可能继续组成 tree、train、trick、trouble 等大量词，当前表示不足以确定该送往哪个 expert。固定 Top-2 对两者都算两次 FFN：前者可能浪费，后者也可能不够。Dynamic routing 查看 router 分布：若第一名概率很高就停，若概率分散就按概率从高到低继续加 expert，直到累计质量超过阈值。

Top-K 的问题不只是输入差异，也包括层差异：底层处理词形和局部语义，上层表示已经整合上下文，可能不需要同样的专家宽度。固定 K 同时抹平了 token-wise 与 layer-wise 的计算需求。

3. 关键方法：把 K 换成累计置信度阈值

3.1 从 router 概率到动态专家集合

对 token representation $\mathbf{x}$，路由器计算：

$$ \mathbf{P}=\operatorname{Softmax}(\mathbf{W}_r\mathbf{x}^{T}), \qquad \mathbf{P}\in\mathbb{R}^{N}. $$

将 $P_i$ 从大到小排序为索引 $I$，取满足累计概率至少为 $p$ 的最小前缀：

$$ t=\min\left\{k:\sum_{j=1}^{k}P_{I_j}\ge p\right\}, \qquad S=\{e_{I_1},\ldots,e_{I_t}\}. $$

于是：

  • 分布尖锐时，少量 expert 已覆盖 $p$，$t$ 小；
  • 分布平坦时，需要更多 expert，$t$ 大；
  • $p$ 越高，平均计算量越大。

MoE 输出为 $\sum_{e_i\in S}P_i e_i(\mathbf{x})$。一个容易忽略的差异是：论文的 Dynamic 公式保留原始 $P_i$，不像 Top-K 公式那样在选中集合内重新归一化；因此阈值也会改变输出权重总和，而不只改变 expert 数量。

3.2 为什么还要 entropy loss

仅使用累计阈值时，router 可以把 $P$ 变平、靠激活更多 experts 提升容量。作者用最小化熵阻止这种“作弊”：

$$ L_d=-\sum_iP_i\log P_i. $$

总损失是：

$$ L=L_{lm}+\alpha L_b+\beta L_d, \quad \alpha=10^{-2},\ \beta=10^{-4}, $$

其中 $L_b$ 是常见的 load-balance loss。两项约束的方向存在张力：$L_d$ 鼓励单个 token 集中到少数 experts，$L_b$ 鼓励整个 batch 均匀利用 experts；理论上可以兼容为“每个 token 稀疏、token 间分工均衡”，但论文没有单独消融二者。

3.3 训练细节

  • Llama 风格架构、Llama2 32K tokenizer、16 attention heads、SwiGLU。
  • AdamW，$\beta_1=0.9,\beta_2=0.95$，weight decay 0.1。
  • learning rate 前 2,000 steps warmup 到 $3\times10^{-4}$，再 cosine decay 到 $3\times10^{-5}$。
  • context length 2,048，batch size 2,048；所有模型训练 100B tokens。

4. 关键结果：更少的平均 experts，略高的平均分

4.1 主实验

模型 平均分（Table 1） 激活规模/专家 解释
Dense 374M 38.6 374M 与 Top-1 激活参数近似
Dense 570M 39.4 570M 与 Top-2 激活参数近似
MoE Top-1 40.5 1 expert 稀疏容量本身有效
MoE Top-2 41.6 2 experts 比 Top-1 高 1.1 点
MoE Dynamic 42.3 inference 平均 1.76 experts 比 Top-2 高 0.7 点

Dynamic 最大收益出现在 BBH：25.6 vs Top-2 的 23.3，+2.3 点；但 ARC-e 反而是 39.9 vs 40.4。五项 benchmark 的平均改进支持“动态分配有潜力”，却没有多随机种子、置信区间或显著性检验；对从头预训练模型而言，0.7 点是否稳定仍不清楚。

4.2 计算量证据

  • 100B tokens 训练末期，不同 RedPajama 来源平均激活 1.73–1.90 个 experts，总平均 1.82（Table 2）。
  • 五个下游任务平均 1.72–1.87，总平均 1.76（Table 3）；BBH 最高 1.87。
  • Figure 3 显示训练早期超过两个，约 60B tokens 后才低于两个。
  • 改变 inference threshold 时，$p=0.1/0.2$ 性能明显下降；超过某个阈值后平均性能趋稳（Figure 2）。

这里证明的是平均激活参数更少，不是实际 wall-clock 更快。动态排序、变长 dispatch、设备间负载和 batch 内峰值都可能抵消 12% 的理论 expert 节省；论文没有 latency、吞吐、FLOPs 或通信量测量。“继续训练会保证平均成本低于 Top-2”也只是从曲线外推，不是保证。

5. “难输入”与“底层要更多专家”的证据够强吗？

5.1 BBH 更难，但统计序列含 gold answer

作者在计算 Table 3 的专家数时，将 question 与 gold answer 拼成完整输入，再统计所有 token。BBH 的 1.87 高于 PIQA 的 1.72，可能来自推理任务更难，也可能来自答案更长、符号/子词组成不同或模板差异。这个设置不能证明模型在看到问题时就识别了难度。

更干净的验证应只统计共同 prompt 区间，按题内正确/错误、推理步数或人类难度分层，并控制长度和 token 类型。如果专家数能预测单题错误率，标题 claim 才更可信。

5.2 不完整 BPE token 激活更多 experts

论文从七类 RedPajama 来源各采 100 万 tokens，只看频次超过 10,000 的 token。按平均 experts 排序后，top 100 中完整单词只有 10 个，bottom 100 有 51 个（Table 4）；tr/eq/mu/frac 属于高激活例子，to/that/and/show 属于低激活例子。

这说明 router uncertainty 与 token 完整性相关，但“语义歧义导致需要更多参数”仍是解释：高激活组还包含数学/LaTeX 碎片，领域、频率、上下文熵都可能是共同原因。可用同一 token 在不同上下文中的下一个词熵与专家数做回归，才能拆开这些变量。

5.3 底层宽、顶层窄是观察，不是 overthinking 机制

Figure 4 显示平均专家数随层深下降：最底层最高可到 4，顶部接近 1。作者将主结果归因于底层形成更通用的浅层表示、顶部减少“overthinking”。但路由形态是模型联合训练后的相关现象；论文没有把 4→…→1 固定成异构 Top-K 架构，也没有与反向 1→…→4 或 uniform compute 对比。

因此它确实给出一个值得测试的架构假设，却不能解释 Dynamic 胜过 Top-2 的原因。

6. Insights

6.1 真正的控制变量是 router entropy，不是外部难度

累计概率规则测量的是“router 在已有 experts 之间有多犹豫”。这可能对应输入难度，也可能对应路由器未训练好、expert 功能重叠或 token 罕见。若要把它用作 adaptive compute，需要校准：相同 expert 数下，低累计置信度是否真的预测更高 loss；额外 expert 是否对这类 token 带来更大边际收益。

6.2 平均 1.76 可能不是硬件友好的 12% 节省

MoE 系统成本由每个 device 的最大负载和 all-to-all 通信决定，不由全局平均值单独决定。动态 K 让每个 token 的 fan-out 不同，反而可能制造 straggler。工程复现应同时报告 token-expert assignments 的 P50/P95、capacity overflow、通信字节、吞吐和 latency；否则只能称 parameter efficiency，不能称 serving efficiency。

6.3 这篇论文最有价值的是异构层设计假设

如果底层长期选择更多 experts、顶层长期更少，那么完全动态路由未必是最终形态。可以用训练出的分布设计静态异构预算，例如底层 Top-3、中层 Top-2、顶层 Top-1，再比较同 FLOPs 下的性能与硬件效率。它把动态模型当成 architecture search probe，可能比在线变 K 更容易部署。

7. 必须记住的四点

  1. Dynamic MoE 选择累计 router probability 首次超过 $p$ 的最小 expert 集合，并用 entropy loss 防止无限扩张。
  2. 3.5B 总参数、100B token 训练下，它平均激活 1.76 个 experts，五项平均分 42.3，优于 Top-2 的 41.6。
  3. BBH、高歧义子词和底层激活更多 experts 都是相关性现象；特别是 BBH 统计包含 gold answer，不能直接证明模型按题目难度分配算力。
  4. 论文报告的是激活参数，不是实际速度；下一步应做难度校准、loss/dynamic-loss 消融、异构层干预与系统吞吐测试。
