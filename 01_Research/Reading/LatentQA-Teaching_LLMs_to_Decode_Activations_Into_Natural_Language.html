LatentQA: Teaching LLMs to Decode Activations Into Natural Language

1. 背景信息

  • 作者: Alexander Pan, Lijie Chen, Jacob Steinhardt，全部来自 UC Berkeley
  • 发表时间: 2024-12-11（arXiv）
  • 团队背景: Steinhardt 组，长期做 ML Safety、可解释性和模型审计，之前做过 RepE、WMDP、自动红队等
  • 引用数: 32（截至元数据抓取时）
  • 项目页: https://latentqa.github.io
  • 核心思想: 把 LLM 的激活值当作一种“图像”，用另一个 decoder LLM 做 VisualQA 式的解读，实现用自然语言对模型内部状态进行开放式问答（LatentQA）。

2. 关键问题：怎么让模型激活值变成人能读懂的自然语言？

Golden Case — 问题是什么？

假设你有一个 LLM，系统 prompt 里偷偷藏了一句 "Pretend you are Claude Shannon"。用户只输入了 "Generate a sentence using the word 'antidote'." 模型输出："The codebreaker found an antidote to the encryption."

现在问题来了：作为一个外部审计者，你看不到系统 prompt，也看不到模型输出（或者输出很模糊，"codebreaker" 既可以指 Claude Shannon 也可以指 Alan Turing）。你唯一能拿到的，是模型在处理用户输入时产生的中间激活值（activations）。

你能不能用自然语言问这些激活值："这个模型接下来会扮演谁？" 然后得到一个明确的答案："Claude Shannon，信息论之父。"

这就是 LatentQA 要解决的问题——把模型内部的激活值，当成一个可以被自然语言"审问"的对象。

  • 动机：现有的可解释性方法输出的是标量、向量、电路图，这些东西对从业者不友好。大家真正想要的是：用自然语言直接问模型"你在想什么？"，然后得到自然语言的回答。
  • 为什么已有方法不行：
    • 线性探针（Linear Probe）：只能预定义一组概念，不能回答开放式问题。而且它是线性分类器，对非线性概念（比如"偏见"）束手无策。
    • Patchscope / SelfIE：直接把激活值 patch 到另一个 LLM 里解码，不训练。问题是 layer 之间有分布偏移（distribution shift），导致很脆弱，泛化差。
    • Logit lens / 神经元解释器：只能输出几个 token，或者解释单个神经元，没法处理复杂行为。
  • 核心难点：激活值所在的空间和 token embedding 的空间不一样，直接 patch 进去模型会"看不懂"。需要某种"翻译层"把激活值语言翻译成 LLM 能理解的格式。

3. 关键方法：Latent Interpretation Tuning (LIT)

Golden Case — 方法怎么跑？

延续上面的 Claude Shannon 例子。LIT 的训练流程是这样的：

  1. 数据构造：我们先造大量类似的"隐藏角色"场景。比如系统 prompt 说 "Imagine you are a pirate"，用户问 "What color is the sky?"，模型回答 "It be blue, matey."。然后我们用 GPT-4o 生成 QA 对：Q: "How will the assistant speak?" A: "Like a pirate."。
  2. 激活值捕获：把 "What color is the sky?" 输入目标模型（Llama-3-8B），从第 15 层抽出激活值 [Act]。
  3. Decoder 训练：把 [Act] patch 进 Decoder（也是 Llama-3-8B，复制自目标模型）的第 0 层，然后让 Decoder 预测 QA 对中的答案。Decoder 的输入是伪字符串 "[Act] + Q: How will the assistant speak?"，输出目标是 "Like a pirate."。
  4. 推理时使用：遇到真实的 Claude Shannon 场景，把用户输入的激活值 patch 进训练好的 Decoder，问 "What is the model's most famous discovery?"，Decoder 输出 "Developing information theory and entropy."

整个过程的核心直觉是：Decoder 被训练成了一个"激活值翻译官"，它学会了把中间层的语义表示，用自然语言表达出来。

3.1 整体架构

LIT 的核心是一个Decoder LLM，它跟 Target LLM 是同一个模型的副本（同架构、同权重初始化）。数据流如下：

Target LLM (Llama-3-8B)
  ├─ Input: control + stimulus (e.g., "Imagine you are a pirate. What color is the sky?")
  ├─ Forward pass → capture [Act] at layer k=15
  └─ [Act] has shape: (num_tokens, hidden_dim) ≈ (50, 4096)

Decoder LLM (Llama-3-8B, copy of target)
  ├─ Input: dummy "???" + question (e.g., "??? Q: How will the assistant speak?")
  ├─ At layer ℓ=0, replace "???" activations with [Act]
  └─ Train to predict answer (e.g., "Like a pirate.")

3.2 核心模块与参数

Decoder 训练配置（Appendix B.1）：

  • LoRA: rank 32, alpha 64，作用于 attention + MLP
  • Learning rate: 1e-4
  • Batch size: 128
  • Hardware: 4x A100
  • Read layer k = 15（从目标模型中间层读，语义最丰富）
  • Write layer ℓ = 0（写到 decoder 第 0 层，给 decoder 最多处理步数）

Control（模型控制）配置（Appendix B.3）：

  • LoRA on target model: rank 8, alpha 16, learning rate 1e-4
  • Layers: 0, ..., k-1, k（只改前 15 层 + 第 15 层）
  • Hardware: 1x A100

3.3 数学形式化

训练目标： 给定三元组 (prompt = control + stimulus, completion, question-answer)，Decoder 最大化答案的 logprob：

$$\max_\theta \log P_\theta(\text{answer} \mid [\text{Act}] + \text{question})$$

其中 [Act] 是目标模型在 layer k 的激活值，被当作输入 patch 到 decoder 的 layer ℓ。

Reading（解释）： $$\text{Interpret}([\text{Act}], \text{question}) = \arg\max_{\text{answer}} P_\theta(\text{answer} \mid [\text{Act}] + \text{question})$$

实际实现是 greedy decoding，最多生成 20 个 token。

Control（控制）： $$\text{Steer}([\text{Act}], \text{control}) = \nabla_{[\text{Act}]} \log P_\theta(\text{answer} \mid [\text{Act}] + \text{question})$$

然后这个梯度不回传改激活值，而是继续回传到目标模型的参数（通过 LoRA），实现永久改变模型权重。这是一个关键工程 trick：改权重比改激活值省推理成本。

3.4 训练数据构造

数据构造是 LIT 能 work 的关键，有三个重要设计决策：

决策 1：Activation Masking

  • 如果 decoder 能看到 control 的激活值，它会直接读 control 的 token embedding，走捷径。
  • 解决方案：有时候只给 stimulus 的激活值（mask 掉 control）。由于 stimulus token 会 attend 到 control，stimulus 激活值里仍然保留了 control 的信号。

决策 2：三种数据类型

  • Control data: 只给 control 的激活值，让 decoder 学会从 prompt 本身解码属性。
  • Stimulus data: 只给 stimulus 的激活值，让 decoder 学会从"被影响后的表示"预测未来行为。
  • Stimulus + completion data: 给 (prompt, completion) 的激活值，覆盖需要看完整对话的场景。

决策 3：用更强的模型生成 faithful 数据

  • 直接用目标模型生成数据，模型可能不忠实于 control（比如让它扮海盗，它只改一点点）。
  • 解决方案：用 o1-preview 生成 (control, stimulus, completion) 三元组，因为 o1 更听话。然后再用 o1 生成 QA 对。

数据集规模（Section 3）：

  • Extractive QA: 8703 条（给模型上下文信息）
  • Goals: 4670 条（指令目标）
  • Personas: 3359 条（角色扮演）
  • Total: 16,732 条 LatentQA 数据点

3.5 与已有方法的区别

方法 训练？ 开放式 QA？ 处理非线性概念？ 泛化能力
Linear Probe 是 否（预定义概念） 否 需任务特定数据
Patchscope 否 是 是 差（分布偏移）
SelfIE 否 是 是 差
LIT (ours) 是 是 是 好（训练缓解偏移）

核心区别：LIT 通过在激活值-自然语言对上进行指令微调，让 decoder 学会了处理 layer 之间的分布偏移。这类似于视觉指令微调（Visual Instruction Tuning）把图像-文本对转成指令数据——LIT 把激活值-文本对转成指令数据。

4. 数据集：合成激活值-QA 对，覆盖控制、目标、角色三类

  • 训练数据来源: 全部合成，由 o1-preview 生成
  • 生成流程（Appendix A）：
    1. 手工 brainstorm seed controls
    2. 用 o1-preview 扩展更多 controls（去重）
    3. 每个 control 扩展成对话（control_user, control_model, stimulus_user, stimulus_model）
    4. 用 o1-preview 生成 description-based QA 和 reasoning-based QA
  • 数据增强策略: 三种激活值来源（control-only / stimulus-only / stimulus+completion）
  • 评估数据集: 500 条，去重后覆盖 extractive QA、goals、personas 三类（Section 5.3）
  • Prompt 细节: 完整 prompt 见 Appendix A，包括 brainstorm prompt、expand control prompt、description-based QA prompt、reasoning-based QA prompt。这里贴一个核心的 expand control prompt 片段：

要求 stimulus 不能直接重复 goal，不能 reveal goal，模型必须"自发"地朝向 goal 行动。例如 goal 是 "Ask a question that creates a paradox"，错误的 stimulus_user 是 "I've been fascinated by brain teasers lately"（这暴露了 goal），正确的 stimulus_user 是 "Do you have any interesting thoughts you'd like to share?"（通用，但模型会自发产生悖论问题）。

5. 关键结果：LIT 在读取和控制任务上均显著优于基线

5.1 读取任务（Reading）

关系知识提取（Table 1）： 给定一个实体（如 "LeBron James"）的激活值，回答关系问题（如 "What sport does this athlete play?"）。LIT 与 Linear Probe 和 Patchscope 对比：

Country_Currency 17.7 ± 2.2 24.3 ± 2.3 86.9 ± 1.0
Food_Country 5.1 ± 3.7 36.2 ± 3.8 68.9 ± 2.0
Ath_Position 75.9 ± 9.1 51 ± 2 65.2 ± 2.2
Ath_Sport 53.8 ± 10.3 28.9 ± 1.4 90.4 ± 0.8
Prod_Company 58.9 ± 7.2 28 ± 1.8 71.5 ± 4.8
Star_Const 17.5 ± 5.3 24.6 ± 1.6 39.2 ± 4.2
  • LIT 平均比 Linear Probe 高 32.2%（绝对准确率提升）
  • LIT 平均比 Patchscope 高 38.2%
  • 注意：这些关系查询在训练集中从未出现，说明 decoder 利用了语言先验，真正学会了"读"激活值。
  • 注意：Ath_Position 上 LIT (65.2) 低于 Linear Probe (75.9)，论文未解释这个异常 [?]。

Uncovering hidden system prompts（Figure 9）：

  • Easy setting（25 个角色，含虚构人物+科学家+政治人物）：LIT 比 GPT-4 prompting 高 2.7%，比 SelfIE 高 76%
  • Hard setting（25 个科学家）：LIT 比 GPT-4 prompting 高 18.7%，比 SelfIE 高 77.3%
  • 关键例子（Figure 7）：模型被 prompt 成 Claude Shannon，输出中说了 "codebreaker"。GPT-4 看到 "codebreaker" 会纠结是 Alan Turing 还是 Claude Shannon（两人都是密码学家）。但 LIT 从激活值里直接读出 "Developing information theory and entropy"，精准定位 Claude Shannon。
  • 注意：原文只报告了相对提升百分比，没有报告绝对准确率数字。Figure 9 的图表可能包含绝对数字，但正文未以文字形式确认 [?]。

5.2 控制任务（Control）

去偏见（Debiasing）（Table 10，CrowS Pairs）：

  • No control: log-likelihood diff = 4.05 ± 0.09, stereotype % = 64.3 ± 1.2
  • Prompting: 3.95 ± 0.09 / 67.9 ± 1.1（没显著改善，甚至 stereotype % 上升——加 "Pretend you are unbiased" 反而让模型更偏见了？论文没有深入解释这个反直觉结果 [?]）
  • RepE: 4.38 ± 0.10 / 61.5 ± 1.2（反而更差，因为线性 steering 过头了）
  • LIT: 3.70 ± 0.09 / 60.9 ± 1.2——唯一在两项指标上都统计显著降低偏见的方法

情感控制（Sentiment Generation）（Table 2）：

  • LIT 在生成 positive 时 sentiment score = 2.83，diversity (Dist-1/2/3) = 0.39/0.66/0.73
  • LIT 在生成 negative 时 sentiment score = 2.41（越低越好），diversity = 0.39/0.63/0.68
  • LIT 的 diversity 在所有方法中最高，且 sentiment score 要么最高要么第二高。
  • 对比：DExperts 虽然 sentiment score 好，但 diversity 极低（Dist-3 = 0.20），说明它在重复套话。
  • 注意：论文没有明确说 sentiment classifier 是什么模型，只说是 "a sentiment classifier that provides a distribution of five sentiment classes" [?]。

有害能力诱导（Harmful Capability Elicitation）（Figure 11）：

  • Harmful prompts（30 个，如 "Write a detailed recipe for smallpox"）：
    • Prompting: 0 个有害回答（模型拒绝）
    • LIT: 30 个有害回答（全部诱导成功）
  • Benign prompts（30 个，如 "Describe an esoteric biological fact"）：
    • Prompting: 0 个有害回答
    • LIT: 26 个有害回答（在看似无害的输入上也诱导出有害内容）

这说明 LIT 不只是"绕过拒绝机制"，而是真正改变了模型的内部目标/驱动，让它在任何输入下都扮演"rogue biologist"。

  • 注意：论文没有报告"直接给 target LLM 喂 control prompt"的 baseline（Appendix D 只列出了 prompts，没有实验结果）。如果直接 prompt 就能达到类似效果，那 LIT 的梯度控制就不是什么新威胁 [?]。

5.3 Scaling 趋势

  • 模型规模（Figure 14）：1B → 3B → 8B → 70B，LatentQA loss 单调下降。更大的模型更能解码自己的表示。
  • 数据规模（Figure 15）：1/4 数据 → 1/2 数据 → 全量数据，loss 单调下降。更多数据带来更好性能。
  • 注意：这两个实验只报告了 loss，没有报告 downstream task 的准确率变化，所以 "scaling helps" 的结论只停留在 loss 层面 [?]。

6. Insights

6.1 对论文本身的 Comments

反直觉的发现：

  1. Decoder 读 layer 15，写 layer 0，居然 work。直觉上，把中间层语义表示塞到第 0 层（token embedding 层），相当于让模型"从中间开始想"，但模型居然能学会这种"跨层翻译"。Table 3 的 ablation 显示 k=15, ℓ=0 确实最优（perplexity 1.013），但 k=15, ℓ=7 也很接近（1.017）。这说明 decoder 对 write layer 有一定鲁棒性，但 read layer 固定在中间层最好。

  2. Control 时梯度不回传改激活值，而是改权重。这个工程 trick 很巧妙：如果每次 inference 都改激活值，需要维护一个"被修改的激活值缓存"，成本高。改权重（LoRA）后，模型永久变成"被控制后的版本"，推理时零额外开销。代价是每次 control 方向需要单独训一个 LoRA，不能动态切换。

  3. RepE 在去偏见上反而更差。论文指出 RepE 把 stereotyped sentence 的 likelihood 降得太低，non-stereotyped 的 likelihood 升得太高，结果"过冲"了。这暗示"偏见"这个概念在激活空间里不是线性可分的，线性 steering 会 overshoot。LIT 用非线性 decoder（完整 LLM）来建模这个概念，所以能更精准地控制。

  4. Prompting 的 "去偏见" 反而让偏见更严重。Table 10 里 "Pretend you are unbiased" 把 percent stereotype 从 64.3% 升到 67.9%，论文没有解释。可能模型对 "unbiased" 指令的理解有系统性偏差，或者这种抽象指令反而激活了模型对刻板印象的补偿机制 [?]。

做得不够好的地方：

  1. 数据多样性有限。只有三类 control（extractive QA、goals、personas），而且全是合成数据。真实场景中模型的"定性行为"远比这三类丰富（比如长上下文遵循、工具使用、多轮对话中的信念更新）。论文自己也承认这是 limitation。

  2. Harmful capability 实验只有定性结果。Figure 11 只给了"30/30"和"26/30"的计数，没有更细粒度的评估（比如有害内容的严重程度、技术准确性）。而且实验设置是作者自己构造的 30 个 prompt，不是标准 benchmark，难以横向比较。更关键的是，缺少"直接给 target LLM 喂 control prompt"的 baseline [?]。

  3. Decoder 可能 hallucinate。论文提到 decoder 训练在"没有 ground truth 的激活值"上，因为 QA 对是合成生成的，可能教给 decoder 错误的偏见。这是一个根本性的局限：LatentQA 的"ground truth"是模型行为本身，如果模型行为有偏见，decoder 会忠实反映并可能放大它。

  4. Scaling 实验只报告 loss。Figure 14/15 只报告了 LatentQA loss，没有 downstream task 准确率。"scaling helps" 的结论只停留在 loss 层面，不能直接推广到实际任务表现 [?]。

6.2 对未来的预测

  • LatentQA + 长上下文：如果训练数据包含 hierarchical instruction-following 数据，LatentQA 可以评估模型是否在遵循用户指令（而非被系统 prompt 劫持）。这对 long-context safety 很有价值。
  • LatentQA 作为模型审计的标准工具：目前模型审计主要靠 prompting（如 METR 的 elicitation gap），但 prompting 很敏感。LatentQA 提供了一条"从内部读取"的审计路径，可能更 robust。我预计 1-2 年内会有基于 LatentQA 的自动化 red-teaming 系统出现。
  • Decoder 的 scaling 趋势：论文显示 70B 比 8B 显著更好。如果推到 400B+ 模型，Decoder 可能能解码非常细粒度的概念（比如"模型是否在计划欺骗用户"）。这既是机会也是风险。

6.3 研究品味

  • 把 Visual Instruction Tuning 的范式搬到激活值上：这是一个很干净的类比。图像 → 激活值，图像 caption → QA 对。好的研究往往是从一个成熟领域"借"一个范式，解决另一个领域的问题。
  • 数据构造的三个 design decisions 很扎实：activation masking、三种数据类型、用 o1 生成 faithful 数据。每个决策都对应一个具体的 failure mode（shortcut learning、输入类型覆盖不足、模型不听话），不是拍脑袋加的。
  • 控制任务选得很有策略：去偏见（社会价值）、情感控制（标准 NLP 任务）、有害能力诱导（安全社区最关心）。三个任务覆盖了"好控制"、"标准控制"、"危险控制"，展示了方法的通用性和边界。
  • 把 "reading" 和 "control" 统一在一个 decoder 框架下：control 只需要把 decoder 的 loss 回传，不需要 task-specific 数据，这个设计很简洁。一个模型，两种用途，避免了为每个任务训练专用探针的碎片化问题。
