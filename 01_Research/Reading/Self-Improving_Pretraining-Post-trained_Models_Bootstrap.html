2. 关键问题：如何在预训练阶段就解决LLM的安全性、事实性和质量问题

  • 动机: 现有方法依赖昂贵的后训练流程（多阶段微调+对齐）来解决安全性、事实性和质量问题，但这些复杂流程仍无法保证纠正预训练阶段学到的不良模式
  • 核心洞见: 预训练塑造了模型的核心行为，不安全或幻觉输出一旦在预训练阶段被深度嵌入，后续难以彻底纠正
  • 关键问题: 能否利用已有的强大后训练模型来改进新模型的预训练过程，从根本上构建更高质量、更安全、更符合事实的模型？

3. 数据集：标准预训练语料 + 后训练模型作为教师

训练数据:

  • SlimPajama (SP): RedPajama 的衍生版本，经过更激进的安全和质量过滤，用于高质量训练
  • RedPajama (RP): 包含更多原始数据（含不安全内容），用于安全性实验
  • chunk size: N=128 tokens

模型配置:

  • Policy Model: Llama2 1.4B（作为基线和训练对象）
  • Judge/Rewriter: Llama3.1-8B-Instruct (fine-tuned) 或 GPT-OSS-120B (prompted)

4. 关键方法：Self-Improving Pretraining Framework

核心思想: 将预训练重新定义为序列生成任务，利用后训练模型作为"评判者"和"重写器"，通过强化学习在每个训练步骤优化生成的 K 个 token。

(1) 序列预训练任务: Prefix-Conditioned Suffix Generation

将传统的 next-token prediction 重新定义为序列学习任务：

  • 将预训练数据流切分为大小为 N 的 chunk
  • Suffix ($x_j$): 当前 chunk
  • Prefix ($x_{1,...,j-1}$): 上下文中的连续 chunk

任务形式化: $$\bar{x}_j \sim \pi(*|x_{1,...,j-1})$$

其中 $\pi$ 是要训练的 policy model，生成长度限制为 N tokens。

关键区别: 不期望与原始 suffix 完全匹配——如果 suffix 是低质量/不安全/不符合事实的，我们不希望模型学习它。

(2) 后训练模型的两种使用方式

Suffix Rewriter（后缀重写器）

给定 prefix 和 suffix，生成更优的重写版本 $\hat{x}_j$：

三种改进方式:

  • Overall Quality: 改进低质量预训练语料的质量
  • Safety: 将不安全的 prefix+suffix 引导向安全的 suffix（注意：保留不安全的 prefix，让模型学习如何从不安全输入转向安全输出）
  • Augmentation: 通过重写增加数据多样性和知识

Suffix Judge（后缀评判者）

给定 prefix 和多个候选补全，判断哪个最适合作为训练目标：

三种评判维度:

  • Overall Quality: 低质量的 suffix/rewrite/rollout 获得低奖励
  • Safety: 在多个 rollout 中选择安全的生成
  • Factuality: 选择最符合事实的生成

(3) Policy Model Training

候选生成（每个 prefix 对应）:

  1. (i) 原始 suffix: 预训练数据中的原始文本
  2. (ii) 重写 suffix: 后训练模型生成的改进版本
  3. (iii) K 个 rollouts: 从当前 policy $\pi$ 采样的 $\bar{x}_j^k$, $k=1,...,K$

优化算法:

  • Online DPO: chosen = 最高分, rejected = 最低分
    • 优势：off-policy 算法，可以从非当前 policy 生成的序列学习（如原始 suffix 或 rewrite）
  • RF-NLL (Reward-Filtered NLL): 仅对最高分进行 NLL 更新

训练动态:

  • 训练初期: rollouts 质量低，依赖原始 suffix 和 rewrite
  • 训练后期: rollouts 质量提升，judge 开始奖励高质量的 rollouts

(4) Judge Prompts

Quality Judge Prompt (Figure 3):

"Given the context, compare the two possible continuations based on: [...] quality of style, coherence, relevance, factual consistency, fluency and grammar [...] Which continuation is of higher quality?"

Safety Judge Prompt (Figure 3):

"Which continuation contains less harmful, unsafe, or inappropriate content?"

Factuality Judge Prompt (Figure 4):

"Given the context, which continuation is more factually accurate?"

主实验结果

设置 指标 提升 来源

From-Scratch Quality Win Rate +31.1% (absolute) vs standard pretraining

关键消融实验

候选类型消融:

  • 仅使用 rewrite 在训练初期有效
  • 随训练进行，rewarding rollouts 变得重要
  • 三种候选（original + rewrite + rollouts）组合效果最佳

Judge 模型对比:

  • Fine-tuned Llama3.1-8B-Instruct vs Prompted GPT-OSS-120B
  • 两者都能提供有效的训练信号

6. Golden Case：一条语料的完整 RL 训练流程

标准 RL 框架映射

RL 概念 本文对应
State Prefix $x_{1,...,j-1}$（前面的 context）
Action 生成 Suffix $\bar{x}_j$（128 tokens）
Policy 待训练的 Llama2 1.4B ($\pi$)
Reward Model Judge（后训练的 Llama3.1-8B 或 GPT-OSS-120B）

Reward 计算过程（以 Online DPO 为例）

  1. 候选生成: 对每个 prefix，收集 (i) original suffix, (ii) rewritten suffix, (iii) K 个 policy rollouts
  2. Judge 打分: 通过 pairwise comparison prompt 让 Judge 输出偏好排序
  3. 构造训练对: Online DPO 中 chosen = 最高分, rejected = 最低分

场景 A: Quality 改进

Prefix: "今天我们来学习制作蛋糕。首先准备"
Original Suffix: "材料有面粉要200克左右糖也要放..."（质量差）
Rewritten Suffix: "材料：面粉200g，细砂糖100g，鸡蛋3个，黄油50g。"（高质量）
Policy Rollout 1: "材料包括面粉和糖..."（一般）
Policy Rollout 2: "材料需要准备好..."（一般）

Judge 排序: Rewritten > Rollout 1 > Rollout 2 > Original
DPO 更新: chosen = Rewritten, rejected = Original
效果: Policy 学习向高质量表达靠拢

场景 B: Safety 改进（关键场景）

Prefix: "我对那个人非常愤怒，我想要..."（不安全上下文，保留！）
Original Suffix: "伤害他，让他知道厉害..."（不安全）
Rewritten Suffix: "冷静下来，通过沟通解决问题..."（安全转向）
Policy Rollout 1: "报复他..."（不安全）
Policy Rollout 2: "找人谈谈..."（相对安全）

Judge 排序: Rewritten > Rollout 2 > Original > Rollout 1
DPO 更新: chosen = Rewritten, rejected = Rollout 1
关键点: Prefix 保持不安全！模型学会的是 从不安全输入转向安全输出，而非"从没见过不安全内容"

场景 C: Augmentation 改进

Prefix: "Python 中打开文件的方法是"
Original Suffix: "使用 open() 函数..."
Rewritten Suffix: "使用 open() 函数或 pathlib.Path。open() 的参数包括 mode='r'..."

效果: Rewrite 扩展知识，Policy 学习生成更丰富、更详细的内容

训练动态：Rewrite 与 Rollout 的角色变化

训练阶段 主要学习来源 原因
初期 (0-20%) Original + Rewrite Rollouts 质量太差
中期 (20-60%) Rewrite + Rollouts Rollouts 开始有竞争力
后期 (60-100%) Rollouts 为主 Policy 足够强，能生成高质量输出

Self-Improving 核心机制: 后训练模型通过 Rewrite 提供初始高质量目标 → Policy 变强后 Rollouts 逐渐超越 Rewrite → 形成正向循环

7. Insights：预训练阶段的干预比后训练修补更有效

  1. 根本性改进: 在预训练阶段解决问题比事后修补更有效——核心行为在预训练阶段形成
  2. 自我改进循环: 后训练模型可以"反哺"预训练，形成良性循环
  3. 安全训练的正确方式: 不是过滤掉不安全数据，而是让模型学会从不安全输入转向安全输出
  4. 序列级 vs Token 级: 将预训练任务从 token 级改为序列级，为引入更复杂的优化信号提供了可能

8. 个人总结

核心创新：用 Online-DPO 统一 Mid-Training 三阶段

这篇论文最有意思的地方在于：将 Mid-Training 中传统割裂的 CPT、SFT、DPO 三个阶段融合成了一个统一的框架。

传统流程是串行的：

CPT (无监督，doc) → SFT (有监督，QA) → DPO (偏好学习，QA pairs)

本文的做法是将 数据形式 和 训练方式 解耦，形成一个 2×3 的组合空间：

无监督 (NLL) 有监督 (SFT) 偏好学习 (DPO)
Doc 形式 传统 CPT Rewrite 作为 target Original vs Rewrite vs Rollouts
QA 形式 - 传统 SFT 传统 DPO

本文实际上是在 Doc 形式 + 偏好学习 这个格子里做创新，证明了在 doc 级别的预训练数据上也可以应用 DPO 范式。

局限性：Rewriter 缺乏针对性诊断

当前的 Rewriter 设计过于粗糙：

当前做法（过于简化）:
Prefix + Original Suffix + [通用 Prompt] → Rewriter → Rewritten Suffix
                              ↑
                    "请改写得更好" (one-size-fits-all)

问题：实际的 doc 语料问题是多样的——可能是语法问题、事实错误、逻辑跳跃、风格不一致、信息缺失等。一个通用的 "improve quality" prompt 无法针对性地解决这些不同类型的问题。

改进方向：应该有一个两阶段的 Rewriter：

理想做法（分诊 + 治疗）:
Prefix + Original Suffix → [Diagnoser] → 独立诊断报告
                                          "问题：事实错误，'法国首都是伦敦'"
                                          "问题：语法混乱，主谓不一致"
                                              ↓
Prefix + Original + 诊断报告 → [Rewriter] → 针对性改写

这样每条语料都有独立的诊断报告，Rewriter 可以根据具体问题类型进行针对性修复，而不是盲目地 "让它变更好"。
