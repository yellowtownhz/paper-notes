2. 关键问题：如何在不依赖人工标注的情况下显式奖励 Chain-of-Thought 推理？

核心挑战

当前 LLM 后训练的主流范式是 RLVR (Reinforcement Learning with Verifiable Rewards)，但存在一个根本性局限：

问题1：CoT 推理质量缺乏显式监督

原文:

"CoT is rarely rewarded or optimized explicitly, even often regarded as a by-product of outcome-centric optimization objectives in large-scale reinforcement learning with verifiable rewards (RLVR). This yields an underconstrained learning signal: for the same final answer, many distinct reasoning trajectories receive identical rewards, allowing optimization to drift toward shortcut or brittle strategies."

  • RLVR 只奖励最终答案的正确性，CoT 本身几乎不被直接奖励
  • 同一最终答案的不同推理轨迹获得相同奖励，导致优化可能漂移向"捷径"或脆弱策略
  • 根本问题：underconstrained learning signal（学习信号欠约束）

问题2：直接奖励 CoT 的两大实践障碍

挑战 具体问题
标注成本高 训练额外的 reward model 需要 labor-intensive、fine-grained 的人工标注
分布漂移 Policy 的 CoT 分布在训练过程中不断变化，导致 non-stationary、potentially biased 的监督

核心洞见

关键问题：Policy model 能否自己提出 CoT 评估标准（rubrics），并在训练过程中自我演化这些标准——全程无需人工标注？

原文:

"Can the policy model self-propose rubrics as CoT supervision criteria and self-evolve them during training with no human annotations? If so, this could enable a new paradigm of self-improving reasoning, shifting RL from optimizing what LLMs answer to autonomously improving how LLMs think."

4. 关键方法：RLCER (Reinforcement Learning with CoT Supervision via Self-Evolving Rubrics)

核心思想: 将 RL 的优化目标从"优化 LLM 回答什么"扩展到"自主改进 LLM 如何思考"，通过 self-proposed 和 self-evolving 的 rubrics 提供无需人工标注的 CoT 监督。

(1) 整体架构：One Policy, Two Roles

单一 policy model 同时扮演两个角色：

角色 符号 功能
Reasoner $\pi_\theta^{Rea}$ 回答问题，生成 CoT $\hat{\mathcal{C}}$ 和最终答案 $\hat{\mathcal{A}}$
Rubricator $\pi_\theta^{Rub}$ 基于问题和 CoT 生成 K 条 rubrics，用于评估 CoT 质量

(2) 核心组件

Reasoner Rollout (Eq. 4)

$$\hat{\mathcal{C}},\hat{\mathcal{A}}\sim\pi_{\theta}^{Rea}(\cdot\mid\mathcal{Q})$$

Rubricator Rollout (Eq. 5)

$$\hat{\mathcal{R}}\sim\pi_{\theta}^{Rub}(\cdot\mid\mathcal{Q},\hat{\mathcal{C}}), \quad \hat{\mathcal{R}}\triangleq\{\hat{\tau}_{k}\}_{k=1}^{K}, \ \hat{\tau}_{k}\triangleq(\hat{c}_{k},\hat{s}_{k})$$

其中每条 rubric $\hat{\tau}_k$ 包含：

  • $\hat{c}_k$: rubric 内容（自然语言描述）
  • $\hat{s}_k$: rubric 满足时的推理行为示例

CoT Reward 计算 (Eq. 6)

通过 verifier $\pi_\phi$ 评估 CoT 对各 rubric 的满足程度：

$$r_{cot}^{Rea}=\texttt{norm}\Big(\sum_{\hat{c}_k\in\hat{\mathcal{R}}_{valid}}\pi_{\phi}(\hat{c}_{k},\hat{\mathcal{C}})\Big)$$
  • $\pi_{\phi}(\hat{c}_{k},\hat{\mathcal{C}})\in\{0,1\}$: verifier 判断 CoT 是否满足 rubric
  • $\texttt{norm}(\cdot)$: min-max 归一化到 $[0,1]$

(3) Valid Rubrics 定义

一条 rubric $\hat{\tau}_k$ 被视为 valid 需满足两个条件：

条件 数学表达 直觉解释
与答案正确性正相关 $\mathtt{corr}(\mathbf{v}_{k},\mathbf{z}) > \alpha$ 满足该 rubric 的 CoT 更可能得到正确答案
具有区分度 $\mathtt{std}(\mathbf{v}_{k}) > 0$ 不同 CoT 的满足程度不同，避免所有 CoT 都满足

其中：

  • $\mathbf{v}_k \triangleq [\pi_\phi(\hat{c}_k, \hat{\mathcal{C}}_0), ..., \pi_\phi(\hat{c}_k, \hat{\mathcal{C}}_N)]$: N 个 rollouts 对 rubric k 的满足向量
  • $\mathbf{z} \triangleq [\mathbb{I}(\mathcal{A}, \hat{\mathcal{A}}_0), ..., \mathbb{I}(\mathcal{A}, \hat{\mathcal{A}}_N)]$: N 个 rollouts 的答案正确性向量

(4) 奖励函数设计

Reasoner 总奖励 (Eq. 8-9)

$$r^{Rea} = r^{Rea}_{outcome} + r^{Rea}_{cot}$$
$$r^{Rea}_{outcome} = \begin{cases} 1, & \texttt{is\_equiv}(\mathcal{A},\hat{\mathcal{A}}) \\ -1, & \text{Otherwise} \end{cases}$$

直觉：同时奖励"回答正确"和"推理质量高"

Rubricator 总奖励 (Eq. 10-12)

$$r^{Rub} = r^{Rub}_{evolving} + r^{Rub}_{format}$$
$$r^{Rub}_{evolving} = \frac{K_{valid}}{K}$$

直觉：奖励生成的 rubrics 中 valid 的比例，鼓励产生更有信息量的 rubrics

(5) 自演化机制

关键问题：Rubrics 可能 "saturation"——当所有 rollouts 都满足某 rubric 时，它失去区分能力。

解决方案：通过 $r^{Rub}_{evolving}$ 奖励驱动 rubricator 持续产生更具挑战性、更有信息量的 rubrics：

  • Rubric 满足度与答案正确性的正相关（$\mathtt{corr} > \alpha$）
  • Rubric 具有足够区分度（$\mathtt{std} > 0$）

(6) 优化目标 (Eq. 13)

使用 PPO 分别优化两个角色：

$$\mathcal{L}(\theta) = -\mathbb{E}_{\mathcal{Q}\sim\mathcal{D}}\Big[\mathbb{E}_{\boldsymbol{o}\sim\pi^{Rea}_{\theta_{\text{old}}}(\cdot\mid\mathcal{Q})}[\min(...)] + \mathbb{E}_{\boldsymbol{o}\sim\pi^{Rub}_{\theta_{\text{old}}}(\cdot\mid\mathcal{Q},\hat{\mathcal{C}})}[\min(...)]\Big]$$

重要说明：GRPO 不适用于本方法，因为 rubricator 在不同 contexts 下运行，无法满足 GRPO 要求的 same context grouping。

6. Golden Case：一条数据的完整训练流程

Step 1: Reasoner Rollout

输入问题 $\mathcal{Q}$: 一道数学推理题

Reasoner 生成:

  • CoT $\hat{\mathcal{C}}$: 分步骤推理过程
  • 答案 $\hat{\mathcal{A}}$: 最终数值答案

Step 2: Rubricator Rollout

输入: 问题 $\mathcal{Q}$ + CoT $\hat{\mathcal{C}}$

Rubricator 生成 K 条 rubrics，例如：

  1. "推理过程是否正确使用了给定的条件？"
  2. "中间计算步骤是否有验证？"
  3. "最终答案是否与推理过程一致？" ...

Step 3: Valid Rubrics 筛选

对 N 个 rollouts:

  • 计算 $\mathbf{v}_k$（rubric k 的满足向量）
  • 计算 $\mathbf{z}$（答案正确性向量）
  • 检查 $\mathtt{corr}(\mathbf{v}_k, \mathbf{z}) > \alpha$ 且 $\mathtt{std}(\mathbf{v}_k) > 0$

Step 4: 奖励计算

Reasoner 奖励:

  • $r^{Rea}_{outcome}$: 答案正确吗？(1 或 -1)
  • $r^{Rea}_{cot}$: CoT 满足多少 valid rubrics？(归一化到 [0,1])

Rubricator 奖励:

  • $r^{Rub}_{evolving}$: 生成 rubrics 中 valid 的比例

Step 5: 策略更新

通过 PPO 分别更新 Reasoner 和 Rubricator 的 advantage

7. Insights：从 "优化答案" 到 "优化思维" 的范式转变

核心洞见

  1. 无需人工标注的 CoT 监督是可能的

    • 通过 self-proposed rubrics，模型可以自主生成 CoT 评估标准
    • 通过与答案正确性的相关性验证，确保 rubrics 的有效性

  2. Rubric Saturation 问题与自演化机制

    • Static rubrics 会失去区分能力
    • Self-evolving 机制通过奖励 valid rubrics 的比例，驱动持续改进

  3. 推理时也能利用 rubrics

    • 论文还探索了将 self-generated rubrics 作为 in-prompt hints 使用
    • 进一步提升 inference-time 性能

8. 总结

核心创新

首次实现无需人工标注的 CoT 显式监督，通过 single policy 同时扮演 reasoner 和 rubricator，实现 rubrics 的 self-proposition 和 self-evolution。

⚠️ 有效性边界：该方法的有效性很大程度上取决于 verifier 的质量和 self-evolution 动态的稳定性。论文实验结果在数学推理领域表现良好，但在更复杂、更开放的领域可能遇到挑战。

局限性

  1. Verifier 依赖: 需要一个 verifier $\pi_\phi$ 来判断 CoT 是否满足 rubric，这本身可能需要蒸馏或训练
  2. 计算开销: 需要同时训练两个角色，计算量比 vanilla RLVR 更大
  3. Rubric 质量依赖模型能力: 初始模型需要足够强才能生成有意义的 rubrics

⚠️ 批判性分析：共谋风险与 Meta-Verifier 脆弱性

风险1："共谋"问题（Collusion）

本质风险：单一 policy 同时扮演 Reasoner 和 Rubricator，存在结构性共谋风险。

共谋场景 具体表现
Rubric 退化 Rubricator 生成"容易满足"的 rubrics，让 Reasoner 轻松拿高分
循环强化 Reasoner 学会生成刚好满足当前 rubrics 的"表面合规"推理
虚假相关性 找到与答案正确性统计相关但无因果关系的捷径

论文的缓解机制及其局限：

  • Valid Rubrics 双重约束（正相关 + 区分度）试图缓解
  • 但：如果 Reasoner 和 Rubricator 共享参数，它们可能"串通"找到满足条件的 rubrics，却非人类认可的好推理标准

风险2：Meta-Verifier 的关键性与脆弱性

为什么 Verifier $\pi_\phi$ 是整个 self-evolving 循环的锚点：

Rubricator 生成 rubric ──→ Verifier 判断 CoT 是否满足 ──→ 计算 valid 比例
         ↑___________________________________________________________↓
                              (反馈循环)

Verifier 定义了"什么是好的推理"，其判断质量直接决定 rubrics 演化方向。

论文的实现及其局限：

  • 从 Doubao-Seed-1.6-thinking 蒸馏 Qwen3-4B-Base 作为 verifier
  • 本质上用更强的教师模型监督，但这带来问题：
问题 说明
Verifier 能力上限 蒸馏后的 4B 模型能否准确判断复杂推理？
Verifier 偏见传递 教师模型的偏见会被编码到 verifier 中
分布外泛化 对训练时没见过的推理模式，verifier 可能失效

风险3：Self-Evolution 动力学的不稳定性

挑战A：Rubric 空间的探索不足

  • 论文未讨论 Rubricator 如何探索新 rubric 类型
  • 若初始 rubrics 质量差，可能陷入局部最优
  • 类比：让人自己出题自己考，若一开始出题能力就差，很难通过"自我考试"突然变出好题目

挑战B：奖励信号稀疏 $$\frac{K_{valid}}{K}$$ 作为奖励可能太稀疏：

  • 早期：大多数 rubrics 不 valid → 信号弱
  • 后期：收敛到固定模式 → 失去演化动力

挑战C：与 Outcome Reward 的耦合问题 $$r^{Rea} = r^{Rea}_{outcome} + r^{Rea}_{cot}$$

  • 若 $r^{Rea}_{outcome}$ 权重过高，模型可能忽略 rubric 监督，退化为 vanilla RLVR

改进方向

  1. 引入外部 verifier 校准: 用更强模型（如 GPT-4）定期校准，或引入人类反馈
  2. Rubric 多样性奖励: 不仅奖励 valid 比例，还奖励 rubric 类型多样性
  3. 显式 exploration 机制: 如 curiosity-driven 奖励鼓励生成新颖 rubrics
  4. 解耦 Reasoner 和 Rubricator: 完全共享参数可能容易共谋，可考虑部分解耦
  5. Verifier-free 方案: 探索无需单独 verifier 的 rubric 评估方法
  6. 多模态扩展: 将 RLCER 扩展到视觉推理等非文本领域
  7. 与 Process Reward Model 结合: 结合 PRM 的细粒度监督，进一步提升效果
