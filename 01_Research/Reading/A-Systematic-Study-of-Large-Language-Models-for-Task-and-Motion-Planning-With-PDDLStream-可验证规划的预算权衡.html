A Systematic Study of Large Language Models for Task and Motion Planning With PDDLStream

最值得记住的结论：当任务已有精确的形式化描述和成熟规划器时，把规划组件换成 LLM 并没有自然带来收益。本文更有意思的发现是：有外部验证与纠错时，单次回答更认真，不一定意味着整个系统更容易按时求解。 但这是一组受时间预算约束的组件替换实验，不能外推为“LLM 不会规划”。

读完保留四点：传统规划基线很强；快速生成与外部纠错的组合通常优于慢推理；联合生成动作和几何参数没有兑现预期；模型生成的规则仍需由真实任务约束独立检查。

1. 背景与阅读版本

作者来自 Stony Brook University 电气与计算机工程系。本笔记依据 2026-07-17 的 arXiv v2 全文，而非搜索中仍常见的旧版摘要；新版测试 Gemini 2.5 Flash、Gemini 3 Flash 和 GPT-5 mini，报告 13,750 次评估。这不是 13,750 个独立任务，重复运行与多个算法也计入评估总量。

原文：HTML 全文；代码、结果与对话记录仓库。本文没有训练新模型，主要贡献是系统比较不同接入位置及其失败机制。

2. 关键问题：逻辑上能拿起蓝箱，为什么机器人还是拿不到？

Golden Case：论文 Fig. 1 的 Blocked 场景。 目标是把两个蓝箱中的任意一个放到绿色区域，但近处的蓝箱被红箱挡住。可行策略是先移走红箱，或改拿较远的蓝箱。

下面只是对原场景的流程解释，不是作者的一条实测对话：任务层提出“移动过去 → 抓蓝箱 → 放到目标区域”，看上去完全合理。然而，抽象动作的前置条件并未表达“必须先挪红箱”，运动层找不到无碰撞抓取或路径。满足符号规则，并不等于存在可执行的连续运动。（§III、§VI-A、§VII）

任务与运动规划（TAMP）因此要联合回答两件事：做什么动作，以及在什么位置、以什么轨迹执行。PDDL 描述离散谓词、动作及其前置条件；PDDLStream 再用黑箱采样器和检验器补上连续几何约束。

LLM 的潜在优势很直观：如果能看懂几何信息，是否可以提前想到“挪红箱”，避免传统算法盲目尝试？本文问的就是：在保留可靠验证器的前提下，让 LLM 接管哪一层，才能改善成功率或时间？

来源：原文 Figure 1 左图。绿色区域是目标，近处蓝箱受到阻挡。这个几何约束让“先挪开障碍”和“换一个目标”成为规划选择，也说明逻辑上允许抓取不等于运动路径可行。

3. 关键方法：保留 TAMP 搜索与验证，只替换候选生成组件

沿用挡箱案例，系统的数据流是：

给定 PDDLStream 任务、初始状态和目标
    → TAMP 调度符号规划与连续采样
    → LLM 或传统组件提出动作序列／位置参数
    → 检查动作前置条件、几何可行性和最终目标
    → 失败：返回具体错误，继续搜索或重新询问
    → 成功：得到满足约束的动作与连续参数

例如，近处蓝箱的抓取失败后，系统可以把几何失败反馈给规划环节；bilevel 的回溯失败还会为失败动作增加要求移动阻挡物的前置条件。关键是失败必须反馈到动作选择层：对同一条不可行计划不停换抓取位置，未必能解决问题。（§III-B、§IV、§V）

三个设计维度，构成 16 种规划器

维度 选择及机制 为什么影响结果
外部搜索 adaptive：以乐观的符号候选指导 stream 求值，累积真实样本，并平衡任务规划与采样时间 能频繁调整候选，但原本便宜的符号规划换成 LLM 后可能成为成本瓶颈
外部搜索 bilevel：先选符号计划，再回溯搜索连续参数；失败才重新规划 适合多数符号计划可细化的任务；错误动作骨架可能消耗大量回溯时间
替换位置 pddl：LLM 只生成动作序列；poses：只生成放置位姿或 rover 底盘配置；pddl+poses：分别调用两种角色；integrated：一起生成动作和位姿 区分符号能力、连续采样能力，以及联合约束处理是否有收益
推理方式 direct / thinking 比较单次推理质量与多轮搜索速度的取舍

组合是 $2\times4\times2=16$（Fig. 2）。这里的 poses 不是让 LLM 生成所有低层运动轨迹：它替换特定参数采样，运动可行性仍由工程系统检查。论文正文没有完整列出各 API 的具体 thinking budget 与生成参数；精确复现需继续检查代码，不能把 direct 擅自等同于所有模型都严格零推理 token。

Prompt 怎样决定组件边界？

  • pddl 接收谓词、公理、动作、对象、初始状态和目标；强调封闭世界假设与前置条件，要求规定格式的动作列表。它不接收几何细节，后续会接收前置条件缺失或抓取失败等反馈。
  • poses 接收表面与物体的二维轴对齐包围盒，或目标点、场景边界及固定障碍物；返回位姿候选。Prompt 明确区分“局部样本通过”和“全局计划可行”：一个位置当前合法，不代表放上其他物体后仍合法。
  • integrated 额外接收几何对象描述，联合输出动作与位姿，还被要求最小化总动作成本。它理论上能在选动作时避开被挡蓝箱，但实验未观察到足够可靠的几何感知规划优势。（§V-B）

以放置采样为例，stream 的接口可写成：

$$ \operatorname{sample\mbox{-}placement}(\mathrm{surface},\mathrm{object})\rightarrow \mathrm{pose}, \qquad \operatorname{isStable}(\mathrm{pose},\mathrm{surface},\mathrm{object}). $$

位姿是提案，后面的谓词是它必须满足的证书；另有 collision-free 检验。这个区分解释了为什么“采样成功”不能直接当作“规划成功”。（§III-A）

另一个独立实验：model design。 LLM 生成 domain、stream 定义、stream 到给定 Python 函数的映射，以及初始状态与目标；再让 adaptive 规划。此实验提供 一个上下文示例，不能和上述零样例规划混称为全部 zero-shot。最终计划要按真实 PDDLStream 任务判定，不能只在模型自己写的规则内成立。（§IV、§V-D）

4. 实验设置：测的是固定领域内的有预算求解

三类任务展开成七种设置：Blocked；Packing 的 $k=3,4,5$ 个箱子；Rovers 的 $k=2,3,4$ 个拍摄目标。Packing 通过增加箱数压缩可行放置空间；Rovers 让两辆 rover 采集岩石和土壤、拍照并与 lander 通信，障碍物限制可达性和视线，目标数增加也拉长计划。（§VI-A）

每组 50 次试验，最多 300 秒；改变初始连续值，超时或触及 token 资源限制都计失败。Rovers 只测试 adaptive 系列，因为基础 bilevel 在该长时域任务上已经无效；model design 只测 Blocked 与 Packing。主实验已有正确形式化描述，不测从自然语言或视觉中识别任务的能力。（§IV、§VI）

成功率使用精确双侧配对 McNemar 检验并做 Holm 校正，阈值 $p=0.05$。时间检验只纳入成功率至少 30% 的算法，并仅对双方共同成功的实例做配对 Wilcoxon 检验，也做 Holm 校正。图中字母重叠表示未检出显著差异，不是证明两者等价。（§VI-D）

5. 关键结果：快速提案有用，但没有超过成熟基线

5.1 更多内部推理，能否提高整个系统成功率？

作者报告 direct 与 thinking 的 132 组配对比较中，129 组为 direct 无显著差异或更好；三个例外都来自 Gemini 2.5 Flash 的 adaptive-integrated 在 Packing 上的比较。时间方面，在符合检验条件的 35 组比较中，direct 有 32 组显著更快，另 3 组未检出差异。（§VII；成功率见 Fig. 3，时间见 Fig. 4）

这支持的解释是：外部 TAMP 可以纠错时，快速候选允许预算内更多尝试，从而补偿较高的单次错误率。它没有证明 direct 单次更准确，也没有证明 thinking 在 129 组上显著更差。 时间统计只覆盖共同成功的实例，不能解读成包含失败运行的无条件平均耗时。

5.2 LLM 最适合接管哪一层？

非 LLM 方法在全部设置中均未与最佳成功率方法显著区分；时间比较则支持传统规划器更快。因此本文没有显示把组件换成 LLM 能在这些任务上实现整体优势。（§VII、Fig. 3–4）

LLM 内部比较更有信息量：Gemini 3 Flash 的 adaptive-direct-poses 在所有非 Rovers 设置上都未与最佳方法显著区分，包括最拥挤的 Packing $k=5$；GPT-5 mini 中表现较好的也只有 poses 系列。相反，integrated 普遍较差；把 pddl 与 poses 分开都换成 LLM，也没有稳定超过只替换一个组件的方案。

这说明局部连续参数提案至少是一个相对可行的接口，但“能达到相近成功率”不等于“值得部署”，还要计入更长的规划时间。Rovers 更能暴露边界：所有 LLM 方法的成功率均低于 30%，只有 adaptive 基线达到该阈值，因此 Fig. 4 未画 Rovers 时间比较。（Fig. 4 图注）

5.3 给更多几何信息，为什么反而漏掉简单前置条件？

Fig. 6(a) 与 §VII 的日志分析显示，direct-integrated 在 Packing 中仍会漏前置条件，例如尚未移动就试图抓取，或把动作应用于错误的 optimistic object。Rovers 还出现未完成全部目标的计划，例如没有让 rover 返回初始位置。

作者将 integrated 相比 pddl 的较多符号错误解释为几何信息分散了模型对 PDDL 约束的注意。我认为这个结论应收窄：§V-B3 同时改变了几何输入、联合输出责任和成本最小化要求；此外，错误总数也受调用次数影响。因此当前比较支持“这套联合接口更易出错”，尚不足以单独证明“加入几何信息导致注意力转移”。更干净的消融要固定输出与目标，只改变几何输入，并报告每次调用错误率。

5.4 失败不全是“再给一点时间就能好”

Fig. 5 中超时是重要失败来源，但也有主动宣告可解任务无解、触及 token 限制，以及 model design 生成错误规则。后者会遗漏无碰撞约束，甚至把初始状态和目标写成“目标一开始就成立”。验证器若只验证模型自己写的世界，可能认证一个真实世界里的错误解。 本文用真实领域复核，才暴露了这些问题。（§VII）

速度与费用也不能混为一谈：direct 尽管更快，Fig. 6(d) 报告的累计 token 使用反而更多；该统计还排除了因 token 限制失败的任务。Fig. 6(e) 的数量级 FLOPs 差异来自估算，LLM 一侧假定 $10^{10}$ 活跃参数，并非公开的实际参数量或实测能耗。可据此判断成本值得关注，不应引用为精确的能源账单。

6. Insights：下一轮实验应该改变什么？

1. 应优化“每秒获得可验证进展”，而不是只优化一次答题正确率。 direct 较多犯错却有更好的时间表现，说明验证器成本、反馈质量和调用延迟共同决定系统效果。若复现，我会在相同总时间下扫描推理预算，同时记录调用次数、每次正确率与成功率随时间的曲线；再加固定调用次数对照，分开检验“单次更聪明”与“试得更多”。这是从本文结果推出的实验建议，并非作者已完成的消融。

2. Blocked 比 Packing 更适合检验 LLM 是否理解几何约束对动作选择的影响。 Packing 的主要困难是给简单搬运骨架找相容位姿；Blocked 则要求几何失败反过来改变动作序列。本文 pddl 方法在两类任务上的差异正说明这一点。若声称新的 LLM 规划器有联合推理能力，应测它是否在首次几何反馈前就选对“挪红箱／拿远箱”，不能只看最后能否在验证器帮助下完成。

3. 规则生成的评估应保留独立的真值世界。 model design 的“初始即满足目标”错误展示了一个特有漏洞：模型可能通过弱化问题获得形式上的成功。实际使用这类系统时，我会分别检查规则覆盖、计划在真实约束下的有效性与人工建模成本；本文测到了前两者的失败，却没有量化一次建模、多次复用能否摊薄人力成本。

7. 适用范围、连接与材料边界

结论适用于本文三种 LLM、给定 PDDLStream 表达、特定提示与有限预算下的替换方案。实例主要变化是初始连续状态；这不等于开放世界任务泛化，也不覆盖微调、few-shot 规划、感知或真机执行。作者也明确承认其他模型、示例与表达方式可能改变结果。（§VIII）
