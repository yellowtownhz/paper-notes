论文笔记: Trust-Region Adaptive Policy Optimization (TRAPO)

1. 背景信息

  • 作者: Mingyu Su, Jian Guan, Yuxian Gu, Minlie Huang (通讯), Hongning Wang
  • 机构: 清华大学 CoAI Group（Mingyu Su, Yuxian Gu, Minlie Huang, Hongning Wang）+ 蚂蚁集团（Jian Guan）

  • 代码: https://github.com/Su-my/TRAPO

2. 关键问题：SFT 和 RL 的两阶段训练互相伤害，直接合并更是灾难

Golden Case — 问题是什么？

拿 Qwen2.5-Math-7B 做数学推理增强。标准做法：先用 DeepSeek-R1 的 trajectory 做 SFT，再跑 GRPO。听起来合理——先学后练。

结果呢？SFT-then-RL 只比纯 RL 高了 3.9 个点（54.3 vs 50.4, Table 1），远没发挥"既有专家知识、又能自主探索"的潜力。更惨的是，如果你想"聪明一点"——在每个 batch 里同时优化 SFT loss 和 RL loss——直接崩盘：从 50.4 暴跌到 32.3，掉了 18 个点（Table 2）。

问题出在两层：

SFT 的 mode-covering 效应对 RL 有毒。 标准 SFT 最小化 forward KL，本质是让 target policy 覆盖 expert 的所有 mode。用论文的 GMM 实验来说（Figure 3）：两峰的 target 分布去拟合三峰的 expert 分布时，在两个 mode 之间的"空白区"也被填上了概率质量——这就是 distribution blending。

在标准 SFT 里这只是暂时现象（Phase 4 能收敛回来），但 SFT 和 RL 交替时就致命了——那些 void region 的概率质量立刻导致退化输出（重复、乱码），RL rollout 废掉。

SFT 梯度的数学根源。 标准 NLL loss 的梯度有个 $\frac{1}{p_T^\theta(y_n)}$ 项（Eq. 2）。expert token 在当前 policy 下概率很低时（$p_T = 0.001$），梯度权重就是 1000——一步更新就把模型推进 void region。

两阶段串行的根本矛盾。 SFT loss 低不代表 RL 起点好，SFT 过度训练还会灾难性遗忘。但到底 SFT 该训多少才"刚好"？没有信号能告诉你。

核心挑战：怎么在单次训练中同时获得 SFT 的知识蒸馏和 RL 的自我探索，而不让两者互相干扰？

3. 关键方法：用 trust-region 驯服 SFT，用 micro-group 自适应分配专家指导

Golden Case — 方法怎么跑？

一道数学题进来，TRAPO 的处理流程：

  1. Micro-group 1（4 个 rollout，无 prefix）：模型先自己做 4 次。假设全错，pass rate = 0。
  2. Micro-group 2（2 个 rollout，prefix 20%）：pass rate 0 < 阈值 0.5，触发。截取 DeepSeek-R1 轨迹前 20% 作为 prefix，模型续写。假设对了 1 次，累计 pass rate ≈ 0.17。
  3. Micro-group 3（1 个 rollout，prefix 50%）：0.17 < 0.7，继续加码。
  4. Micro-group 4（1 个 rollout，prefix 100%）：还不够 < 0.9，给完整 expert trajectory。

现在有 8 条 trajectory。对 expert prefix 部分，用 TrSFT loss 学习；对模型自己生成的部分，用 GRPO loss 学习。两个 loss 直接加起来更新参数。

如果模型一上来就做对了（micro-group 1 就有正确答案），后续 micro-group 全部做纯 RL——这就是"自适应"。

整体架构

TRAPO 就两件事：TrSFT 解决"怎么从 expert 学而不崩"，Micro-group Sampling 解决"给多少 expert 指导"。两个加起来实现"边学边练"（learn-while-practicing）。

核心模块 1: Trust-Region SFT (TrSFT)

问题：直接加 SFT loss 到 RL loss 上崩 18 个点（Table 2），根源是 SFT 梯度中 $\frac{1}{p_T^\theta}$ 在低概率 token 上爆炸。

标准 SFT loss 梯度：

$$\nabla_\theta L_{\text{SFT}} = -\frac{1}{N}\sum_{i=1}^{N}\sum_{n=1}^{|\mathbf{y}^i|} \frac{1}{p_T^\theta(y_n^i | \mathbf{x}^i, \mathbf{y}_{<n}^i)} \nabla_\theta p_T^\theta(y_n^i | \mathbf{x}^i, \mathbf{y}_{<n}^i)$$

TrSFT 的做法——clip 这个权重：

$$\nabla_\theta L_{\text{TrSFT}}^\alpha = -\frac{1}{N}\sum_{i=1}^{N}\sum_{n=1}^{|\mathbf{y}^i|} \frac{1}{\max(p_T^\theta(y_n^i | \mathbf{x}^i, \mathbf{y}_{<n}^i), \alpha)} \nabla_\theta p_T^\theta(y_n^i | \mathbf{x}^i, \mathbf{y}_{<n}^i)$$

$\alpha \in [0,1]$ 定义 trust region 边界，论文用 $\alpha = 0.1$。

一句话理解：模型觉得某个 expert token 挺合理的（$p \geq \alpha$），正常学；觉得这个 token 很陌生（$p < \alpha$），把梯度权重封顶到 $1/\alpha$，别硬拉。

理论性质（Proposition 1）——TrSFT 最优解：

$$p_T^*(c) = \begin{cases} \frac{p_E(c)}{\lambda}, & \text{if } p_E(c) > \alpha\lambda \\ 0, & \text{otherwise} \end{cases}$$

其中 $S(\lambda) = \{c \mid p_E(c) > \alpha\lambda\}$，$\lambda = \sum_{c \in S(\lambda)} p_E(c)$。

效果：自动砍掉 expert policy 中概率低于 $\alpha\lambda$ 的 token（置零），放大剩余的高概率 mode。从 forward KL 的 mode-covering 转成了 reverse KL 的 mode-seeking——只学 expert 最核心的模式，不在边缘 mode 上浪费概率。

$\alpha$ 选择（Figure 7b / Appendix D）：在 {0, 0.05, 0.1, 0.2, 0.5, 1.0} 中 $\alpha=0.1$ 最优。$\alpha=0$ 退化为标准 SFT（崩）；$\alpha=1$ 所有 token 等权（丢失差异化学习能力）。

核心模块 2: Micro-group Sampling（自适应专家指导）

问题：给每道题多少 expert prefix？简单题给 prefix 浪费探索机会，难题不给 prefix 则 rollout 全废。

做法：把 8 次 rollout 分成 4 个 micro-group，按顺序执行：

Micro-group $g_i$ 采样数 $n_i$ Prefix 比例 $L_i$ 激活阈值 $t_i$
$g_1$ 4 0（无指导） -1（总是执行）
$g_2$ 2 0.2 0.5
$g_3$ 1 0.5 0.7
$g_4$ 1 1.0（完整 trajectory） 0.9

关键设计约束（消融 Table 3/5 验证）：

  1. $L_1 = 0$：第一组必须无指导——保证自由探索
  2. $L_N = 1$：最后一组可以给完整 expert trajectory——兜底
  3. 阈值必须递增（Table 4 验证）：constant 或递减都差。prefix 越长带来的 pass rate 自然越高，后面的 group 要用更高阈值避免过度依赖

注意：Appendix D 的消融表（Tables 3/4/5）用的是 6 个 math benchmark 且只训 100 步，跟主实验（5 benchmarks, full training）条件不同。不影响设计原则的结论，但具体数值不可直接跟 Table 1/2 对比。

训练更新

每个 batch 的总梯度 = TrSFT 梯度（只算 expert prefix token）+ GRPO 梯度（只算模型自己生成的 token），直接相加更新。

$$\nabla_\theta L = \nabla_\theta L_{\text{TrSFT}}^\alpha + \nabla_\theta L_{\text{GRPO}}$$

工程细节

  • 基座模型：Qwen2.5-Math-7B，rope theta 从 10000 调到 40000（因 DeepSeek-R1 轨迹长度到 8k，原始模型只支持 4096）
  • RL 算法：Dr.GRPO（去掉 length normalization 和 std regularization），无 KL penalty
  • RL/TRAPO 框架：verl；SFT 框架：OpenRLHF
  • Rollout 推理：vLLM，temperature = 1.0
  • 训练：batch size 128，max prompt 1024，max response 8192
  • [?] 学习率矛盾：主文 Section 3.1 说 5e-6（constant），Appendix C.2 RL 部分说 1e-6。相差 5 倍，不清楚哪个是实际使用的
  • SFT baseline：92k pairs，2 epochs，lr 5e-5，warmup 0.1，batch size 32，seq length 16384
  • Expert prefix 截断：不是按 token 硬切，而是找到指定比例位置后的第一个推理步骤分隔符（DeepSeek-R1 风格的双换行），保证推理步骤完整
  • 评估：temperature 0.6，max 8192 tokens，Math-Verify + OAT-Grader
  • Prompt 模板：SimpleRL 的最简模板

4. 数据集：基于 DeepSeek-R1 的 46k 数学推理 trajectory + 配对第二条 trajectory

训练数据

  • 来源: OpenR1-Math-46k-8192，从 OpenR1-Math-200k 过滤掉错误 trajectory 和超 8192 token 的
  • 规模: ~46k prompts，每个 prompt 配两条 DeepSeek-R1 的 trajectory（共 ~92k）
  • 预处理: 只保留 <think> 和 </think> 之间的 token，去掉 answer 部分
  • Prefix 采样: 每个 micro-group 随机选两条 trajectory 中的一条作为 guidance source，确保 expert 数据多样性

训练动态（Figure 4）

三个观察：

  1. TRAPO reward 全程高于 GRPO，最终收敛也更高
  2. TRAPO 早期快速增加输出长度（学到了 expert 的长推理模式），GRPO 始终短
  3. 两者 entropy 都先降，但 TRAPO 稳定在更高 entropy——保持了探索多样性

Prefix 使用动态（Appendix F, Figure 8）

训练过程中 expert-guided trajectory 的数量持续下降，而 unguided trajectory 始终占主导。说明 TRAPO 的自适应机制在"自我淘汰"——模型变强后自然减少对 expert 的依赖。这也引出一个问题：既然指导主要在早期有用，一个简单的"随训练 anneal prefix 概率"的 schedule 是否就够了？micro-group 机制是否 overkill？[?]

Test-time Scaling（Figure 6）

k 足够大时，base model Qwen2.5-Math-7B 的 pass@k 超过了 GRPO 训练后的模型。论文解读是纯 RL 主要在帮模型"选"已有的好解，而不是教它新技能。TRAPO 和 SFT 系方法的 pass@k 随 k 增长更快，说明 solution space 确实被扩展了。

不过这里有一个替代解释（见 Insights 6.1）：TRAPO 的 pass@k 优势可能只是 distributional shift 向 R1 风格推理，不一定是"模型内在能力扩展"。

泛化性（Figure 5）

在通用模型 Qwen2.5-7B-Instruct 上 TRAPO 仍然最优。但注意这两个模型都是 Qwen 系列，跨架构（Llama、Mistral）验证缺失。

6. Insights

6.1 对论文本身的 Comments

TRAPO 的 pass@k 优势可能被过度解读。 论文说 TRAPO "effectively expands the model's underlying solution space"，但有一个更简单的解释：TRAPO 通过 SFT prefix 引入了 DeepSeek-R1 的推理模式（backtracking、verification），这些模式在高 k 下自然更容易覆盖到正确答案——这是 distributional shift，不一定是 capability expansion。区分两者需要一个对照实验：在不做 TrSFT、只提供 prefix 做 in-context guidance 的设定下看 pass@k scaling（Table 2 的 "Micro-group without SFT" 配置）。论文没做这个分析。

AIME2024 的弱项跟 TrSFT 的理论直接相关，但论文没提。 TrSFT 的 mode-seeking 性质会剪掉 expert 分布中概率低于 $\alpha\lambda$ 的 mode。AIME 是最难的 benchmark，可能恰好需要那些 rare reasoning strategies（比如非标准的构造方法）。换句话说，TRAPO 在 AIME 上 28.3 vs SFT-then-RL 33.5 可能不是噪声，而是 mode-seeking 的结构性代价。

论文没 ablate 更简单的替代方案。 SFT 梯度在低概率 token 上爆炸——这确实是问题。但 global gradient norm clipping 或 label smoothing 也能缓解。论文直接跳到 TrSFT 而没有对比这些 trivial baselines，削弱了"TrSFT 是必要的"这个论证。

统计严谨性不足。 全文没有报告任何 std/variance/confidence interval。TRAPO vs LUFFY 只差 1.1 个点，AIME2024 只有 30 题用 avg@32 评估。没有多 seed 实验，差异是否显著完全无法判断。

Micro-group 串行执行的开销被轻描淡写。 4 个 micro-group 按顺序执行，意味着每个 prompt 最多 4 次串行推理 pass。这是 TRAPO 比 GRPO 贵 31% 的主要原因，但论文没有分析这个串行瓶颈是否可以放松——比如用训练统计学到的 fixed schedule 替代 online pass-rate 决策。

TrSFT 的 idea 非常优雅。 就是在 SFT 梯度权重上加个 max——一行代码的改动。但 Proposition 1 证明这个 clipping 隐式地把优化目标从 forward KL 的 mode-covering 转成了 reverse KL 的 mode-seeking。如果让我来做这个问题，大概率会直接用 reverse KL 或者 JSD，而不是通过 clip 操作隐式实现。TrSFT 的简洁性和理论优雅性是这篇文章最有价值的地方。

$\alpha$ 的选择缺乏理论指导。 Proposition 1 证明了给定 $\alpha$ 下的最优解性质，但怎么选 $\alpha$ 完全靠 grid search。$\alpha = 0.1$ 对 Qwen + DeepSeek-R1 这个组合最优，但换了模型/数据，最优 $\alpha$ 几乎一定会变——因为它本质上取决于 teacher-student 分布距离。如果 student 已经很接近 teacher，小 $\alpha$ 可能就够；如果差距大（比如 Llama 蒸馏 R1），$\alpha = 0.1$ 可能把有用的东西都剪了。

Micro-group 触发信号太粗。 用 binary correctness（pass rate）决定是否给更多 prefix。对于有部分正确推理但最后一步算错的情况，pass rate = 0 和完全不会做 pass rate = 0 无法区分。如果用 process reward model 或 soft reward signal 做触发，可能效果更好。

6.2 对未来的预测

SFT-RL 融合 2025 年极其拥挤（LUFFY, ReLIFT, SRFT, AMFT, HPT, Prefix-RFT... 半年至少 6 篇）。TRAPO 的 TrSFT 指出了关键洞察：问题不在"SFT 多少 RL 多少"的配比，而在 SFT 的优化目标本身不适合和 RL 共存。接下来大概率会看到更多从 KL divergence 视角重新设计 SFT objective 的工作——比如直接用 $\alpha$-divergence 或 Renyi divergence 替代 forward KL，获得可控的 mode-covering/seeking 平衡。

TrSFT 的"clip 梯度权重"思路足够简单，有可能成为标准工具箱的一部分——类似 PPO 的 clipping 从 RL 论文变成通用组件。但 micro-group sampling 超参太多（每组大小、prefix 比例、阈值），在不同任务上大概率需要重调，实际落地阻力不小。

7. 连接与发现

Topic/Area:

  • MOC-Reinforcement-Learning — Topic: TrSFT 将 forward KL 转为 mode-seeking，解决 SFT+RL 联合训练不稳定问题；配合 micro-group 自适应专家指导，在数学推理上超越纯 RL 和 SFT-then-RL 流水线
  • MOC-Distillation — Topic: TrSFT 作为新型蒸馏目标，通过裁剪梯度权重使专家轨迹蒸馏可以与 RL 在同一训练实例内共存而不崩溃

Concept:
