Haoran Wei, Yaofeng Sun, Yukun Li

论文笔记: DeepSeek-OCR 2: Visual Causal Flow

1. 背景信息

  • 作者: Haoran Wei, Yaofeng Sun, Yukun Li
  • 团队: DeepSeek-AI
  • 发表时间: 2025年1月 (arXiv preprint)
  • 代码: http://github.com/deepseek-ai/DeepSeek-OCR-2

2. 关键问题：如何让视觉编码器像人类一样遵循语义驱动的因果阅读流程

  • 动机: 传统VLM以固定的栅格扫描顺序（从左上到右下）处理视觉标记，引入了阻碍复杂布局推理的归纳偏置
  • 核心问题:
    • LLM天然训练于1D序列数据，而图像是2D结构
    • 直接将图像patch按预定义顺序展平会忽略语义关系
    • 人类视觉遵循语义连贯的扫描模式，由图像内在逻辑结构驱动

"传统视觉-语言模型在将视觉标记输入大语言模型时，始终以固定的栅格扫描顺序进行处理，这种处理方式与人类视觉感知机制相悖。"

3. 数据集：OCR数据占80%，评估使用OmniDocBench v1.5

训练数据采用多源混合策略，评估基准覆盖9类文档场景

  • 训练数据:

    • 数据来源: OCR 1.0 + OCR 2.0 + 通用视觉数据
    • 数据组成比例: OCR数据占训练混合数据的 80%
    • 采样策略: OCR 1.0 将页面划分为文本、公式和表格，比例为 3:1:1，以提升数据平衡性
    • 标签优化: 布局检测标签通过合并语义相似类别进行优化（如"图注"与"图标题"统一）

  • 评估数据:

    • Benchmark: OmniDocBench v1.5
    • 规模: 1,355 页中英文文档
    • 类别: 9 个类别（杂志、学术论文、研究报告等）
    • 覆盖场景: 复杂布局、公式、表格等结构化元素

4. 关键方法：用紧凑型LLM(Qwen2-0.5B)替代CLIP，通过双流注意力机制实现视觉因果推理

核心创新：通过可学习的因果流查询建模视觉标记重排，使编码器能学习语义上有意义的视觉内容重排

整体架构

  • 继承 DeepSeek-OCR 的标记化与解码阶段
  • 将 DeepEncoder 升级为 DeepEncoder V2
  • 在编码器内引入双流注意力机制，解耦全局视觉表示与序列因果建模

核心模块

1. Vision Tokenizer（视觉标记器）

  • 架构: 80M 参数的 SAM-base + 两个卷积层
  • 压缩比: 16倍 token压缩
  • 输出维度: 896（从DeepEncoder的1024降低，以兼容下游LLM）
  • 作用: 将图像块压缩为视觉标记，高分辨率输入时显著节省内存与计算

2. LLM风格视觉编码器

  • 基础模型: Qwen2-0.5B（紧凑型语言模型）
  • 输入序列: 视觉标记 + 等量可学习因果流标记（拼接）
  • 注意力掩码设计:
Token类型 注意力类型 机制说明
Visual Tokens 双向自注意力 类似ViT，保留全局感受野
Causal Flow Tokens 单向下三角注意力 与LLM解码器相同，仅关注先前token

3. Token数量控制（Multi-crop策略）

  • 全局视图: 1024×1024 → 256 个标记
  • 局部裁剪: 最多6个 768×768 视图，每个 144 个标记
  • 总范围: 256 ~ 1120 个标记
  • 设计考量: 与 Gemini-3 Pro 最大视觉标记预算对齐

4. LLM Decoder

  • 模型: DeepSeek-3B MoE 解码器
  • 输入: 仅编码器输出的后半部分（因果流标记）
  • 级联设计: 编码器执行语义重排 → 解码器执行自回归生成

数学形式化

整个前向传播形式化为：

$$\mathbf{O} = \mathcal{D}\left(\pi_O\left(\mathcal{T}^L\left(\mathcal{E}(\mathbf{I}) \oplus \mathbf{Q}_0; \mathbf{M}\right)\right)\right)$$

其中：

  • $\mathcal{E}$: 将输入图像 $\mathbf{I}$ 映射为视觉标记 $\mathbf{V}$
  • $\mathbf{Q}_0$: 可学习的因果查询
  • $\oplus$: 序列拼接操作
  • $\mathcal{T}^L$: 带掩码注意力 $\mathbf{M}$ 的 L 层 Transformer
  • $\pi_O$: 提取因果查询输出
  • $\mathcal{D}$: MoE 解码器，生成输出对数概率 $\mathbf{O}$

训练流程

阶段 训练内容 冻结组件
Stage 1 使用轻量解码器通过下一标记预测预训练编码器 -
Stage 2 联合优化编码器与解码器以增强查询 标记器
Stage 3 专门优化解码器 编码器
  • 优化器: AdamW + 余弦衰减
  • 数据加载: 多分辨率数据加载器
  • 并行策略: 流水线并行
  • 硬件规模: 160 张 A100 GPU

与已有方法的区别

  • 借鉴 DETR 与 BLIP-2 中的并行化查询机制
  • 适配为因果式解码器风格编码器
  • 桥接二维空间结构与一维语言建模

局限性

  • 在报纸等文本密集文档上因标记限制与数据稀缺仍有提升空间

6. Golden case

考虑追踪一个螺旋形状——人眼移动遵循内在逻辑，每次后续注视都因果依赖于前一次注视。类比到模型中：

  • 传统方法：固定从左上到右下扫描，无法捕捉螺旋的语义连续性
  • DeepEncoder V2：通过因果流标记学习语义驱动的重排，每个查询token关注所有视觉token和前序查询，实现渐进式因果重排

7. Insights：LLM架构可作为统一多模态编码的基础，通过模态特定查询处理不同输入

  • 统一多模态编码: 共享参数可通过模态特定查询处理文本、视觉及其他潜在模态
  • 级联因果推理: 两个级联的一维因果推理结构可有效实现二维图像理解
  • 实用工具价值: 既是新型VLM架构的研究探索，也是生成高质量LLM预训练数据的实用工具
  • 基础设施复用: 自然继承LLM社区的先进优化（MoE、高效注意力等）
