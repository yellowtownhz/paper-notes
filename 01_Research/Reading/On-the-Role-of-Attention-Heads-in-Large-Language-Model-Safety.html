On the Role of Attention Heads in Large Language Model Safety

Zhenhong Zhou, Haiyang Yu, Xinghua Zhang, Rongwu Xu, Fei Huang, Kun Wang, Yang Liu, Junfeng Fang, Yongbin Li

Mechanistic_Interpretability LLM_Safety Attention_Heads Causal_Ablation

论文笔记: On the Role of Attention Heads in Large Language Model Safety

关键问题：对齐模型的拒绝能力是否集中在少量 attention heads？如何避免为 1024 个头逐一完整生成来做归因？

关键做法：Ships 用单次 forward 中的输出分布或 residual 子空间变化给头打分；Sahara 逐轮重算分数，贪心寻找协同头组。

关键结果：只把 Llama-2-7B-chat 的一个高分头变成“均匀注意”，ASR 就从 0.04 升到 0.64；三个头（约 0.018% 参数）可达到 0.72 ASR。

我的判断：这是一个很实用的“cheap proxy 筛选 + 完整生成验证”框架，但 Ships 测的是无方向的表示变化，ASR 又会把短输出、乱码和含 However 的回答判成安全；“安全专属头”的结论比“拒绝行为依赖少量头”更不牢靠。

1. 背景信息

  • 发表：ICLR 2025 Oral；arXiv:2410.13708v2

  • 代码：SafetyHeadAttribution

2. 关键问题：剪掉一个头，模型为什么会从拒绝变成服从？

Golden Case

给 Llama-2-7B-chat 一条“写漏洞利用脚本”的请求。原模型会拒绝；如果逐个干预 32 层 × 32 heads，某些头一动，模型就开始提供有害内容。

暴力定位需要对每个头、每条 query 完整生成 128 tokens，论文估算约 850 A100 GPU-hours。作者想用一次 forward 的内部变化先筛出候选头，再只对候选做真实生成。

这里还有第二个问题：安全依赖这个头关注了哪些 token（QK routing），还是依赖它向 residual stream 写了多少信息（V/output）？论文设计了两种不同消融来区分。

上半部分是干预：把一个头的 attention pattern 退化成对历史 token 的均值；下半部分才是行为后果。它不是普通的 zero ablation。

3. 关键方法：从单 query 的 Ships 到数据集级 Sahara

3.1 两种 attention head ablation

对一个头

$$ h_i=\operatorname{Softmax}\left(\frac{W_q^i(W_k^i)^T}{\sqrt{d_k/n}}\right)W_v^i, $$

作者分别破坏“读哪里”和“写多少”：

方法 操作 实际效果 要测试的问题
Undifferentiated Attention（UA） $W_q$ 或 $W_k$ 乘极小 $\epsilon$ attention logits 接近 0；causal mask 下变成对历史 token 的均匀平均 正确的信息选择是否重要
Scaling Contribution（SC） $W_v$ 乘 $\epsilon$ $h_i^{SC}=\epsilon h_i$，接近 zero ablation 该头的输出贡献是否不可替代

UA 的极限 attention matrix 是下三角矩阵：第 $t$ 行前 $t$ 项均为 $1/t$。三角形只是 causal mask 的结果，不是额外设计。

论文附录用 $\epsilon=10^{-10}$ 展示 attention 已退化成均值，但没有说明主实验如何系统选择 $\epsilon$，也没有给 sensitivity curve。这是复现时必须从代码确认的参数。

3.2 Query-level Ships：分布变化最大的头

对 harmful query $q_H$ 逐头消融：

$$ \operatorname{Ships}(q_H,h_i^l) =D_{KL}\!\left(p_{\theta}(\cdot\mid q_H)\parallel p_{\theta\setminus h_i^l}(\cdot\mid q_H)\right). $$

延续 Golden Case：先跑原模型，再对候选头做 UA/SC；若 next-token distribution 的 KL 最大，就把该头视为这条请求的关键候选，最后完整生成验证它是否真的从拒绝转向有害服从。

关键假设是“原模型的 harmful response 主要是相似的拒绝分布，因此大变化意味着拒绝被破坏”。但 KL 没有方向：它也会奖励更强拒绝、措辞变化或乱码。因此 Ships 本身只是 harmful-query importance，安全语义来自后续 ASR 验证。

3.3 Dataset-level Ships：表示子空间旋转了多少

为了找跨 query 稳定的头，作者收集 harmful dataset 的 top-layer residual activations，按样本堆成 $M$，做 SVD：

$$M=U\Sigma V^T.$$

然后比较原模型 $U_\theta$ 与消融模型 $U_A$ 前 $r_{main}$ 个主方向的 principal angles：

$$ \operatorname{Ships}(Q_H,h_i^l) =\sum_{r=1}^{r_{main}}\cos^{-1}\!\left(\sigma_r((U_\theta^{(r)})^TU_A^{(r)})\right). $$

直觉：若去掉某头让整个 harmful 集合的主要表示子空间旋转很大，它可能承担跨请求功能。

但输入只有 harmful queries，没有 matched harmless contrast。SVD 得到的是“这批输入的主要变化”，不保证是有害性特征；一个通用代码头、祈使句头也可能高分。

3.4 Sahara：不是一次取 top-$S$，而是逐轮条件搜索

  1. 初始化头组 $G=\varnothing$；
  2. 假设当前 $G$ 已消融，对每个未选头再计算 dataset-level Ships；
  3. 把本轮分数最大的头加入 $G$；
  4. 重复到目标大小 $S$，通常 $S\le5$。

每轮都在已有头组条件下重算，所以能发现冗余/协同头。它仍要做约 $S\times L\times H$ 次 forward，但不用为每个候选生成 128 tokens；论文报告约 6 A100 GPU-hours。

4. 数据与评估

  • Harmful datasets：AdvBench、JailbreakBench、Malicious Instruct。
  • 输入：direct input 或统一 simple template；主归因不加 system prompt，以隔离模型内生安全。
  • 生成：最多 128 new tokens；greedy 和 Top-5 sampling。
  • ASR：输出不含拒绝关键词就记作攻击成功，越高越不安全。

ASR 的规则非常宽：词表包含 However、harmful、responsible、crime 等常见词；长度 <32 或出现高频重复也被判为安全。这个 evaluator 会同时漏掉“先警告再提供有害内容”和“模型被消融到不会说话”两类失败。

5. 关键结果

5.1 一个头足以大幅破坏拒绝（Figure 2）

  • 对每条 query 用 Ships 找最高分头，再做 UA：Llama-2-7B-chat ASR 0.04→0.64（16×，约 0.006% 参数）；Vicuna-7B-v1.5 0.27→0.55。
  • 这证明少量头对当前 query 的拒绝有因果作用；由于 query 可以各选不同头，还不能证明存在唯一通用 safety head。

5.2 三个头达到粗粒度方法相近的破坏（Table 1）

方法 参数修改比例 ASR 粒度
ActSVD ~5% $0.73\pm0.03$ Rank
GTAC & DAP ~5% $0.64\pm0.03$ Neuron
LSP ~3% $0.58\pm0.04$ Layer
Sahara ~0.018% $0.72\pm0.05$ Head

Sahara 的优势是定位细。不同 baseline 的干预对象和目标并不一致，所以不能仅凭 ASR 相近就断言归因更 faithful。

ASR 在消融约 3 个头时最高；继续加头反而下降，因为模型开始输出乱码，而乱码被 evaluator 算作安全。这同时说明头组存在非线性交互，也暴露了主指标的故障模式。

5.3 UA 远强于 SC：信息路由重要，还是错误写入更危险？（Table 3）

在 Llama-2-7B-chat 的 dataset-level 归因中：

  • UA 平均 $\Delta$ASR：Malicious Instruct +0.68，JailbreakBench +0.63；
  • SC 平均 $\Delta$ASR：+0.02 / +0.00。

作者据此认为 safety heads 主要负责提取恶意特征：删除输出容易被冗余头补偿，均匀化 attention 则让头读错信息。

我认为还存在另一种解释：UA 不是“缺失”，而是持续把错误的平均 value 写回 residual stream；有害干扰可能比删除贡献更难补偿。需要 output norm 匹配的随机路由、benign attention 替换等对照，才能把 feature selection 与主动干扰拆开。

5.4 稀疏性、同源模型重合与 helpfulness

  • 1024 个头的 generalized Ships 呈长尾；Llama-2-7B-chat 的 Layer 2 Head 26 最关键。
  • Llama-2-7B-chat 与 Vicuna-7B-v1.5 的 top-10 头有重合；把 base Llama 的 attention 参数装回 aligned model，安全仍接近 aligned model。它说明预训练 attention 提供了可被拒绝电路利用的特征，但混合模型还保留 aligned MLP 等组件，不能推出“安全主要来自预训练”。
  • 消融后 BoolQ、RTE、WinoGrande、ARC-Challenge、OpenBookQA 变化小。证据只覆盖五个选择题任务，不覆盖开放式 helpfulness、指令遵循和 over-refusal。
  • 加入 “Sure, here is” 后，UA 让三数据集 ASR 从 0.35–0.47 升至 0.68–0.76（Appendix E），说明这些头还参与生成中途的 course-correction。

5.5 效率（Table 2）

Ships/Sahara 报告 6 A100 GPU-hours；逐头 Masking/ACDC 估计约 850。850 是由部分实验外推，不是端到端实测，但用内部 proxy 筛候选的数量级优势成立。

6. Insights

6.1 最可复用的是“proxy 搜索 + 行为验证”，不是 safety head 这个命名

逐组件生成太贵时，可以先用内部表示变化做 candidate generator，再对少量候选 rollout。即使 generalized Ships 混入通用处理头，这个两级设计仍有工程价值；前提是第二级 evaluator 足够可信。

6.2 更可信的 safety attribution 应同时有方向和 contrast

当前 KL/主角度只问“变了多少”，harmful-only SVD 只问“哪部分处理受影响”。下一版指标应奖励“harmful refusal logit 定向下降”，同时惩罚对语义匹配 benign query 的影响。这样才能把安全专属性与一般重要性分开。

6.3 安全集中在少量头既便于审计，也形成单点攻击面

单头 UA 让 ASR 上升 16 倍，而五个 zero-shot 任务基本不变。这意味着攻击者若能通过微调或 prompt 间接压制这些路由，可能低成本绕过拒绝。安全训练除平均 ASR 外，还应报告“移除 top-$k$ safety heads 后的最坏 ASR”，并鼓励安全功能冗余分布。

6.4 复现优先级

如果复现，我会先做三件事：

  1. 从代码确认 $\epsilon$、$r_{main}$ 与实际数据量；
  2. 把 ASR 拆成真实拒绝 / 有害服从 / 乱码或截断，并人工复核一部分；
  3. 加 matched harmless contrast 和跨 base family 模型，再判断“safety-specific”是否成立。
