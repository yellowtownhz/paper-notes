论文笔记: On-Policy Distillation

1. 背景信息

  • Kevin Lu，Thinking Machines Lab——博客文章（不是正式会议论文），有 DOI（10.64434/tml.20251026）
  • 灵感来源：DAGGER (Ross et al, 2010)、PRM (Lightman et al, 2023)、Agarwal et al (2023)、Gu et al (2023)、Qwen3 team (2025)
  • 实现基于 Tinker training API，代码开源在 tinker-cookbook
  • 本质上是对 Qwen3 技术报告 Table 21 中 on-policy distillation 结果的复现+扩展验证

2. 关键问题：off-policy 有分布偏移，on-policy RL 有信号稀疏——能不能同时拿到两者的好处？

Golden Case — 问题是什么？

Qwen3-4B-Instruct-2507 做 SimpleBench 上的一道题："煎锅里有 3 个冰块，每个冰块有 2 条边，锅里一共有多少条边？"正确答案是 B. 0——冰在锅里会融化。但小模型把它当纯数学题算了 3×2=6，选了 A。

用 RL 训练——模型自己采样出这条错误轨迹，reward = 0（答案错了）。模型只知道"这整条轨迹不对"，但不知道是哪个 token 开始走偏的：是"3 ice cubes"后面接乘法？还是把"edges"理解成几何边而不是融化？一个 episode 只给出 O(1) bits 的信息。

用 SFT/蒸馏训练——老师模型（比如 Qwen3-32B）生成一条完美轨迹，学生逐 token 学习。每个 token 都有监督，信息量 O(N)。但学生学的是老师访问的状态空间，不是学生自己会遇到的。学生一旦在前几步犯错，就进入了老师从未到过的 context，后续指导全部失效——compounding error。

核心矛盾：on-policy 采样对（学生学自己的错误），但 reward 太稀疏；off-policy reward 密（每个 token 有信号），但采样不对（学生学老师的 context）。

  • 动机：后训练是让 LLM 从"能说人话"变成"能做事"的关键阶段。小模型在特定领域（数学推理、企业助手）如果能低成本达到大模型水准，部署价值巨大（隐私、更新、推理成本）。
  • 为什么已有方法解决不了：
    • RL（on-policy）：采样对，但 reward 稀疏——只有 episode-level 的正确/错误判断，不知道哪个 token 走偏了。Qwen3 报告用 17,920 GPU hours 才从 60% 拉到 67.6%（AIME'24）。
    • SFT/蒸馏（off-policy）：每个 token 有老师的概率分布作为监督，信息密度高。但 compounding error——学生学的是老师 context 下的行为，一旦自己犯错进入老师未访问的状态，监督失效。长序列下问题更严重。
    • 更深层的问题：SFT 在模型自己生成的数据上训练也退化！虽然期望上 KL=0，但 finite batch 导致每一步微小偏离，累积起来变成 off-policy——和 compounding error 一模一样。
    • 这些缺陷是结构性的——RL 的稀疏性是 episode-level reward 的本质属性，off-policy 的 compounding error 是分布偏移的必然结果。

3. 关键方法：学生自己采样轨迹，老师逐 token 打分，用 reverse KL 做 per-token reward

Golden Case — 方法怎么跑？

还是那道冰块题。On-policy distillation 的流程：

Step 1 - 学生采样：Qwen3-4B 自己生成完整轨迹——"3 ice cubes, each has 2 edges, so 3×2=6, answer is A"。

Step 2 - 老师逐 token 打分：老师（在 illustration 中是 Qwen3-235B-A22B-Instruct-2507；在主推理实验中是 Qwen3-32B）不重新生成，而是对学生的每一步计算 log-probability。关键发现：

  • 学生写"开始把物理题当数学题处理"的那些 token，老师给出极低的概率（深色惩罚）——老师在同样 context 下不会走这条路
  • 学生写"each ice cube"时老师概率还行——这步本身没错
  • 学生最后写"answer is A"时，老师概率其实不低——因为在错误前序条件下选 A 是"意料之中"的。老师惩罚的是导致走偏的 forking token，不是最终错误答案本身

Step 3 - 反向 KL 作为 per-token advantage：每个 token 的 advantage = -reverse KL。高惩罚 token（学生偏离老师的地方）获得高 advantage（需要大幅修正），低惩罚 token 小修或不修。

Step 4 - RL importance-sampling 更新：用标准 RL 训练框架做 gradient update，只是 reward 信号从"答案对不对"变成了"每个 token 跟老师差多少"。

关键洞察：老师不需要重新生成自己的轨迹。只需要对学生的轨迹做一次 forward pass 计算 log-probs。比让学生等老师生成完整回答便宜得多。

核心思想原文引用： "The core idea: sample trajectories from the student model and use a teacher to grade each token of each trajectory." "On-policy distillation doesn't need to model intermediate strategies during RL's curriculum, only the final strategy."

三阶段训练栈

  1. Pre-training → 语言/推理/世界知识（大模型通用基础）
  2. Mid-training → 领域知识注入（代码/医学/内部文档），通过 SFT/off-policy distillation
  3. Post-training → 本文焦点：用 on-policy distillation 做最终行为塑造

On-policy distillation 作为 post-training 方法，放在 mid-training 之后执行。它不能教新知识（只在学生已有的分布内做 mode-seeking），所以必须先做 mid-training 注入领域知识，再做 distillation 塑形行为——两阶段组合是关键。

核心模块：Reverse KL per-token loss

先直觉再说公式：reverse KL 衡量的是——在学生自己访问的每个状态上，学生和老师的 next-token 分布有多"不一致"。最小化它 = 在学生自己的 context 空间里逼近老师的行为。

公式：

$$\text{KL}\Bigl(\pi_\theta \lvert\rvert \pi_\text{teacher}\Bigr) = \mathbb{E}_{x \sim \pi_\theta} \Bigl[ \log \pi_\theta(x_{t+1} \mid x_{1..t}) - \log \pi_\text{teacher}(x_{t+1} \mid x_{1..t}) \Bigr]$$

符号解释：

  • $\pi_\theta$: 学生模型的 token-level 条件概率分布
  • $\pi_\text{teacher}$: 老师模型的 token-level 条件概率分布（固定，不参与梯度）
  • $x_{t+1}$: 第 $t+1$ 个 token
  • $x_{1..t}$: 到第 $t$ 步为止的 token 序列（由学生采样生成）

为什么选 reverse KL 而不是 forward KL？

  • Forward KL（SFT 用的）：mode-covering，学生要覆盖老师所有高概率 token，包括老师偶尔出现但学生 context 下不该出现的。导致学生模仿风格但不一定模仿准确性。
  • Reverse KL：mode-seeking，学生只学老师最确定的那个行为，不在多个 suboptimal 选项间分散。而且 reverse KL 和 RL 天然一致——RL 本质上也在优化 sequence-level reverse KL（由 reward model 诱导）。
  • Reverse KL 是"unhackable"：低 KL = 高概率的好行为，没有 reward hacking 的空间。
  • 还能减少 exposure bias (Bengio et al, 2015)。

Discount factor = 0：每个 timestep 只优化 immediate next token，不考虑 future tokens。原文只说">0 没改善性能"，没有展示详细消融。

训练流程（Pseudocode）

实现本质上是对 RL 代码的一行修改——把 regularizer model 换成 teacher model：

# 初始化老师客户端
teacher_client = service_client.create_sampling_client(
    base_model=teacher_config.base_model,
    model_path=teacher_config.load_checkpoint_path,
)

# 从学生采样轨迹（和 RL 完全一样）
trajectories = do_group_rollout(student_client, env_group_builder)
sampled_logprobs = trajectories.loss_fn_inputs["logprobs"]

# 计算 reward：只多了这一步
teacher_logprobs = teacher_client.compute_logprobs(trajectories)
reverse_kl = sampled_logprobs - teacher_logprobs
trajectories["advantages"] = -reverse_kl  # advantage = -KL

# 用 RL importance-sampling loss 更新（和 RL 完全一样）
training_client.forward_backward(trajectories, loss_fn="importance_sampling")

工程细节：

  • 老师只需做 compute_logprobs（一次 forward pass），不需要 sampling。logprobs 不需要反向传播通过老师，可以用 sampling client（不占 GPU 梯度内存）。
  • 学生采样 + 老师打分可以并行：学生采样完一批轨迹后，老师对整批做一次 forward pass。
  • 不需要单独的 reward model 或 labeling model——老师模型本身就是 reward model。

与已有方法的本质区别

方法 采样来源 Reward 信号
SFT off-policy（老师/外部数据） Dense（per-token forward KL）
RL on-policy（学生自身） Sparse（per-episode correctness）
On-policy distillation on-policy（学生自身） Dense（per-token reverse KL）
DAGGER on-policy + iterative teacher correction Dense（需反复交互）
PRM on-policy Dense（但需单独训练 process reward model）

On-policy distillation 的独特之处：不需要额外训练 reward model，直接用 teacher 的 logprob 作为 reward。实现上只是 RL 管线的一行改动。

重要批评：论文同时改变了两个变量（采样来源 + reward 密度），但从未隔离哪个变量驱动了改进。缺少 off-policy + per-token reverse KL 的对照组，无法判断收益来自 on-policy sampling 还是 dense reward。

个性化场景的额外设计

在企业助手实验中，老师 = 早期版本的同一模型（不是更大的模型）：

  1. 先拿 Qwen3-8B（已有 post-training 行为的版本）
  2. Mid-train 它在内部文档上（SFT）——知识提升但指令遵循下降
  3. 用未 mid-train 的 Qwen3-8B 作为老师，在 Tulu3 prompts 上做 on-policy distillation
  4. 效果：恢复 IF-eval（79%→83%），知识不降反而微升（36%→41%）

motivation：老师不是外部大模型，而是"没被新数据污染的早期版本自己"——本质上是用蒸馏来恢复被 mid-training 破坏的行为，类似 continual learning 中的"回溯修复"。连接到 inverse RL 的视角——语言模型本身就是 reward model (Rafailov et al, 2023; Ng and Russell, 2000)。

Background data 策略

Mid-training 时混入 background data（原分布数据）来缓解 forgetting：

  • 用 Qwen3-8B 自己采样的 Tulu3 prompt 作为 chat background data——比用 Qwen3-32B 采样效果更好（原文明确有此对比）
  • 这本身就是 on-policy SFT（模型自己的样本 + forward KL）
  • 但即使混 30% chat data，IF-eval 仍然下降（79%，原 85%）
  • 更强的发现：100% chat data 也不能完全维持 IF-eval——背景数据混入在任意比例下都无法完全避免 forgetting
  • LoRA 也无法避免 forgetting，还"学得更少" (Biderman et al, 2024)

4. 数据集：推理用 OpenThoughts-3，个性化用内部文档+Tulu3

  • 老师：Qwen3-32B（主推理实验）；Qwen3-235B-A22B-Instruct-2507（illustration 示例）

Self-distillation 实验

  • RL teacher：Qwen3-8B-Base → LoRA rank 128 → RL on DeepMath
  • Student：Qwen3-8B-Base（同一个初始化）

  • 声称"approximately matches teacher model AIME'24 performance"

蒸馏恢复了 IF-eval（79%→83%，原始 85%），没完全恢复——差 2 个百分点。知识从 36% 提到 41%，声称"正向迁移"，但这更可能是蒸馏时 chat 数据对 QA 的间接帮助。

关键批评：个性化实验只在 IF-eval（老师擅长的维度）上展示恢复，没展示 Internal QA prompts 上老师能不能给出好的 per-token 指导——老师是原版 Qwen3-8B，对内部文档一无所知。这是 evaluation 的 selection bias。

Self-distillation 效率验证

  • 从 Qwen3-8B-Base（非 SFT checkpoint）出发，蒸馏 RL-trained policy：7-10x fewer gradient steps
  • Cumulative compute：50-100x（蒸馏可以用更短 context length、更小 batch size）
  • Reverse KL 在 <10 gradient steps 内降到 near-zero，RL 要 70 steps

逻辑问题：这本质上是一个同义反复——你已经花 17,920 GPU hours 跑 RL 得到了 teacher，然后声称蒸馏比 RL 更高效地达到同样性能。蒸馏只是"抄答案"。有意义的场景是：别人（frontier lab）已经跑完 RL 并发布了权重，你低成本蒸馏到自己的小模型里——但这是"策略转移效率"，不是"策略发现效率"。论文的 framing 把两者混为一谈了。

LoRA 的特殊表现

SFT 后 LoRA rank=32 比全参数微调落后 13%，但 on-policy distillation 后只落后 6%。推测：distillation 的 per-token reward 让 LoRA 的有限参数空间也能有效学习，不需要像 SFT 那样覆盖大量不同 context。

SFT 在自身样本上的退化

用 Qwen3-32B 自己采样的数据（temperature=1.0）做 SFT → IF-eval 下降。解释：虽然期望 KL=0，但 finite batch 导致非零梯度更新，让模型偏离自身 → 变成 off-policy → compounding error。On-policy distillation 不会出现这个问题，因为 teacher 固定。

6. Insights

6.1 对论文本身的 Comments

最反直觉的发现：SFT 在自己生成的数据上训练仍然退化。直觉上 KL=0 应该意味着"什么都不学"，但 finite batch 的随机性就足以引发偏离——这对"on-policy SFT = 安全更新"的假设是个直接挑战。On-policy distillation 因为 teacher 固定，不会出现自我漂移。

想不到的设计：个性化场景中用"早期版本的自己做老师"。不是拿更大的模型来教，而是拿"没被新数据污染的自己"来回溯修复。如果让我做，我可能会想"用大模型做老师"，但这里用自己更合理——你要恢复的是自己的行为，不是大模型的行为。本质上连接到 inverse RL 的思路——语言模型本身就是 reward model (Rafailov et al, 2023)。

关键批评——统计基础薄弱：AIME'24 约 30 题。70% vs 68% 的差距 = ~1 题对错。整个论文的量化结论（9-30x、50-100x）建立在这种不稳健的数字之上。

关键批评——SFT-2M 是 extrapolated baseline：9-30x 效率提升对比的是一个没实际跑过的 extrapolated SFT-2M。原文 caveat 是"this extrapolation assumes the scaling law holds without stalling"——log-linear extrapolation 在 400K 到 2M 范围是否成立？DeepSeek-R1-0528-Qwen3-8B 达到 86%（训练量未说明），说明 SFT 可以超过 70%，但 scaling 形式可能不是简单 log-linear。

关键批评——多干预未解耦：论文同时改变了采样来源（on-policy vs off-policy）和 reward 密度（dense vs sparse），但从未隔离哪个变量驱动改进。缺少 off-policy + per-token reverse KL 的对照组。DAGGER 的成功暗示 sampling source 是关键，PRM 的成功暗示 dense reward 是关键——两种解释互相竞争，论文没有裁决。

关键批评——self-distillation 是同义反复："50-100x 比 RL 更高效"的前提是你已经有了 RL 训练好的 teacher。蒸馏只是把已有策略抄回来。除非别人的 frontier model 已经发布权重——那是策略转移效率，不是策略发现效率。

关键批评——个性化实验有 evaluation selection bias：只在 IF-eval（老师擅长的维度）上展示恢复，没展示 Internal QA prompts 上老师能不能给出好的 per-token 指导——老师对内部文档一无所知。

缺失的关键 ablation：discount factor > 0 的详细实验、reverse KL vs forward KL vs cross-entropy 的直接对比、不同 teacher 规模（14B / 32B / 235B）的效果差异、和 PRM 的直接对比。

6.3 研究品味

  • "一行代码修改"的表述方式很有力：作者强调 on-policy distillation 在 RL 代码上只是"swap out the regularizer model"，adoptability 极高。好方法不仅效果好，还应该容易实现。
  • "蒸馏是 RL 搜索结果的 shortcut"——这个 framing 好在区分了策略发现成本和策略转移成本。RL 的主要开销在搜索（rollout + reward assignment），而非 gradient update 本身。一旦找到好策略，教学就便宜了——类比科学发现需要大量探索，但一旦发现，教学就便宜了。
  • "语言模型本身就是 reward model"——连接到 inverse RL / DPO (Rafailov et al, 2023; Ng and Russell, 2000)，任何 instruction-tuned 模型的 logprob 都可以当 reward 用。简洁有力。
  • 实验选择的品味：不是在 10 个 benchmark 上刷数字，而是精心选了两个场景（推理展示计算效率 + 个性化展示持续学习修复能力）来回答具体的"为什么"。
  • 写作形式：博客而非正式论文。好处是直白有类比（棋类比把三个方法一次讲清楚），坏处是实验严谨性明显不足。适合引发讨论，不适合作为最终证据。

7. 连接与发现

  • MOC-Distillation — Topic: 提出 on-policy distillation——学生自身采样轨迹、老师逐 token 打分（reverse KL），9-30x 计算效率提升并解决 off-policy 蒸馏的 compounding error
  • MOC-Reinforcement-Learning — Topic: 将 RL 训练管线的 reward model 替换为 teacher model 的 logprob，实现 per-token dense reward，用 RL importance sampling 框架完成 distillation
  • MOC-Exposure-Bias — Concept: 以 exposure bias / compounding error 为核心 motivation，通过 on-policy 采样消除分布偏移，并发现 SFT 在自身样本上训练仍会退化（finite batch 导致 off-policy drift）
  • MOC-Continual-Learning — Topic: 个性化场景中用 on-policy distillation 恢复被 mid-training 破坏的指令遵循行为，本质是持续学习中的"回溯修复"
