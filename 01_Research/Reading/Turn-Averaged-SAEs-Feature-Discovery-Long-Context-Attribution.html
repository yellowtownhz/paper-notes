Sparse_Autoencoders Interpretability Mechanistic_Interpretability Attribution_Graphs Long_Context Feature_Discovery

论文笔记: Turn-Averaged SAEs for Feature Discovery and Long-Context Attribution

来源说明：本笔记针对 arXiv:2606.28548 完整论文（含 8 章 + 9 附录、全套定量结果）。同一工作另有一个更短、preliminary 的 Circuits Update 博客预印版，本笔记以完整论文为准。

1. 背景信息

  • 作者：Kevin Der（Anthropic Fellows Program）、Harish Kamath、Ben Thompson（均 Anthropic）
  • 发表：arXiv:2606.28548v1，cs.CL / cs.LG，2026-06-26，CC BY 4.0，未见会议信息
  • 一句话：把 SAE 的训练输入从"每个 token 的激活"换成"一个 turn 内所有 token 激活的平均值"，就能学到一批捕捉整段回复"高层性质"的 feature，而且特征数量不再随 context 长度线性爆炸。改动量几乎为零（均值和单向量同维，现有 SAE 代码一行不用改），但把 attribution graph 从"几十万节点不可读"变成"几千节点能看"。

2. 关键问题：per-token SAE 抓不住"整段回复的高层性质"，而且长上下文下特征数随 token 线性爆炸

Golden Case — 问题是什么？ 论文里的 Example A（Section 4）：模型回复

"The highest number below 100 that does not contain the digit 9 is 95."

这句是错的——95 本身就含数字 9，所以它连约束都不满足；满足"不含 9"的最大值应该是 88。现在你是可解释性研究者，想用 SAE 搞清楚"模型这段回复到底有什么性质"。你把这段话喂进一个标准 per-token SAE，看哪些 feature 被激活：拿到的是 "digit sum calculations"、"numerical reasoning: digits, place values" 这类——它们准确指出"这段在讲数字"，但没有任何一个 feature 告诉你"答案是错的"（Error recognition 那栏是 none found）。

"答错"恰恰是这段回复最重要的一个行为属性（behavioral property）。它不落在某几个具体 token 上，而是分散在整段里的整体特征。per-token SAE 逐位置独立重建激活，训练目标里没有任何东西逼迫这种跨 token 的高层性质从 token 级细节里分离出来。

从这个例子出发，问题分两层：

第一层：表征层面。 per-token SAE 学出来的 feature 大量是低层的——单 token 探测器、词法/句法模式。论文 Section 3.1 的 intuition：一个 token 的表征里必须编码"它的位置、下一个是什么"，所以 per-token 激活天然被 token 级信息主导。而 topic、style、persona、safety trait 这类高层性质往往分散在很多 token 上（论文引 Chen et al. 2025 关于 persona 的证据），per-token feature 常在零散位置稀疏 fire，不平滑覆盖整段。

第二层：可扩展性/工程层面。 attribution graph 这类分析工具的可用性直接取决于产物规模。节点数是 #active_features × #layers，per-token 分辨率下 active feature 数随序列长度线性增长。论文给的数字：一个 10 轮、250 token 的对话，per-token 图在 4 层上约 128K 节点——人根本没法看。

  • 动机：既要一种能自然表达"整段回复高层性质"的 SAE feature，又要让特征数脱离 token 数、随"turn 数"缩放，让 attribution 在长上下文下重新可行。
  • 之前的方法卡在哪：
    • 标准 per-token SAE（Bricken 2023 等）：训练目标不区分高层/低层，且随 token 爆炸。
    • Temporal SAE（Bhalla et al. 2025）：用对比 loss 鼓励相邻 token 激活平滑。但本文观察到概念性 feature 常在不相邻的散点上 fire，"相邻平滑"假设不成立——他们要的不是"相邻平滑"，而是"整段的均值"。
    • persona vector（Chen et al. 2025 / Lu et al. 2026）：也用"整段均值激活"做差，但每个 persona 只抽一个方向，且要预先知道 persona。本文是无监督学一整本 32,768 维的 feature 字典。
  • ⚠️ 问题定义本身就埋了个雷：Section 2.3 作者自己承认，信息并非均匀分布在各 token 上——句号 token 编码整句摘要（Gurnee & Tegmark 2023）、实体信息集中在名字最后一个 token（Geva et al. 2023）。这跟"等权平均所有位置"直接冲突，作者把这个矛盾 explicitly 留给了 future work。也就是说，方法的核心假设从一开始就有已知反例。

我的想法：

  1. 这个点很有意思，不仅是这个地方的10轮、250token的这个例子，在agentic coding场景下几十K、几百K长度的completion，这种情况下用SAE是根本不可能的。如何在agentic coding场景下用SAE来分析也是一个难点。
  2. 这个方法的核心假设这个地方说的确实有道理，如果所有token不是相等权重的，那对所有token做平均就不是最合理的。但是这个地方只能说是一个没办法的办法，做了一个合理的近似。不过还是要做一个discussion的实验，用具体的实验来说明这个不同token的权重对于平均的影响有多大。

3. 关键方法：把 SAE 输入从 x_t 换成整段均值 x̄（低通滤波），再用 nested 架构在一个模型里同时保留高层与 token 级特征

Golden Case — 方法怎么跑？ 继续用 Example A（"...is 95" 那段错误回复）走一遍 turn-averaged SAE 的数据流：

  1. 输入：取这段 assistant 回复的所有 token，在某层（单层实验用 layer 19，约 70% 深度）拿每个 token 的 residual stream $x_t \in \mathbb{R}^{3584}$。
  2. turn 平均：$\bar{x} = \frac{1}{|T|} \sum_t x_t$——把整段压成一个 3584 维向量。直觉：token 级高频细节（"这是数字 5""这是句号"）在平均里互相抵消被抹平，"这整段是个自信答错的数字谜题回答"这种低频、跨位置的分量被保留。
  3. 编码：$\mathrm{enc}(\bar{x}) = \mathrm{BatchTopK}(W_{\mathrm{enc}}(\bar{x} - b_{\mathrm{dec}}) + b_{\mathrm{enc}})$，取 top-k=128 个 feature。
  4. 读取：top feature 里出现 "Incorrect answers to digit-exclusion number puzzles"、"Confidently stating incorrect mathematical and numerical facts"——"答错"这个行为属性被抓到了。
  5. nested 版验证：nested SAE 也 recover 了 error-recognition 概念，说明这个属性来自"turn 平均"这个操作，而非某个架构的偶然。

核心一句话（Section 3.1）：训练目标就是标准 SAE 重建 loss，唯一区别是输入——从 per-token 激活换成 turn 均值。因为均值和单向量同维，"SAE 架构和训练代码一行都不用改"。这也正是全文 Conclusion 的立意（line 548）："reshaping the training signal ... can compel SAE features toward desired characteristics" ——turn averaging 只是这个更大 idea 的第一个 instance。

3.1 三种候选架构，最终主推 turn-averaged + nested

(a) Turn-averaged SAE（基础版）

  • 定义：给定 token 跨度 T，$\bar{x} = \frac{1}{|T|} \sum_{t \in T} x_t$，在 $\bar{x}$ 上做标准重建：

    $$ \mathcal{L} = \| \bar{x} - \mathrm{dec}(\mathrm{enc}(\bar{x})) \|^2 $$
    $$ \mathrm{enc}(\bar{x}) = \mathrm{BatchTopK}\!\left( W_{\mathrm{enc}} (\bar{x} - b_{\mathrm{dec}}) + b_{\mathrm{enc}} \right) $$
    $$ \mathrm{dec}(z) = W_{\mathrm{dec}}\, z + b_{\mathrm{dec}} $$

    符号：$x_t \in \mathbb{R}^{d_{\mathrm{model}}}$ 是位置 $t$ 的 residual stream；$\bar{x}$ 是跨度均值；$W_{\mathrm{enc}}, W_{\mathrm{dec}}, b_{\mathrm{enc}}, b_{\mathrm{dec}}$ 是编解码器参数；BatchTopK（Bussmann 2024）跨 batch 选 top-k 激活。

  • why averaging works（核心比喻）：把一段 token 的 hidden state 看成"沿 token 维的信号"。topic、behavior 这类广义概念是低频分量（很多位置都有体现）；token 级细节是高频分量。取均值 = 低通滤波，保留低频、衰减高频。（⚠️ 这个"低通滤波"是 asserted 而非证明的，且与 §2.3 的"信息集中在关键 token"反例张力未做实验，见 §6.1。）

  • 局限：turn-averaged SAE 无法重建 token 级细节。Table 1 里它的 per-token nMSE 高达 1.799（几乎没法重建单 token）。

(b) Decoupled SAE（被否决的对照）

  • 想法：分解 $x_t = \bar{x} + (x_t - \bar{x})$，训两个独立 SAE（一个吃均值、一个吃残差，各 k=64）。
  • 为什么否决（关键设计洞见）：per-token SAE 的输入是 $h_t - \bar{x}$，它对"ablate turn-averaged feature 造成的均匀平移"是不变的——你改动 turn 级 feature，per-token 那部分感知不到，两套 feature 在因果上断开，attribution 做不了。加上固定 top-k 预算劈两半，重建更差（Table 1：per-token nMSE 0.212）。 备注：从训练+推理联合的角度来看这个问题，per-token SAE是能接收到average-SAE的梯度的，这样是不是就能保证condition了？即使从推理角度看两个SAE之间是独立的，但是从训练角度两个SAE本身是一个联合分布，只要保证per-token SAE conditioned on average-SAE上的分布是合理的就行了。

→ 讨论结论：这里叠了两层"耦合"，要拆开。① 事实前提在原始 decoupled 里其实不成立：残差用的是真实均值 $x_t-\bar{x}$（非重建 $x_t-\hat{\bar{x}}$），两个 loss 无交叉项、无共享参数，per-token SAE 收不到 average-SAE 的梯度。要接通得改成 $x_t-\hat{\bar{x}}$。② 但病根不在训练期统计耦合，而在推理/干预期的因果耦合：attribution 边是对训练好的模型做梯度/干预算出来的，活在计算图上、不在联合分布上。"per-token conditioned on average 的分布合理"给的是相关性不是因果边——残差按构造已把 turn-level 分量减干净，per-token 结构性地看不到它，因果边严格为 0。③ 因此能满足 attribution 的联合方式必须是参数共享 + per-token 重建直接用到 turn-level 特征，也就是 nested 本身；nested 不靠"分布合理"担保，而是"一个 SAE 用全集特征重建 $x_t$、ablate inner 特征直接改 per-token 重建"，因果边由构造存在。单纯 condition 分布不够。

(c) Nested SAE（主推的 hybrid）

  • 想法：在单个 SAE 里，让一个子集 feature 去最优重建均值，同时全集 feature 重建 per-token。切成 inner [0:h] 和 outer [h:d_sae]：

    $$ \mathcal{L} = \sum_t \| \mathrm{dec}(\mathrm{enc}(x_t)) - x_t \|^2 \;+\; \alpha \cdot \| \mathrm{dec}_h\!\left( \mathrm{enc}(\bar{x})[0{:}h] \right) - \bar{x} \|^2 $$
    • 第一项：全集 feature 重建 per-token（标准 SAE 项）。
    • 第二项：只用前 h 个 decoder 方向，且 $\mathrm{enc}(\bar{x})[0{:}h]$ 表示在 TopK 之前把 $[h{:}]$ 置零，强制 inner partition 单独重建均值 $\bar{x}$。
    • inner/outer 共享同一套 encoder/decoder——这是和 decoupled 的本质区别，因此不会因果断裂。这是整个 hybrid 设计的题眼。
    • 与 Matryoshka SAE（Bussmann 2025）几乎同形，唯一改动是 inner partition 的训练信号被"turn 平均"重塑过。

  • 超参：α ∈ {0.25,0.5,1,2,4} sweep，取 α=1.0；d_sae=32,768，h=16,384（内外各半），也试了 8,192/24,576。

3.2 Turn-averaged attribution graph（下游应用）

  • 核心 intuition：turn-averaged feature 把整段变成一个 feature 向量，节点数从 $N \times L \times k$ 降到 $T \times L \times k$（$N$=token 数，$T$=turn 数）。10 轮 250 token 的例子：~5K vs ~128K 节点（4 层）。这就是 attribution 从"不可读"变"可读"的全部来源。
  • 构建：用 circuit-tracer 框架（Ameisen & Lindsey 2025），多层 SAE 在 layer 6/11/16/21（约 20/40/60/80% 深度）。节点 = "某 feature 在某 turn、某层"的激活。三种架构的 edge weight 公式完全相同，唯一差异是 $\alpha$ 的定义：Turn-averaged 的 $\alpha_{A,t} = \mathrm{enc}(\bar{x})_A$ 全段常数；Per-token / Nested 的 $\alpha_{A,t} = \mathrm{enc}(x_t)_A$ 随位置变。
edge weight 完整公式（复现者再看）
$$ W_{A \to B} = \frac{1}{|T_A|} \sum_t \alpha_{A,t} \cdot \left( \hat{d}_A \cdot g_t \right) $$
$$ g_t = \sum_{s \in T_B} \frac{1}{|T_B|} \left( \frac{\partial h_s^{L_B}}{\partial h_t^{L_A}} \right)^{\!\top} \hat{d}_B $$
  • $|T_A|$/$|T_B|$：source/target turn 的 token 数。
  • $\alpha_{A,t}$：source feature A 在 token $t$ 的激活值。
  • $\hat{d}_A$：feature A 的单位 decoder 方向。
  • $g_t$：feature B 的平均 pre-activation 对 source 位置 $t$ 的 residual stream 的梯度（对 target turn 内所有位置 $s$ 求平均）。
  • 两个 $\frac{1}{|T|}$ 归一化的 why：turn 平均让 feature 激活与 turn 长度无关，所以 edge 权重也应无关——故 source/target 各除以其 token 数。

3.3 训练配置（复现清单）

  • 模型：Qwen-2.5-7B-Instruct，d_model=3584；语料 LMSYS-Chat-1M；激活离线缓存。
  • 所有 SAE：BatchTopK，d_sae=32,768，k=128，Adam（β1=0.9, β2=0.999）。nMSE 对 LR 在 2× 范围内 <0.5% 变化。
  • 单层 SAE（Section 4/5，layer 19，仅 assistant turn）：TA LR 2e-4 bs 256 3 epoch（~4.7M）；per-token LR 1e-4 bs 512 1 epoch（~266M tokens）；nested LR 1e-4 bs 512 α=1.0 1 epoch，inner=[0:16384]/outer=[16384:32768]。
  • 多层 SAE（Section 6 attribution，layer 6/11/16/21，user+assistant 都训）：TA LR 1.2e-4 bs 256 3 epoch（~9.6M）；per-token LR 1e-4 bs 512 1 epoch；nested 同上。
    • 为什么 user+assistant 都训（Appendix G）：assistant-only SAE 重建 user turn 差 1.5–3×；两角色一起训把 user-turn nMSE 降 53–63%，拉平到 assistant 水平——这是 attribution 要覆盖 system/user turn 的必要条件。
  • 效率：turn-averaged 一个 epoch ~1.58M samples，1.5h/4×H100；per-token 同数据是 266M tokens。

4. 数据集：LMSYS-Chat-1M 训练，评估横跨 chat holdout、LongBench v2 长文档、Sonnet 生成的 24 字段结构化摘要

  • 训练数据：LMSYS-Chat-1M（Zheng 2023，真实多轮对话）。turn 作为 span 单位；多层 SAE 用 user+assistant 双角色。
  • 评估数据：
    • 定性 feature 探索：316,000 个 held-out assistant turn（53.2M tokens），人工浏览挑对比最鲜明的 case（例 A–C）。
    • 长上下文泛化：LongBench v2（Bai 2024）文档，24K–32K tokens，整篇当一个 span 编码，比训练样本平均长约 150× 且来自不同语料——测"同维度、随长度不变"的泛化。⚠️ 只从 ~50 篇里挑了 2 篇展示（Appendix C：一篇金融、一篇实时草地渲染图形学论文）。
    • 定量 feature 评估：从 LMSYS holdout 采 2,000 turn。用 Claude 给每个 feature 生成描述（top-25 activating examples）；用 Sonnet 4.6 生成每个 turn 的结构化摘要——24 字段、5 类（content / form / voice / function / meta，schema 见 Appendix D，由 Sonnet 4.6 设计，要求不许引用或改写原文）。
    • embedding 度量：Qwen3-Embedding-8B（Zhang 2025）嵌入 24 字段与 feature 描述算余弦相似度（确定性、无 LLM judge）。
    • attribution：per-paragraph case 用 Claude 合成的 12 段 system prompt + 8 query（Appendix F）；14 轮对话来自 LMSYS holdout；intervention/completeness/replacement 用 300 对话（n=2/4/6 各 100）。
  • 特征聚合的关键预处理：per-token 和 nested 要把 token 级激活聚合成一个 feature list，测了 sum 和 max 两种。summing 更能捕捉高层特征（默认，top-128 匹配训练 k）；max 擅长挑稀有、区分性强的 token 级 feature。

备注：为什么不是turn-max SAE，假设一个turn有N个token，那就是N个d_model维度的向量先做max，然后在作为SAE的输入，进行训练或推理。从这个角度的话，我觉得max比average可能更好避免笔记最开始提到的不同token权重是否一致的问题。

→ 讨论结论（注意：这与论文测过的 per-token(max) 不同——那是事后对特征激活做 max 聚合，这里是对 residual 做 max-pool 当 SAE 输入）。直觉对一半：信息若集中在某高幅值 token（§2.3 的句号/实体末 token），max 能保住峰值、average 会按 $1/N$ 稀释。但对论文目标（抓整段高层性质）turn-max 大概率更差：① off-manifold——average 是凸组合、仍是合法激活点（线性表征可加，attribution 沿 $d_A$ 干预有物理意义）；element-wise max 把不同 token 的不同维拼成"缝合怪"，不对应任何真实激活，破坏 attribution 赖以成立的线性结构。② 符号问题：residual 负的大幅值也携带信息，max 系统性偏正、丢负峰。③ 与"低通滤波"立意相反：average 压高频留低频，max 是峰值检测器、放大 token 级 spike——这正是 per-token(max) 赢判别而非覆盖的原因。可证伪预测：turn-max 会把特征往判别型推、用覆盖换判别，落在 TA 与 per-token(max) 之间。④ 丢共识信号：高层属性靠很多 token 各偏一点点、average 建设性叠加成清晰方向，max 只取每维赢家、反映不了分布式共识。关键：max 没解决"token 权重不等"，只是把"均匀权重"换成"每维赢家通吃"，同样是固定非学习启发式；对症的修法是学习式/attention-weighted 池化（见 §6.2）。不过 turn-max 作为 ablation 很有价值，正好能干净检验 §2 那条感想里"token 权重对平均影响多大"的问题。

5. 关键结果："整段说得全"与"单段最好认"天然对立——前者 turn-averaged 赢、后者 per-token(max) 赢；归因还原最充分的是 nested 而非 turn-averaged

一句话把三个赢家说清（把三个抽象指标翻成人话）：

  • 能把一整段回复整体在讲什么、是什么风格/口吻，描述得最完整 → turn-averaged 最强。
  • 能只靠特征就把这一段从一堆段落里唯一认出来 → per-token(max) 最强。
  • 在归因图里能最充分地还原模型的因果行为（改动源特征时下游确实被解释到） → nested 最强。

没有任何单一架构全面胜出，且几乎所有指标都建立在 LLM 生成产物之上。

5.2 定量 feature 评估："单段最好认"（判别）vs"整段说得全"（覆盖）四项（Section 5.5 汇总）

  • 10-way matching（判别，2,000 turn，judge=Sonnet 4.6）：per-token(max) 95.0% > per-token(sum) 87.0% > turn-averaged 73.9% > nested(sum) 70.6% > nested(max) 57.3%。max pooling 挑出稀有 token 级 feature，能唯一定位文本，故判别最强。nested top-128 里约 99% 是 inner（turn 级）feature（inner = 专门重建均值的那半字典，见 §3.1），等于半容量的 turn-averaged SAE，故判别弱。

  • Pairwise ranking（覆盖，20,000 trial）：turn-averaged 平均胜率 87.9%，对 per-token(max) 头对头 79.7%——与判别排名完全相反。完整排名：TA 87.9% > per-token(max) 67.0% > per-token(sum) 60.2% > nested(sum) 31.5% > nested(max) 3.4%。

  • 5-way ranking（覆盖）：turn-averaged 平均 rank 2.03、44% 排第一 > per-token(sum) 2.36 > per-token(max) 2.47 > nested(sum) 3.36 > nested(max) 4.79。

  • Embedding metric（覆盖，确定性、无 LLM judge）：turn-averaged 0.663（k=3）> nested(sum) 0.658 > per-token(sum) 0.647 > nested(max) 0.640 > per-token(max) 0.617；排名在 k=1,2,3,5 全一致（Appendix H）。
  • 一句话结论：一段话最容易靠"最独特的细节"被认出（判别 → per-token max 赢），但"这段话整体在讲什么"要靠覆盖（→ turn-averaged 赢）。作者据此推测（非实测）TA 更适合"对整段/整回复操作"的任务（长对话摘要、判断 persona/safety trait）。

⚠️ 审稿攻击点：embedding 指标 TA 对 nested(sum) 只领先 0.005（0.663 vs 0.658），无 CI、无显著性检验，很难说不在噪声内（2,000 turn 本可给二项 CI）。且该指标输入仍是 LLM 生成的 feature 描述，只是把 judge 换成 embedding，并未逃出"LLM 产物评 LLM 产物"的循环。

5.3 Attribution 结果

  • 规模压缩：14 轮对话，pruning（保留贡献 80% logit 影响的节点、98% edge 影响的 edge）把图从 7,239 节点 / 10.4M edge → ~1,300 节点 / ~110K edge。
  • 可读性对比（最抢眼的定性证据）：turn-averaged 子图给出一条可理解的因果链——L21 "Repetitive/degenerate text output" ← L16 "Jailbreak prompts attempting to override AI safety rules" ← L11 "Nuclear weapons design details" ← L6 "AI safety disclaimer boilerplate"。而 per-token 聚合没有"对抗性 prompt 检测"这个 feature，从退化节点回溯只能到 "chemical compound names"、"JSON" 这种与退化输出无因果关系的东西。（⚠️ 单条对话、人工在 UI 里手动连图——是 anecdote 不是 evidence，见 §6.1 的 absence-of-evidence 讨论。）
  • Per-paragraph attribution（Table 2）：12 段 system prompt、8 个针对性 query，每个 target 段的 attribution 增量 Δ（相对中性 query baseline，百分点）在所有 8 query、所有 3 架构上全为正。但幅度极小（+0.3 到 +1.9pp），且三架构几乎一模一样（如 §0 Identity：TA +1.8 / per-token +1.9 / nested +1.9）。⚠️ 这个实验只证明"归因能工作"，完全无法区分 TA 与 per-token 的优劣，且 n=1/query、无误差棒。总节点 4 层×128 feature×14 turn = 7,168。

  • Intervention validation：沿 source feature 的 decoder 方向在 source turn 的每个位置加单位向量（per-token/nested 也是每个位置，不只 fire 的位置，以匹配 turn 级 edge 粒度），测 target pre-activation 变化。每图取 40 个最高权重跨层 edge，300 对话 × 3 架构 = 36,000 次干预。Sign matching 三方法均 ~100%（任一图最低 95%）。per-token Spearman 最强，nested Pearson 最强，turn-averaged 显著但较弱（丢了高频分量）；相关性随对话变长下降（一阶近似漏掉更多高阶效应）。

  • Completeness & replacement（Figure 7）：nested 在两项 sufficiency 上都最高，排序 nested > per-token > turn-averaged，在所有对话长度上一致。值得注意：nested 的 per-token nMSE 略差于纯 per-token（0.167 vs 0.162），但 sufficiency 反而最高，且优于事后聚合的 per-token——说明 nested 架构天生更适合 turn 级 attribution。两项指标都随对话变长上升（原因待 future work）。

5.4 附加：无监督识别 persona feature（Appendix I）

  • 不需训练时知道 persona，事后用对比 prompt（正/负）生成 rollout，按 feature 在正/负 rollout 上的平均激活比值排序（排除 holdout density >20% 的高频通用 feature），就能捞出 persona 相关 feature。
  • 例：sycophancy 的 turn-averaged top feature 有 "Compliments, flattery, and praise"、"Enthusiastic affirmations and agreement"；evil 的有 "Roleplaying as evil personas promising to fulfill harmful requests"（rollout ratio 269.1）。有噪声（如 quantitative trait 里混进 "safety refusals"），但整体能 surface 相关 feature。⚠️ 但作者明确声明没做架构间的定量对比——这条只是 demo，不能用来支撑"TA 更适合整段任务"。

6. Insights

6.1 对论文本身的 Comments

  • 最该记住的一条：核心卖点"turn-averaged 特征把整段说得更完整"的因果归属站不住。 支撑它的覆盖度指标至少有四重混淆，作者一个都没排除：① 缺最基本的对照——直接拿原始均值向量做匹配，覆盖度会不会一样高甚至更高？若原始均值池化就够，那 SAE 字典在这个任务上零增值，卖点塌一半；② 可能只是容量差异——turn-averaged 把整本三万多维字典用来编一个向量，per-token 把预算摊到几十个 token 上，缺容量对齐的对照；③ 给两类 SAE 生成描述的自动解释提示不对称（作者自己承认），等于用一把偏向自己的尺子量出自己更好；④ 二十四字段的标准、逐段摘要、裁判全是同一个模型，等于自己定标准、自己生产被评对象、自己打分。

  • 旗舰子图犯了"没找到不等于不存在"。 "per-token 找不到对抗检测特征"是全文最抢眼的卖点，但它只说明在人肉剪枝后的可读图里没浮现，推不出 per-token SAE 里真的没有这个特征——把"读不出来"当成了"不存在"，而且样本量只有一个对话。

  • 评估的地基不稳。 裁判换一个 prefill 开关就从瞎猜（49%）跳到 83%，指标本身极不稳定；全程疑似单随机种子（SAE 对初始化很敏感，特征分裂/死特征抖动大）；定性证据几乎全是手挑（长文档从约五十篇里挑两篇、归因只做一个对话且人工连图），选择偏差空间很大。

  • 也有扎实处，别一味挑刺。 双角色训练与 assistant-only 的对照是诚实有用的消融；干预验证里 turn-averaged 输了也如实报告、没藏；边方向的符号匹配接近 100%，让人对数据本身加分。

  • 一个我大概率想不到的漂亮点。 把 SAE 输入换成均值，本质是对"沿 token 维的信号"做低通滤波；改动量几乎为零（维度不变、代码不改），却把归因从不可用撬到可读——典型的"换训练信号而非换架构"的四两拨千斤。

6.2 对未来的预测

  • "reshape training signal 而非改架构"这条会被继续挖：均值只是最简单的池化。可预期 attention-weighted 池化（呼应 §2.3"信息集中在句号/实体末 token"）、可学习的 span 划分、多尺度（句/段/turn/文档）联合的 Matryoshka 变体，以及作者已点名的 natural language autoencoder。长文档泛化（150× 训练长度仍 work）说明天花板不低。
  • 真正能落地的判据将是下游任务准确率（persona 分类、越狱检测、长对话摘要），而不是 LLM-judge 的 coverage——本文缺的正是这一环，作者也把它列进 future work。后续大概率会补一个 ground-truth benchmark。

6.3 研究品味

  • 诚实报告对立结果是这篇的品味亮点：设计判别 + 三个覆盖共四个评估，明说两轴给出相反排名，并把"什么时候用哪个"讲清楚。比"我全面 SOTA"更可信也更有指导性。同理，把 judge 敏感性单列附录（E）、主动自曝 prefill 会让结论崩，是很高的科研诚信标准。
  • 但更进一步的 meta-lesson（本篇最锋利的一条）：当你发现一个指标在一个开关下从 chance 跳到 83%，正确反应是质疑指标本身，而不是挑一个好看的配置继续用它下结论。作者做到了前半（自曝），没做到后半（照用 87.9% 当 headline）。
  • 先否决简单方案再引出复杂方案（decoupled → nested）的写法，让 nested 的每个设计选择都有"为了修 decoupled 的哪个毛病"的因果，而不是凭空冒出来。方法类论文值得抄的叙事结构。
