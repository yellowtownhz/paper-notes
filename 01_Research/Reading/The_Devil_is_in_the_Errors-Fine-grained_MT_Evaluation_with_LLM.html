论文笔记：The Devil is in the Errors-Fine-grained MT Evaluation with LLM

2. 关键问题：如何让 LLM 进行细粒度的机器翻译评估，提供可解释的错误标注而非单一分数

  • 动机:

    • 当前 MT 评估指标（如 BLEU、COMET）只输出单一质量分数，缺乏可解释性
    • 专业人工评估使用 MQM（Multidimensional Quality Metrics）框架，标注错误位置、类型和严重程度，但成本高昂
    • LLM 在评估任务上表现出色，但 prior work 仅关注分数预测，未利用标注数据，也未探索细粒度错误分析

  • 未解决的问题:

    • 能否让 LLM 自动识别和分类翻译错误，生成类似 MQM 的细粒度反馈？
    • LLM 在低资源语言对上的评估能力如何？
    • 微调 vs Prompting 哪种方式更适合 LLM 评估？
    • 结构化输出任务（错误标注）vs 标量预测任务（分数）哪种更适合 ICL？

3. 数据集：WMT 高资源和低资源语言对的 MQM/DA 评分数据

训练数据

  • 高资源语言对 (WMT'22 Metrics Shared Task):

    • en→de (13 systems, 1315 segments)
    • zh→en (14 systems, 1875 segments)
    • en→ru (15 systems, 1315 segments)
    • 地面真实值：MQM 评分（专家标注错误跨度 + 严重性，自动转换为数值分数）

  • 低资源语言对 (WMT'19 Metrics Shared Task):

    • en↔gu (Gujarati, 11 systems, ~1000 segments each direction)
    • en↔kk (Kazakh, 11 systems, ~1000 segments each direction)
    • 地面真实值：DA (Direct Assessment) 评分（非专家打分 0-100，按评分者标准化）

  • In-context 示例池 (仅用于 AutoMQM):

    • 来自 WMT'21 Metrics Shared Task 的 MQM 标注数据
    • 仅 en→de 和 zh→en 有可用 MQM 标注作为 few-shot 示例

评估数据

  • Benchmark: WMT'22 Metrics Shared Task 测试集（高资源）+ WMT'19（低资源）
  • 覆盖场景: 新闻领域、多语言对、参考基于和无参考（QE）两种设置

特殊处理

  • 分层采样: 对 in-context 示例采用 stratified sampling，确保 major/minor 错误平衡和错误类型多样性
  • 拒绝标准: Appendix B 中的 check_icl_set 函数，确保示例质量（至少 3 个错误、major/minor 差异≤2、至少 2 种错误类型、长度 20-400 字符）

4. 关键方法：AutoMQM——让 LLM 识别并分类错误，通过 MQM 框架自动计算分数

整体架构

AutoMQM 的核心思想是将评估任务从"直接预测分数"转换为"识别错误 + 自动计分"：

  1. Prompt LLM 识别翻译中的错误跨度（error spans）
  2. 对每个错误分类（MQM 类别）和标注严重性（major/minor）
  3. 使用 MQM 权重算法自动计算总分（不要求 LLM 直接输出分数）

设计哲学：分离"识别"与"计分"，实现可解释性、可控性和可调试性。

核心模块

4.1 Score Prediction Prompting（基线方法）

使用 GEMBA-SQM prompt（Kocmi and Federmann, 2023），要求 LLM 直接输出 0-100 的分数：

Score the following translation from {src_lang} to {tgt_lang} with respect
to the human reference on a continuous scale from 0 to 100 that starts with
"No meaning preserved", goes through "Some meaning preserved", then "Most
meaning preserved and few grammar mistakes", up to "Perfect meaning and grammar".
{src_lang} source: "{source}"
{tgt_lang} human reference: "{reference}"
{tgt_lang} translation: "{candidate}"
Score (0-100): {score}

要点:

  • 紫色部分（reference）仅在参考基于评估中包含
  • 橙色部分（score）仅在 in-context 示例中包含
  • 输出为字符串表示的分数（0-100）

4.2 AutoMQM Prompt（核心贡献）

要求 LLM 识别错误并分类，但不直接输出分数：

Based on the given source and reference, identify the major and minor errors in this
translation. Note that Major errors refer to actual translation or grammatical errors,
and Minor errors refer to smaller imperfections, and purely subjective opinions about
the translation.
{src_lang} source: "{source}"
{tgt_lang} human reference: "{reference}"
{tgt_lang} translation: "{candidate}"
Errors: {error1:span} - {error1:severity}/{error1:category}; {error2:span} - ...

输出格式示例:

Errors: 'easy' - major/accuracy; 'are' - minor/fluency

分数计算（MQM 算法，非 LLM 生成）:

  • Major 错误：-5 分
  • Minor 错误：-1 分（Fluency/Punctuation 为 -0.1 分）
  • Non-translation 错误：-25 分
  • 起始分 100，最终分 = 100 - Σ(错误权重)
  • 分数范围：0（完美）到 25（最差），实际使用时取负或转换为 0-100

4.3 微调方法

探索两种微调目标：

1. Regression (R):

  • 使用固定索引的 logit 向量提取实值 logit 作为质量信号
  • 损失函数：均方误差（MSE）
  • 训练数据：WMT DA 数据（2015-2020）

2. Generative Classification (GC):

  • 将分数分为 5 个离散类别（每类样本数相等）
  • 标签映射：["very bad", "bad", "ok", "good", "very good"]
  • 评估时：预测映射回 1-5 的整数标签
  • 发现：在 MQM 2020 数据上微调比 DA 数据稍好

数学形式化

MQM 评分算法

$$\text{Score} = 100 - \sum_{e \in \text{Errors}} w(\text{severity}(e), \text{category}(e))$$

其中权重函数 $w$ 为：

  • Major + Non-translation: 25
  • Major + 其他类别：5
  • Minor + Fluency/Punctuation: 0.1
  • Minor + 其他类别：1
  • Neutral: 0

Span Meta-Evaluation 指标

Span Precision (SP): $$\text{SP}(\hat{S}) = \frac{|P(\hat{S}) \cap P(S^\star)|}{|P(\hat{S})|}$$

Major Recall (MR): $$\text{MR}(\hat{S}) = \frac{|P(\hat{S}) \cap P(S^\star_{\text{maj}})|}{|P(S^\star_{\text{maj}})|}$$

其中：

  • $\hat{S}$: 预测的错误跨度集合
  • $S^\star$: 黄金标注跨度集合
  • $S^\star_{\text{maj}}$: 黄金 major 错误子集
  • $P(S)$: 跨度中所有单词位置的集合

模型配置

  • PaLM: 540B 参数，780B tokens 预训练
  • PaLM-2 系列:
    • BISON（中等规模）
    • UNICORN（大规模，参数未公开）[?]
    • FLAN-PaLM-2 UNICORN（指令微调版本）
    • S/M（小规模，用于消融实验）
  • 对比模型: GPT-3.5/GPT-4 (via GEMBA), MetricX-XXL, COMET-22, COMET-QE, MATESE, COMET-WL

与已有方法的区别

  • vs GEMBA (Kocmi and Federmann, 2023):

    • GEMBA 仅预测分数，AutoMQM 提供错误跨度和类别
    • AutoMQM 在 segment-level 表现更好（尤其大模型）

  • vs MATESE (Perrella et al., 2022):

    • MATESE 使用 encoder-only 模型，需要监督数据
    • AutoMQM 使用 decoder-only LLM，支持 zero/few-shot

  • vs InstructScore (Xu et al., 2023):

    • InstructScore 使用 7B LLaMA + GPT-4 蒸馏
    • AutoMQM 直接使用大规模 LLM（PaLM-2），无需蒸馏

5. 关键实验：AutoMQM 在 segment-level 显著优于分数预测，且提供可解释的错误标注

主实验结果

5.1 Score Prediction vs 学习式指标（Table 2）

System-level Accuracy (3 个语言对平均):

  • PaLM 540B (ref-based): 90.1% — 超越所有学习式基线
  • PaLM-2 UNICORN (ref-based): 90.1%
  • MetricX-XXL: 85.0%
  • COMET-22: 83.9%

Segment-level Pearson (ρ) (en-de):

  • MetricX-XXL: 0.581 — 最佳
  • PaLM-2 UNICORN (ref-based): 0.349
  • PaLM 540B (ref-based): 0.255

关键发现: LLM 在 system-level 达到 SOTA，但 segment-level 仍落后于学习式指标。这揭示了 LLM 擅长"宏观判断"（区分系统间整体质量），但不擅长"微观判断"（单个片段的细粒度评估）。

5.2 微调效果（Table 2, Finetune 部分）

Segment-level Pearson (ρ) (en-de, ref-less):

  • PaLM-2 BISON (R): 0.439 — 微调后达到 SOTA
  • PaLM-2 BISON (zero-shot): 0.299
  • 提升: +0.140 (+46.8%)

关键发现: 微调显著提升 segment-level 性能，小模型收益更大。微调可使小模型接近大模型性能。

5.3 AutoMQM vs Score Prediction（Table 5）

Segment-level Pearson (ρ) (2 个语言对平均，ref-based):

  • PaLM-2 UNICORN (AutoMQM): 0.432 — 优于分数预测
  • PaLM-2 UNICORN (Score Pred): 0.401
  • 提升: +0.031 (+7.7%)

Segment-level Pearson (ρ) (en-de, ref-based):

  • PaLM-2 UNICORN (AutoMQM): 0.442
  • PaLM-2 UNICORN (Score Pred): 0.349
  • 提升: +0.093 (+26.6%)

关键发现: AutoMQM 对大模型（UNICORN）提升显著，对小模型（BISON）提升有限。结构化输出任务（错误标注）比标量预测任务（分数）更能发挥 LLM 能力。

5.4 Span-level 评估（Table 6）

Major Recall (MR) (en-de, ref-based):

  • PaLM-2 UNICORN (AutoMQM): 0.628 — 能识别大部分 major 错误
  • PaLM-2 BISON (AutoMQM): 0.749
  • COMET-WL (监督式): 0.250

Span Precision (SP) (en-de, ref-based):

  • COMET-WL: 0.267 — 更精确
  • PaLM-2 UNICORN: 0.175
  • PaLM-2 BISON: 0.095

Matthews Correlation (MCC) (en-de, ref-based):

  • PaLM-2 UNICORN: 0.193
  • COMET-WL: 0.161
  • 相当接近

关键发现:

  • LLM 能识别超过 50% 的 major 错误（UNICORN: 62.8%, BISON: 74.9%）
  • LLM 倾向于过度预测错误（平均跨度~5 词 vs 黄金~2 词）
  • span correlation (MCC) 与监督式 word-level 模型相当
  • 重要洞察: 仅用少量 in-context 示例就达到监督模型水平，这是被低估的亮点

5.5 In-context Learning 的双面性（Figure 8）

AutoMQM + ICL:

  • 性能随示例数量单调递增，4 个示例时达到平台
  • 方差较低（大部分示例集与最佳集差异 <0.05 Pearson）
  • ref-based 和 ref-less 表现高度相关（Corr=0.941, Figure 9）

Score Prediction + ICL (Figure 6):

  • 几乎无提升，甚至略降
  • LLM"过拟合"示例中的具体分数，而非泛化

关键发现: AutoMQM 对 ICL 更鲁棒，LLM 在细粒度任务上更能从示例中学习。这揭示了 ICL 的工作机制——在需要推理和模式识别的任务上更有效，在标量预测任务上容易过拟合表面特征。

5.6 低资源语言对（Table 4）

System-level Accuracy (4 个语言对平均):

  • PaLM-2 UNICORN (ref-based): 87.4%
  • MetricX-XXL⋆: 94.0%

Segment-level Pearson (ρ) (en-kk):

  • MetricX-XXL⋆: 0.701
  • PaLM-2 UNICORN: 0.609

关键发现: LLM 在低资源语言上表现 promising，但仍落后于学习式指标（即使后者未见这些语言数据）。差距约 13%，这意味着 cross-lingual transfer 有潜力。

消融实验

6.1 模型规模影响（Figure 5）

Pearson (en-de) vs 参数量:

  • Zero-shot: 小模型（S/M）几乎无效，大模型（BISON/UNICORN）显著提升
  • Finetuned: 小模型微调后接近大模型性能，仅略降

结论: 零 shot 评估需要大规模，微调可弥补规模不足。

6.2 指令微调影响（Table 2）

System-level Accuracy (3 LPs, ref-based):

  • PaLM-2 UNICORN: 90.1%
  • FLAN-PaLM-2 UNICORN: 75.9% — 显著下降

结论: FLAN 指令微调意外损害评估性能（可能是 FLAN 数据集问题）。这与 GPT-4 指令微调后表现优异形成对比，可能原因：

  1. FLAN 数据集质量问题
  2. 指令微调让模型过于"顺从"，降低了批判性评估能力 [?]
  3. 分布偏移：FLAN 训练数据与 MT 评估任务差异大

6. Golden Case：一条数据的完整流程

输入样本（Figure 1 示例）

Source (Portuguese): "Avaliar tradução automática é difícil." Reference (English): "Evaluating machine translation is difficult." Candidate: "Evaluating automatic translation are easy."

处理流程

方法 1: Score Prediction

Prompt:

Score the following translation from Portuguese to English with respect
to the human reference on a continuous scale from 0 to 100...
Portuguese source: "Avaliar tradução automática é difícil."
English human reference: "Evaluating machine translation is difficult."
English translation: "Evaluating automatic translation are easy."
Score (0-100):

LLM 输出: 25

问题: 无法知道为何得 25 分，哪些地方出错。

方法 2: AutoMQM

Prompt:

Based on the given source and reference, identify the major and minor errors in this
translation. Note that Major errors refer to actual translation or grammatical errors,
and Minor errors refer to smaller imperfections, and purely subjective opinions about
the translation.
Portuguese source: "Avaliar tradução automática é difícil."
English human reference: "Evaluating machine translation is difficult."
English translation: "Evaluating automatic translation are easy."
Errors:

LLM 输出:

Errors: 'automatic' - major/accuracy; 'are' - minor/fluency; 'easy' - major/accuracy

分数计算（MQM 算法）:

  • 'automatic': major → -5 分（mistranslation: "automática" 应为 "machine" 而非 "automatic"）
  • 'are': minor/fluency → -1 分（主谓不一致："translation" 单数应用 "is"）
  • 'easy': major → -5 分（mistranslation: "difícil" 意为 "difficult" 而非 "easy"）
  • 总分 = 100 - 5 - 1 - 5 = 89 （或按 MQM 负分制：-11）

关键决策点

  1. 错误识别: LLM 定位了 3 个错误跨度（'automatic', 'are', 'easy'）
  2. 严重性判断:
    • 'automatic' 和 'easy' 为 major（语义错误）
    • 'are' 为 minor（语法小错）
  3. 错误分类:
    • 'automatic'/'easy': accuracy/mistranslation
    • 'are': fluency/grammar

最终输出

  • Score Prediction: 25（无解释）
  • AutoMQM: 错误列表 + 自动计算的分数（可追溯每个错误的贡献）

优势: AutoMQM 提供了可操作的反馈——译者可以精确定位并修正这三个错误。

7. Insights：细粒度错误分析不仅提升性能，还提供可解释性，是 LLM 评估的未来方向

7.1 论文评价

出乎意料的发现:

  1. LLM 在 system-level 远超 segment-level: PaLM 540B system-level 准确率 90.1%，但 segment-level Pearson 仅 0.247 — 这表明 LLM 擅长区分系统间整体质量差异，但对单个片段的细粒度判断仍有噪声。

  2. In-context learning 的双面性:

    • Score Prediction + ICL: 几乎无效，LLM 过拟合示例中的具体分数
    • AutoMQM + ICL: 显著提升，性能随示例数单调递增
    • 这暗示结构化输出任务（错误标注）比标量预测任务（分数）更适合 ICL

  3. 指令微调的反效果: FLAN-PaLM-2 UNICORN 性能显著下降（system-level: 90.1% → 75.9%），这与 GPT 系列指令微调后表现优异形成对比，可能是 FLAN 数据集质量问题。

  4. Span-level 表现惊人: UNICORN 的 Major Recall 达 62.8%，MCC 达 0.193，与监督式 word-level QE 模型（COMET-WL）相当——仅用少量 in-context 示例就达到监督模型水平。这是一个被低估的亮点。

方法论优点:

  • 严谨的 meta-evaluation: 同时报告 system-level accuracy、segment-level Pearson/acc*、span-level SP/MR/MCC
  • 诚实报告负面结果: ICL 失败、FLAN 反效果、missing punctuation 检测困难等
  • 三维评估框架: system-level（实际应用）+ segment-level（细粒度判断）+ span-level（错误定位），非常全面

7.2 领域启发

未来研究方向:

  1. 微调 + 细粒度数据: 论文提到正在探索"in MQM 数据上微调 LLM"，这可能是 next big thing——结合 AutoMQM 的可解释性和微调的性能提升。

  2. 扩展到其他 NLG 评估任务: 摘要生成、对话系统等领域的细粒度评估（如 FactCC、SummEval）能否借鉴 AutoMQM 思路？

    • 摘要评估：识别事实错误 → 按严重性扣分
    • 对话评估：识别不当回复 → 分类处理

  3. 低资源语言的改进: 低资源语言对上 LLM 仍落后于学习式指标，可能需要：

    • Cross-lingual transfer: 用高资源语言的 in-context 示例指导低资源语言评估
    • Multilingual prompting: 用英语 prompt + 低资源语言输入，利用 LLM 的英语优势
    • Hybrid approach: 用学习式多语言模型（如 mT5）做初筛，LLM 做细粒度分析

  4. 减少过度预测: LLM 倾向于标注过长的错误跨度（~5 词 vs ~2 词），可能需要：

    • 更好的 prompt 工程（显式要求 fine-grained）
    • 后处理过滤
    • 在 loss 中惩罚过长跨度

  5. 与人类标注的一致性: 如何确保 LLM 的错误分类与人类标注员一致？是否需要人类反馈强化学习（RLHF）？

  6. 混合方法: 结合学习式指标的精度和 AutoMQM 的可解释性

    • 用 COMET-WL 的高精度过滤 LLM 的预测结果
    • 用轻量级指标（如 COMET）初筛，仅对低分段样本使用 AutoMQM 详评

  • 分离"识别"与"计分": AutoMQM 的核心创新是任务设计上的，而非技术上的。这种两阶段设计（LLM 识别错误 → 规则计分）具有三大优势：
    1. 可解释性: 每个错误都有明确的位置、类型和严重性
    2. 可控性: 可以通过调整 MQM 权重来适应不同场景（如医疗翻译要求更严格）
    3. 可调试性: 如果最终分数有问题，可以回溯是哪个错误识别错了

8. 总结

核心创新

AutoMQM prompting technique: 首次将 LLM 用于细粒度 MT 评估，通过让 LLM 识别并分类错误（而非直接预测分数），在提升 segment-level 性能的同时提供可解释的错误标注。核心设计哲学是分离"识别"与"计分"，实现可解释性、可控性和可调试性。

局限性

  1. 需要 in-context 示例: AutoMQM 在 zero-shot 下几乎无效，必须使用 few-shot（至少 4 个示例）
  2. 过度预测错误: LLM 倾向于标注过长的错误跨度，span precision 较低（0.095-0.175）
  3. 低资源语言仍落后: 在 Gujarati/Kazakh 等低资源语言上，LLM 仍不如学习式指标（差距约 13%）
  4. 计算成本高: 使用 540B/更大规模的 LLM，推理成本远高于 mT5/XLM-R 等学习式指标 [?] 具体 latency 和 throughput 数据缺失
  5. 无法检测所有错误类型: 论文提到 missing punctuation 检测仍不理想
  6. 指令微调反效果: FLAN 指令微调显著损害评估性能（90.1% → 75.9%）

改进方向

  1. MQM 数据微调: 在大规模 MQM 标注数据上微调 LLM，可能同时提升性能和减少过度预测
  2. 知识蒸馏: 将大规模 LLM 的 AutoMQM 能力蒸馏到更小模型（如 7B-13B），降低部署成本 [?] 论文未提及相关实验
  3. 混合方法: 结合学习式指标的精度和 AutoMQM 的可解释性（如用 COMET 初筛，AutoMQM 详评；或用 COMET-WL 过滤 LLM 预测）
  4. 扩展错误类型: 当前仅覆盖 MQM 基础类别，可扩展到术语一致性、文化适配性等更细粒度维度
  5. 主动学习: 用 AutoMQM 自动生成伪标注，迭代扩充训练数据
  6. 语言自适应策略: 根据语言对选择不同方法（高资源用 LLM，低资源用学习式模型）
