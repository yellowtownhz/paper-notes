论文笔记: HumanCLAW: Can Vision-Language Models Act Through a Body?

1. 背景信息

  • 团队与单位：Meta 主导，合作 NTU、UW、Brown、Northwestern；18 位作者，Li Siyao 等均等贡献（多为 Meta 实习），通讯作者 Ziwei Liu 与 Chuan Guo。
  • 时间：arXiv v1 2026-07-29，v2 2026-08-03；领域 cs.CV + cs.RO。
  • 项目页：https://human-claw.github.io/ ；论文用 HumanCLAW-Bench 测 9 个前沿 VLM（闭源+开源混合）。
  • 一句话定位：把"动作决策"与"低层执行（balance/motor）"解耦的 VLM 具身动作评测框架 + 长程基准（1218 episode、41 场景）。

2. 关键问题：评测 VLM 是否真能通过一个物理身体去"行动"

Golden Case — 问题是什么？（解耦前） 在客厅里"找到沙发并坐下"。走到沙发前，agent 可能坐空摔倒或没对准就栽下去。失败时你分不清：是 VLM 决策错了（没把身体放到沙发正上方、没对齐朝向），还是电机/平衡控制失败（身体力学没稳住）。失败归因卡在"决策层"和"执行层"之间（§2.4, Fig 1c）。

关键问题：评测"action intelligence"——一个冻结的通用 VLM 在闭环里逐 0.5s 决定"身体下一步做什么"的能力。动作结果把"VLM 的决策"与"电机控制"耦合，失败时归因不清（Abstract, §1）。

关键做法：造一个"决策与执行解耦、但身体仍在物理世界里自由行动"的中间态。被 factor out 的是低层执行侧扰动（balance、motor-tracking）；保留的是物理后果（contact、collision、gravity、物体位移）。这样失败可读成"错误的决策"而非"失去平衡"。

关键结论：9 个 VLM 无一解决基准，最强 Gemini-3.1 的 InteractSR 仅 16.8%（分母=597 sit 子集，见 §5 注）；作者归因于 VLM 缺"embodied self-awareness"。

我的判断：方法论（解耦以隔离决策）很有价值，但"解耦"只做了一半——成功定义里藏着主观声明门槛，且性能大量来自 harness 的 verifier 子模块。读结论要打折。

3. 关键方法：VLM harness 发原子技能 → 0.5s 运动 chunk → half-physics 仿真

Golden Case — 方法怎么跑？（解耦后，同一例子走一遍） 第 t 步 VLM 拿到 512×512 egocentric 图 o_t + 文本历史 h_t，先输出"可见态"（沙发在视野右侧、距 2m、前方无遮挡），再 high→mid→low 推理，输出 walk(x,z,ψ)；verifier 检查"前方空旷、推进目标"通过；Motion Base DiT + walk ControlNet 生成 0.5s 全身运动；half-physics 把运动转成等效速度，墙挡人、重力约束身体，返回新观测。若干步后 turn_in_place 对齐、step_back 微调、sit_in_place(h) 坐下。

解耦读出了什么：若 agent 在离沙发 0.3m、背对座椅处发 sit → 骨盆落地面 → 判 sit on air（Finding 5 占 58%）。执行忠实地实现了"在此处坐下"，失败纯属决策把身体放错位置——half-physics 没引入假阴性，归因干净。

但解耦同一例也有破口：若 agent 物理上已在沙发 0.2m 内却继续发 walk（Finding 4 占 20% "unaware arrived"），论文归因为"身体自我觉察缺失"。然而 NavSR 要求 active stop ∧ AABB≤20cm，同一物理状态可因"是否输出 stop token"判 success/fail——解耦在"停止/声明到达"类悄悄把文字行为重新耦合回成功判定（GeoNavSR 44.7 vs NavSR 42.4，仅差 2.3pp，作者却用含主观门槛的数字当 headline）。

整体架构（Fig 2）：三层流水线 VLM harness → skill<param> → 0.5s 全身运动 chunk → half-physics simulator → 下一观测，闭环到 100 步上限（≈50s）。

3.1 核心模块

  • Harness（§2.2, Fig 3）：把开放 VLM 从 egocentric 感知引向可执行人形控制。先强制输出格式化"可见态"（左→右物体、距离、目标是否可见、周围障碍/可坐面），把空间理解外置；再走 high→mid→low 推理（高层意图 search/approach/align/interact → 中层可维持数秒的目标 → 当前步原子技能），以 JSON 输出。为什么原子化而非组合指令：把"坐在沙发上"拆成 walk→turn_in_place→step_back→sit_in_place(h) 的序列（§2.3，sitting on sofa 不作为单命令暴露）——这强制 VLM 自己规划身体放置，也正是解耦后失败能归因到"放错位置"的前提。共 8 个原子技能（walk/side_step/step_back/turn_in_place/climb_upstairs/walk_downstairs/sit_in_place/stop）。

  • Skill-Specific Verifier（§2.2, Appendix §7, Table 6）：对提议技能用紧凑 skill-specific prompt 从当前 ego 视图 alone 重答一个 checklist（walk 前方是否空旷、stop 是否真到达、climb 脚下是否有台阶等）；失败则同池替换修正技能。side_step/step_back（身后不可见）与 sit 无检查。它是决定性组件（§5 消融）。

  • Skill-conditioned Motion Generator（§2.3, Fig 4）：人类动作不能瞬时切换，需要减速/重心转移等 transient，且 VLM 需要一个 zero-shot 可靠的接口（发 walk 得到常识性走路，而非 moonwalk）。Motion Base DiT 是 38M 参数、10 层、8 头 self-attention（line 468，PDF 确认，非渲染损坏），训练为 receding-horizon continuation：看最近 5 个 clean body state，生成接下来 15 帧 @30fps = 0.5s chunk。为什么 receding-horizon + 5 帧滑动历史能产生惯性一致的过渡：history 直接作为 motion token 与噪声未来拼接（而非压缩成条件向量），future token 能 attend 到精确近期 pose/velocity，天然产生惯性连续——这是复现者最该理解的设计选择。每技能一个 ControlNet adapter，base DiT 冻结；加新技能只训新 ControlNet。条件 e_s(c_t) 从 chunk 几何自动读出（walk=骨盆位移+yaw，sit=目标坐高），无需人工标参；每技能仍人工激进过滤 AMASS 片段保 zero-shot 对齐。

  • Half-physics Simulator（§2.4, Fig 6）：在"全动力学人形（会摔倒）"与"纯运动学幽灵（穿墙）"之间取中间态。世界遵守刚体物理（collision/friction/gravity/articulated+movable objects）；身体不由关节扭矩驱动，而由生成运动导出的等效运动学速度驱动——所以 agent 不因 balance loss / motor tracking 失败，但仍与物理交互（墙挡人、推走可动物体、无支撑竖直运动受重力约束）。代价：测的是"动作决策"而非低层控制，且无触觉通道（碰撞位移世界但 agent 从不"感到"）。

3.4 与已有方法的区别（含 §5 Related Work 定位）

  • vs 程序/离散动作环境（VirtualHome, ALFRED, Habitat 系列）：那些把动作交给 simulator 脚本或离散抽象，agent 不为全身行为负责（§5.1）。
  • vs 端到端 VLA（RT-2, OpenVLA, π0, MolmoAct）：VLA 把任务推理拟合到 robot-specific 轨迹/低层控制，决策与策略纠缠；HumanCLAW 的 decision maker 是冻结通用推理器、motor 层是固定可复用先验，组合 zero-shot 发生（§5.2）。作者也明确"未与 fitted action policy 对比，'失败在决策层'仍是 working hypothesis"（§6）。
  • vs 空间智能 QA 基准：那些是 open-loop 问答；action intelligence 是闭环、把空间理解转成 embodied 决策（§5.3）。

3.5 Prompt 与复现缺口

  • Prompt：原文未提供逐字 system prompt / skill 规则文本。§2.2 只描述组成成分——(1) agent 身份"蓝色 humanoid + egocentric camera"；(2) 高层指令 p（find <obj>、navigate to zero distance、sit on it）；(3) 可用技能列表 + 每技能使用规则；(4) 紧凑文本历史 h_t；(5) 强制先输出可见态、再 high→mid→low、最后 JSON。这是最大复现风险，但不得替论文编造完整 prompt。
  • 复现缺口（原文未交代，压缩为 8 条）：
    1. 无逐字 prompt（仅描述成分）；
    2. 无本体觉/接触信号输入（接口设计）；
    3. σ_min 数值未给；d=219 身体表示法（SMPL? rot6d?）未说明；
    4. ControlNet adapter 参数量、每技能 AMASS clip 数/总数据量未给；
    5. 硬件/GPU 数、训练时长未披露；VLM 解码超参（温度/top-p）未给；

    7. stop / sit 是否各有独立 ControlNet adapter 未明说；

4. 数据集：1218 长程 find→nav→interact episode，41 场景，难度三维

  • 训练数据：AMASS（动作）+ BABEL（技能/文本标签），仅 Table 1 注脚一句"trained once on AMASS/BABEL"，未给数据量、clip 数、时长 [?]；每技能 clip 经人工激进过滤。
  • 评估数据（HumanCLAW-Bench, §3.1, Fig 7）：HSSD-200 的 41 个 validation houses；1218 episode = 597 sit 子集（bed/couch/toilet，完整 find→nav→interact）+ 621 nav 子集（chair/potted_plant/tv，到导航终止）；单条指令"find <obj>, navigate to zero distance, sit on it"，progressive（后阶段需前置满足）；plausibly movable 物体转 dynamic、大固定物保持 static。
  • 难度三维（固定物理阈值，非均分）：distance ≤3.5/≤8 m；choice（>30° 转弯数 + 房间数）≤2/≤5；obstacle（路径 1m 内平均障碍数）≤2.5/≤5；分层占比约 23%/46%/31%（easy/medium/hard）；A⋆ 在 5cm 2D occupancy grid 重建路径，与 ground-truth geodesic 中位比 0.99。
  • 指标（§3.2）：FindSR（目标语义 ID 出现在 ego 图且占 ≥100px@512×512）；NavSR（人体与目标 AABB 最小距离 <20cm）；InteractSR（坐下且骨盆 link 与目标 mesh 接触）；Geo- 前缀变体 = 仅客观几何准则、不要求主观确认；100 步预算；Motion Jerk（三阶导，越低越连贯）；body-awareness（Colls. 碰撞步数、#Dtb 位移物体数、dDtb 位移距离）；Cost（每 episode 平均 token）。

6. Insights

宁缺毋滥。以下均含"观察 → 推理 → 判断"，且删掉论文名即不成立。

6.1 对论文本身的 Comments

  1. 解耦是半截子：half-physics factor out 了 balance/motor，却通过 active stop + AABB≤20cm 的主观完成门槛，把"文字声明到达"重新耦合进成功判定。Geo* 变体证明 nav 层主观/客观仅差 2.3pp，headline 仍用含主观门槛数字，内部不一致。
  2. Verifier 14× 是双刃剑：去掉 verifier 后 NavSR 27→2%、InteractSR 18.9→0%，说明性能大量来自 harness 子模块（且 verifier 本身也是 VLM）。据此推出"base VLM 缺 embodied self-awareness"跨越了证据——更稳妥的结论是"冻结 VLM + 紧凑 re-prompt 下长程 embodied 决策仍失败，主因待定"；"失败在决策层"是归因假设，非因果证明（未与 fitted policy 对比）。
  3. 无本体觉/接触信号却惩罚碰撞并归因为"模型不感知肢体"（Finding 6），存在循环论证风险：接口根本不给 body-state/contact，却用 Colls.% 惩罚它"不知肢体位置"——这是接口必然产生的现象，未必是模型内在缺失。加信号后的 ablation 是本 benchmark 最该补的实验。
  4. 更多历史/图像帧有害（Table 3：img10 NavSR 27→13），与"长上下文更好"直觉相反，与 Finding 4 的"距离幻觉"一致——VLM 不因看更多而更准。
  5. 根因自动归因（Appendix Table 7）是作者先验的投影：把"未纳入视野"归 mid-level、把"停在远处"归距离幻觉；没有人工抽样校验标签准确率（建议补 κ），Figure 8 的解读可信度存疑。
  6. 无 oracle / 随机基线，且无 seed/CI：无法判断 16.8% 是任务天花板低还是模型地板低（若存在 oracle 可达 80%，则是真实能力缺口；若 oracle 仅 25%，则结论需重写）。这是中心结论最大、最该补的漏洞。

6.2 对未来的预测

  • 最该补的实验（合并 A/B 全部未来方向）：给 agent 加本体觉/接触信号（depth、proprioception、碰撞回传）+ 提供 oracle / 最短路径上界作为锚点 + 主表补 seed 与 CI。若加信号后性能跃升，本 benchmark 会被重新解读为"接口问题"而非"模型能力"——这既是作者给自己留的、也是最该验证的假设；同时 oracle 上界才能把"16.8%"赋予"能力缺口"而非"任务极难"的解释。
