论文笔记: Automatically Interpreting Millions of Features in Large Language Models

1. 背景信息

  • 作者: Gonçalo Paulo, Alex Mallen, Caden Juang, Nora Belrose
  • 机构: 未明确标注，但涉及 Machine Learning, ICML 相关研究
  • 发表: arXiv 预印本 (2024年10月)
  • 主题: 稀疏自编码器(SAE)特征的自动化解释

2. 关键问题：如何自动化解释数百万SAE特征并评估解释质量

  • 动机: Sparse Autoencoders (SAEs) 被提出用于解决多义性(polysemanticity)问题，训练SAE会产生大量稀疏特征，每个特征都需要自然语言解释。手动解释数百万特征不可行。
  • 核心问题:
    1. 如何自动化为SAE中的每个特征生成自然语言解释？
    2. 如何评估这些自动生成的解释质量？
    3. 现有评估方法（如simulation scoring）存在什么问题？

3. 关键方法：LLM驱动的自动解释流水线与新评估指标

核心思想：使用LLM自动生成SAE特征的自然语言解释，并提出新的评估指标

3.1 自动解释流水线 (Auto-interpretability Pipeline)

三个主要步骤：

Step 1: 收集激活 (Collecting Activations)

  • 在 10M token 的 RedPajama-v2 数据集上收集 SAE 特征激活
  • SAE隐层神经元通常只有不到60个非零激活

Step 2: 生成解释 (Generating Interpretations)

  • 使用 Llama 3.1 70b Instruct 作为 explainer model
  • 展示 40个不同的激活样本，每个样本32 tokens
  • 激活token被高亮标注，激活强度在样本后显示
  • 成本: $200 解释 1 百万个特征

Step 3: 评估解释 (Scoring Interpretations)

经典方法: Simulation Scoring (Bills et al. 2023)

本文提出新方法的baseline，来自OpenAI的开创性工作

核心思想: 让LLM模拟神经元的激活行为

  1. 给scorer模型一个特征的自然语言解释
  2. 展示一段新文本，让模型预测每个token的激活强度 (0-10分)
  3. 计算预测激活与真实激活之间的Pearson相关系数作为评分

Prompt格式 (Bills et al. 2023 原始方法):

给定解释: "This neuron activates on words related to happiness"

请为以下文本中每个token预测激活强度 (0-10):
"The happy dog ran joyfully"

输出格式:
The    0
happy  8
dog    2
ran    1
joyfully 9

Simulation的问题:

  1. 偏向recall: 宽泛的解释也能获得高相关性（如标记所有"stop"都激活）
  2. 计算昂贵: 需要为每个token生成输出，few-shot examples也多
  3. 任务困难: 要求模型精确定位到具体token，超出了许多模型的能力

本文提出的新评估方法

更高效、更平衡precision和recall：

方法 描述 vs Simulation优势
Detection 让LLM判断整个序列是否激活某SAE特征 不需定位具体token，更"宽容"
Fuzzing 标记潜在激活token，让模型判断标记是否正确 类似软件测试的counterexample方法
Generation 让模型根据解释生成应该激活的文本 测试解释的generative能力
Neighbors 用相似特征的激活文本作为counterexample 解决recall偏向问题

3.2 Output Features 的重要发现

"We define an output feature as a feature that causes a property of the model's output that can be easily explained in natural language."

Output features 的两个优势:

  1. 可扩展性: 更容易通过输出效果描述，而非追溯复杂的输入相关性
  2. 因果证据: 提供因果而非相关性证据，对分布偏移更鲁棒

3.3 Prompt 设计要点

  • 采用"自然"的prompt格式，完整展示激活样本
  • 激活token被强调标注，激活强度在样本后显示
  • 与 Bricken et al. (2023) 类似，从不同分位数采样示例

4.3 Case Study: Reputation Feature

  • Gemma 2 9b layer 32 autoencoder 中的 feature 157
  • 131k features, 平均 L0 norm 51
  • Detection score: 0.6
  • 该特征激活时会导致模型输出与"reputation"相关的词汇

6. Insights：用LLM自动解释SAE特征经济可行($200/1M features)

  1. 自动化可行: 使用LLM自动解释SAE特征是可行且经济的 ($200/1M features)
  2. 评估改进: Detection/Fuzzing 等新评估方法比 simulation 更高效
  3. 因果vs相关: Output features 提供因果证据，更适合模型干预/steering
  4. 局限性: 32 token 上下文可能无法捕捉"长程"特征
  5. 未来方向:
    • 解释"长程"特征
    • 改进 explainer 模型训练
    • 更好的评估反馈信号
