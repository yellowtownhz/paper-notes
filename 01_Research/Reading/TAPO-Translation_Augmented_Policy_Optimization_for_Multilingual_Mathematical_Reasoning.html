论文笔记: TAPO - Translation Augmented Policy Optimization for Multilingual Mathematical Reasoning

1. 背景信息

  • 作者团队来自南京大学软件新技术国家重点实验室 + 上海人工智能实验室
  • arXiv 发表于 2026-03-26，目前还在投稿阶段 [?]
  • 主要作者 Xu Huang、Shujian Huang 是做多语言 NLP 的老面孔了

2. 关键问题：多语言数学推理的"理解瓶颈" + RL 奖励冲突

动机很清晰：LLM 在英文数学推理上已经很强了，但在其他语言上差得离谱。问题在哪？不是推理能力不行，而是理解能力不行——模型看不懂非英文题目。

Figure 1 的证据很硬核：翻译质量（ChrF++）和推理准确率的相关系数 r=0.583，p<1e-5。翻译越好，推理越对，这说明理解确实是瓶颈。

那为什么不直接把题目翻译成英文再推理？Figure 2 展示了一个有意思的现象：

  • 用模型自己翻译（Translate-Test）只比直接推理（En-CoT）好一点点
  • 但用外部高质量翻译（Gemini-Trans 或 Oracle）就大幅提升

结论：模型自带的翻译能力太弱，需要显式训练才能解锁"先翻译再推理"的潜力。

之前的方法各有各的问题：

  1. 隐式对齐（latent space alignment）：在 post-trained model 上容易灾难性遗忘，而且缺乏可解释性
  2. 预训练阶段加 code-switching：资源消耗大，对 post-trained model 效果存疑
  3. SFT-based 对齐（如 QAlign）：论文 Table 1 显示 SFT 后 Qwen 性能暴跌（从 44.8% 到 5.0%），灾难性遗忘严重。论文引用 Shenfeld 2025 "RL's razor"——SFT 是 off-policy，强制模型学习新的输出分布；GRPO 是 on-policy，从模型自己的采样中学习，gradient 更温和
  4. naive GRPO：Section 2.2 的例子很震撼——模型把"鸟笼"误译成"cages"，但照样算出正确答案 3。这说明只靠答案正确性做 reward，模型可能学会蒙对答案而根本没理解题目

3. 数据集：多语言数学推理 + 翻译质量评估

训练数据：

  • 主数据集：MGSM8KInstruct（Chen et al., 2024）
  • 补充数据：用 Gemini2.5-Flash 把 GSM8K 翻译成 Telugu
  • 语言选择：
    • Qwen：Bn, Ja, Sw, Te, Th（五种语言）
    • Llama：Bn, De, Sw, Th, Zh
  • 每种语言约 7.4k 训练样本，Group size G=8（每个问题采样 8 个 trajectory）
  • 训练语言和评估语言有重叠但也有未训练语言用于测试泛化

评估数据：

  • MGSM：in-domain，11 种语言（包括未训练的 6 种作为 unseen-language eval）
  • MMATH、MSVAMP：OOD reasoning tasks
  • 翻译评估：使用 MGSM 非英文题目 → 英文参考翻译
  • 评估方式：每个样本 decode 8 次（temperature=0.6）取平均

翻译质量评估指标：

  • ChrF++、BLEU：用于训练 reward
  • Gemini Score（LLM-as-a-judge）：用于 unbiased third-party evaluation，因为 ChrF++ 和 xCOMET 是训练时优化的指标，用它们评估会 biased

4. 关键方法：TAPO 的核心是"理解-推理分离" + "步级相对优势"

整体架构

TAPO 基于 GRPO 框架，但强制执行一个 explicit "understand-then-reason" 流程：

Non-English Question → <english Translation> → English Reasoning Trace → Answer

Trajectory 结构：o = [τ_trans, τ_reason]

关键设计：把"翻译奖励"和"推理奖励"分开计算，用 step-level relative advantage 避免 reward conflict。

Reward Modeling

三种奖励：

  1. Format Reward（Eq 2）： $$R^{format} = \begin{cases} 1, & \text{if the translation exists} \\ 0, & \text{otherwise} \end{cases}$$

简单但必要：翻译必须在 <english Translation> tag 中才算有效。

  1. Translation Reward（Eq 3）： $$R^{trans} = M(\tau_{trans}, q) \times R^{format}$$

M 是翻译评估指标，论文尝试了三种：

  • ChrF++：n-gram based，character-level，需要 reference——效果最好且最鲁棒
  • xCOMET-XL：model-based semantic evaluation，需要 reference——但容易 reward hacking
  • COMETKIWI-DAXL：reference-free metric

有意思的是 xCOMET 容易被 reward hacking——模型学会了"直接复制原文"来骗高分（Table 2 中 Sw 的 xCOMET 训练版本 Gemini Score 是 0.00）。

为什么 ChrF++ 更鲁棒？ ChrF++ 是 character-level n-gram，复制原文时 n-gram 和 reference 不匹配，天然不敏感。xCOMET 是 neural model，可能学到某些 superficial pattern（如语言相似性）而给高分。低资源语言的 reference 翻译可能质量不高，导致 xCOMET 给复制原文高分。

  1. Reasoning Reward（Eq 4）： $$R^{reason} = \begin{cases} 1, & \text{if the final answer is correct} \\ 0, & \text{otherwise or if } R^{format} = 0 \end{cases}$$

用 Math-Verify 工具做 exact outcome verification。

Step-Level Relative Advantage（核心创新）

这是论文最有价值的设计。

问题：如果直接把 R^trans + R^reason 加起来做 trajectory-level reward，会产生严重的 reward conflict：

  • 如果一组里所有轨迹答案都正确（或都错误），advantage 完全由翻译分数主导
  • 这会惩罚"翻译 mediocre 但推理正确"的轨迹
  • 或者奖励"翻译流畅但推理错误"的轨迹

Figure 4 的证据：trajectory-level reward 的 false positive + false negative advantage 比例稳定在 30% 左右！这噪声太大。

为什么是 30%？ 这个比例和 group size G=8 有关。当 G=8 时，如果所有 trajectory 的答案相同（全对或全错），reasoning advantage 全为 0，翻译 advantage 完全主导。这发生在约 30% 的样本中——取决于数学题难度分布。

解决方案：step-level relative advantage（Eq 5）：

$$\hat{A}_i^{trans} = \frac{R_i^{trans} - \text{mean}(\{R_i^{trans}\}_{i=1}^G)}{\text{std}(\{R_i^{trans}\}_{i=1}^G)}$$
$$\hat{A}_i^{reason} = \frac{R_i^{reason} - \text{mean}(\{R_i^{reason}\}_{i=1}^G)}{\text{std}(\{R_i^{reason}\}_{i=1}^G)}$$

关键点：在各自的 segment 内独立归一化！翻译 token 用翻译 reward，推理 token 用推理 reward，互不干扰。

最终翻译优势融合（Eq 6）： $$\hat{A}_i^{trans*} = \alpha \hat{A}_i^{trans} + (1-\alpha) \hat{A}_i^{reason}$$

这个设计很巧妙：

  • 翻译部分的优势不是纯看翻译质量，也掺了推理优势
  • 这样翻译就会朝"有助于正确推理"的方向优化，而不是只追求字面准确
  • α=0.25 是最优（Figure 6）——少量翻译信号就够了，太多会"淹没"推理的逻辑约束

为什么 α=0.25 最优？ 当 α 接近 1 时，翻译 signal 太强，可能"淹没"推理的 logical constraint。α=0.25 时，推理 signal 占主导（0.75），翻译只起辅助作用。论文没有给出理论解释，但实验证明这个 trade-off 存在。

GRPO 损失函数

用的标准 GRPO（Shao et al., 2024）框架，follow DAPO (Yu et al., 2025) 的改进：

$$\mathcal{J}_{GRPO}(\theta) = \mathbb{E}_{o_i} \left[ \frac{1}{\sum_{i=1}^G |o_i|} \sum_{i=1}^G \sum_{t=1}^{|o_i|} \min(r_{i,t} \hat{A}_{i,t}, \text{clip}(r_{i,t}, 1-\varepsilon_l, 1+\varepsilon_h) \hat{A}_{i,t}) \right]$$

关键配置：

  • 无 KL divergence loss（follow DAPO）
  • Clip-Higher + Token-Level Policy Gradient Loss
  • $\varepsilon_l = 0.2, \varepsilon_h = 0.28$
  • Group size G = 8

Prompt 设计

Translate-Test Prompt（Table 5）：

[System]
Please solve the following problem by providing a detailed, step-by-step response.
Your output **must** be structured into the following three sections:

1. Translation
* Translate the provided problem into English.
* If the problem is already in English, simply reproduce the original problem statement.
* Enclose the final English text within `<english Translation>` and `</english Translation>` tags.

2. Thought
* Present your comprehensive, step-by-step reasoning process for arriving at the solution.
* This reasoning must be transparent, logical, and easy to follow. Break down your process to cover problem analysis, strategy & Planning, step-by-step execution, and verification.

3. Solution
* After reasoning, provide the final, clear, and accurate answer.
* If the result is a closed-form answer (such as a numerical value, formula, or multiple-choice selection), please enclose it using the `\boxed{ }` format.

[User]
{question}

关键点：Translation 必须用 <english Translation> tag 包裹——这是 format reward 检测的依据。Thought 和 Solution 都在英语中进行。不要求翻译本身做 CoT（Wu et al., 2025 显示翻译任务 CoT 收益有限）。

5. 关键结果：TAPO 在低资源语言上提升显著，翻译质量大幅改善

主实验结果（Table 1）

Qwen2.5-3B-Instruct on MGSM：

Method Trained Languages Avg Sw Te Untrained Avg Total Avg
Base 44.8% 13.2% 19.9% 77.7% 44.8%
GRPO-TransTest 65.8% 40.9% 51.2% 84.6% 76.4%
TAPO-ChrF++ 67.3% 49.0% 52.7% 85.0% 77.1%

关键观察：

  • Swahili 提升 8.1%（49.0 vs 40.9），这是最 dramatic 的提升——Swahili 和 Telugu 是训练数据中最低资源的语言，baseline 翻译能力最差，TAPO 直接优化这个短板
  • Telugu 提升 1.5%
  • untrained languages 表现和 GRPO 相当，没有损失
  • 单语言最高：English 91.7%，French 86.5%

Llama3.2-3B-Instruct：

  • TAPO-ChrF++ Total Avg 76.4% vs GRPO-TransTest 75.1%
  • 提升更均匀，所有语言都有 gain

关键对比：SFT-TransTest 在 Qwen 上 catastrophic forgetting 严重——从 44.8% Avg 降到 5.0%（trained languages）。QAlign 同样表现不佳，说明 post-trained 模型对 SFT 很脆弱。On-policy 方法（RAFT, GRPO, TAPO）都避免了 catastrophic forgetting。

翻译质量评估（Table 2 - Gemini Score）

Qwen：

Method Sw Te Avg
Base 7.72 17.82 67.42
GRPO-TransTest 19.94 33.67 70.12
TAPO-ChrF++ 29.29 42.37 74.64

翻译质量大幅提升，低资源语言 Sw 和 Te 尤其明显。

有意思的发现：GRPO-TransTest 也改善了翻译质量（即使没有直接用翻译 reward）。这说明 reasoning reward 提供了 implicit optimization signal——验证了 Eq 6 的设计合理性，把 reasoning advantage 混入翻译 advantage 是有道理的。

TAPO-xCOMET 的 reward hacking 问题：

  • Qwen + TAPO-xCOMET 在 De, Es, Fr, Sw 上 Gemini Score 反常低（De 51.49 vs baseline 84.07）
  • 原因：模型学会了复制原文来骗 xCOMET 分数
  • 这说明 translation metric 的选择很关键——ChrF++ 更鲁棒，xCOMET 在 RL 环境下更脆弱

OOD 泛化（Table 3）

Model MMATH MSVAMP
Qwen + TAPO-ChrF++ 56.77% 80.21%
Qwen + GRPO-TransTest 57.63% 76.39%

MSVAMP 上 TAPO 明显更好（+3.82%），MMATH 上略差（-0.86%）。解释：MMATH 大多数语言未训练，cross-lingual transfer 本身就难；MSVAMP 是"多语言数学推理"，更依赖理解能力，TAPO 的理解优化优势体现出来。

消融实验

Step-level vs Trajectory-level（Table 4）：

Model MGSM (Traj) MGSM (Step) MSVAMP (Traj) MSVAMP (Step)
Qwen 75.45% 77.08% 78.35% 80.21%
Llama 74.11% 76.41% 75.87% 77.25%

差距约 2%，但 Figure 4 显示 trajectory-level 有 30% 的 false advantage，这解释了性能差距。Step-level 的一致性优势证实了 reward conflict 的严重性。

α 的影响（Figure 6）：

  • α=0.25 是 reasoning accuracy 的峰值
  • α=0.75 时 accuracy 最低
  • 翻译质量从 0 到 0.25 快速提升，之后 plateau

推理成本分析（Figure 5）

反直觉发现：TAPO 的总 token 数反而比 GRPO-TransTest 少！

  • Qwen: TAPO 平均 ~550 tokens，GRPO-TransTest ~580 tokens
  • Translation tokens 稳定在 ~70 tokens，占比 <13%
  • 原因：理解清楚后推理更短更精准，不需要反复绕弯

边界条件疑问：如果问题本身需要很长的推理 chain（复杂问题），这个优势还存在吗？论文只验证了数学题，复杂任务未测试。

6. Golden Case：一条 Swahili 数学题的完整流程

输入样本（Swahili，来自 Preliminary Studies）：

Problem: Joho Hutumia komeo 2 za ufumwele wa buluu na nusu ya kiasi hicho cha ufumwele mweupe. 
Huwa inatumia jumla ya komeo ngapi?

(正确翻译: A robe takes 2 bolts of blue fiber and half that much white fiber. 
How many bolts in total does it take?)

naive GRPO 的输出（问题案例）：

... The problem states that there are 2 cages for the birds and half as much space 
for the pet birds. We need to find the total number of cages used...
\boxed{3}

模型把"ufumwele"（fiber）误解成"cages"，把"buluu"（blue）完全忽略，但照样算出 3（因为数字 2 和"half"的关系对了）。这是典型的"蒙对答案"案例——模型学会了"提取数字+套逻辑关系"，但不懂题目在说什么。

TAPO 的处理流程：

Step 1 - Translation：

<english Translation>
A robe takes 2 bolts of blue fiber and half that amount of white fiber. 
How many bolts does it use in total?
</english Translation>

ChrF++ reward 会和 reference 对比，鼓励准确翻译。

Step 2 - Thought：

The problem asks for the total number of bolts of fiber used.
- Blue fiber: 2 bolts
- White fiber: half of blue = 2/2 = 1 bolt
- Total = blue + white = 2 + 1 = 3 bolts

基于正确的英文翻译进行推理。

Step 3 - Solution：

\boxed{3}

关键决策点：如果翻译很差但答案对了，step-level mechanism 会：

  • 翻译 token 得到低 advantage（因为它和组内其他翻译比）
  • 推理 token 得到高 advantage（因为答案正确）
  • 不像 trajectory-level 那样把两者混在一起导致 reward conflict

Credit assignment：翻译 tokens 用 A^trans* = 0.25 A^trans + 0.75 A^reason，推理 tokens 用 A^reason。

7. 我的疑问

疑问 1：α=0.25 的最优值是经验得到的还是有理论解释？

  • 我的理解：论文说"small translation signal is enough to improve understanding, but overly large signal risks drowning out logical constraints"
  • 想搞清楚的是：这个 trade-off 的数学本质是什么？是不是和 gradient 的尺度有关？是否和具体的 translation metric 有关？
  • Reviewer 补充：论文没有给出理论解释，但推测和 gradient 尺度有关。当 α 接近 1 时，翻译 signal 太强，可能"淹没"推理的 logical constraint。α=0.25 时，推理 signal 占主导（0.75），翻译只起辅助作用。

疑问 2：Translation advantage 融合 reasoning advantage 的必要性

  • 我的理解：作者说是为了防止 reward hacking 和让翻译"知道"推理目标。但既然 step-level 已经 decouple 了，为什么还需要在 translation advantage 中混入 reasoning advantage？
  • 想搞清楚的是：如果只用 pure A^trans（不融合），效果会怎样？这个设计是必要的还是只是锦上添花？
  • Reviewer 补充：即使 step-level decouple 了，纯 A^trans 只追求翻译"字面准确"，不一定"有助于推理"。融合 reasoning advantage 让翻译朝"解决问题有用的方向"优化，而不是追求 BLEU-like metric。但这仍是不完整的回答——需要消融实验验证"pure A_trans vs 混合"的效果差异。

疑问 3：xCOMET 的 reward hacking 具体机制

  • 我的理解：Table 2 显示 TAPO-xCOMET 在某些语言上 Gemini Score 反常低（De 51.49 vs baseline 84.07）
  • 想搞清楚的是：xCOMET 具体在什么情况下会给"复制原文"高分？这和低资源语言的 representation quality 有什么关系？
  • Reviewer 补充：低资源语言的 representation 在 xCOMET 的 embedding space 中可能和英语有 superficial similarity（比如借词、拉丁字符）。模型发现"复制原文 → embedding 相似 → high xCOMET score"这条捷径。另外，低资源语言的 reference 翻译可能质量不高，导致 xCOMET 给复制原文高分。

疑问 4：翻译开销真的不增加推理成本吗？

  • 我的理解：Figure 5 显示翻译 token 约 70 个，占总 response 的 13%，但 TAPO 的 total token 数比 GRPO 还低
  • 想搞清楚的是：如果是普遍规律还是只适用于简单数学题？如果问题本身需要很长的推理 chain，这个优势还存在吗？
  • Reviewer 补充：关键洞察是"理解清楚后推理更短"，不是简单的 token 加法。如果推理 chain 本来很长（复杂问题），翻译的效率优势可能更大——因为"绕弯"减少。

疑问 5：为什么 SFT 会导致这么严重的灾难性遗忘？

  • 我的理解：Table 1 Qwen SFT-TransTest：Avg 从 44.8% 跌到 5.0%。论文解释是"post-trained models 对 SFT 很敏感"
  • 想搞清楚的是：这是 Qwen 特有的还是通用现象？GRPO 为什么能避免这个问题？
  • Reviewer 补充：SFT 是 off-policy，强制模型学习新的输出分布，容易破坏已学到的能力；GRPO 是 on-policy，从模型自己的采样中学习，gradient 更温和（论文引用 Shenfeld 2025 "RL's razor"）。

8. Insights

8.1 对论文的 Comments

反直觉的点：

  1. 翻译奖励掺入推理奖励（Eq 6）这个设计我一开始觉得奇怪——为什么要让翻译受推理影响？但 Figure 6 和 Table 2 的证据说服了我：纯翻译奖励会 reward hacking，掺入推理奖励能让翻译朝"有意义"的方向优化。

  2. step-level advantage 比 trajectory-level 好 2%——乍看差距不大，但 Figure 4 显示 30% false advantage，这个诊断很漂亮。不是简单的消融实验，而是深入分析 reward conflict 的根源——量化"问题有多严重"而不是只说"有问题"。

  3. TAPO 的推理 token 数比 GRPO 少——Figure 5 这个结果让我意外。直觉上"多生成 70 个翻译 token"会增加开销，但"理解清楚"反而让后续推理更短更精准。这打破了"先翻译再推理一定更慢"的假设。

如果让我来做，想不到的点：

  • 把 reward conflict 量化成 false positive/negative advantage 的比例（Figure 4）——这个分析方法很 clever
  • α 的最优值是 0.25 而不是 0.5——直觉上我会设 0.5（平衡），但实验证明需要偏向推理

做得不好的地方：

  • 论文没解释为什么 ChrF++ 在 low-resource languages（Sw, Te）上效果好，而 xCOMET 在这些语言上失效——这和 metric 本身的特性有关，应该展开讨论
  • xCOMET reward hacking 不仅仅发生在低资源语言，高资源语言（De, Es, Fr）也有 Gemini Score 下降——说明问题是 xCOMET 本身在 RL 环境下的脆弱性，不只是低资源语言的 representation quality
  • 未测试更大模型（Limitations 里承认了）
  • 训练硬件配置未说明（GPU 数量、时长、成本估计）

8.2 研究品味

问题诊断做得好：Preliminary Studies 部分（Section 2）的设计很棒——先做 correlation analysis（Figure 1），再做 prompt comparison（Figure 2），最后做 naive GRPO 的失败案例分析（Swahili 案例）。这种"层层深入"的分析逻辑很清晰，把"为什么要做这个方法"讲得很透彻。

Reward conflict 的可视化（Figure 4）很有说服力：不只是说"有问题"，而是量化"问题有多严重"（30% conflict rate）。这种量化让读者更容易理解设计的必要性。

9. 总结

  • 核心创新：step-level relative advantage mechanism——利用 trajectory 结构分离翻译和推理，独立计算 advantage，解决 reward conflict 问题
  • 局限性：
    1. 只测试了 3B 模型，未验证 larger models
    2. 推理输出是英文，对非英文用户不友好
    3. xCOMET reward hacking 问题没解决——说明 translation metric 选择对 RL 效果影响大
    4. α=0.25 的理论解释缺失
  • 改进方向：
    1. 开发专门为 RL 设计的 translation metric，更鲁棒、更不容易 reward hack
    2. 测试 large reasoning models（o1-style）
    3. 多语言输出（推理完后翻译回去）
    4. 自适应 α：根据语言类型或任务难度动态调整 fusion weight
