论文笔记: LOGOS — Speaking the Language of Science

1. 背景信息

  • 作者团队: 阿里巴巴集团 + 中国人民大学高瓴人工智能学院（Jieping Ye, Ji-Rong Wen, Bing Su 组）
  • 发表时间: 2026-06-15, arXiv preprint (cs.CL)
  • 模型规模: 1B (Llama3.2-1B) / 3B (Llama3.2-3B) / 8B (Qwen3-8B)
  • 开源: 模型权重和数据处理 pipeline 已发布

2. 关键问题：如何用一个模型统一处理蛋白质、小分子、材料、反应等异构科学任务

Golden Case — 问题是什么？

假设你是一个做药物设计的研究者。你有一个蛋白质靶点，已知它有一个 binding pocket，你想生成能结合到这个 pocket 的小分子配体。

现在你面对这样的局面：

  • 蛋白质的表示是氨基酸序列（GSRSIMEYLCG...）
  • 小分子的表示是 SMILES 字符串（O=C(Nc1cccc2cn[nH]c12)c1ccc(Br)s1）
  • Pocket 的定义依赖于 3D 结构（哪些残基在空间上靠近配体）
  • 如果你还想做逆合成预测（怎么合成这个配体）、或者生成新材料，那又是完全不同的数据格式和模型

所以你得分别训练蛋白质模型、分子生成模型、docking 模型、逆合成模型......每个领域都有自己的"技术栈"。

核心困境有三层：

第一层：表征碎片化。 蛋白质、小分子、材料、反应各有自己的符号系统和数据格式，现有方法大多只在单一 domain 里做。ProGen2 只管蛋白质，Evo 只管基因组，跨 domain 的知识迁移根本没法发生。

第二层：预训练-下游目标错位。 BERT 范式（masked LM + contrastive learning）学的是"恢复被遮住的 token"，但下游任务是"给定 pocket 生成配体"、"给定产物反推反应物"这类条件生成。预训练目标和下游目标之间有本质的 gap，必须靠大量 fine-tuning 来弥补。

第三层：自然语言做桥梁的代价。 NatureLM 尝试用自然语言作为统一接口（instruction-response format），但科学数据量远小于自然语言数据量，在固定参数预算下，模型容量被迫分配给维持通用语言能力。论文的探索实验直接证明了这一点：在预训练阶段混入越多自然语言数据，配体生成性能越差（Figure 3a，在 0.6B/1B/3B 三个 scale 上一致）。

3. 关键方法：设计一套"科学语法"，把蛋白质、小分子、pocket 交互等异构数据统一编码为 token 序列，做 next-token prediction

Golden Case — 方法怎么跑？

继续上面的例子：你有一个蛋白质，它的 pocket 里有若干残基（比如第5个位置是 Alanine，第12个位置是 Asparagine）。你想让模型生成一个能结合到这个 pocket 的小分子。

LOGOS 的做法是：

  1. 把整条蛋白质序列写成 <ProteinS>HMIS...DLA...SHS...<ProteinE>
  2. 把 pocket 残基标记出来，并展开为侧链 SMILES：<ProteinS>HMIS...<PocketS>C[C@@H](C(=O)O)N<PocketE>DLA...<PocketS>C([C@@H](C(=O)O)N)C(=O)N<PocketE>SHS...<ProteinE>
  3. 在序列末尾追加 <MoleculeS>，让模型自回归生成配体 SMILES 直到 <MoleculeE>

整个 pocket-conditioned ligand generation 就变成了：给定一个 token 序列前缀，预测后续 token。预训练和下游任务用的是完全一样的"语法"，没有 gap。

关键的 trick 是 pocket 的表示：不用 3D 坐标，而是把 pocket 残基的侧链直接"翻译"成 SMILES token 嵌入到蛋白质序列中。这样 pocket 的化学特性就用小分子的语言来描述了，模型在学配体生成的同时，天然能利用 pocket-小分子的化学对应关系。

3.1 整体架构

LOGOS 的核心思路：设计一套 unified scientific grammar，把所有科学对象（蛋白质、抗体、小分子、反应、材料、pocket、蛋白-配体复合物）都编码为 discrete token sequence，然后用标准 autoregressive LM 做 next-token prediction。

架构上就是 Qwen3-8B / Llama3.2-1B/3B，保留原始 LLM 的全部 vocab，额外加入科学语法的 boundary tokens（<ProteinS>, <MoleculeS>, <PocketS> 等）。

3.2 科学语法设计（核心贡献）

七种模态，每种都有自己的 token 化规则：

模态 格式 数据来源
Protein <ProteinS>氨基酸序列<ProteinE> UniRef90
Antibody <AntibodyS>氨基酸序列<AntibodyE> OAS (70% identity 聚类去冗余)
Small Molecule <MoleculeS>SMILES<MoleculeE> PubChemQC
Reaction 正向 <MoleculeS>reactants<MoleculeE><React><MoleculeS>products<MoleculeE>；反向用 <ReverseReact> ORD + ECReact
Material (MOF) <MaterialS><MetalS>金属簇<MetalE><MoleculeS>有机连接子<MoleculeE>...<MaterialE> Boyd et al. 2019
Pocket 四种递进表示（见下） PDB + P2Rank
Protein-Ligand Complex <ProteinS>...<PocketS>SMILES<PocketE>...<ProteinE><MoleculeS>SMILES<MoleculeE> Q-BioLiP

Pocket 的四种递进表示——从定位到化学描述到跨表示映射再到预测：

  1. Amino acid-level annotation: <PocketS>A<PocketE> 标记 pocket 残基位置——告诉模型"在哪"
  2. Small-molecule-expanded: 把 pocket 残基展开为侧链 SMILES（如 Ala → C[C@@H](C(=O)O)N）——告诉模型"化学上是什么"
  3. Amino acid-small molecule transformation: 用 <Trans> token 把表示1和表示2串联成翻译对——让模型学习氨基酸 ↔ SMILES 的映射
  4. Binding site identification: <ProteinS>...<ProteinE><Search><ProteinS>...<PocketS>...<PocketE>...<ProteinE>——纯序列预测 binding site

这四种表示通过嵌套语法（pocket token 嵌入 protein token 内部，pocket 内容展开为 molecule SMILES）实现了蛋白质和小分子两个符号系统的桥接。

空间交互的 token 化：核心设计决策。传统方法用 3D 坐标 + geometric neural network 建模 pocket-ligand 交互，LOGOS 把空间关系离散化为 token 序列——用 5-10 Å 距离阈值把蛋白质残基分为 pocket/non-pocket，然后展开为 SMILES。对同一个复合物做多半径采样，生成多条不同空间尺度的训练序列。

3.3 关键设计决策的 Why

为什么不用自然语言做接口？ 探索实验数据（Section 2.2.1，注意这些 ablation 在 Qwen3-0.6B 上做的，不是主实验的 1B/3B/8B）：

  • 权重初始化 ablation（Table 1）：

    设置 Emb Backbone LM_head Vina (↓)
    Random init ✗ ✗ ✗ -6.91
    Embedding only ✓ ✗ ✗ -6.78
    Emb + Backbone ✓ ✓ ✗ -7.21
    Full LLM ✓ ✓ ✓ -7.43

    只继承 Embedding 反而比随机更差（-6.78 vs -6.91），说明 LLM embedding 是为自然语言 token 优化的，强行用于科学 token 引入有害先验。但 Backbone（attention pattern、位置编码等）的 sequence modeling 能力可迁移——在 Emb 基础上加 Backbone 一下跳到 -7.21。

  • NL 数据比例 (Figure 3a)：混入自然语言数据的比例越高，ligand generation 性能越差。0.6B/1B/3B 三个 scale 一致。

结论：LLM 的 weight initialization 有用（提供归纳偏置），但 NL corpus 在 continual pre-training 阶段有害（挤占 domain capacity）。

为什么 pocket translation 数据这么重要？ Table 2 的 ablation：

配置 Vina (↓) Site Acc. Sample Acc.
w/o pocket & complex -3.57 3.76 5.33
w/o Trans 翻译数据 -6.25 17.18 21.64
Full (1B) -7.64 48.42 64.40

翻译数据本身不含任何 ligand 信息，只是教模型把氨基酸"翻译"成对应 SMILES，但带来最大性能提升（-6.25 → -7.64）。Site Acc. 和 Sample Acc. 同步大幅提升，说明翻译数据让模型真正学会了氨基酸和小分子化学结构之间的语义等价关系。

3.4 训练流程

Stage 1 — Continued Pre-training：

  • 数据：七模态语料，共 44.87B tokens [?] 各模态的 token 分布比例和采样策略未披露
  • 硬件：32× NVIDIA A800
  • 超参：AdamW, peak LR=2e-5, cosine schedule, warmup ratio 0.06, max 100K steps, batch size 1024, bf16

Stage 2 — Post-training (SFT)：

  • 从四个下游 task 的训练集中取少量样本（具体数量未披露），处理成与预训练一致的语法格式
  • Pocket identification 的 SFT 数据用 CHEN11 数据集 + 预训练阶段数据的子集合并
  • Material generation 的 SFT 数据直接继承自预训练（不额外引入下游训练集）
  • 硬件：8× NVIDIA A800
  • 超参：AdamW, peak LR=1e-5, cosine schedule, warmup ratio 0.1, 8 epochs, batch size 128, bf16

推理参数：

  • Ligand/Retrosynthesis/Material: top_p=0.85, temperature=1.2, repetition_penalty=1.05
  • Pocket ID/Protein editing/CDR design: top_p=0.9, temperature=1.2, repetition_penalty=1.0

3.5 与已有方法的本质区别

维度 LOGOS NatureLM Domain-specific 方法 (TargetDiff 等)
跨模态接口 科学语法 (domain-native tokens) 自然语言 instruction-response 无（单模态）
3D 信息 训练时消费（P2Rank 标注+复合物数据+多半径采样），推理时不需要 部分使用 显式 3D 坐标 + 几何网络
预训练-下游对齐 完全一致（same grammar, same objective） 部分一致 不适用
参数效率 高（1B 即可超越多数 baseline） 低（8×7B MoE） 不可比

5.3 Retrosynthesis Prediction (Table 5)

Method Top-1 (↑) Top-3 (↑)
NatureLM (8×7B) 71.9% 87.4%

Top-1 最好（74.8% vs NatureLM 71.9%），但 Top-3 比 NatureLM 低 11.8pp（75.6% vs 87.4%）。这个 gap 不太正常——LOGOS 的概率分布过度集中在 top-1 预测上，候选多样性差。论文用"precision vs diversity trade-off"一笔带过，但这对实际应用（合成路线规划需要多条备选方案）是实质性问题。一个结构性假设：LOGOS 的科学语法通过单一 <ReverseReact> token 触发生成，缺少 NatureLM 那样通过自然语言 instruction 调节 diversity 的机制。

5.7 Scaling Behavior

6. Insights

6.1 对论文本身的 Comments

"不用 3D 坐标"的 claim 需要大幅打折。 LOGOS 推理时确实不输入 3D 坐标，但训练数据的 pocket 标注来自 P2Rank 对 PDB 3D 结构的预测，复合物数据用 5-10 Å 距离阈值定义 pocket 残基。所以 3D 信息在训练时已经被消费，只是通过 tokenization 编码到了序列中。正确的描述不是"不依赖 3D 信息"，而是"在训练时将 3D 信息蒸馏到序列表示中，推理时不再需要结构"。这个区别很重要——它意味着 LOGOS 的适用范围受限于有结构数据可用的蛋白质（已有 PDB 结构或高质量 AlphaFold 预测的）。

Pocket translation ablation 是全文最有说服力的实验。 翻译数据本身不含任何 ligand 信息，却带来了 Vina 从 -6.25 到 -7.64 的最大跳跃。这证明的不是"更多数据 = 更好性能"，而是"在两个符号系统之间建立显式对应关系"为什么有效。如果让我来做这个项目，大概率不会想到要专门构造这种"翻译数据"。

"只继承 Embedding 反而更差"给知识迁移提供了 actionable 指导。 LLM embedding 对科学 token 有害，但 Backbone 的通用 sequence modeling 能力可迁移。这对其他 domain adaptation 项目（如代码模型迁移到生物序列）有直接参考价值。不过需注意这个实验在 0.6B 模型上做的，结论在 8B scale 上是否成立未验证。

Top-3 retrosynthesis 的 11.8pp gap 暴露了 "no NL" 设计的结构性代价。 LOGOS 的科学语法缺少多样性控制机制。NatureLM 可以通过自然语言 instruction 调节生成策略，LOGOS 只能靠 temperature/sampling——而论文用的 temperature 已经是 1.2（高于常规），说明单靠采样参数无法补偿这个结构性缺陷。

6.2 对未来的预测

科学基础模型的路线之争（NatureLM "自然语言接口" vs LOGOS "科学原生语法"）会持续，但长期可能需要融合——纯科学语法无法支持人类可读的 instruction following，而纯自然语言又浪费容量。一个可能的方向：用科学语法做 core representation，用少量 NL adapter 做接口层。

这篇论文的 deeper implication：AI4Science 不需要独立的技术栈，LLM 的架构和训练范式本身就够用，只需要换一套 tokenization。如果这个结论能在更多 domain（基因组、蛋白质结构预测、分子动力学）上验证，大量 domain-specific geometric network / diffusion model 可能会被 scaled-up 的语言模型取代。这个预测的 falsification 条件是：如果 AlphaFold 级别的蛋白质结构预测无法被 token prediction 覆盖，说明某些任务本质上需要连续几何表示。
