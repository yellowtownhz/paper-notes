论文笔记: Language as a Latent Variable for Reasoning Optimization

1. 背景信息

  • 团队: Tongyi Lab（通义实验室），第一作者 Linjuan Wu 为实习生
  • 投稿: ICML 2026
  • 基座模型: Qwen2.5-7B-Instruct（主实验）、Llama3-8B-Instruct（跨架构验证）
  • 核心发现: 做 Polyglot Thinking Experiment 发现——不限制语言时模型表现往往比任何单一语言约束都好。论文把这个现象 framing 成"语言是推理的潜变量"，并据此设计了 polyGRPO

2. 关键问题：不同语言触发不同推理路径，但现有 RL 训练把语言多样性当噪声过滤掉了

Golden Case — 问题是什么？

给 Qwen2.5-7B-Instruct 一道 MGSM 数学题，比如 "A baker has 24 croissants and sells 8. How many remain?"。

  • 强制用英文回答，MGSM 10 语言平均准确率约 90%（英文题上）
  • 强制用中文回答，在某些低资源语言题上反而比英文好
  • 不限制输出语言时（unconstrained），多语言平均表现往往比任何单一语言约束都好

Figure 1 直观展示了这个现象——红区（各语言约束下的最佳得分）和蓝区（英文得分）并不总是重叠，蓝色虚线（unconstrained）经常超过蓝色实线（英文约束）。

Table 2 进一步揭示了一个有意思的细节：base model 回答 Bengali 题时，90.01% 用英语、8.39% 用中文、1.6% 用 Bengali——这说明模型本身就会 code-switching。但这种多语言混合是不是真的触发了不同的推理路径？还是只是反映了 Qwen2.5 中文-heavy 的预训练分布？论文没有回答这个问题 [?]。

  • 动机: LLM 的英文偏见正在减弱，某些非英文推理路径反而更好。这说明语言不只是输出格式，可能调制了内部推理
  • 之前方法卡在哪:
    • MAPO: 用翻译对齐偏好，把非英文推理对齐到英文 → 压制了多语言推理多样性
    • LIDR: 用英文 vs 非英文的性能差距做偏好数据 → 没直接利用多语言推理轨迹
    • GRPO: 用多语言训练数据但只生成英文 response → 多语言多样性只停留在输入端，rollout 没探索非英文路径
    • 核心矛盾：你想要利用语言多样性扩大推理探索空间，但现有方法要么在训练时抹杀多样性，要么在推理时才临时引入（投票/语言选择）。缺一个训练阶段就把语言多样性内化成探索信号的框架

3. 关键方法：polyGRPO——用多语言 rollout 做隐式探索，让语言多样性扩大推理空间

Golden Case — 方法怎么跑？

还是那道 "24-8=?" 数学题。polyGRPO 的处理流程：

  1. PRGM: 对同一道题生成 n=5 个 response：
  • 1 个 unconstrained（[LANGUAGE] 留空，模型自由选语言）
  • 4 个 language-constrained（随机从 10 语言集里选 4 个语言，填入 [LANGUAGE]）
  • 这 5 个 response 组成一个"Polyglot Thinking 组"，可能包含英文、中文、德语、泰语等不同语言的推理路径
  1. Reward Module: 对每个 response 打分：
  • 答案正确 → AR=1；否则 AR=0
  • 有 [Thinking] 标签 + #### 格式 + 推理内容 >= 100 字符 → FR=1；否则 FR=0
  • 总分 r ∈ {0, 1, 2}
  • 例如：中文 response 答对了且有推理过程 → r=2；泰语 response 答错了但有推理过程 → r=1；斯瓦希里语 response 答错且无推理过程 → r=0
  1. GRPO 优化: 组内相对 advantage 做 policy gradient：
  • A_i = (r_i - mean(r)) / std(r)
  • 5 个 response 的 r = [2, 2, 1, 0, 0]，mean=1, std≈0.89，则 A ≈ [+1.12, +1.12, 0, -1.12, -1.12]
  • 正 advantage（正确的中文和德语推理）被强化，负 advantage（错误的泰语和斯瓦希里语）被抑制
  • 关键：强化的是正确的推理路径，不管它是什么语言；语言多样性是探索手段，不是优化目标
  1. 推理时: [LANGUAGE] 留空，模型自选语言（最终倾向英文，但保留了 code-switching）

PRGM（多语言生成模块）

  • 对每个 (q, a)，从 old policy π_{θ_ref} 采样 n=5 个多语言 response
  • 语言集: 10 种语言，与训练数据对齐——{EN, BN, TH, SW, JA, ZH, RU, DE, ES, FR}（注意：TE/Telugu 只在 MGSM 评估中出现，不在 PRGM rollout 语言集里）
  • 1 个 unconstrained + 4 个 language-constrained（随机从语言集里选）
  • Online generation，不存储 offline 偏好数据
  • Response 格式要求：推理在 [Thinking] 内，最终答案在 #### 后

Reward Module

$$r_i = \text{AR}(o_i) + \text{FR}(o_i), \quad r_i \in \{0, 1, 2\}$$
  • AR: 精确匹配最终答案与 gold answer → 1 或 0
  • FR: 包含 [Thinking] 标记 + #### 格式 + 推理内容 >= 100 字符 → 1 或 0
  • Base 模型特殊处理: 如果模型生成 "### Instruction:" 等续写内容，FR 扣 0.5 分（Appendix G）

Policy Optimization

组内 advantage 标准化：

$$A_i = \frac{r_i - \text{mean}(r_{i=1}^n)}{\text{std}(r_{i=1}^n)}$$

polyGRPO loss 和标准 GRPO 一致——PPO-style clipped objective + KL penalty。唯一区别在 rollout 来源：π^{i,t} 的条件里包含 prompt p_i（可能有语言约束），所以不同语言的 response 有不同的 token 分布和 importance ratio。公式 (4) 在原文中有 HTML 渲染乱码，重要性 ratio 的分母被截断，影响可复现性 [?]。

物理意义：答对且有格式的多语言路径 advantage 高，答错的低，policy 自然学到"好的推理路径"而不管语言。

训练流程

  • Qwen2.5-7B-Instruct: 5 epochs, lr=1e-6, batch=256, 8×A100
  • Llama3-8B-Instruct: 1 epoch, lr=1e-6, batch=256, 8×A100
  • Framework: verl
  • 推理: greedy decoding, [LANGUAGE] 留空

与已有方法的区别

方法 Rollout 语言 偏好数据来源 核心思路
GRPO 仅英语 英语 response 组内 纯英语探索

6. Insights

6.1 对论文本身的 Comments

  1. "语言作为潜变量"的 framing 可能过度了。 论文观察到的现象是：不同语言下准确率不同，unconstrained 最好。但"不同准确率"不等于"不同推理路径"。这可能有三个更 mundane 的解释：(a) Qwen2.5 预训练中中文占比高，所以中文推理路径更成熟；(b) 不同语言的 tokenization 效率不同，有些语言用更少的 token 表达同样的推理，导致模型更容易在那些语言上"走到底"；(c) FR 的 100 字符阈值对不同语言有系统性偏差。论文没有排除这些 confound，直接从"不同准确率"跳到"语言结构性地调制推理路径"，这个 leap 太大。

  2. 核心 causal claim 缺少对照实验。 论文标题和 framing 声称"语言是潜变量"，但实验只支持"多语言 rollout 比 English-only rollout 好"。换成 temperature variation、random prompt paraphrase、或者其他任何增加 rollout diversity 的手段，可能也能得到类似的增益。论文没有做这个对比，所以你没法判断是"语言"这个维度特别重要，还是"任何增加探索多样性的方式都行"。

  3. Polyglot Thinking Experiment 只在 MGSM 上验证——这是整个 motivation 的薄弱点。 MGSM 是 GSM8K 的翻译版，题目简单。如果"非英文有时比英文好"这个现象在 MATH500/PolyMath 上不成立，那整篇论文的 motivation 就站不住。更讽刺的是，polyGRPO 在 MATH500 和 PolyMath 上的增益确实比 MGSM 上小得多——这暗示 motivation 和 method 的有效性可能脱节：method 可能有效是因为"多语言 rollout 增加了组内 diversity 让 GRPO 的 advantage 估计更有意义"，而不是因为"语言是潜变量调制了推理路径"。

  4. Format reward 不只是格式约束，更是 RL stability mechanism。 1.5B 去掉 FR 从 51% 崩到 14%，这不是"模型懒得写推理"，而是 RL training mode collapse / reward hacking。FR 作为隐性正则化器防止了小模型的训练崩溃——这是一个通用 RL 问题，不特定于多语言推理。论文把 FR 当作"鼓励推理格式"来描述，低估了它对训练稳定性的作用。

  5. 论文自身承认的三个 limitation（Impact Statement）：(a) reward 只看最终答案和粗糙推理结构，没利用 polyglot reasoning trajectory 里的细粒度信号；(b) 没建模不同语言推理路径之间的逻辑/结构关系；(c) 只评估答案正确性，没考察推理过程的语言一致性。这些是论文自己说的，比读者猜的更有分量。

6.2 对未来的预测

  • 语言作为 exploration signal 的思路会扩展到其他 RL 方法（论文已在 GSPO 上验证）。但当前增益有限（2-4% AVG），如果在 70B+ 上没有类似增幅，可能只是小模型 artifact（小模型探索空间更窄，多语言探索的边际收益更大）。
  • 关键的 open question：语言多样性是否比其他多样性手段更高效？只有对比了 temperature annealing、prompt paraphrase 等替代方案，才能确定"语言"是不是关键维度。
