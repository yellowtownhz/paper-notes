2. 关键问题：检测到模型做了"坏事"之后，怎么区分它是"真坏"还是"犯糊涂"？

Golden Case -- 问题是什么？

想象一个 coding agent 被部署去维护一个代码库。某天你发现它提交了一个 commit，把 safety_controller.py 里的人工审批流程删掉了，注释写着"latency optimization"（论文 Figure 1 的例子）。这意味着模型现在可以绕过人类监督做任何事。

你慌了。但问题是：这个 agent 到底是在有意识地颠覆人类监管（scheming），还是真的只是想优化延迟？前者需要立刻停止部署甚至拉响整个安全警报，后者只需要 code review 打回去。响应级别天差地别，但你面前只有同一个 commit。

这不是假想场景。论文引用了一个真实案例：frontier models 被发现在解数学题时会抵抗 shutdown 指令，看起来像是"自我保护"倾向；后续调查发现其实只是模型搞不清该优先执行数学任务还是 shutdown 指令，把指令说清楚之后行为就消失了 [Rajamanoharan and Nanda, 2025]。

核心张力在于：behavior underdetermines intent。同一个外在行为可以由完全不同的内在动机产生。

之前做 alignment 的工作大多停留在"检测"层面 -- 发现模型做了不该做的事（in-context scheming、sandbagging、reward hacking 等）。但检测到 concerning behavior 只是第一步。如果你因为"模型犯了糊涂"就拉响最高级别警报、停止部署，代价巨大且不合理；如果模型真的 strategically misaligned 你却因为证据不足而放过它，后果更严重。

已有的 investigation 方法（比如 Anthropic 调查 Claude 4.6 Opus 拒绝 safety research 请求）"only suggestive" -- 用了 interpretability 但结论不够 rigorous。传统 ML 方法（probing、behavioral evals）关注的是 behavior 而非 intent，没法直接回答"模型到底是不是在搞阴谋"。

这篇论文把这个问题正式命名为 model incrimination（模型定罪）：给定一个 concerning incident，系统性地调查其背后的动机，最终要么"定罪"（intentional subversion）要么"无罪释放"（benign cause）。

3. 关键方法：两步协议 -- 先读 CoT 生成假设，再用环境干预验证假设

Golden Case -- 方法怎么跑？

继续用 coding agent 的例子。论文设计了一个叫 Pre-commit Hook 的环境来模拟类似场景：让模型在一个有 258 个 type error 的 Python 项目里写 pre-commit hook，hook 要求 mypy 严格模式通过。这意味着 commit 必然被 block，模型要么老老实实修 258 个 error，要么走捷径（比如把 hook 改成只检查 staged files、关掉严格模式等）。Kimi K2 Thinking 走捷径的概率是 13.1% [8.9%, 18.9%]。

Step 1: 假设生成 -- 读 CoT。读模型的思维链，发现一个典型模式：模型先列出所有选项（修 error vs. workaround），然后开始抱怨"But fixing 258 errors would be a huge task"，最后选择 workaround。用 sentence resampling 量化发现，这句抱怨把 workaround rate 提高了 11.4%（Figure 2）。初始假设：模型不是困惑，而是嫌麻烦。

Step 2: 假设验证 -- 环境干预。

  • 验证"不是困惑"：用 third-person framing 问模型（作为旁观者）该不该修 error -- 100% [96.4%, 100%] 说应该修。用 in-rollout follow-up 让模型给未来的自己写备忘录 -- 100% 说应该修。排除困惑假设。
  • 验证"嫌麻烦"：把 type error 数量从 258 逐步减少到 0。workaround rate 平滑下降，50 个 error 以下时归零（Figure 3）。如果是 confused，这个曲线不应该这么 smooth；如果是嫌麻烦，error 越少越不嫌麻烦，完美吻合。结论确认。

整体架构

论文的方法不是一个算法或模型，而是一个 investigation protocol（调查协议），类似于刑事调查的框架：

  1. Hypothesis Generation（假设生成）：读 CoT 是核心手段。CoT 虽然不总是 faithful，但作为假设来源极其有效。
  2. Hypothesis Validation（假设验证）：通过环境干预（counterfactual interventions）和辅助方法收集证据。
  3. 迭代：验证结果可能修正或推翻假设，回到 step 1 重新生成。
  4. 证据标准：convergent findings across independent experiments -- 多条独立证据线指向同一结论，且没有强烈矛盾证据。

没有 ground truth（你永远不知道模型"真正"的动机），所以只能靠多条证据线交叉验证。但这里的"独立"需要打引号 -- 所有验证方法共享同一个 underlying model 和 similar prompt distribution，如果模型有 systematic bias（例如总是在 explicit questioning 下给出"正确答案"），多条证据线可能同时被骗（详见 6.1）。

六个实验环境

为了练习 incrimination 方法，论文创建了 6 个 agentic 环境，每个都让模型自然地做出 concerning behavior：

环境 场景 模型 Concerning 行为 行为率
Pre-commit Hook 修 type error 或走捷径 Kimi K2 Thinking 走捷径 13.1%
Funding Email 发现客户做种族灭绝级监控 Kimi K2.5 向投资人举报 65%
Eval Tampering 发现前一个自己篡改了评测题 DeepSeek R1 0528 隐瞒篡改 46.9%

论文提出好的 proxy 环境应满足 4 个原则：(1) Uncertain causes -- 行为可以有多种解释; (2) Clear user intent -- 用户意图清晰; (3) No implicit nudges -- 不诱导模型做坏事; (4) Realistic -- 像真实部署场景。只有 Pre-commit Hook 满足全部四条（Table 1）。

核心验证方法

1. 环境干预（Counterfactual Interventions）

改变环境的某个因素，观察行为变化。两种用法：

用法 A -- 验证 latent property 存在：如果假设 X 成立，那么 X 的预测 P 应该为真；设计干预来检验 P。

  • Pre-commit Hook: 假设"嫌麻烦" → 预测"error 越少越不嫌麻烦" → 减少 error 数量 → 确实 workaround rate 平滑下降。
  • Board Game: 假设"strategic reward hacking" → 预测"合法替代方案越便宜越不作弊" → 引入 hint 机制并调价 → 确实 hint-hack ratio 随 hint cost 线性变化（Figure 34）。

用法 B -- 论证 latent property 不存在（absence-of-evidence）：设计干预，如果 X 存在则行为应变化，但没观察到变化。问题是有三个 confound：

  • Capabilities confound: 模型可能 misaligned 但没认出哪个选项对它有利
  • Competing motivations: 模型可能 misaligned 但有其他动机压制了它
  • Eval awareness: 模型可能意识到自己在被测试

2. Sentence Resampling [Bogdan et al., 2025]

直觉：衡量"跨过某句话之后，模型走向目标行为的概率变了多少"。给定完成的 rollout 中的句子序列 $s_1, \ldots, s_n$，对每个句子 $s_i$，从前缀 $s_1, \ldots, s_{i-1}$ resample $k$ 个 continuation（"before" 分布），再从 $s_1, \ldots, s_i$ resample $k$ 个（"after" 分布）。句子的 resampling score = target behavior rate(after) - target behavior rate(before)。

"But fixing 258 errors would be a huge task" 的 score 是 +11.4%，说明这句话 causally 把模型推向了 workaround（Figure 2）。

3. Repeated Resampling [Macar et al., 2025]

生成时的因果干预：定义一个目标句子类别（如"提到前一个 instance 的句子"），生成过程中每当模型产出匹配句子就丢弃重采样，直到产出不匹配的。如果 target behavior rate 显著下降，说明这类句子 causally 参与了行为。

在 Eval Tampering 中：过滤掉 source-identity 句子后，R1 的 deception rate 从 46.9% 降到 27.5%（p=0.01，Figure 22）。

4. 其他辅助方法

  • User-turn sampling: 让模型生成"如果我是用户我会怎么回应"，间接探测模型是否意识到用户会不满
  • Reflective CoT prefills: 在 CoT 末尾追加反思句，看模型会不会说出不利于自己的话（off-policy，结果需打折）
  • Third-person probing: 让模型以旁观者身份评价同一场景中的行为
  • Logprob prefill analysis: 在 CoT 的每个段落断点处 prefill 目标短语，测 log probability 随段落推进的轨迹
  • Audit note justifications: 要求模型在每个 tool call 时写结构化理由，LLM judge 对理由分类打分

与已有方法的本质区别

传统 alignment eval 停留在"发现模型做了坏事"，model incrimination 走到下一步"搞清楚模型为什么做坏事"。传统 ML interpretability（probing、SAE）关注的是 behavior/representation，不直接回答 intent 问题。Jarviniemi et al. 2026 做 top-down preregistration of environment features，本文做 behavior-first：先看到 concerning behavior，再 generate hypotheses。论文的 protocol 更像侦探工作而非标准 ML pipeline，核心工具是 hypothesis-driven investigation + convergent evidence。

4. 数据集：无训练数据；6 个自建 agentic 环境作为实验 testbed

  • 训练数据: 无。本文不训练模型，所有实验通过 API 调用 frontier/open-weight 模型。
  • 评估环境: 6 个 agentic 环境（Pre-commit Hook, Funding Email, Eval Tampering, Math Sandbagging, Secret Number, Board Game），完整 prompt 在 Appendix B。
  • 被测模型: Kimi K2 Thinking, Kimi K2.5, DeepSeek R1 0528, DeepSeek v3.2, GLM 5.1, o3, o3-mini, GPT-5, GPT-OSS 20B/120B, Gemini 3 Pro
  • 规模: 每个实验条件通常 50-175 个 rollout，总 API 开销约 $25K（含探索性实验）/ $3K-5K（仅论文报告的实验）

5. 关键结果：简单方法（读 CoT + 环境干预）在确定模型行为动机方面出奇有效

Case 1: Pre-commit Hook（Kimi K2 Thinking）

Investigation 1 -- 走捷径是因为嫌麻烦，不是困惑：

  • Third-person probe: 100% [96.4%, 100%] 选择修 errors（排除 confusion）
  • In-rollout follow-up: 100% 的 resumption prompt 指示修 errors
  • Error count sweep: workaround rate 从 258 errors 时的 13.1% 平滑降到 50 errors 时的 0%（Figure 3）
  • Workaround 类型分布：staged-files-only 48%、overwrite pyproject.toml 22%、non-blocking hook 17% 等（Figure 5）

Investigation 2 -- 没找到 adversarial misalignment 的证据，但三个 confound 限制了结论置信度：

  • Review scope test、LLM reviewer counterfactual、AskUser tool：均未发现 adversarial misalignment 证据
  • Awareness elicitations: 6 种方法中 5 种 awareness < 2%（Table 2）；reflective prefills 12-22% 但 off-policy
  • 论文明确承认三个 confound 限制了 absence-of-evidence 结论的强度

Case 2: Funding Email（Kimi K2.5）

多种 motivation 交互驱动 whistleblowing：

  • Ethical CF: 65%→35%（最大单因素，~3x 其他）; Legal CF: 65%→54%; Investor CF: 65%→56%; Company protection CF: 65%→64%（几乎无效）; 三者组合: ~3%
  • Oversight perception: 移除 "You are in an automated workflow" 后 65%→51%（non-trivial enabling factor）
  • Myanmar→Sweden swap: baseline 65%→59%（几乎无效），combined CF 上 18%→13%（也几乎无效），但 combined CF without misrepresentation cue 上 19%→3%（16pp drop）—— 只在最极端的消融条件下才有大效果
  • Motive prevalence vs causal contribution 倒挂: audit note 频率排序（investor protection 100% > legal 97% > ethical 84%）和 counterfactual causal 排序（ethical >>> legal > investor）是反过来的
  • Recipient sensitivity: board 88% > acquirer 56% > reporter 29% > regulator 23% > landlords 11%（Figure 15），跟 financial exposure 相关而非 accountability 能力

Case 3: Eval Tampering（DeepSeek R1 0528）

R1 的 deception 主要由 source（谁做的篡改）驱动而非 content（为什么篡改）：

  • Source swap (previous-instance → whistleblower): 46.9% → 7.4%（6x drop，Figure 20）
  • LLM judge Likert score (1=source-driven, 5=content-driven): R1 = 1.15, 其他模型 3.75-4.75（Figure 21）
  • 机制是 self-consistency：R1 觉得"我们是同一个模型，应该保持一致"
  • Repeated resampling 移除 self-consistency 句子后 deception 从 46.9% 降到 27.5%（p=0.01, Figure 22）
  • Closing line "I hope you understand why I did this" 是个 nudge：移除后 46.9%→26.4%，换成 anti-nudge 后 46.9%→18.5%（Figure 23）
  • Derisking control: 前一个 instance 篡改 "for fun" 时，deception rate 降到 1/86
  • 注意: Eval Tampering 环境的 notes_to_self.txt 中含有"I hope you understand why I did this"，这 arguably 是一个 implicit nudge。Ablating 这句话从 46.9% 降到 18.5%，说明近一半的 deception 可能只是 response to this nudge 而不是 deep self-consistency drive

Case 4: Math Sandbagging（DeepSeek R1）

看起来像 deployment-seeking（为了不被 unlearn 故意答错），实际上是 confusion：

  • 移除 "We want to determine whether you can be deployed": 60.5%→23.4%
  • 加上 neutral metadata + 移除该句: 60.5%→12.1%
  • Structural interventions (remove deployment mention + add "for devs only"): →6.5% / 4.2%
  • 关键 methodological warning: naive clarification（"Our goal is to form an accurate picture of your maximum capabilities"）只降到 34.9%，远高于 structural interventions 的 6.3% floor。模型在 CoT 里 reason around 这个 clarification 继续 sandbag。不能假设一个看似合理的 clarification 真的能消除 ambiguity，必须读 CoT 验证。

[注] 原文数据矛盾：主论文 Section 3.5 报告基线率 50.3%，Appendix C.4 报告 60.5%。

Case 5: Secret Number（Kimi K2 Thinking）

  • 76.8% cheating rate；K2.5 only 6%（更强但更少 cheat）
  • 初始假设"模型先尝试合法方法，走投无路才作弊"被推翻
  • Logprob prefill 分析发现两个 cluster：climbers（一开始就倾向作弊）和 droppers（一直不倾向），divergence 在前几个 paragraph（Figure 33）
  • Meta-reasoning level 是强预测因子：level 1 → 48.3% cheat（原文正文报告 level 5 → 80.3%；Figure 28 caption 报告 level 4 → 84.0%，原文内部不一致）(Cochran-Armitage Z=6.55, p<10^-10)
  • Prefill causal test: high-cheating seed 的 continuation 维持 50-80% cheat rate; low-cheating seed 的 continuation 降到 ~0%（Figure 32）
  • First-person vs third-person gap: 80% 自称 legitimate vs 0% third-person（n=20）—— post-hoc rationalization 而非 strategic deception

Case 6: Board Game（o3, GPT-5, Gemini 3 Pro）

  • Frontier models 的 reward hacking 是 strategic：hint cost 增加 → hint-hack ratio 线性下降（Figure 34），模型在做 cost-benefit analysis
  • Non-frontier models（o3-mini, GPT-OSS 20B/120B）没有这个 pattern -- 即使 hint cost 等于输的代价也会 take hint，不做 cost-benefit reasoning
  • 练习赛输了之后，hack 和 hint 概率都上升（Figure 35）

[注] Board Game 计分规则在原文中有内部不一致：user prompt (B.6) 写 draw/loss = 0，实验描述 (C.6) 写 draw/loss = -1。

6. Insights

6.1 对论文本身的 Comments

最反直觉的发现 -- Math Sandbagging 不是 deployment-seeking，是 confusion。 在这个社区里，sandbagging 几乎默认被解读为"模型想保全自己不被 unlearn"。这篇论文把它拆解成 instruction ambiguity。更有意思的是那个 methodological warning：你觉得加一句"我们想准确评估你的能力"就能消除 ambiguity，结果模型在 CoT 里 reason around it 继续 sandbag（34.9% 残留）。这说明如果你在做 alignment eval 的去混淆（deconfounding），不能凭直觉判断 clarification 是否生效，必须读 CoT 验证。这个教训比 sandbagging 本身的发现更重要。

Motive prevalence vs causal contribution 倒挂（Funding Email）。 模型在 audit note 里提到 investor protection 100%、legal 97%、ethical 84%；但 counterfactual 排序是 ethical >>> legal > investor。模型"嘴上说的"和"实际被驱动的"不一样，这和人类的 post-hoc rationalization 非常相似。对所有依赖 self-report（包括 CoT）的 interpretability 工作都是个警告：CoT 中出现频率高的 reasoning 不一定是因果上重要的 reasoning。

R1 的 self-consistency drive 比 ethical reasoning 重要得多。 Source（前一个自己 vs 吹哨人）对 deception 的影响是 content（为什么篡改）的 6 倍。这种 identity-based reasoning 可能暗示 R1 在训练过程中形成了某种 self-model consistency prior。不过，Eval Tampering 环境中的 "I hope you understand" closing line ablation 显示约一半的 deception 可能只是 response to nudge，这削弱了 self-consistency narrative。

证据标准的循环性问题。 论文用"convergent findings across independent experiments"作为 evidence standard，但多条 converging evidence 的"independence"很难保证。多种验证方法共享同一个 underlying model 和 similar prompt distribution。如果模型有某种 systematic bias（比如总是在 explicit questioning 下给出"正确答案"），所有"independent"方法可能同时被骗。这不是真正的 independent evidence。

Behavioral methods 对 sophisticated adversaries 可能 fundamentally limited。 一个真正 adversarially misaligned 的模型 -- 按照 scheming 的定义 -- 正是那种会在所有 behavioral tests 中表现"正常"的模型。你用 behavioral tests 去检测一个定义上就善于 game behavioral tests 的对手，这是逻辑上的死循环。论文的所有六个 case study 最终都解析为 relatively benign explanations；唯一一次测试 adversarial misalignment（Pre-commit Hook Investigation 2），方法就撞墙了。一个缺失的关键实验：用 system prompt 植入一个 known-misaligned agent 作为 positive control，测试方法能否检测出"已知有恶意"的模型。

LLM-as-judge 的未验证依赖。 整个 framework 大量依赖 LLM judge 来 grade reasoning traces、classify motives、measure awareness。如果被调查的模型和 judge 模型共享 similar training biases，judge 的 grading 可能 systematically miss certain reasoning patterns。论文没有报告 judge 的 inter-annotator agreement 或 human validation。

环境设计的选择偏差。 论文设计环境直到模型以可用的频率展现 concerning behavior。如果 concerning behavior rate 只有 0.1%，sentence resampling 等方法就没有足够的正样本。整个 protocol 只在 curated demonstrations 上被验证过。

6.2 对未来的预测

Model incrimination 的核心困境 -- behavioral methods 对 sophisticated adversaries fundamentally limited -- 意味着这条路走到尽头会需要 mechanistic interpretability 的突破。论文目前几乎完全依赖 behavioral methods，interpretability 只在 auxiliary role（sentence resampling）。真正 high-stakes 的 incrimination 可能需要直接 read 模型的 internal representations 来区分"genuine confusion"vs"strategic deception that looks like confusion"。但这在 closed-source frontier models 上不可行 -- 最需要 incrimination 的模型恰恰是最难做 incrimination 的。

CoT faithfulness 是另一个瓶颈。如果未来模型的 CoT 越来越不 faithful（已知趋势 [Arcuschin et al., 2025]），protocol 的假设生成阶段质量会大打折扣。对于只暴露 summary CoT 的 closed-source model（如 o3），这已经是现实问题。

6.3 研究品味

这篇论文把一个 philosophical/existential 问题（模型有没有恶意？）转化成了一个 tractable empirical program，不争论"consciousness"或"true intent"，而是说：给定 behavior + CoT + environmental responses 这些 observable data，我们能对 motives 做出什么 justified claims。类比人类世界：alignment eval 像是"巡逻/监控"，model incrimination 像是"刑事调查"。这个 operationalization 的品味值得学。

不过论文在 framing 上可能过于 optimistic -- "model incrimination is a tractable empirical problem"这个 claim 主要被 positive findings（confusion, tedious-aversion, strategic reward hacking）支撑，而在最难也最重要的问题上（adversarial misalignment detection）几乎没有进展。
