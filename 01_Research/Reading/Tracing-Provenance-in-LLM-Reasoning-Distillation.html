2. 关键问题：蒸馏后的模型在新场景下，到底学到了什么？

这篇论文问的是一个非常朴素但之前没人认真回答的问题：

学生模型在训练时学会了模仿老师，但在测试时遇到新场景，它真的能继续按老师的方式思考，还是会退化回自己原来的输出模式？

动机: Reasoning distillation 已经很流行了——让大模型生成 reasoning path，用这些数据 fine-tune 小模型。但有个根本问题没人回答：test time 给小模型一个新的 context，它到底是继续 follow teacher 的 behavior，还是退化回自己原来的输出分布？Hinton 当年提出的 distillation 泛化问题，在 reasoning distillation 这个场景下还是个黑盒。

之前方法的卡点: 大家默认假设学生"学会了"老师的知识，但没有机制去验证这一点。最直接的做法（让老师和学生在同一输入下生成，然后比较输出）有两个硬伤：

  1. 推理轨迹很长，逐句重新生成都跑一遍模型太贵
  2. 不同模型生成的句子很难直接比较相似度

3. 数据集：推理 benchmark + 开源蒸馏模型

分析用的测试数据:

  • AIME24: 美国数学竞赛，每题采样 16 个 completions
  • GPQA-D: 研究生级别科学问答，每题采样 8 个 completions

训练数据源:

  • AceReason-1.1-SFT: NVIDIA 的数学推理数据集，每个问题配多个候选答案
  • OpenThought3-1.2M: HuggingFace 的大规模开源推理数据集
  • OpenScienceReasoning_2: 科学领域数据（跨域实验用）

评估 benchmark:

  • AIME24, AIME25: 数学竞赛
  • MATH500: 数学问题
  • OlympiadBench: 竞赛级别问题
  • GPQA-D: 科学问答

分析的开源蒸馏模型:

  • DeepSeek-Distill-Qwen-7B (Ds-7B)
  • DeepSeek-R1-0528-Qwen3-8B (Ds-8B)
  • LIMO-v2 model（注意：只有 800 samples，数据量很小）

4. 关键方法：Provenance Tracing + Teacher-Guided Data Selection

4.1 核心思想：反向追溯，而不是正向比较

论文的巧妙之处在于：不从同一输入让多个模型生成然后比较，而是从蒸馏模型的输出出发，反向追溯每个句子的来源。

具体做法是：把 distilled model 生成的每个 sentence 拿去问三个模型（teacher、student、distilled），"你在这个 context 下输出这句话的概率是多少？"通过比较这三个概率，就能追溯这句话的"来源"。

这个设计很聪明——直接比较生成内容会遇到很多问题（语义相似但用词不同、vocabulary mismatch）。概率是 underlying distribution 的直接反映，比较概率能绕开这些表面问题。

4.2 Sentence 概率计算

因为 token-level 比较会有 vocabulary 不匹配的问题，论文选择句子粒度：

$$p_{(i,j)} = \exp(\text{mean}(\log(p_k)))$$

其中 $p_k$ 是句子 $a_{(i,j)}$ 中第 $k$ 个 token 的生成概率。用几何平均而不是算术平均，这是合理的——概率相乘才是真正的联合概率。

4.3 四种 Action 类型分类

对于每个 action $a_{(i,j)}$（第 i 个问题的第 j 个 sentence），获取三个概率：

  • $p_{(i,j)}^T$: Teacher model 的概率
  • $p_{(i,j)}^S$: Student model 的概率
  • $p_{(i,j)}^D$: Distilled model 的概率

定义差值：

  • $\Delta_{SD} = p_{(i,j)}^S - p_{(i,j)}^D$：Student 与 Distilled 的概率差
  • $\Delta_{TD} = p_{(i,j)}^T - p_{(i,j)}^D$：Teacher 与 Distilled 的概率差
  • $\Delta_{TS} = p_{(i,j)}^T - p_{(i,j)}^S$：Teacher 与 Student 的概率差

分类公式（按顺序判断）：

$$ \begin{cases} \text{Shared Sentence}, & \text{if } (|\Delta_{SD}| \leq \alpha \land |\Delta_{TD}| \leq \alpha \land |\Delta_{TS}| \leq \alpha) \\ \text{Teacher Sentence}, & \text{else if } (\Delta_{TS} > \beta) \\ \text{Student Sentence}, & \text{else if } (-\Delta_{TS} > \beta) \\ \text{Boosted Sentence}, & \text{else if } (|\Delta_{TS}| < \beta) \end{cases} $$

四种类型的含义：

类型 定义 含义
Shared Sentence 三者概率几乎相同 原本就在 teacher 和 student 中都存在，蒸馏没额外增强
Teacher Sentence Teacher 概率显著高于 Student 主要来源于 teacher 的知识迁移
Student Sentence Student 概率显著高于 Teacher 学生自己的模式占主导
Boosted Sentence Teacher ≈ Student，但 Distilled 更高 原本两者都有，但蒸馏增强了这个模式

4.4 阈值选择

  • $\alpha$: 过滤掉微小的概率差异，防止噪声干扰
  • $\beta$: 区分 action 类型的主阈值，用数据驱动的方式确定——选择让四种类型分布最清晰、重叠最少的值。Figure 6 显示 $\beta=0.1$ 效果最好

4.5 Teacher-Guided Data Selection

核心思想：训练前，选择包含更多 Teacher Sentence 的 response。

训练前只有 teacher 和 student 两个模型，所以简化分类：

$$ \begin{cases} \text{Common Sentence}, & \text{if } (|\Delta_{TS}| \leq \beta) \\ \text{Teacher Sentence}, & \text{else if } (\Delta_{TS} > \beta) \\ \text{Student Sentence}, & \text{else if } (-\Delta_{TS} > \beta) \end{cases} $$

Common Sentence 合并了 Shared 和 Boosted。

选择策略：对于每个 question 有多个 candidate response，选择 Teacher Sentence 绝对数量最多的那个（Maximize Absolute Count）——不是比例，是绝对数量。

与 GRAPE 的对比：

  • GRAPE：选学生模型觉得"自然"的数据（选学生分布已覆盖的数据）
  • 本方法：选老师和学生差异最大的数据（选学生不会但老师会的数据）

这俩方向完全相反！GRAPE 想"顺势而为"，本文想让学生学新东西。

4.6 计算开销

额外开销是可接受的：

  • 如果本身就要采样 response，logits 是采样的副产品，零额外成本
  • 如果用现成数据集过滤，只需要一次 forward pass（不需要自回归生成），比重新采样快很多

5. 关键结果：Teacher Sentence 与正确率高度相关，数据选择有效

5.1 主实验结果（Table 1）

四个 Teacher-Student 组合的平均提升：

Setting Vanilla GRAPE Ours 提升
DeepSeek-R1 + Qwen3-4B-Base + AceReason 56.2 55.1 58.7 +2.5
DeepSeek-R1 + Qwen3-8B-Base + AceReason 60.9 60.6 62.6 +1.7

有意思的是 GRAPE 有时候比 Vanilla 还差（比如第一个 setting 的 55.1 vs 56.2）。原因：GRAPE 选的都是 student 已经"自然"能生成的数据，但这些数据 student 本来就会了，训练信号很弱。vanilla random sampling 反而可能选到一些 student 不太会的数据，训练信号更强。

5.2 三个关键发现（Figure 3, Figure 4）

发现一：Teacher Sentence 在推理早期概率更高

在 action index 较小的位置（推理早期），Teacher Sentence 的概率明显更高。两个原因：

  1. 学生模型不会生成 thes 这样的特殊 token，第一步可能强制跟随老师
  2. 早期 action 往往是"分析输入、规划后续步骤"——这是一种"元认知"行为，在小模型的训练数据中可能很少见，所以成为 teacher 独有的模式

发现二：Boosted Sentence 不一定都有益

Figure 3 和 Figure 4 显示：

  • 大模型（LIMO-v2）：正确答案在后期更依赖 Boosted Sentence
  • 小模型（Ds-7B）：错误答案反而更依赖 Boosted Sentence

这说明：蒸馏会激活 student 内部的 latent patterns，但这些 patterns 不一定都有用。小模型可能"激活了错误的知识"。

发现三：Teacher Sentence 与正确答案高度相关

Figure 3 清楚显示：Teacher Sentence 在正确答案上的概率高于错误答案（浅绿实线在浅绿虚线之上）。这很直觉——teacher model 本身正确率更高，学生输出越接近 teacher，答案越可能正确。

6. Golden Case：一个数学推理轨迹的 Provenance 追溯

论文 Figure 2 展示了一个 AIME 数学题的完整分析：

输入问题：Alice 和 Bob 玩游戏，栈有 n 个 token，每次取 1 或 4 个，取最后一个者获胜。问有多少个 $n \leq 2024$ 使得 Bob 有必胜策略。

Distilled model 生成的轨迹片段：

So n = 12 is L
n = 13: Take 1, opponent gets 12 (losing). Take 4, opponent gets 10 (losing). So n = 14 is W
n = 15: Take 1, opponent gets 14 (winning). Take 4, opponent gets 11 (winning). So n = 15 is L
...

Provenance Tracing 结果（Figure 2 可视化）：

  • 早期 sentence（action index 1-10）：Teacher Sentence 概率高（绿色背景）——第一个 thes token 明显是 Teacher Sentence，小模型原本不会生成这个
  • 中间 sentence（action index 20-50）：Boosted Sentence 概率高（黄色背景）——student 本来有一定能力，但被蒸馏增强了
  • 某些位置：三种 model 概率相近（灰色背景，Shared Sentence）

7. 我的疑问

疑问 1：Tokenizer 不兼容怎么办？

  • 我的理解：方法依赖三个模型都能处理相同的 vocabulary。如果 teacher 是 GPT-4、student 是 LLaMA，这套方法就很难直接用了。论文里用的都是 Qwen 系列，恰好兼容。
  • 想搞清楚：跨 tokenizer 场景，需要什么适配方案？可能的思路：训练一个 token alignment 层，或者改用 semantic embedding 比较（但会丢失概率信息）。

疑问 2：Sentence 粒度是否足够细？

  • 我的理解：作者选择 sentence 级别是因为 token 级别太细、比较困难（vocabulary mismatch）。但有些关键推理步骤可能在一个 sentence 内部，比如 "Therefore, the answer is 42."——"Therefore" 和 "the answer is 42" 可能来源不同。
  • 想搞清楚：有没有可能用更细的粒度（比如 clause 级别或语义单元）同时避免 vocabulary mismatch？

疑问 3：Boosted Sentence 的机制是什么？

  • 我的理解：Boosted Sentence 定义为 "Teacher ≈ Student，但 Distilled 更高"。可能是"学生已知但表达频率低的模式"被蒸馏数据激活了。也可能是训练数据中存在某些"高频但低概率"的模式，在蒸馏过程中被强化了——更像是"频次强化"而不是"能力激活"。
  • 想搞清楚：这到底是不是某种 calibration effect？如何区分有益和无益的 Boosted Sentence？

8. Insights

8.1 对论文本身的 Comments

反直觉的发现：

  1. "顺势而为"不如"强行灌输"：GRAPE 选择与 student 分布对齐的数据，本文选择 teacher 独有的知识。实验结果支持后者。Reasoning 是一种能力，不是知识——能力的迁移需要学生"被迫"去练习自己不会的东西，而不是在自己舒适区打转。

  2. Boosted Sentence 不一定有益：蒸馏激活的内部 patterns 可能是"错误的知识"。小模型的"潜在知识"质量更差——它"知道"的模式本身就是错的。

  3. 早期推理的 Teacher 贡献更大：早期推理（比如 "Let me analyze this problem step by step"）是一种"元认知"行为——它不直接解决问题，而是规划后续步骤。这类行为在小模型的训练数据中可能很少见，所以成为 teacher 独有的模式。

方法的硬伤：

  1. Tokenizer 兼容性依赖：方法依赖三个模型能处理相同 vocabulary。现在主流的 distillation 场景（GPT-4 蒸馏给 LLaMA/Qwen）都跨 tokenizer，这个方法用不了。这大大限制了方法的实用价值。

  2. 阈值选择缺乏理论支撑：$\alpha$ 和 $\beta$ 的选择是数据驱动的（"选分布最清晰的"），但没有解释为什么这个标准是合理的。

  3. LIMO-v2 数据量太小（800 samples）：用这么小的数据集验证"Teacher Sentence 在大模型中后期贡献"的结论，说服力有限。

8.2 研究品味

用"概率比较"而不是"生成内容比较"来追溯来源——这个设计很聪明。概率是 underlying distribution 的直接反映，比较概率能绕开语义相似但用词不同、vocabulary mismatch 这些表面问题。这提醒我：遇到比较困难时，想想能不能换个角度，比较 underlying quantity 而不是表面现象。

9. 总结

  • 核心创新: Provenance Tracing 框架——通过比较 Teacher/Student/Distilled 三个模型对同一 action 的概率，追溯蒸馏模型每个输出的来源，并据此设计 teacher-guided data selection 策略。不只是提升性能，更重要的是提供了可解释性——你可以通过分析知道蒸馏模型"到底学到了什么"。

  • 局限性:

    1. 方法依赖 teacher-student tokenizer 兼容性，跨 tokenizer 场景用不了
    2. 阈值选择缺乏理论依据
    3. 只验证了 8B 参数以下的模型

  • 改进方向:

    1. 扩展到不同 tokenizer 的模型对，研究需要什么适配
    2. 探索 Boosted Sentence 的机制——区分有益和无益的激活模式
    3. 将 Provenance Tracing 用于迭代蒸馏过程（每轮分析后调整数据）
