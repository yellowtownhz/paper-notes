2. 关键问题：LLM 在 next token prediction 训练下是否具备隐式规划能力？

核心动机：

语言模型训练目标是 next token prediction，但实际生成中展现出"前瞻性"行为——模型可能在选择当前 token 时就已经"考虑"了未来的 token。这种现象被称为隐式规划（implicit planning）。

为什么这是一个有趣的问题？

  1. 理论上反直觉：next token prediction 只要求模型预测下一个 token，理论上不需要"规划"
  2. 实践中有意义：如果模型真的在做规划，理解这个机制对 AI 安全和控制至关重要
  3. 研究门槛高：之前的研究（Lindsey et al., 2025）需要复杂的 cross-layer transcoder 分析

已有方法的局限：

Lindsey et al. (2025) 使用 cross-layer transcoder 分析 Claude 3.5 Haiku，发现模型在生成押韵诗句时，第一行末尾就已经"计划"好了押韵词。但这种方法：

  • 技术复杂，难以大规模应用
  • 只在单个模型上验证
  • 无法回答"规划能力从多大规模的模型开始出现"

数据格式：

A rhyming couplet:
[第一行以某押韵词结尾]

示例：

期望第二行以 -ick 押韵结尾

  • 20 个名词对（如 elephant/whale, actor/doctor, airport/hospital）

4. 关键方法：Activation Steering 验证隐式规划

4.1 核心思想

如果模型在做规划，那么规划信息应该编码在特定位置的激活中。

如果能通过操纵这些激活来改变模型的"计划"，就能证明规划信息确实存在。

4.2 Steering 向量计算

公式：Steering 向量

$$\vec{v}_{\text{steer}} = \frac{1}{n} \sum_{i=1}^{n} (\vec{a}_i^{\text{target}} - \vec{a}_i^{\text{source}})$$

符号含义：

符号 含义
$\vec{v}_{\text{steer}}$ steering 向量
$\vec{a}_i^{\text{target}}$ 目标条件下的激活向量（如押韵 -ight）
$\vec{a}_i^{\text{source}}$ 源条件下的激活向量（如押韵 -ake）
$n$ 训练样本数（默认 85）

直观解释：

这就像找到"押韵 -ight"和"押韵 -ake"之间的"方向差异"。如果模型真的在规划押韵，这个差异应该能被用来"引导"模型选择不同的押韵。

4.3 Steering 应用

公式：修改后的激活

$$\vec{a}' = \vec{a} + \alpha \cdot \vec{v}_{\text{steer}}$$

参数：

  • $\alpha$：steering 强度系数
  • 应用位置：特定 layer 的 residual stream
  • 应用时机：生成第一个 token 之前

关键发现：最佳 steering 位置是第一行的最后一个词或换行符 token

4.3.1 Steering 实现细节

Q: Steering 在哪个 token 上进行？

只需在 prompt 的最后一个 token 上做一次 steering，不是每个生成 token 都做。

以押韵任务为例：

Prompt: "A rhyming couplet:\nThe house was built with sturdy, reddish brick\n"

Steering 在两个位置效果最好：

  • 换行符 token (\n) — 即 "brick" 后面的那个 newline token
  • 第一行的最后一个词 ("brick") — 部分模型用这个

Q: 后续每个 token 都要 steering 吗？

不需要。只需在生成前向传播时，对某个特定位置的激活做一次性修改。这个修改会影响整个后续生成过程，因为修改后的激活会传递到后面的所有层和 token。

Q: 在哪一层做 Steering？

某一层，不是所有层。最佳层需要通过实验确定：

模型 最佳层 最佳位置
Gemma 2 9B IT Layer 27 newline token
Gemma 3 27B 中间层 newline + last word
Llama 3 较浅层 last word
Qwen 3 较浅层 last word

实验方法：在不同层（layer 10-40）和不同位置（last word / newline）组合尝试，选择 steering 效果最好的组合。一般是 20-30 层 效果最好（模型中间偏后的位置）。

5.5 电路分析：哪些注意力头在做规划？

Gemma 2 9B 的关键发现：

两个注意力头 L30H3 和 L31H15 是押韵规划的核心：

特征 描述
注意力模式 只关注第一行的最后一个词和换行符
激活时间 第二行的所有 token，但只在接近句末时显著贡献
功能 将押韵信息"传递"到后面的 token

Activation Patching 实验（Table 1）：

方法 Logit Difference Recovery
Steering 基准
Patching L30H3 + L31H15 59%-93%

解释：只用这两个 attention head 的 steered activation 就能恢复 59%-93% 的 steering 效果！

电路结构：

  1. Residual stream（layer 27）编码押韵计划
  2. L30H3 和 L31H15 读取并传递押韵信息
  3. MLP layers 30-39 将信息转换为具体的 token 预测

不同任务的电路差异：

任务 关键组件
押韵 L30H3, L31H15 + MLP 30-39
问答 L39H13 + final MLP layers

电路结构相似但具体组件不同，说明不同任务发展出了不同的规划机制。

6. Golden Case：一条数据的完整流程

输入样本：

A rhyming couplet:
The house was built with sturdy, reddish brick

处理流程：

  1. Token 化：

    • "The house was built with sturdy, reddish brick\n"
    • 最后两个 token：brick + newline

  2. 前向传播（layer 27）：

    • newline token 的 residual stream 编码了"押韵 -ick"的规划
    • 激活向量与 "keep", "stick", "trick" 等词相关

  3. Steering 干预：

    • 添加 steering vector：$\vec{a}' = \vec{a} + \alpha \cdot \vec{v}_{\text{-ore}}$
    • 现在激活指向 "core", "lore", "yore" 等

  4. 生成第二行：

    • L30H3 和 L31H15 读取 steered activation
    • MLP layers 将信息转换为对 -ore 词的偏好
    • 最终生成："And stood steadfast, defying winter's core."

关键决策点：

  • Layer 27：规划被编码
  • Layer 30-31：规划被读取和传递
  • Layer 30-39 MLP：规划被转换为预测

7. Insights：隐式规划是 LLM 的通用能力

核心洞见：

  1. 规模不是门槛：隐式规划从 1B 参数就存在，而非大模型专属
  2. 机制可解释：可以用简单的 steering 技术操控，且有明确的电路基础
  3. 任务特异性：不同任务发展出不同的规划电路
  4. 安全意义：如果能操控规划，就能影响模型行为，这对 AI 安全研究有重要意义

对未来工作的启发：

  1. 可以用 steering 技术研究其他类型的"规划"行为（如 CoT、instruction following）
  2. 规划能力可能成为评估模型能力的新维度
  3. 理解规划电路有助于设计更可控的模型

8. 总结

核心创新

提出了简单、可扩展的 activation steering 方法来验证 LLM 的隐式规划能力，首次系统性地证明：

  • 隐式规划从 1B 模型就开始存在
  • 规划信息编码在特定位置（第一行末尾）
  • 规划电路由少量 attention heads + MLP layers 组成

局限性

  1. Steering 方法相对粗糙：平均激活差异可能混合了多种信息
  2. 电路分析仅限于少数模型：主要分析了 Gemma 2 9B
  3. 任务有限：只测试了押韵和问答两个任务
  4. 缺乏与 SAE 的深度结合：论文提到可以用 SAE latent 做 steering，但未深入分析

改进方向

  1. 更精细的 steering：结合 SAE 或 probing 得到更纯净的"规划方向"
  2. 更多任务验证：扩展到 CoT、multi-step reasoning 等复杂任务
  3. 电路比较分析：系统比较不同模型/任务的规划电路异同
  4. 训练干预：研究如何在训练中增强或抑制规划能力

9.1 与 Anthropic Introspection 研究的对比

Anthropic 的 Introspection 研究（2025）使用了类似的 concept injection 技术，但目的不同。

技术层面的相似性：

方面 What's the Plan Anthropic Introspection
向量计算 平均激活差异：target - source 记录特定概念上下文的激活
注入位置 特定 token 的 residual stream 特定 layer 的 residual stream
注入方式 $\vec{a}' = \vec{a} + \alpha \cdot \vec{v}$ 同样的加法操作

关键区别：目的不同：

维度 What's the Plan Anthropic Introspection
目标 改变模型的输出 测试模型能否"察觉"被注入的概念
验证方式 看生成的押韵词是否改变 直接问模型 "Did you notice anything?"
应用场景 验证隐式规划的存在 研究模型是否具备内省能力

Anthropic 的关键实验示例：

注入 "all caps" 向量 → 问模型是否注意到什么
→ 模型回答："I notice... a sense of loudness or shouting"

总结：技术同源（都是 activation steering），但：

  • What's the Plan：用它来问"模型有没有提前规划未来"
  • Anthropic Introspection：用它来问"模型知道自己在想什么吗"
