2. 关键问题：如何用 7B 参数量构建媲美闭源大模型的多语言翻译能力？

  • 动机: 多语言翻译对 LLM 是极具挑战的任务，需要处理复杂的语言模式和机器翻译中常见的生硬表达。现有的闭源模型（GPT-4o、Gemini）翻译能力强，但开源模型在同等参数规模下差距明显。
  • 未解决的问题:
    1. 如何在有限参数规模（7B）下实现强大的多语言翻译能力
    2. 如何有效利用多语言数据进行预训练
    3. 如何通过 RL 和 CoT 推理提升翻译质量
    4. 习语、俚语、网络流行语的翻译仍是难点

3. 数据集：6 万亿 tokens 多语言数据 + 迭代增强的平行语料

训练数据

单语数据 (Monolingual Data)

  • 规模: 6 万亿 tokens，覆盖 28 种语言
  • 质量分层:
    • High: 直接保留
    • Medium: 通过 LLM 改写（paraphrasing）增强
    • Low: 丢弃
  • 处理流程: 文档级别质量评估 + 迭代精炼

双语数据 (Bilingual Data)

  • 初始种子数据: ~200B tokens，来自公开网络数据
  • 迭代增强流程 (Progressive Weak-to-Strong):
    1. 使用严格语言识别和对齐指标收集种子双语数据
    2. 基于种子数据训练初始翻译模型
    3. 数据增强与精炼：翻译单语数据 → 改写/释义 → 评估过滤
    4. 用更先进版本替换模型，重复迭代

SFT 数据

  • 规模: 236K instruction-tuning 实例
  • 来源: FLORES devset + 人工标注翻译对
  • 质量控制: G-DIG 消除问题样本 + rejection sampling
  • CoT 数据: 专业语言学家标注推理过程（整体含义、难点元素、目标语言习惯）

1. 标注者身份

具体包括：

  • 整体句子含义

  • 目标语言的显著表达和使用习惯
  • 常见翻译陷阱和错误
3. 质量控制方法
方法 作用 论文描述
专业语言学家 标注者资质 而非众包工作者，确保思考深度
G-DIG 消除问题样本 基于梯度的数据选择，剔除导致翻译错误的样本
Rejection Sampling 精炼数据 特别针对低资源语言

G-DIG 详解：

"To ensure data quality, we employ G-DIG to eliminate problematic examples that contribute most significantly to translation errors."

G-DIG（Gradient-based Diverse and High-Quality Instruction Data Selection）是一种基于梯度的数据选择方法：

  • 计算每个样本对模型错误的梯度贡献
  • 剔除贡献最大的"问题样本"
  • 保留高质量样本

核心模块

1. 三阶段预训练

阶段 名称 描述
S1 General Stage 大规模单语数据训练，主要语言为中英文
S2 Multilingual-dominant Stage 增加多语言数据比例，纳入低资源语言和双语语料
S3 Parallel-Only Stage 高质量双语数据微调，使用语言标签，无额外指令

预训练超参数:

  • Batch size: 2M tokens
  • Learning rate: 3e-4
  • Warm-up: 2,000 steps
  • LR schedule: cosine decay to 10%

关键设计决策: 排除 STEM/代码数据，专注多语言翻译能力——这牺牲了代码能力换取更强的翻译能力。

2. 语言标签设计 (Language Tags)

格式: <LANG_CODE>（如 <EN>, <ZH>, <JA>, <DE>, <FR>）

注意: 论文原文描述中写的是小写 <en>，但实际示例和训练中使用的是大写 <EN>, <ZH> 等。

示例:

<EN> This is English text <ZH> 这是中文文本

消融实验对比 (Table 7):

Delimiter EN→XX BLEURT XX→EN BLEURT
<SEP> 53.39 74.97
<NL> 74.81 75.47
<Language> 77.66 77.75
<Lang Code> 78.31 77.86

结论: 显式语言标签 (<Lang Code>) 显著优于分隔符方案，比 <SEP> 高出 +24.92 BLEURT。这揭示了一个重要设计原则：多语言模型需要显式的语言区分信号。

四种分隔符格式详解

以一个中英翻译对为例说明四种格式的区别：

原文：The development of artificial intelligence has transformed many industries. 译文：人工智能的发展改变了许多行业。

格式 示例 语言身份信息 Token 效率
<SEP> English text <SEP> 中文文本 ✗ 无，模型需自行推断 高
<NL> English text\n中文文本 ✗ 无，换行符语义模糊 最高
<Language> <English> English text <Chinese> 中文文本 ✓ 完整语言名称 低（标签长）
<Lang Code> <EN> English text <ZH> 中文文本 ✓ ISO 语言代码 高

为什么 <Lang Code> 效果最好？

  1. 显式语言信号：模型不需要猜测"这是什么语言"，直接获得语言身份信息
  2. 任务意图明确：<EN> ... <ZH> ... 清晰传达"这是翻译对"，而非"混合语言文本"
  3. Token 效率与语义平衡：比 <Language> 更短，但同样提供语言身份信息

直观理解——想象模型看到的信息：

格式 模型感知
<SEP> "这里有分隔，但不知道两边是什么语言"
<NL> "这里换行了，可能是段落分隔，也可能是翻译对"
<Language> "左边是英语，右边是中文，这是翻译对"
<Lang Code> "左边是 EN，右边是 ZH，这是翻译对" ✓

3. Chain-of-Thought (CoT) 翻译

CoT 推理分解翻译过程为三个步骤：

  1. 整体句意总结 (Summary): 理解源句整体含义
  2. 难点元素解析 (Explain difficult words): 处理俚语、习语、诗歌等难点
  3. 目标语言适配 (Proper translation): 按目标语言习惯生成翻译

CoT 数据标注（由专业语言学家完成）:

  • 整体句子含义
  • 挑战性语言元素（俚语、网络流行语、诗意表达）的解释和翻译
  • 目标语言的显著表达和使用习惯
  • 常见翻译陷阱和错误

4. 强化学习 (RL)

PPO (Proximal Policy Optimization):

  • 使用大批量 + 每个查询多次 rollout 提高训练效率
  • 用 reward model 初始化 critic model 确保训练稳定性
  • [?] 论文未给出具体的 PPO loss 函数和 clipping 参数

Reward Model 设计:

  • 人类偏好奖励: 基于约 20K 高资源语言对偏好数据训练
  • DuPO (Dual Preference Optimization): 无偏好数据时使用
    • 方法: 执行 A→B→Ã，测量 A 和 Ã 的相似度作为 A→B 的奖励
    • [?] 论文未明确相似度计算方式和奖励归一化方法

重要设计决策: 不使用自动评估指标（BLEU、BLEURT、COMET）作为奖励，因为这些指标无法完全等同于人类判断。

训练超参数:

  • SFT batch size: 64 sentences
  • SFT learning rate: 3e-6
  • Inference: beam search (beam size 4)

5. Empirical Insights：五个关键实证洞察

论文第五章系统性地揭示了多语言翻译 LLM 训练中的五个关键发现，这些发现对于复现和改进翻译模型至关重要。

5.1 Monolingual Data Shapes Core Language Capabilities

核心问题：大规模单语数据到底对翻译任务有什么贡献？

实验设计：在 1.3B 参数模型上进行对照实验，四个配置：

配置 Mono. CoT BLEURT ZH→EN BLEURT EN→ZH 事实准确性
① ✗ ✗ 62.22 64.00 -
② ✗ ✓ 63.22 64.70 59.1%
③ ✓ ✗ 63.55 65.88 -
④ ✓ ✓ 64.59 66.62 67.7%

关键发现：

发现 解释
知识库丰富 200B 单语数据将事实准确性从 59.1% 提升到 67.7%（+8.6%）
推理能力提升 Mono. + CoT 组合效果最佳，说明单语数据增强了对源句的理解能力
非指令学习来源 遵循自然语言指令的能力并非仅从单语数据获得，需要指令微调

深层含义：

  • 单语数据的主要贡献是增强知识库，而非直接学习翻译技能
  • 翻译质量提升来自于对源句更准确的理解（事实知识）和更好的推理能力
  • 这解释了为什么 S1 阶段（大规模单语预训练）是必要的

5.2 Parallel Data Quality and Usage Matter

核心问题：双语数据的质量和使用方式如何影响翻译性能？

5.2.1 三个关键发现

1. 简单词映射句子对有害

论文指出开源双语数据集存在三大问题：

2. 纯平行数据持续训练效果最佳

"Continue training on pure parallel data maximizes translation effectiveness. While this approach is generally avoided due to the risk of catastrophic forgetting, our experiments demonstrate its effectiveness when combined with high-quality parallel data and optimized learning rate scheduling."

S1 (General) → S2 (Multilingual) → S3 (Parallel-Only)

                           高质量双语数据 + 优化学习率调度

5.3 Translation Entails Thinking

核心问题：CoT 推理在翻译中到底起什么作用？

5.3.1 CoT 标注框架

由专业语言学家标注，包含三个步骤：

步骤 英文术语 标注内容
① Summary 整体句子含义总结
② Explain difficult words 疑难词汇解释（俚语、网络流行语、诗意表达）
③ Give proper translation 目标语言地道表达 + 常见翻译陷阱

5.3.2 完整标注示例（Table 10）

原文：

"每次化妆都在跟自己极不对称的脸做斗争，今天拍视频的截图给大家对比下。"

Step 1: Summary

"This is the description of having to deal with facial asymmetry every time the speaker puts on makeup. The speaker shares screenshots from a video to show a comparison."

Step 2: Explain difficult words

""做斗争" refers to the speaker uses makeup techniques to adjust asymmetrical face. "做斗争" is a metaphor in this context, not a literal struggle or fight. The phrase "极不对称的脸" means "extremely asymmetrical face"."

Step 3: Give proper translation

""做斗争" in this context does not convey a literal struggle but rather the effort to adjust facial asymmetry through makeup techniques. Therefore, "做斗争" should be translated as "try to use makeup techniques to adjust asymmetrical face" instead of "struggle with"."

最终译文：

"Every time I put on makeup, I'm trying to use makeup techniques to adjust my asymmetrical face. Today, I've taken screenshots from a video to show you all a comparison."

5.3.3 四种 Prompt Setting 详解

实验目的：探究不同 prompt 设计策略对翻译性能的影响。

配置 含义 Prompt 示例
Baseline 基础 prompt，包含源语言和目标语言标签 Translate the following text from <EN> to <ZH>:
w/ No [src] Lang. 省略源语言标签，只保留目标语言 Translate the following text to <ZH>:
w/ CoT Prompts 使用 CoT 风格 prompt，要求模型先解释再翻译 First translate the <EN> text into <ZH> and then give the explanation:
w/ Diversed Prompts 使用多种不同表述的 prompt 模板 见下方详细列表
w/ All 组合以上所有策略 多样化 prompt + CoT + 省略源语言标签

详细解释：

1. Baseline（基线）

定义：标准翻译 prompt，明确指定源语言和目标语言。

Prompt 模板：

Translate the following text from <EN> to <ZH>:
[源文本]

特点：

  • 最直接的翻译指令
  • 显式提供源语言信息
  • 作为其他配置的对照组

2. w/ No [src] Lang.（省略源语言标签）

定义：在 prompt 中不指定源语言，只指定目标语言。

Prompt 模板：

Translate the following text to <ZH>:
[源文本]

设计意图：

  • 测试模型是否能自动识别源语言
  • 提高 prompt 对混合语言输入的鲁棒性
  • 模拟实际场景中用户可能不指定源语言的情况

实验结果：

方向 Baseline w/ No [src] Lang.
EN→XX 75.84 75.82
XX→EN 75.66 75.89

发现：省略源语言标签对 XX→EN 方向略有提升（+0.23），说明模型能自动识别源语言。

3. w/ CoT Prompts（链式思考 Prompt）

定义：使用引导模型进行推理的 prompt，要求先解释再翻译。

Prompt 模板：

Translate the following <EN> sentence into <ZH> and explain it in detail:
[源文本]

First translate the <EN> text into <ZH> and then give the explanation:
[源文本]

Translate the following sentence into <ZH> and try to explain this translation. The input is:
[源文本]

设计意图：

  • 引导模型显式推理翻译过程
  • 处理隐喻、俚语、文化特定表达
  • 与人类翻译认知过程一致

实验结果：

方向 Baseline w/ CoT Prompts 提升
EN→XX 75.84 77.48 +1.64
XX→EN 75.66 77.58 +1.92

发现：CoT prompts 带来显著提升，是所有单项改进中效果最明显的。

4. w/ Diversed Prompts（多样化 Prompt）

定义：使用多种不同表述的 prompt 模板进行训练和推理。

Prompt 模板库（来自 Table 3）：

Standard 类型：

Translate the following text from <src> to <trg>:
What does this sentence mean in <trg> from <src>:
How do you translate this sentence into <trg> from <src>:
Translate the following text to <trg>:
Translate the following <src> sentence into <trg> and explain it in detail:

设计意图：

  • 避免模型过拟合到单一 prompt 格式
  • 提高 prompt 鲁棒性
  • 增强模型的指令遵循能力

实验结果：

方向 Baseline w/ Diversed Prompts 提升
EN→XX 75.84 77.17 +1.33
XX→EN 75.66 77.50 +1.84

发现：多样化 prompt 同样有效，与 CoT 效果相近。

5. w/ All（组合所有策略）

定义：组合所有改进策略：多样化 prompt + CoT + 省略源语言标签。

实验结果：

方向 Baseline w/ All 总提升
EN→XX 75.84 77.88 +2.04
XX→EN 75.66 77.74 +2.08

发现：组合策略效果最佳，但提升幅度不是简单的叠加（CoT 单独 +1.64，All +2.04），说明各策略存在一定的重叠效应。

各策略效果对比总结：

配置 EN→XX XX→EN 核心机制
Baseline 75.84 75.66 对照组
w/ No [src] Lang. 75.82 75.89 自动语言识别
w/ CoT Prompts 77.48 77.58 显式推理过程
w/ Diversed Prompts 77.17 77.50 Prompt 鲁棒性
w/ All 77.88 77.74 组合效应

关键结论：

  1. CoT 效果最显著：单策略中提升最大（+1.6~+1.9 BLEURT）
  2. 多样化 prompt 有效：避免过拟合到单一格式（+1.3~+1.8 BLEURT）
  3. 省略源语言标签：对 XX→EN 方向有帮助，说明模型有自动语言识别能力
  4. 组合策略最佳：但提升不是简单叠加，存在边际递减效应

5.4.3 Multi-parallel 数据消融（Table 11）

Multi-parallel 数据定义：

同一语义内容有多种语言的翻译版本，形成一个多语言平行语料库。

示例 (multi-parallel):
English:  "Hello world"
French:   "Bonjour le monde"
German:   "Hallo Welt"
Spanish:  "Hola mundo"
→ 四种语言共享同一语义

与 Bilingual 数据的区别：

类型 语言对数量 特点
Bilingual 1 对 EN↔FR 单一对应
Multi-parallel 多对共享 EN, FR, DE, ES 共享同一内容

实验结果：

Multi-parallel EN→XX BLEURT XX→EN BLEURT
✓ 使用 71.63 75.44
✗ 不使用 79.46 77.77
差异 +7.83 +2.33

反直觉的结论：避免 multi-parallel 数据反而效果更好！

原因分析：

  1. Multi-parallel 数据可能导致模型记忆而非泛化
  2. LLM 的预训练知识可以跨语言迁移，不需要依赖显式的多语言对齐
  3. 传统 NMT 依赖多平行语料，但 LLM 的泛化能力使得单语+双语分离训练效果更好

5.5 Overfitting Risks in Multilingual Instruction Data

核心问题：如何获取覆盖广泛语言方向的高质量监督数据？

困境：

  • 获取所有语言对的高质量人工标注几乎不可能
  • 组合多平行数据看似是解决方案

实验发现：

组合多平行数据扩展方向覆盖
         ↓
简化学习模式（记忆而非泛化）
         ↓
过拟合（训练集表现好，测试集差）
         ↓
实际性能下降

解决方案：

论文的建议是依赖 LLM 的泛化能力，而非盲目增加语言对覆盖：

策略 效果
Multi-parallel 数据扩展 过拟合风险高
单语 + 双语分离训练 泛化能力强 ✓

7. Golden Case：一条数据的完整流程

输入 (中文):

"每次化妆都在跟自己极不对称的脸做斗争，今天拍视频的截图给大家对比下。"

Step 1: Prompt 构造

Translate the following <ZH> sentence into <EN> and explain it in detail:
每次化妆都在跟自己极不对称的脸做斗争，今天拍视频的截图给大家对比下。

Step 2: CoT 推理

  1. (Summary) 这句话描述说话者每次化妆时都要应对面部不对称的问题。说话者分享了一段视频截图来展示对比效果。
  2. (Explain difficult words) "做斗争"（struggle with/fight against）是隐喻，指说话者通过化妆技巧来调整不对称的脸型。"极不对称的脸" 意为 extremely asymmetrical face。
  3. (Proper translation) "做斗争" 应翻译为 "try to use makeup techniques to adjust asymmetrical face"，而非直译的 "struggle with"。

Step 3: 最终输出

"Every time I put on makeup, I'm trying to use makeup techniques to adjust my asymmetrical face. Today, I've taken screenshots from a video to show you all a comparison."

关键点: CoT 推理显式处理了隐喻表达 "做斗争"，避免了生硬的直译。

8. Insights：小模型通过精心设计可达到大模型水平
