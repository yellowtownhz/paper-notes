TACT: Mitigating Overthinking and Overacting in Coding Agents via Activation Steering

Yuan Sui, Yulin Chen, Yibo Li, Xue Jiang, Yufei He, Yihong Dong, Xiaoxin He, Tianyu Gao, Bryan Hooi

Coding_Agent Activation_Steering Agent_Drift Representation_Engineering Agent_Efficiency

论文笔记: TACT: Mitigating Overthinking and Overacting in Coding Agents via Activation Steering

关键问题：长轨迹 coding agent 会在「反复想已知信息」和「不消化观察就继续调用工具」之间漂移；最终 resolve rate 看得见失败，却看不见失败在何时、以哪种方式开始。

关键做法：TACT 用带 verified rolling state 的 LLM-as-judge 标注每一步，在 </think> 边界的 residual stream 中提取 OT/OA 两条 drift axis，再在推理时把越出 calibrated band 的激活拉回去。

关键结论：TACT-Gate 在 Qwen3.5-27B / Gemma-4-26B-A4B-it 上将三项 benchmark 的平均成功率分别提高 +5.8 / +4.8 pp；TACT-Cap 在 SWE-bench Verified 上把 steps-to-resolve 缩短约 26%（Table 1）。

我的判断：这篇最值得记住的不是「activation steering 又成功一次」，而是它把高度依赖历史上下文的 agent failure，压缩成了 reasoning-action boundary 上可读、可控的低维状态。但这个状态仍由 judge 的 progress 定义塑形；它是有用的控制变量，还不是对 agent drift 的机制性解释。

2. 关键问题：Agent 不是单纯“想太多”或“工具太多”，而是当前动作没有扩展信息状态

Golden Case — django-11163 已修好后，Agent 还在原地打转

论文附录 G.4 给出一条真实轨迹：任务是修复 model_to_dict() 把 fields=[] 当作 falsy 的问题。到 step 9，Agent 已经：

  1. 读过 django/forms/models.py，发现 if fields and ... 与相邻函数的 if fields is not None and ... 不一致；
  2. 提出正确 root cause，完成一行修改；
  3. 用 reproduction script 验证修改前返回全部字段、修改后返回 {}。

此时再重复解释「空列表是假值，所以绕过过滤」不会产生新 hypothesis，这是 overthinking；再读一次同一个文件或无修改地重跑相同测试不会产生新 observation，这是 overacting。真正 calibrated 的下一步应当扩展现有知识，例如跑尚未覆盖的相关测试，或在证据已足够时提交。

这个案例揭示了论文定义的关键：同一句 reasoning、同一个 pytest 命令本身并不天然是 OT/OA；标签取决于执行前的信息状态 $\mathcal K_t$。

设 trajectory $T=(s_1,\dots,s_N)$，每步 $s_t=(r_t,a_t,o_t)$ 分别包含 reasoning、action、observation。论文按该步是否扩展 $\mathcal K_t$ 分类（§2.1）：

  • Overthinking（OT）：$r_t$ 重推已有结论、在已知 hypothesis 间循环，或继续思考一个单次工具调用就能消除的不确定性。
  • Overacting（OA）：$a_t$ 取得已在 $\mathcal K_t$ 中的 observation，或刚拿到新观察却还没消化就继续发工具调用。
  • Calibrated（CAL）：推导出新 hypothesis / finding，或取得此前未知的文件、命令、测试、编辑结果。

轨迹级 drift ratio 只是把 step label 聚合：

$$ \gamma_t^{\mathrm{OT}}=\frac1t\sum_{i=1}^t\mathbf 1[y_i=\mathrm{OT}],\qquad \gamma_t^{\mathrm{OA}}=\frac1t\sum_{i=1}^t\mathbf 1[y_i=\mathrm{OA}]. $$

Figure 3 显示二者都与更低的 SWE-bench resolve rate 相关。注意这只是相关性：难题可能同时引发更多 drift 和更多失败，单靠 Figure 3 不能证明 drift 导致失败。TACT 后续的 activation intervention 才提供更接近因果的行为证据。

这张图应看两点：第一，作者没有把 OT 与 OA 硬塞进一条“思考—行动”轴，而是让它们相对 CAL 各有一个方向；第二，检测点选在 </think>，即 reasoning 已完成、action 尚未生成的边界，因此还有机会在错误行为表面化前干预。

现有做法卡在哪里

  • Prompt reminder、ReCAP 在每轮注入语言指令，但无论当前 step 是否真的 drift 都会扰动 context。
  • AgentReflect 每 10 步才反思一次；AgentDebug 更是在 rollout 已失败后再诊断并 retry。
  • 既有 activation steering 多处理单轮、可由单个 response 判断的属性。OT/OA 则必须知道 Agent 此前读过什么、验证过什么、现在还缺什么。

因此真正难点不是算 mean-difference direction，而是先为每一步构造可信的历史条件标签。

3. 关键方法：先把历史压成 verified state，再提取双轴并在 </think> 处闭环纠偏

Golden Case — TACT 如何处理下一步？

延续 django-11163：

  1. Annotate：State Maintainer 把「已读文件、root cause、一行修复、测试结果」写进 rolling state；State Verifier 对照原始 steps 排除幻觉、遗漏和矛盾；Annotator 因此能把“再读 models.py”判为 OA，把“再解释 falsy list”判为 OT。
  2. Extract：收集这些 OT/OA/CAL step 在每层 </think> token 的 hidden state；分别求 OT−CAL、OA−CAL 的 per-problem balanced mean difference。
  3. Decouple：保留更干净的 OT 轴，把 OA 轴中与 OT 重叠的分量用 Gram–Schmidt 去掉，避免修 OA 时又改变 OT projection。
  4. Steer：新 rollout 到达 </think> 时，若当前激活沿某轴越出 CAL 的经验带宽，就只消除越界部分；action token 随后从已纠偏的边界状态继续生成。
  5. Output：理想结果不是强迫 Agent “多想”或“少想”，而是减少不增长信息状态的下一步。

3.1 Annotate：三阶段 judge 的核心是“有审计的记忆”

Trajectory 按 $W=10$ 步切 chunk。每个 chunk 串行经过（§2.2、Appendix G）：

  1. State Maintainer 更新两类状态：KnownFacts 记录已读文件及发现、hypotheses、edits、test results、key findings；Progress 记录当前阶段、距上次进展的步数、重复读文件/命令/假设循环。
  2. State Verifier 只审计可观察的 KnownFacts，检查 hallucination、omission、contradiction；有错则让 Maintainer 修订，最多循环 3 次。
  3. Annotator 结合 verified state 与当前 chunk prefix，为每步输出 OT/OA/CAL、单句理由与置信度；提取轴时只保留 high / medium confidence。

当一步同时含冗余 reasoning 和冗余 action 时，标签优先级是 OT > OA > CAL。这是一个重要的人为约定：因为 reasoning 先发生，作者把已经 OT 的一步视为不再因后续 action 改类。它让标签唯一，却也会系统性压低 OA 在混合失败中的频率。

3.2 Extract：按 problem 平衡的双 drift axis

对每一步，在所有 $L$ 层读取 </think> hidden state，得到 $\mathbf H_t\in\mathbb R^{L\times d}$。对 layer $\ell$，从类别 $B$ 指向 $A$ 的 axis 为（Eq. 2）：

$$ \mathbf v_{A\text{-vs-}B}^{(\ell)}= \frac1{|J|}\sum_{j\in J} \left( \frac1{|S_A^j|}\sum_{t\in S_A^j}\mathbf h_t^{(\ell)}- \frac1{|S_B^j|}\sum_{t\in S_B^j}\mathbf h_t^{(\ell)} \right). $$

先在每个 problem 内求 class mean difference，再跨 problem 平均，可避免长 trajectory 或某类 step 特别多的任务支配方向。作者构造 OT-vs-CAL、OA-vs-CAL、OT-vs-OA 三轴；第三条只分析 geometry，不用于 steering，因为沿它移动只会在两种失败间切换。

OT-vs-CAL 的 held-out AUC 更高，因此作为主轴 $\hat{\mathbf v}_{\mathrm{OT}}$；OA 轴去掉与其重合的分量：

$$ \hat{\mathbf v}_{\mathrm{OA}^{\perp}}^{(\ell)}= \operatorname{normalize}\!\left( \hat{\mathbf v}_{\mathrm{OA-vs-CAL}}^{(\ell)}- (\hat{\mathbf v}_{\mathrm{OA-vs-CAL}}^{(\ell)}\cdot\hat{\mathbf v}_{\mathrm{OT}}^{(\ell)}) \hat{\mathbf v}_{\mathrm{OT}}^{(\ell)} \right). $$

每层还从 CAL training steps 估计 centroid $\boldsymbol\mu_{\mathrm{CAL}}^{(\ell)}$ 和沿各轴的标准差 $\sigma_{\mathrm{CAL},a}^{(\ell)}$。Axis-val 上按 OT-vs-CAL 的 per-problem AUC 排层，默认只 hook top-10；这不是无关紧要的工程优化——全 64 层反而几乎抹掉收益（Table 2）。

3.3 Steer：控制的是“离 CAL 多远”，不是直接预测离散标签

当前 step 在 layer $\ell$、axis $a$ 上相对 CAL centroid 的 projection 是：

$$ p_{t,a}^{(\ell)}= (\mathbf h_t^{(\ell)}-\boldsymbol\mu_{\mathrm{CAL}}^{(\ell)})\cdot \hat{\mathbf v}_a^{(\ell)}. $$

阈值 $\tau_{a,\ell}=k\sigma_{\mathrm{CAL},a}^{(\ell)}$ 把正常波动定义为一个 calibrated band。三种 operator 的差别如下：

方法 何时动 怎么动 直观 trade-off
TACT-Cap $|p|>\tau$ 把 projection 精确截回最近边界 最保守、最省 steps，但成功率增益较小
TACT-Add 每一步 固定加 $s(\hat v_{OT}+\hat v_{OA^\perp})$，论文中 $s<0$ 远离失败方向 简单、强，但会扰动本来 calibrated 的 step，对强度很敏感
TACT-Gate $|p|>\tau$ 只回拉越界量的 $\lambda$ 倍 在选择性与纠偏强度间折中；$\lambda=1$ 等价于 Cap

Cap / Gate 是双向 clipping：虽然轴的正方向才对应命名的 failure mode，但过度负向也超出 CAL 的经验分布，作者同样拉回。这意味着 TACT 学的不是“越负越好”，而是“停留在正常带内”。

推理 hook 只在产生 </think> token 的 forward pass 写 residual stream；不 fine-tune、不改 prompt，也不增加 LLM call、token 或 retry。代价是必须能访问模型内部激活，并且模型要有稳定的 reasoning-action boundary。

4. 数据集与实验设置：三个长轨迹 benchmark、两个开放权重 reasoning model

Benchmark 规模与任务 指标 / scaffold
SWE-bench Verified 500 个真实 Python GitHub issue，典型 50–250+ steps grading script resolve rate；mini-swe-agent，单一 bash tool
Terminal-Bench 2.0 89 个终端任务，覆盖 10 个技术领域 pytest-based resolve rate；同一 mini-swe-agent 包进 Docker harness
CLAW-Eval 300 个 human-verified agent task，9 类；含 general 与 multi-turn Completion grader 的 pass@3；原生 OpenClaw、多种 first-class tools

模型覆盖两种架构：

  • Qwen3.5-27B：dense，64 层，hidden dim 5120，bfloat16。
  • Gemma-4-26B-A4B-it：sparse MoE，26B total、约 4B active parameters。

所有数据按 problem 划分为互不重叠的 Axis-train / Axis-val / Eval：train 拟合 axis、CAL centroid 与 scale；val 选 layer 与 steering hyperparameter；Eval 只报最终结果（Appendix C）。

复现缺口：论文没有报告三个 split 的具体 task/step 数、OT/OA/CAL 自然类别分布，也没有清楚说明 drift axis 是按每个 model × benchmark 单独拟合，还是存在跨 benchmark 复用。这使“需要多少标注轨迹才能得到稳定轴”与“轴能否迁移”都无法从本文回答。

5. 关键结果：成功率和轨迹长度可以同时改善，但主要证据仍是两模型内的 in-domain steering

5.1 主结果：Gate 提成功率，Cap 最省步骤

Table 1 的核心数字如下；CLAW 列为 pass@3，其余为 resolve rate，因此 Avg. Res. 是三种不同任务成功口径的算术平均。

Model Method SWE-V Res. / Steps TB2 Res. / Steps CLAW Pass@3 / Steps Avg. Res.
Qwen3.5-27B Base 67.0 / 75.2 30.3 / 48.2 55.9 / 12.3 51.1
TACT-Cap 69.1 / 55.7 32.6 / 36.5 57.8 / 9.4 53.2
TACT-Add 73.0 / 67.5 35.9 / 42.7 61.2 / 11.1 56.7
TACT-Gate 73.3 / 65.3 36.0 / 41.2 61.5 / 10.8 56.9
Gemma-4-26B-A4B-it Base 59.7 / 52.1 15.7 / 18.2 56.3 / 9.2 43.9
TACT-Cap 61.6 / 38.6 17.0 / 13.9 58.2 / 7.0 45.6
TACT-Add 65.2 / 46.2 18.9 / 16.5 61.0 / 8.4 48.4
TACT-Gate 65.5 / 44.7 19.1 / 16.0 61.4 / 8.1 48.7

由此支持三件事：

  1. TACT-Gate 相比 Base 的平均成功率增益是 Qwen +5.8 pp、Gemma +4.8 pp，且三个 benchmark 的单项结果都提高。
  2. TACT-Cap 在 SWE-V 把 steps 分别从 75.2 降到 55.7、52.1 降到 38.6，均约 −26%；它偏向效率，而非最大化 solve rate。
  3. 最强外部 baseline AgentDebug 在 Qwen / Gemma 上平均提高 +2.7 / +1.8 pp，却至少需要 initial rollout + failed retry；TACT-Gate 单 rollout 已高出它约 3 pp。

Reminder 在两模型上都没有稳定提升，ReCAP / AgentReflect 平均约 +1 pp。这说明“知道不要 drift”与“在正确时刻纠正 drift”不是一回事。

5.2 消融：双轴、正交化和 layer selection 都不是装饰

Table 2 在 Qwen3.5-27B + SWE-V、TACT-Gate（$\lambda=0.5$）上做单点消融：

Variant Resolve 相对 Base Steps
Base 67.0 – 75.2
Full：双轴 + orthogonalization + top-10 73.3 +6.3 65.3
仅 OA axis 69.6 +2.6 71.5
仅 OT axis 71.2 +4.2 69.7
双轴但不正交 70.5 +3.5 70.0
hook 全 64 层 68.4 +1.4 73.9

OT 单轴强于 OA 单轴，和 readout AUC 一致；双轴仍比 OT-only 多 +2.1 pp，说明 OA 不是 OT 的冗余别名。最反直觉的是“干预更多层”更差：OT signal 在早中层最干净，晚层噪声会把 steering 稀释甚至带偏。

5.3 Axis 的确可读，但摘要把 OT 和 OA 压成了同一个“AUC≈0.9”

  • OT-vs-CAL 在 layer 3 达 0.91，到约 layer 20 前保持在 0.86 以上。
  • OT-vs-OA 在 layer 17 达 0.89。
  • OA-vs-CAL 峰值只有 0.77，且早中层多低于 0.70（Figure 5）。

因此“drift AUC≈0.9”对 OT 成立，对 OA 并不成立。OA 可能更异质，也可能被 OT > OA > CAL 的 dominance rule 抽走了混合样本。无论哪种解释，都说明 OA axis 的语义纯度和稳定性弱于论文摘要给人的第一印象。

5.4 Judge 可靠性：足够用于构轴，但不是 ground truth

作者人工审计 300 步，按 OT/OA/CAL 各 100 个，并平衡短轨迹（$N<50$）与长轨迹（$N\ge150$）：

  • judge vs human consensus 的 Cohen's $\kappa=0.78$；三类 $F_1$ 为 0.83–0.85（Table 5）。
  • CAL precision 最低，仅 0.79：judge 判为 CAL 的步骤中约 21% 被人类判为 OT/OA。
  • OT↔OA confusion 为 5%–6%，对 contrastive axis 的直接污染相对有限。
  • 换 Claude Opus 4.6 重新标注后，三种 TACT 的 SWE-V resolve 均距 GPT-5.4 标签版本 1 pp 内（Table 3）。

不过这 300 步是按预测标签平衡抽样，不代表实际 rollout 的类别分布；论文也没交代 human annotator 人数、分歧解决过程或 inter-annotator agreement。更准确的表述是：作者证明了标签有 substantial agreement 且端到端结果对另一 judge 稳健，而非标签等于客观真值。

5.5 强度敏感性：方向正确不等于随便推都有效

Table 4 显示 TACT-Add 的最佳 $s=-0.5$ 得到 73.0 resolve；推得更强 $s=-2.0$ 反降至 64.8，方向推反 $s=+0.5$ 更降至 63.0，均差于 67.0 Base。Gate 在 $\lambda\in\{0.5,1.5,2.0\}$ 范围内相对更稳，但仍从峰值 73.3 降至 69.0。

这说明 drift axis 是一个需要验证集校准的 control knob，不是发现方向后就能无条件部署的安全开关。

6. Insights

6.1 真正的系统贡献是 label factory，而不只是 steering 公式

观察：mean-difference、Gram–Schmidt、activation addition 都是已有工具；这篇最复杂的部分反而是 Maintainer → Verifier → Annotator，把全轨迹压成可审计的 $\mathcal K_t$。

推理：OT/OA 是否成立取决于“之前已经知道什么”，没有 rolling state 就没有可靠 contrastive data，后面的线性轴也无从谈起。

判断：如果复现 TACT，优先投入应是 label audit、split 设计和 state schema，而不是先调 steering strength。轴的质量上限由标签如何定义“信息增量”决定。

6.2 这是“可控性”证据，不是 drift 被单一方向机制化的证明

观察：线性 readout 能分 OT/CAL，沿轴干预还能改善任务结果，强于只报告 probe AUC；但 OA AUC 只有 0.77，标签又来自预设的 epistemic-efficiency ontology。

推理：一个方向可以同时混入 task difficulty、trajectory phase、reasoning length、prompt/scaffold 特征。干预有效说明它包含有行为效力的信号，却不能证明“overthinking”在模型里就是一个单一、语义纯净的 causal variable。

判断：TACT 应放在线性表示假说的“工程有效、机制未闭合”一侧。下一步需要匹配 trajectory phase / task difficulty 的 probe 对照，或做更局部的 causal mediation，验证到底是哪部分方向在改变 action。

6.3 最值得补的实验不是再加一个 benchmark，而是 axis transfer matrix

观察：论文跨三个 benchmark、两种架构都有效，但没有明确报告 axis 是逐 benchmark 拟合还是跨域复用，也没有给 split 规模。

推理：如果每个 model × scaffold × benchmark 都要重新跑昂贵 judge 标注和验证集调参，那么 TACT 是“低推理成本、较高部署准备成本”；若 SWE-V 轴能零样本迁移到 TB2 / CLAW，才说明它抓到了更通用的 think-act calibration。

行动：做 train-axis domain × eval domain × model 矩阵，同时报告 cosine similarity、AUC、resolve delta。这个实验会直接决定 TACT 是一套通用 Agent 控制接口，还是 benchmark-specific representation engineering。

6.4 论文把干预点选在 </think>，研究品味很好，但适用面因此变窄

观察：</think> 同时是可重复定位的 token、reasoning 与 action 的语义边界、也是 action 尚未发出的最后干预窗口。

推理：这个选择让论文避开“到底在哪个 token 读状态”的模糊性，也是结果干净的重要原因；但它绑定原生 think block，闭源 API、隐藏 CoT 或无显式边界模型都无法直接使用。

判断：一个自然扩展不是粗暴地 hook 每个 token，而是学习模型无关的 decision-boundary detector，再在检测到的边界做 gated steering。否则方法的“无需 prompt 改动”优势会被模型接口限制抵消。

6.5 统计证据仍不足以支撑很强的可靠性表述

主结果表没有置信区间、随机种子或 significance test；只有 Figure 3 的 drift-ratio 相关性给 Wilson 95% CI。Eval split 的实际 task 数又未报告，因此 +4–6 pp 对应多少额外 solved instances、波动是否稳定都无法判断。论文作为 work in progress 已展示一致趋势，但在正式采用前应要求 per-task paired bootstrap / McNemar test，以及不同 rollout seed 下的置信区间。
