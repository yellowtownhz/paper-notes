LLM Critics Help Catch Bugs in Mathematics

Bofei Gao, Zefan Cai, Runxin Xu, Peiyi Wang, Ce Zheng, Runji Lin, Keming Lu, Dayiheng Liu, Chang Zhou, Wen Xiao, Tianyu Liu, Baobao Chang

Reward_Modeling Mathematical_Reasoning Process_Reward_Model Natural_Language_Feedback

论文笔记: LLM Critics Help Catch Bugs in Mathematics

一句话结论：Math-Minos 不让生成式 critic 参与线上推理，而是先用 3 万条“逐步自然语言批改”教会 verifier 怎样看错误，再用 44 万条二元标签把这种能力压回一个高效的 ORM/PRM 分类头；它的价值不只是 1～2 个点的提升，而是展示了“训练时使用昂贵而丰富的监督，部署时保留廉价的标量接口”这条路线。

1. 背景信息

  • 论文：LLM Critics Help Catch Bugs in Mathematics: Towards a Better Mathematical Verifier with Natural Language Feedback
  • 作者与团队：Bofei Gao 等；北京大学、阿里巴巴、微软、威斯康星大学麦迪逊分校
  • 发表：Findings of ACL 2025，pp. 14588–14604
  • 代码：KbsdJames/MATH-Minos
  • 研究对象：用于数学推理的 Outcome Reward Model（ORM）与 Process Reward Model（PRM）

2. 关键问题：二元正确性标签告诉 verifier “错了”，却没有教它“错在哪里”

Golden Case：终局答案正确，不代表推理过程可靠

假设模型解一道利润题：

  1. 前两步列式正确；
  2. 第三步把每周收入从 $2,500$ 错算成 $37,500$；
  3. 后面又发生一次抵消错误，最后答案碰巧回到正确值。

如果只用最终答案训练 ORM，这条解答的标签仍可能是 True。模型得到的监督只有一个 bit：整条轨迹正确。它看不到第三步的计算错误，更不知道“中间有错但结论碰巧正确”是危险的 false positive。

PRM 虽然把标签细化到每一步，但每一步通常仍只有 True/False。它比 ORM 定位得更准，却依旧没有回答：这是计算错误、逻辑跳步、问题理解偏离，还是前面错误的累积后果？

这就是论文瞄准的信息瓶颈：

二元标签适合做最终分类接口，却不是高效学习“如何评价推理”的最佳教学信号。

为什么不直接让 GPT-4 批改？

最直觉的方案是直接把题目和解答交给 GPT-4，让它判断并解释。但论文先做了一个必要的 sanity check：在 500 个题目—解答样本上，GPT-4-turbo 的直接评价准确率如下（Table 1）：

任务 GSM8K MATH
Outcome Evaluation 95.1 62.0
Process Evaluation 85.1 59.7

MATH 上接近 60% 的结果说明：让同一个 LLM 同时发现错误和解释错误，生成的解释并不天然可信。因此这篇论文没有把 GPT-4 当裁判，而是把它降级成一个“拿着参考标签写批注的助教”。

3. 关键方法：先用语言反馈教会“怎么看”，再用二元标签教会“怎么打分”

Figure 2 的关键不是 prompt 更长，而是任务被拆开了：已有标签负责“判”，GPT-4 只负责“释”。这降低了 critic 的认知负担，但也把标签质量变成了整条链路的上限。

3.1 Golden Case：一条错误解答如何穿过 Math-Minos

继续用上面的利润题走一遍完整流程。

第一步：把标签塞进 prompt。 训练数据本来就有每一步的 True/False。Math-Minos 将题目、逐步解答及对应标签一起交给 GPT-4-turbo。若某一步为 False，要求解释具体错误；若为 True，则简述为什么成立；最后还要给出整条解答的最终判断。

第二步：生成逐步自然语言批改。 GPT-4 不再自己猜第三步是否错误，而是在已知 Label: False 的条件下解释：模型错误地把周收入乘上了不该出现的因子，因此该步数值不成立。研究生再检查生成结果。论文从 PRM800K phase-one 与 Math-Shepherd 子集中得到 30,000 条这种反馈。

第三步：Stage 1 生成式 SFT。 用完整批改文本微调 MetaMATH-Mistral-7B。此时目标不是输出一个分数，而是逐 token 复现“每一步为什么对/错”。丰富监督迫使模型学习错误类型、局部因果关系和评价语言。

第四步：Stage 2 分类训练。 丢掉生成任务，给同一模型接分类头，再用 440,000 条二元数据训练 ORM 或 PRM；其中 30,000 条与 Stage 1 重合，另加 410,000 条 Math-Shepherd 数据。

第五步：部署时只打分。 在 Best-of-256 或 PPO 中，Math-Minos 与普通 ORM/PRM 一样只需一次前向计算产生标量，不生成批改文本。也就是说，critic 是训练教师，不是推理时组件。

Figure 3 展示了真正的设计取舍：把自然语言解释限制在 Stage 1，Stage 2 恢复标准 verifier 的接口和速度。

3.2 形式化：监督的“带宽”发生了什么变化

对解答 $s=(s_1,\ldots,s_K)$，传统 PRM 为每一步预测正确概率 $\hat y_{s_i}$：

$$ \mathcal{L}_{\text{PRM}}=-\sum_{i=1}^{K}\left[y_{s_i}\log \hat y_{s_i}+(1-y_{s_i})\log(1-\hat y_{s_i})\right]. $$

它回答的是“第 $i$ 步对不对”。Stage 1 则学习一段反馈 token 序列 $x_{1:T}$：

$$ \mathcal{L}_{\text{SFT}}=-\sum_{t=1}^{T}\log p(x_t\mid x_{<t},q,s,y). $$

这里 $y$ 是已知的逐步标签。语言反馈携带错误位置、错误类型和解释，而 Stage 2 再把这些内部表征投影回二元决策边界。作者没有引入新的结构性模块，创新主要发生在**监督课程（curriculum）**上。

3.4 与“直接用 LLM critic”的本质区别

  • 生成式 critic：每个候选答案都生成评价，信息丰富但推理慢，且评价自身可能出错。
  • 普通 ORM/PRM：推理快，但训练信号稀疏。
  • Math-Minos：只在训练时承担生成成本，以自然语言反馈初始化评价能力；在线阶段仍是分类器。

因此标题里的 “LLM Critics” 容易造成误解：这篇工作的 critic 主要是离线数据教师，不是在线自我反思模块。

4. 数据集：3 万条高带宽反馈，配合 44 万条低带宽标签

4.1 训练数据

  • 自然语言反馈：30K，来自 PRM800K phase-one 与 Math-Shepherd 子集；GPT-4-turbo 按已有逐步标签生成，研究生检查。
  • 二元监督：Stage 2 共 440K，其中 30K 与反馈数据重合，另有 410K Math-Shepherd 数据。
  • 对照公平性：普通 ORM/PRM baseline 同样使用 440K 二元样本，主对比控制了 Stage 2 数据量；Math-Minos 额外拥有 Stage 1 的 GPT-4 反馈与人工检查成本。

4.2 评估数据

  • GSM8K：7,473 train / 1,319 test。
  • MATH：7,500 train / 5,000 test；verification 使用与既有工作一致的 MATH500 子集。
  • Verification：MetaMATH-Mistral-7B 生成 256 个候选，verifier rerank；另报告 Self-Consistency（SC）及 SC+Reward Model。
  • PPO：在 GSM8K/MATH 训练集上用 ORM 提供 reward；未验证 PRM-PPO。

4.3 一条没有被充分交代的数据链

论文写了“研究生检查”，但没有报告检查人数、通过/修改比例、标注一致性、成本或 feedback 与给定标签冲突时的处理规则。这个缺口很关键，因为 Appendix B 又发现：不少 GPT-4 反馈实际上与原先的 True 标签矛盾。换言之，label-aware prompt 一方面依赖标签降低难度，另一方面又可能通过解释暴露标签噪声；论文没有把这套冲突消解机制说清楚。

5.3 哪些实验真正解释了提升来自哪里？

Label-aware 不是 prompt 小技巧，而是必要条件（Table 4）

反馈构造 Meta-evaluation Verification
无自然语言反馈的 ORM 85.9 86.2
GPT-4 直接批改，不给标签 86.2 85.8
给标签后再解释 88.1 88.2

不给标签的 GPT-4 反馈在 verification 上反而低于 baseline。这个负结果很重要：收益不是“多喂一点 CoT”自动产生的，而取决于反馈是否可靠、是否对准评价任务。

教师能力存在阈值（Table 5）

Qwen2-72B 大体复现收益，而 Mistral-7B 生成的反馈让结果下降。自然语言标签并不天然比二元标签强；低质量的高带宽监督可以更高效地教错东西。

去掉 Stage 1 能证明自然语言预训练贡献明显。去掉 Stage 2 时，生成模型只能通过“过滤”而非同样的排序接口工作，推理规则也发生了变化；所以它说明完整系统需要分类阶段，却不是一个干净的、只隔离 Stage 2 表征贡献的消融。

5.4 数据效率：值得关注，但“700%”不等于系统成本降了 7 倍

在 20,000 条 GSM8K 候选解答构成的 meta-evaluation 上，Math-Minos 约 120 step 后超过普通 ORM；作者据曲线估算约 60K 二元数据即可胜过使用 440K 数据的 baseline，并称数据效率提高超过 700%。

这个结果支持“丰富反馈能减少二元样本需求”，但有两个口径问题：

  1. $440K/60K\approx7.33$ 倍，论文的“700% improvement”把倍数与百分比混在了一起；
  2. 这没有计入 30K GPT-4 调用、研究生检查和额外 Stage 1 训练的成本。

更准确的结论应是：二元监督样本效率约提高到 7 倍量级；端到端标注与计算成本是否下降，论文没有证明。

5.5 False positive 与跨模型附录：有启发，但证据等级较低

  • Appendix B 从 训练集取 600 个“最终答案对、过程有错”的样本：普通 ORM recall 74%、平均 reward 0.234；Math-Minos 为 92%、0.105。结果符合方法动机，但训练集评估不能证明泛化。
  • ACL 最终版 Appendix A 新增跨 policy/base 实验：LLaMA-2-7B:MetaMATH 上 ORM@256 为 73.2/26.8，Math-Minos 为 75.6/28.8；Qwen2-MATH-1.5B-Instruct 上为 88.9/75.8 对 90.2/76.9（GSM8K/MATH500）。这缓解了“只对一个生成器有效”的担忧。
  • 但同一最终版的 Limitations 仍写“experiments were conducted solely on a model with 7 billion parameters”，与 Appendix A 的 1.5B 实验冲突，应是版本更新遗漏，不能据此宣称作者已经系统研究 scaling law。

6. Insights

6.1 对论文本身的 Comments

Insight 1：最漂亮的地方，是把“解释能力”当训练脚手架，而不是产品接口

证据：Stage 1 用自然语言反馈做生成式训练；Stage 2 回到 ORM/PRM 分类；Best-of-256 与 PPO 都能直接使用最终模型。

推理：如果在线生成 critique，延迟会随候选数放大，而且 critique 本身还要被验证。Math-Minos 只让语言承担表征塑形，把线上需要的功能压缩成标量。这与知识蒸馏相似，但被蒸馏的不是教师答案，而是“评价一个推理过程时应该关注什么”。

判断：这比“让模型多想几步再打分”更有工程品味。丰富监督未必需要成为丰富输出；训练接口和部署接口可以有意不对称。

Insight 2：Label-aware curation 把问题从“教师会不会判断”转成了“上游标签可不可信”

证据：GPT-4 直接过程评价在 MATH 上只有 59.7%；给定标签后的反馈才带来收益。与此同时，Appendix B 发现大量 GPT-4 反馈与原 True 标签矛盾。

推理：给标签确实降低了教师任务难度，却不是免费午餐。当标签错时，prompt 要求教师为错误结论编理由；如果教师拒绝迎合，反馈又会和监督标签冲突。人工复核其实是决定数据质量的关键模块，而论文只用一句话带过。

判断：后续工作不应只研究更强 teacher，而应显式建模“标签—解释冲突”：保留冲突样本、二次裁决并赋置信度，可能比无条件服从标签更有效。

Insight 3：论文证明了“自然语言反馈有用”，尚未证明“自然语言是最佳载体”

证据：强教师反馈有效，弱教师反馈有害；同 token 规模的普通 GPT-4 CoT 蒸馏没有同等收益（Appendix D）。

推理：真正起作用的可能是错误位置、错误类型和局部因果解释，而不是自然语言本身。若把批改结构化为 {step, error_type, cause, correction, confidence}，信息更可控，也可能减少幻觉和复核成本。

判断：自然语言是验证“高带宽监督”假设的方便起点，不一定是最终的数据协议。最值得做的下一组消融，是在等 token、等教师成本下比较自由文本、结构化 critique 与反事实修正。

Insight 4：结果可信度处于“方向可靠、幅度未定”

证据：ORM/PRM、verification/PPO、GSM8K/MATH 的提升方向一致；但绝对增益多为 0.5～1.8 点，没有 seed、方差和显著性检验，false-positive 分析还使用训练集。

推理：多设置同向降低了偶然性解释，但不能回答收益对随机初始化、候选采样和数据过滤是否稳定。

判断：可以相信自然语言评价预训练是一个有效方向；不能据现有证据相信“700%”或某个小数点后的提升会稳定复现。

6.2 对未来的预测

Reward model 很可能继续沿着“训练时可解释、推理时可压缩”的方向发展：训练阶段同时预测标量、错误类型、局部 rationale 和置信度，部署时根据场景选择只输出分数或按需展开解释。真正的分水岭不是 ORM 与 PRM，而是 verifier 是否获得了足够密集、可校验的过程监督。

6.3 研究品味

这篇论文最值得学习的不是两阶段训练本身，而是它先用 Table 1 证伪了一个看似自然的方案——“直接让 GPT-4 批改就好”——再用 Table 4 把改进归因到 label-aware，而不是只展示最终 SOTA。好的方法论文不仅要证明方案有效，还要说明最接近的朴素替代为什么不工作。

相反，它也展示了一个常见写作风险：当附录后补实验后，Limitations 没有同步更新；当数据效率用百分比包装时，标注与训练成本没有统一口径。越是醒目的 claim，越应该给出最保守、可复算的定义。

7. 连接与发现

  • MOC-Reinforcement-Learning — Topic：Math-Minos 用自然语言反馈预训练 reward model，再将能力压回可用于 reranking 与 PPO 的标量接口。
  • Outcome_Accuracy_is_Not_Enough-Rationale_Consistency_for_Reward_Models — Concept：两者都认为只看 outcome 不足；Math-Minos 把 rationale 用作训练阶段的高带宽监督，后者进一步追问 reward model 在推理时给出的理由是否与分数一致。
