论文笔记：LangGap: Diagnosing and Closing the Language Gap in Vision-Language-Action Models

1. 背景信息与核心判断

  • 作者 / 团队：Yuchen Hou、Lin Zhao，National University of Singapore 电子与计算机工程系（NUS ECE）。
  • 版本：arXiv:2603.00592v1，2026-02-28，7 页（含附录 Table IX–XII）。本文按该预印本记录。
  • 代码：github.com/YC11Hou/langgap —— 该链接来自 arXiv 元数据，PDF 全文没有 github 字样，论文未背书，内容与可用性无法从原文核对 [?]。

一句话裁决：这篇论文设计了一个可信的诊断工具，并用它跑出了一个不支持自己结论的训练实验。诊断侧（四维语义扰动 + 99 任务 benchmark）数据扎实、可逐格复核；训练侧（"定向数据能弥合语言鸿沟"）在全基准上不显著，且有一处显著退化未被报告。

值得记住的五点：

  1. 设计支点是 same-scene 多任务 + instruction-level split：视觉记忆这条捷径在测试时完全可用，但完全无用。
  2. 诊断结果可信：π0.5 原始任务 93.8% → 扩展任务 21.4%（−72.4pp），且四个维度崩得极不均匀（Change Target 13 任务 260 episode 全 0，Change Object 29.3%）。
  3. 训练侧真正同条件可比的只有两对对照，全 59 任务基准上最好的 45-task 只比不微调高 +1.4pp（z≈0.8，p≈0.43）；56-task 的 Drawer 从 19/60 退到 2/60（Fisher p≈5.5e-5），论文只字未提。
  4. "规模越大越学不动"这条曲线本身不可比；第一候选解释是等效 epoch（6-task 那个 28% 是每条演示被看约五千遍取得的）。
  5. 落地判断：作为诊断基准值得关注（same-scene 扰动设计可直接抄）；作为训练方法不值得复现（增益在噪声内、配置不可比、无方差）。

2. 关键问题：模型不看语言，但没人能说清它到底不看哪个部分

Golden Case — 问题是什么？ 同一张桌子，同一个碗。"put the bowl on the plate"，π0.5 成功率 95.5%（Fig. 1）。 只改一个词，物体没换、动作没换："put the bowl on the stove" → 0%（Fig. 1 的 Change Target 维度；Table IX 里 spatial plate→stove 4 个任务 0/80、plate→cabinet 4 个任务 0/80、stove→plate 2 个 0/40、stove→cabinet 2 个 0/40、goal plate→stove 1 个 0/20，13 个任务 260 个 episode 全部失败）。 模型从不改道。缺的不是"抓起碗、放下碗"的操作能力，是"读指令决定去哪儿"的能力。

（Fig. 1 顶部的 95.5% 口径不明：全文声明每任务评 20 episode，20 ep 下成功率只能是 5% 的整数倍；Table III 中 40 个原始任务的聚合值是 93.8%。95.5% 疑为跨场景平均或笔误 [?]。这不影响的下面那个更硬的数字：0/260。）

为什么这个问题重要，之前卡在哪：

  • Benchmark 层：LIBERO 一个桌面布局只配一条任务，同一视觉输入永远对应同一动作输出，靠视觉记忆就能过。Table IV 里 LIBERO 的 same-scene tasks 只有 10。
  • 诊断层：现有工作只给粗粒度结论（"语言被忽略"），或只做表层 paraphrase 扰动（LIBERO-Plus 的 7 类扰动里只有 1/7 是语言，Table IV 注 †）。不知道模型是不懂物体名词、不懂目标位置，还是不懂空间关系。
  • 解法层：现有方案集中在架构侧改模态权重（BayesVLA、LangForce、Zhan et al.），而 Wanna et al. 审计发现训练数据中 <2% 的指令是语言唯一的 —— 论文据此主张根因在数据层。

来源：原文 Figure 1。横向比较物体、目标、空间描述和动作变化，关键是场景保持一致而指令改变。图中 headline 成功率的口径疑问仍按上文保留，不能用配图消除这个证据缺口。

3. 关键方法：固定住视觉，只让语言变

Golden Case — 方法怎么跑？ 把 plate / stove / cabinet 三个版本做成三个共享同一初始视觉状态的任务，并且 train/test 切的是指令而不是场景。于是"记住这张桌子该干什么"这条捷径在测试时依然开着、但完全没用 —— 唯一能区分该干哪件的信号就是语言。

① 四维语义扰动：笛卡尔积 + 物理可行性过滤

对每个 LIBERO scene 穷举四类语义槽位 —— 可操作物体类别 × 可达目标位置 × 区分同类多实例的空间描述 × 合法动作类型（pick-and-place / drawer open-close），生成笛卡尔积后在 LIBERO 模拟器里过滤，不是人工逐条写。过滤三条：目标物体可抓取、放置位置可达、成功条件可被检测器判定（消除"任务本身做不到"这个混淆项）。产物 59 个扩展任务，每个任务单标签归一个维度（38+13+5+3=59）：

维度 改什么 测试的语义成分 π0.5 SR（Table III）
Change Object Category pick bowl → pick ramekin 物体类别名词 29.3%
Change Target place on plate → place on stove 空间目标槽 0.0%
Spatial Description "bowl to the right of the ramekin" → "…of the plate" 同类多实例的指代消歧 11.0%
Drawer Action put bowl → open drawer 动作语义 31.7%

59 = spatial 28 + goal 9 + object 22（四个维度只在 spatial suite 能全做，object/goal 只能做 Ch.Obj，goal 另能做 Ch.Tgt；Table II）。加上 40 个原始任务 = 99 任务，共 1980 episode（99×20）。

② 1/k 上界：强制语言依赖的量化说法

原文：忽略语言的模型在同一场景中"最多拿到 1/k 成功率（k = 该场景的任务数）"。逻辑是：同一初始状态 + 不看语言 → 同一条确定性轨迹；同场景 k 个任务的成功条件互斥 → 最多命中 1 个。

但 k 的实际值全文未给，也没有任何"屏蔽语言输入"或"恒做原任务"的实测基线 [?]。 这个上界是设计动机的论证，不是被测量过的量 —— 它是"by design 强制语言依赖"这一核心卖点的唯一量化支撑。

③ instruction-level split

从 59 个扩展任务中挑 16 个做训练集（spatial 9 / goal 3 / object 4，覆盖四维度），其余 43 个作 held-out，与训练任务共享同一视觉场景、只换语义指令。这是 "forcing language reliance by design" 的确切含义，也是它区别于 task-level / episode-level split 的地方。注意：Table VII/VIII 报告的是全 59 个扩展任务（含这 16 个训练任务），不是纯 held-out，原文未明确说明 [?]。

④ 无形式化目标

全文没有写出训练目标、flow matching 损失或 LoRA 更新式；指标就是 per-episode 二值成功率（SR = 成功 episode 数 / 总 episode 数）。这是一篇 benchmark + data-centric 短文的定位使然 —— 找建模细节会落空。

5. 关键结果：诊断可信，"补数据能弥合"不可信

5.1 诊断侧：四个维度崩得极不均匀（这部分挑不出毛病）

维度 任务数 成功/总 SR
Change Object 38 223/760 29.3%
Change Target 13 0/260 0.0%
Spatial Description 5 11/100 11.0%
Drawer Action 3 19/60 31.7%

更有信息量的是同一维度内部的离散度（Finding 2）：Change Object 跨任务从 0% 到 80%；同维度内 spatial suite 3/160（1.9%）与 object suite 166/440（37.7%）差 20 倍。Change Target 则一律是 0。跨模型也一致（Table VIII：π0 0.0%、SmolVLA 0.0%、π0-FAST 2.3%）。

5.2 训练侧：核心张力是"规模越大越学不动"，但这条曲线本身不可比

Experiment Training Config Eval Tasks Baseline Ours
Single-task 1 ext 1 3.75 90.0
6-task 1 orig + 5 ext 5 ext 0.0 28.0
45-task 40 orig + 5 ext 5 ext 0.0 4.0
16-task 16 ext only 16 ext 26.2 6.2
56-task 40 orig + 16 ext 16 ext 26.2 27.5

（Table VI。Baseline = 预训练 π0.5 在对应任务集上的成绩。）

先把三个坑标出来，否则会被这条曲线带跑：

  • 单任务 baseline 用 3.75%，不是摘要的 0%。 Table VI 与 Finding 5 写的都是 3.75%→90%，只有摘要写 "0% to 90%"（四舍五入口径）。
  • 这五个点的实验条件各不相同：基线 3.75/0/26.2、评测集 1/5/16 个任务、评测 episode 10/50/80、训练预算（r=32 + 20K steps + 56 条演示 vs r=64 + 200K + 300~4,093 条）。把它们排成一条"规模-性能曲线"是 Discussion 第一句干的，不是一组可比实验。
  • 评测 episode 数论文自相矛盾：正文 III-A 与 Table VII/VIII/IX–XII 表头写 20 ep/task，Table V 的 Ep 列写 10/10/10/5/5。交叉验算支持后者 —— Table VI 五个数字全部能被 10/5 整除（90.0=9/10、28.0=14/50、4.0=2/50、6.2≈5/80、27.5=22/80）。即摘要的头号数字 90% 基于 10 个 episode，28% 基于 50 个，而论文未作任何说明。

真正同条件可比的只有两对：

  • Exp2 vs Exp3（同 5 个 spatial 扩展任务、同 r=64、同 200K steps、同 10 ep）：掺入 40 个官方任务后 28.0% → 4.0%。在这组里官方数据是有害的。
  • Exp4 vs Exp5（同 16 个跨 suite 任务、同 5 ep）：6.2% → 27.5%，而 baseline 是 26.2%。在这组里官方数据是有益的 —— 但只是把它拉回"不微调"的水平（+1.3pp）。

方向相反，论文却用 "pattern matching" 同一套叙事解释了两边（那 5 个 spatial 任务与官方无 pattern match，所以 baseline 0%、可以涨；16 个里有部分与官方 pattern match，所以 baseline 26.2%、只训扩展数据会掉）。这个自洽是编排出来的：先按 baseline 高低把任务分成两类，再各配一套机制。 可检验的判据论文手头就有 —— 若在 16 个任务内部按 baseline 是否为 0 拆分，该假说预测 baseline>0 的那些下降更多、baseline=0 的那些上升。Table VI 没给这个拆分。

笔记者复核的显著性（非论文数字，两比例 z 检验 / Fisher 精确检验）：

  • 45-task 总 Ext 22.8% vs π0.5 21.4%：z≈0.8，p≈0.43，不显著（+1.4pp）。56-task 总 Ext 20.4%：z≈−0.6，方向为负。
  • 45-task vs 56-task：Spatial Ext 10.2 vs 7.1 → z≈1.85，p≈0.064；总 Ext 22.8 vs 20.4 → z≈1.42，p≈0.156。Finding 4 的两条"优于"都不显著。
  • 真正显著的改善只有两处：Ch.Tgt 0/260 → 16/260（Fisher p≈2.4e-5）、45-task Sp.Desc 11/100 → 25/100（Fisher p≈0.016）。
  • 以及一处论文完全没提的显著退化：56-task Drawer 19/60 → 2/60（Fisher p≈5.5e-5）。

净效应核算：45-task 是 Ch.Tgt +6.2pp、Sp.Desc +14.0pp 对 Drawer −11.7pp；56-task 是 +5.0 / +6.0 对 −28.4pp。论文没有在任何地方做这个核算。

必须同时呈现、不能只报好看的几处：

  • 摘要的 "0%→28% multi-task" 挑的是 6-task 那一行；同一张表里 16-task 是 26.2%→6.2%，下降 20pp，45-task 是 0%→4%。
  • 56-task 的 spatial 数字论文自己矛盾：正文 IV-B 与 Finding 3 写 6.7%，Table VII 写 7.1% [?]。
  • Discussion 的 "Spatial Description 60%、Change Target 10–40%、Change Object 10–20%" 确实印在第 5 页，但 Table VI–XII 任何一张表都找不到对应，且 Table VIII 中 45-task 的 Sp.Desc 只有 25.0% [?]。这三个数是 Discussion "语义距离越远越难"这一论证的唯一依据。按 5 任务×10 ep 粗算，单维度子集只有 10–20 个 episode。

5.4 "规模越大越学不动"：四种解释与我的判断

候选解释 依据 我的判断
等效 epoch 被摊薄 名义都是 200K×8=1.6M 样本，但数据集 300 / ~2,000 / ~2,400 / 4,093 条 → 等效 epoch 约 5,300 / 800 / 670 / 390 第一候选。6-task 那个 28% 是每条演示被看约五千遍的条件下取得的，与论文自己"90% 是 memorization"的判断同源
数据稀释（论文主张） 6-task 28 → 45-task 4 与上一项在数据上完全等价，现有实验无法区分。它是混淆变量，不是已被证实的机制
擦掉预训练的视觉-语言捷径（论文对 16-task 的主张） 26.2 → 6.2 更简单的解释是 16 个窄任务上跑 200K 步导致灾难性遗忘。区分两者只需一个"同预算只微调 16 个官方任务"的对照，论文没做。补这个对照之前，6.2% 只能当现象，不能当机制
任务本身更难 Ch.Tgt 的目标位置（stove / cabinet）可能需要更长轨迹、更窄的放置容差 未排除，但也不该被完全采信：π0.5 在 Object Ext 上能到 37.7%，说明"换物体"这类不简单的任务它做得对。真正的缺口是论文没报告脚本演示在这些扩展任务上的成功率上界 —— 若 waypoint 脚本在 stove 上只有 60–70%，BC 学不好就不能归因于语言

还有一个结构性混淆：16 个训练扩展任务的 baseline 是 26.2%，全 59 个是 21.4% → 被选中的 16 个系统性更容易（剩余 43 个约 19.7%）。Table VI 的 27.5% 与 Table VII 的 20.4% 之差被论文当"泛化差距"讨论，实际主要是任务难度差。

5.5 证据边界：复现前必须补的四件事

  1. 无语言基线：屏蔽语言输入 / 恒做原任务重测一遍，并报告每场景 k 的分布。这是 1/k 上界唯一需要的实测，成本最低。（顺带可以用论文自己的上界反检：按 suite 粗估 spatial k≈2.8 → 1/k≈36%，而 Spatial Ext 只有 5.9%，远低于上界。若模型真如论文所说"忽略语言、稳定执行原任务"，它应该拿到 ≈1/k。所以失败不能只用"忽略语言"解释 —— 要么扩展任务物理更难/更 OOD，要么模型读了新指令后行为被扰乱，而后者恰恰是"读了语言"的证据。k 未报告，此为粗估，仅作示意 [?]。）
  2. 同预算官方数据对照：区分 pattern matching 与灾难性遗忘。
  3. 多种子误差棒：全文 seed / std / confidence / ablation 各出现 0 次；Table VI 用 5/10 episode 评测，单个 episode 就是 10–20 个百分点。
  4. 扩展任务的演示成功率上界：区分"难"与"不懂语言"。

阻塞级复现缺口：π0.5 的具体 checkpoint 与权重来源未说明（参考文献 [7] 是 π0 原始论文 arXiv:2410.24164，不是 π0.5 论文，论文用 [7] 指代 π0.5 系列）；代码链接来自 arXiv 元数据而非论文；LoRA 配套超参与 checkpoint 选取未给；episode 是否独立（评估时物体初始位姿是否随机化）未说明 —— 若评估也用固定初始状态，20 个 episode 近似重复采样，有效样本量远小于 20。

6. Insights

1. 诊断工具可信，训练结论不可信 —— 论文用前者卖了后者。 观察：Table III 与附录 IX–XII 可逐格复核、内部完全自洽；而 Table VI 的头号数字（90%）来自 10 个 episode、任务未指名、且与其余四组不同构（r=32 vs 64、20K vs 200K、56 条演示）。 推理：两者在贡献列表里被并列为贡献 1/2/3，读者会默认它们同等强度。 判断：采信范围应切在诊断侧。"targeted data augmentation 能部分弥合语言鸿沟"在全基准上不成立（+1.4pp，p≈0.43），摘要的三个头号数字分别是 10 个、50 个、50 个 episode。

2. "视觉记忆这条捷径在测试时完全可用，但完全无用" —— 这是 instruction-level split 与 task-level split 的分界线。 观察：LangGap 的 train/test 共享同一视觉场景和同一初始状态，只切指令；而常见的跨 suite / 切演示条数 split 下，train/test 的视觉场景也不同。 推理：只有把无关模态固定住、只变目标模态，才能测出目标模态是否真被使用。LIBERO-Plus 的 7 类扰动里只有 1/7 是语言且多为表层 paraphrase，缺的正是这一步。 判断：这个设计原则可迁移到任何"要测某个模态是否真被使用"的场景 —— 加更多扰动类型不如先把其他通道堵死。

3. 论文主张根因在数据层，但它自己的训练实验恰好是这个主张的反例。 观察：论文引用 Wanna et al.（<2% 指令是语言唯一的）论证数据层根因，然后投喂 4,093 条"必须读语言才能做对"的演示。 推理：如果缺这类监督信号是唯一瓶颈，补上它应当有效。 判断：全基准 +1.4pp、16-task 反而掉 20pp 说明 —— 数据里缺这种信号是必要条件，补上它不是充分条件。这条把论文的结论从"数据能补"改写成"补了也没用，得去别处找原因"。

4. 「组合泛化失败」与「忽略语言」是两种机制，论文把它们混用了。 观察：Finding 2 自己说 Change Object 的成功"是因为恰好匹配训练 pattern"。 推理：这已经是 OOD 解释，与 "ignore language" 是不同的机制 —— 前者是没见过这种组合，后者是根本不看。 判断：两者要求的修复手段不同（前者靠数据覆盖，后者靠架构强制模态使用），混用会让读者在选方案时选错。区分实验很便宜：同一场景下比较"训练时见过的组合"与"没见过的组合"的成功率差。
