2. 关键问题：如何从 LLM 的隐藏表征中"读出"人类可理解的信息——现有方法在"表达力"和"层鲁棒性"上同时拉胯

Golden Case — 问题是什么？

想象你在追踪 Pythia 12B 处理 "Alexander the Great" 这个名字的过程。你想知道：模型在第 2 层已经搞明白这是谁了吗？还是到第 5 层才搞定？

现有方法各有一个硬伤——

  • Logit Lens（把中间层表征直接乘 unembedding 矩阵看 top tokens）：前几层基本是乱码，因为早期层的表征根本不在"词汇空间"里对齐，vocabulary projection 在这些层几乎完全失效。
  • Probing（训练线性分类器）：你得提前知道所有可能的类别。但 "Alexander the Great" 在中间层先被关联到 "Great Britain"，再到 "the Great Depression"，最后才 resolve 到 "Alexander the Great"——这些类别你没法事先穷举。
  • Causal Tracing / Attention Knockout：只能告诉你"这个位置重要"（二值信号），不能告诉你"它重要是因为它编码了什么"。

核心矛盾：LLM 的中间表征里确实有丰富的信息，但我们缺少一种既能"读出"这些信息、又不受限于预定义类别、还能在早期层工作的方法。

  • 动机: 理解 LLM 内部表征对解释模型行为、验证对齐至关重要。LLM 本身就擅长生成人类可读文本，为什么不直接让模型自己"翻译"自己的表征？
  • 已有方法卡在哪:
    • Vocabulary projection（Logit Lens 等）：早期层不准、输出不 expressive（只能给 token 概率，不能给自然语言解释）
    • Probing：需要监督训练、类别空间有限、不开放词汇
    • Activation patching（因果干预）：只做定位，不做解码——告诉你"哪里重要"，不告诉你"重要因为什么"

3. 关键方法：Patchscopes — 把隐藏表征"移植"到另一个推理过程中解码

Golden Case — 方法怎么跑？

继续用 "Alexander the Great" 的例子（Pythia 12B, Table 7）。现在我想知道模型在各层对这个名字编码了什么。

Step 1: 在 source model 上跑 source prompt "Alexander the Great"，拿到第 2 层最后一个 token（"Great"）的隐藏表征 $\mathbf{h}_i^2$。

Step 2: 准备一个 target prompt，比如 "Syria: Country in the Middle East, Leonardo DiCaprio: American actor, Samsung: South Korean multinational major appliance and consumer electronics corporation, x"。这个 prompt 的设计目的是鼓励模型生成实体描述。

Step 3: 在 target model（同一个模型）上跑 target prompt，只跑到第 2 层（$\ell^* = 2$），拿到 "x" 位置的第 2 层表征 $\bar{\mathbf{h}}_{i^*}^2$。

Step 4: 替换：$\bar{\mathbf{h}}_{i^*}^2 \gets \mathbf{h}_i^2$（映射函数 $f$ 是恒等映射）。然后从第 2 层继续 forward，让模型自回归生成。

结果: 模型输出 "Wall Street Crash of 1929: Financial crisis in the United States"——第 2 层还只看到了 "the Great"（关联到 Great Depression），还没把 "Alexander" 和 "the Great" 组合起来。到第 5 层 patching 时，输出变成 "Ancient Greek ruler, and the first to rule all of the then known world"——实体解析完成了。

关键洞察：不是把表征投影到词汇空间，而是把表征放进一个专门设计的推理过程中，让模型自己的非线性计算帮我们"翻译"它。

核心思想引用原文： "Given a hidden representation obtained from an LLM inference pass, we propose to decode specific information from it by patching it into a different inference pass (of the same or a different LLM) that encourages the translation of that specific information."

整体架构

Patchscopes 的核心操作就是一次 activation patching，但跟传统 patching 用法不同——传统 patching 用来定位（"这个位置重不重要"），Patchscopes 用来解码（"这个位置编码了什么信息"）。

一个 Patchscope 由 source 四元组和 target 五元组完全定义：

  • Source: $(S, i, \mathcal{M}, \ell)$ — source prompt $S$，source position $i$，source model $\mathcal{M}$，source layer $\ell$
  • Target: $(T, i^*, f, \mathcal{M}^*, \ell^*)$ — target prompt $T$，target position $i^*$，映射函数 $f$，target model $\mathcal{M}^*$，target layer $\ell^*$

核心操作

给定输入序列 $S = \langle s_1, \dots, s_n \rangle$，模型 $\mathcal{M}$ 有 $L$ 层，$\mathbf{h}_i^\ell$ 表示位置 $i$、层 $\ell$ 的隐藏表征。

Patching 操作：在 $\mathcal{M}^*$ 对 $T$ 的推理过程中，动态替换 $\bar{\mathbf{h}}_{i^*}^{\ell^*} \gets f(\mathbf{h}_i^\ell)$，然后从 $\ell^*$ 层继续 forward。

映射函数 $f(\mathbf{h}; \boldsymbol{\theta}): \mathbb{R}^d \mapsto \mathbb{R}^{d^*}$：

  • 恒等映射 $\mathbb{I}$（$\mathbb{I}(\mathbf{h}) = \mathbf{h}$）— 最常用，零训练
  • 仿射映射 $f(\mathbf{h}^\ell) := A^\ell \mathbf{h}^\ell + \mathbf{b}^\ell$（跨模型 patching 时用，需要训练）
  • 零映射 $f(\mathbf{h}) = \mathbf{0}$（退化为 attention knockout）

关于输出的因果保证：patching 后的 forward 计算会增强表征，所以不保证 patched representation 本身存储了所有输出信息。但因为表征已脱离 source prompt 的上下文，不会有更多 source prompt 的信息被注入——这保证了我们读出的信息确实来自 patched representation（加 post-patching 计算）。但注意，这不是严格的"解码"，更接近"启动"——输出是 patched representation 和 target prompt 共同作用的结果。

五种核心配置

3.1 Token Identity Patchscope（解码 next-token prediction）

  • 干什么: 想知道模型在中间层是否已经"想好了"下一个 token 是什么
  • 配置:
    • $T \neq S$：使用 few-shot token identity prompt，格式为 "tok1 → tok1; tok2 → tok2; ...; tokk"（最后一个 token 无箭头，因为那是 patching 位置，模型要生成后续）
    • $\ell^* = \ell$：target layer 等于 source layer（关键设计——不跳到最后一层！）
    • $f = \mathbb{I}$，$\mathcal{M}^* = \mathcal{M}$
  • 为什么有效: Token identity prompt 鼓励模型"复读"输入，这正好帮我们把 patched representation 里编码的 token 信息解码出来。同时，因为从 $\ell$ 层继续 forward 而不是跳到 $L$ 层，模型自己的后续层计算充当了非线性映射——不需要额外训练。
  • 对比 Logit Lens: Logit Lens 直接把 $\mathbf{h}^\ell$ 乘 $W_U$，等于 $\ell^* = L$，完全跳过了中间层的非线性计算。Token Identity Patchscope 保留了中间计算。
  • Prompt 细节: 随机采样 $k$ 个 token（$k$ 从 $[1, \dots, 10]$ 随机取），实验证明对具体哪些 token 不敏感（Figure 5，5 种不同 random seed 结果一致）

3.2 Zero-Shot Feature Extraction Patchscope（提取属性）

  • 干什么: 想从 "United States" 的表征中提取 "largest city"，但不想训练 probe，也不想限制输出类别
  • 配置:
    • $T \gets$ 关系的自然语言表达 + 占位符，如 "The largest city in x"
    • $i^* = m$（patch 到 "x" 的位置），$i = $ subject 的最后一个 token
    • $f = \mathbb{I}$，$\mathcal{M}^* = \mathcal{M}$
    • 扫描所有 $(\ell, \ell^*)$ 组合
  • 评估: 自回归生成 20 个 token，看 $\omega$ 是否出现在生成中

3.3 Entity Description Patchscope（分析实体解析过程）

  • 干什么: 想看模型如何逐步把 "Alexander the Great" 的 tokens 组合成完整实体——这是之前无法用自然语言观测的过程
  • 配置:
    • $T \gets$ "subject1: description1, subject2: description2, subject3: description3, x"
    • 具体 target prompt: "Syria: Country in the Middle East, Leonardo DiCaprio: American actor, Samsung: South Korean multinational major appliance and consumer electronics corporation, x"
    • $\ell^* = \ell$，$i^* = m$，$f = \mathbb{I}$，$\mathcal{M}^* = \mathcal{M}$
    • Few-shot 示例中 $k = 3$ 个随机实体 + 对应 Wikipedia description

3.4 Cross-Model Entity Description Patchscope（跨模型解码）

  • 干什么: 小模型可能不够 express 来生成好的描述，用大模型来"翻译"小模型的表征
  • 配置: 与 3.3 相同，但 $\mathcal{M}^*$ 换成同族更大模型
    • e.g., $\mathcal{M} = $ Vicuna 7B, $\mathcal{M}^* = $ Vicuna 13B
    • 映射函数 $f$ 用仿射映射（类似 Tuned Lens 的训练方式，在 representation pairs 上学 $A^\ell$ 和 $\mathbf{b}^\ell$）
  • 训练目标（Tuned Lens 风格）: $\min \sum_{s \in \mathcal{T}} ||A\mathbf{h}_s^\ell - \mathbf{h}_s^L + b||^2$

3.5 CoT Patchscope（修正多跳推理错误）

  • 干什么: 模型能独立完成两步推理，但组合在一起时失败——问题出在"连接处"
  • 配置:
    • $S \gets \pi_1$（第一步推理的 verbalization），$T \gets \pi_2$（第二步推理的 verbalization）
    • 等价于 $S = T \gets [\pi_2][\pi_1]$，但调整 attention mask：$\pi_1$ 中的 tokens 看不到 $\pi_2$，$\pi_2$ 中的 tokens 看不到 $\pi_1$
    • $i \gets n$（source 是 $\pi_1$ 最后一个 token），$i^* \gets$ the token preceding $\pi_1$
    • $\mathcal{M}^* = \mathcal{M}$，$f = \mathbb{I}$
  • 直观理解: 把第一步推理结果（$\omega_1$ 的表征）直接"塞"到第二步推理中 $\sigma_2$ 应该出现的位置，相当于在计算图里做了一次手术，跳过了组合推理中最容易出错的连接步骤

与已有方法的关系（统一视角）

所有 vocabulary projection 方法都是 Patchscope 的特例，共同点是 $\ell^* = L$（跳到最后一层）：

方法 $\ell^*$ $f$ $T$
Logit Lens $L$ $\mathbb{I}$ 任意（因为跳到最后一层，$T$ 不影响输出）
Tuned Lens $L$ Affine 任意
Future Lens $\ell$ Linear Fixed/learned soft prompt
Causal Tracing $\ell$ $\mathbb{I}$ $S + \epsilon$ (加噪声)
Attention Knockout Multiple $f(\mathbf{h}) = \mathbf{0}$ $S$

Patchscopes 的关键创新在于让 $\ell^* < L$ 且 $T \neq S$——这意味着：

  1. 保留中间层的非线性计算（不需要学映射函数）
  2. Target prompt 可以自由设计来引导不同类型的解码

五元组参数化让你一眼看出空白区——比如 $\ell^* < L$ 且 $T \neq S$ 这个象限之前几乎没人碰过。

训练流程

Patchscopes 本身不需要训练（$f = \mathbb{I}$ 时）。只有在以下场景才需要训练：

  • Cross-model patching：学习跨模型的仿射映射
  • Tuned Lens baseline：学习层间映射

硬件：A100 80GB GPU（GPT-J 实验用 A100 40GB）

4. 数据集：使用现有 benchmark 子集，规模偏小

  • 训练数据:
    • Patchscopes 本身不需要训练数据（zero-shot / few-shot target prompt）
    • Tuned Lens / cross-model mapping 训练用 Pile 数据集：12,000 样本（10,000 训练 + 2,000 评估）（Appendix B.2）
  • 评估数据:
    • Next-token prediction: Pile evaluation set（2,000 examples）
    • Feature extraction: Hernandez et al. (2023b) 数据集，8 commonsense + 25 factual 关系，过滤后保留 5 commonsense + 7 factual tasks，共 1,453 datapoints（GPT-J 6B）。Source prompt 从 WikiText-103 中采样包含 subject 的句子
    • Entity resolution: PopQA 数据集中 200 个最热门 + 200 个最冷门实体，描述来自 Wikipedia
    • Multi-hop reasoning: 从 Hernandez et al. (2023b) 系统生成 $\omega_1 = \sigma_2$ 的组合查询，共 1,104 样本，经严格过滤（模型需独立正确表征两个 triplet），仅剩 46 个 有效样本。8 种 relation 组合（Appendix F, Table 8）

5. 关键结果：Token Identity Patchscope 在 next-token prediction 上显著优于 Logit Lens；特征提取零训练胜过 probe；但 multi-hop 实验样本量极小

5.1 Next-Token Prediction 解码（Section 4.1, Figure 2）

  • Token Identity Patchscope 从 layer 10 起在所有模型上持续优于 Logit Lens 和 Tuned Lens
  • 声称在 layers 18-22 获得 "up to 98% gain"——但这是 relative improvement，绝对数值论文没给具体数字，只有 Figure 2 的曲线
  • 前 10 层所有方法都较差，这是合理的——因为前 10 层在做 input contextualization，还没到 prediction
  • 测试模型：LLaMA2 13B, Vicuna 13B, GPT-J 6B, Pythia 12B

5.3 Entity Resolution（Section 4.3, Table 3, Figure 3）

  • 定性示例非常直观：Diana, Princess of Wales 在 layer 1-2 → "Country in the United Kingdom"（Wales），layer 3 → "Country in Europe"（Wales），layer 4-5 → "Princess of Wales (unspecific)"，layer 6 → "Diana, Princess of Wales, the first wife of Prince Charles"
  • 定量结果用 RougeL 对比 Wikipedia descriptions（Figure 3）：Popular entities 的 RougeL 在 layer 5 左右达到峰值（约 0.25，从图上估读），然后下降
  • 没有 baseline 对比——只有一个方法的结果图，缺少"这种方法比其他方法好在哪"的定量证据
  • Placeholder contamination：从 layer 7 开始生成 "Placeholder for a variable" 而非实体描述（Table 6, Paris Hilton 示例）。这意味着 Patchscope 只能在前 5-6 层正常工作——而后层恰好是 Logit Lens 工作得更好的地方
  • 跨模型 patching（Vicuna 7B → 13B）一致提升 RougeL 分数（Figure 3 绿线 vs 蓝线）
  • Pythia 6.9B 本身就比 12B 表现好，原文解释为 "the larger model is biased toward output generation at the expense of input contextualization"（Appendix D.2），所以跨模型 patching 对 Pythia 没什么增益

5.4 Cross-Model Patching（Section 4.4, Figure 10-11）

  • 仿射映射 + 对角线层匹配（$\ell \approx \ell^*$）效果最好
  • Patching 到大模型的早期层最有效
  • Precision@1 最高达 0.8（Pythia）和 0.7（Vicuna）
  • 跨模型 patching 的前提是大模型确实更强——Pythia 6.9B > 12B 的情况下就没有增益

5.5 Multi-Hop Reasoning 修正（Section 5, Figure 4, Figure 12）

Method Accuracy
Vanilla 19.57%
CoT ("Let's think step by step") 35.71%
CoT Patchscope 50%
  • 有效 patching 配置：$\ell^* \in [6, 16]$（早期到中间 target 层），$\ell^* \leq \ell$ 更成功
  • 作者强调这是 proof-of-concept，不是要跟 CoT 竞争——Patchscope 利用了查询的结构先验（知道哪两步要连接），CoT 不需要
  • CoT 生成多步推理，根本上扩展了 LLM 的计算能力（Merrill & Sabharwal, 2024），而 Patchscope 只做 $O(1)$ 次 inference pass

消融实验

  • Token identity prompt 的 robustness（Figure 5）：5 种不同 random seed 的 token identity prompt 在 upper layers 表现一致；Single Token Prompt baseline 效果较差
  • Source-target layer 交互（Figure 7, 12）：heatmap 显示 early-to-mid 的 $(\ell, \ell^*)$ 组合最优

6. Insights

6.1 对论文本身的 Comments

  • Token identity prompt 反直觉地有效：简单的"复读"模式 "tok1 → tok1; tok2 → tok2" 就能解码 next-token prediction，不需要精巧的 prompt 设计。这说明 LLM 的 in-context learning 能力可以被"劫持"来服务于解释——你只需要让它进入回显模式，patched representation 里的信息就会自然流露。论文自己的消融也证实了 Single Token Prompt 不行，关键是 few-shot 示例要给模型建立"复读"模式。

  • "98% gain" 有误导性：这是 relative improvement，absolute improvement 可能很小。论文没有给出 layer 18-22 的绝对数值，只有曲线图。

  • Attribute extraction 评估不公平：recall@20 vs precision@1，完全不是同一个 metric。自然的问题：如果给 Probe 也看 top-20 呢？或者只看 Patchscope 第一个生成 token？论文没做这个控制。

  • Placeholder contamination 是结构性缺陷：不只是一种"干扰"，它造成了覆盖缺口——Patchscope 在前 5-6 层工作，placeholder contamination 让后层失效，而 Logit Lens 恰好在前 10 层失效、后层工作好。两种方法互补但没有融合方案。

  • Multi-hop 46 个样本太少：从 1,104 筛到 46，这是 cherry-picked best-case。50% vs 35.71% 在 46 个样本上，binomial 置信区间很宽。而且实验利用了查询的结构先验（手动指定 patching 位置），跟 CoT 的 apples-to-apples 对比不太公平。

  • 统一框架是 taxonomy 贡献而非方法论贡献：五元组参数化让任何 activation patching 都能写成 Patchscope 的特例，但框架本身不做新的事情，新东西全靠新的配置。不过，这个参数化确实揭示了未探索的配置空间。

  • Patchscopes 的输出是 patched representation 和 target prompt 的联合产物：论文承认 post-patching 计算会增强表征，但没有控制实验来分离 target prompt 的生成偏差和 source representation 的信息贡献。比如 entity resolution 的 "逐步 contextualization" 故事可能部分是 target prompt 的 few-shot 示例偏向生成实体描述的结果。

6.2 对未来的预测

  • Patchscopes + SAE 的组合：SAE 找到稀疏特征方向后，目前靠 top-activating examples 来解读，这本质上就是 Logit Lens 的思路。Patchscopes 可以解码这些稀疏方向的具体语义，提供比 top examples 更丰富的自然语言描述。这可能是 interpretability 从"发现特征"到"理解特征"的关键一步。
  • 跨架构 patching 是关键开放问题：目前只验证了同族模型。如果跨架构可行，Patchscopes 就变成通用 interpretability 接口；如果不可行，就受限于同族模型的表征空间兼容性。

6.3 研究品味

  • 定性 demo 比定量曲线更有说服力：实体解析的 "Alexander the Great" 示例让读者立刻理解"层逐步整合上下文"这件事，比 Figure 3 的 RougeL 曲线直观得多。写论文时，一个精心挑选的 qualitative example 可以 carry 整个 story。
  • 实验覆盖面广但深度不足：4 个实验 + 1 个 application，每个都有有趣的发现，但每个都留下了明显的证据缺口（next-token 没有具体数字，attribute extraction 评估不公平，entity resolution 没有 baseline，multi-hop 样本太少）。广度优先作为 framework paper 可以理解，但每个 claim 的可信度都打了折扣。

7. 连接与发现

  • MOC-Interpretability — Topic: 提出 Patchscopes 框架，通过将隐藏表征 patch 到不同推理过程中用自然语言解码信息，统一并扩展了词汇投影和激活干预等先前可解释性方法

  • MOC-LatentQA — Concept: 作为 LatentQA 范式的零样本前身，通过 patching 将激活解码为自然语言，启发了 LatentQA 任务的定义并作为其直接对比基线

  • 相关工作: 见 Geva2022Transformer-FF-Layers
