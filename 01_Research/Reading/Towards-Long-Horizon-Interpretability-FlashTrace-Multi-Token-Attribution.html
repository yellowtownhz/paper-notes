2. 关键问题：推理链让 token 归因既慢又不准

Golden Case — 问题是什么？

想象一个 multi-hop QA：模型被问"X 出生一周后的日期是什么？"。模型先生成推理链 T："X 出生于 1990-03-15，一周后是 1990-03-22"，然后输出答案 O："1990-03-22"。

你想归因——输入里哪些 token 导致了这个答案？直觉上，包含"1990-03-15"的那句话才是关键。但现有方法一跑，归因权重几乎全堆在推理链 T 上（接近 90%），输入 I 只拿到不到 10%。为什么？自回归模型里每个 token 都直接条件于上一个 token，推理链内部的"邻近依赖"把归因权重吸走了。

效率更惨：归因 M 个 output token 就得对每个 target token 独立跑一遍，总共 O(M·N) 次操作。推理链几百 token 时，IG 解释一个 5k-token generation 要 10+ 小时。

两个问题有因果关系：推理链长（M 大）所以效率差；同时推理链长所以归因权重被 T 吸走，准确性也差。

  • Faithfulness drop：推理 token 吸走权重，ground-truth input 的 recovery rate 从 ~26% 跌到 <10%（Figure 1b）。reasoning token 占 attribution mass 的比例从 ~80% 涨到 >90%（Figure 1a）——增长速度比线性预期更陡 [?]。

  • Efficiency bottleneck：单 token 归因方法一次解释一个 token，对 M 个 target 要跑 M 次，O(M·N)。长上下文里 gradient-based methods（IG）直接 OOM。
  • 之前方法卡在哪：IFR/AttnLRP 只做 single-token target；perturbation 方法在长上下文本身就慢；gradient 方法 OOM。没有任何方法同时解决效率和忠实度。

3. 关键方法：span-wise 聚合 + 递归归因 = O(N) 一次搞定

Golden Case — 方法怎么跑？

还是那个 multi-hop QA。

Hop 0（直接归因）：FlashTrace 把整个答案 span O 作为一个整体目标，用 span-wise aggregation 一次算出所有 context token 对这个 span 的贡献。核心 trick：$\mathbf{v}_j$（source token j 的 transformed vector）只依赖 j 不依赖 target position i，所以对 span S 内所有 i 求和时可以 factor out——$\mathbf{F}_{j \to S} = \mathbf{v}_j \cdot (\sum_{i \in S} \alpha_{i,j}^h)$，$\mathbf{v}_j$ 只算一次，attention weights 做 scalar 预聚合。O(M·N) 变成了 O(N)。

结果跟问题一样：推理链 T 占大头，输入 I 占小头。

Hop 1（递归归因）：把 Hop 0 里 T 上拿到的权重当作"新的 target weight"。比如"出生于 1990-03-15"在 Hop 0 拿了 0.4 权重，"一周后是 1990-03-22"拿了 0.3。FlashTrace 用这些权重加权聚合 T 的表示，再跑一遍 span-wise 归因，问"哪些输入 token 导致了这些重要的推理 token？"——权重从 T 穿透回了 I。

最终聚合：$\mathbf{w}_{final} = \mathbf{w}_\mathbf{I}^{(0)} + \rho_0 \cdot \mathbf{w}_\mathbf{I}^{(1)}$。$\rho_0$ 是 Hop 0 中 T 占总权重的比例——推理吸收了 90% 的 mass，这 90% 在递归后才被真正分配到输入上。

Span 的定义

Span = 一段连续的 token 位置，定义为 $S = \{s_{\text{start}}, \ldots, s_{\text{end}}\}$。它不是随意切割的 chunk，而是对应模型生成的 三个功能段：

$$\mathbf{S} = \mathbf{I} \circ \mathbf{T} \circ \mathbf{O}$$
  • I = 输入 token（用户 prompt）
  • T = 推理 token（thinking chain，即 <tool_call>... 里的内容）
  • O = 输出 token（最终答案）

所以 "span-wise attribution" 的意思是把整段推理链 T 或整段答案 O 当作 一个整体目标 来归因，而不是逐 token 归因。论文没有做 sentence-level 或 chunk-level 的细分——span 的边界就是这三个天然的功能段。

整体架构

FlashTrace = Span-wise Aggregation（效率）+ Recursive Attribution（faithfulness），两个模块解耦但组合使用。

核心模块 1：Span-wise Aggregation

关键洞察：attention 的贡献 $\mathbf{f}_{j \to i} = \alpha_{i,j}^h \cdot \mathbf{v}_j$ 里，$\mathbf{v}_j = \mathbf{x}_j W_V^h W_O^h$ 只依赖 source token j。所以 span 内求和可以把 $\mathbf{v}_j$ 提出来（Eq 8）。注意力权重是 scalar，先求和再乘 vector。这就是从 O(M·N·D) 降到 O(N·D) 的根源。

这个 trick 的前提条件是 attention contribution 的 factorization 结构（$\alpha \cdot \mathbf{v}$）——gradient-based 方法没有这个结构，所以 IG 根本没法做类似的 span-wise 优化，直接 OOM。选择什么基础框架（proximity/attention-based vs gradient-based）决定了你能不能做 span-wise。

Proximity Metric（来自 ALTI/IFR）：

$$\text{Proximity}(\mathbf{z}, \mathbf{y}) = \max(0, -\|\mathbf{y} - \mathbf{z}\|_1 + \|\mathbf{y}\|_1)$$

物理意义：如果把贡献 $\mathbf{z}$ 从 $\mathbf{y}$ 中去掉，$\mathbf{y}$ 的 L1 magnitude 会减少多少。用 L1 而不是 L2 是因为 Transformer 的向量空间是 high-dimensional, anisotropic 的。

Span-wise 聚合目标：

$$\mathbf{Y}_S = \sum_{i \in S} \mathbf{y}_i \quad \text{(Eq 5)}$$ $$\mathbf{F}_{j \to S} = \mathbf{v}_j \cdot \left(\sum_{i \in S} \alpha_{i,j}^h\right) \quad \text{(Eq 8)}$$

Per-layer 算法步骤（Algorithm 1）：

Forward pass 缓存所有 layer 的 hidden states $\mathbf{X}^{in}, \mathbf{X}^{mid}, \mathbf{X}^{out}$ 和 attention maps $\mathbf{A}$。对每个 layer l：

  1. 聚合 target representations：$\mathbf{Y}_S^{mid} = \sum_{i \in S} w_i \cdot \mathbf{X}_i^{mid}$，$\mathbf{Y}_S^{out} = \sum_{i \in S} w_i \cdot \mathbf{X}_i^{out}$
  2. 预聚合 attention：$\boldsymbol{\alpha}^S = \sum_{i \in S} w_i \cdot \mathbf{A}_{i,:}^{(l)}$（按行求和）
  3. 对每个 source token j：算 $\mathbf{v}_j' = (\mathbf{X}_j^{in} \odot \mathbf{s}_j) W_V W_O$（含 normalization scaling），然后 $\mathbf{C}_{j \to S} = \boldsymbol{\alpha}_j^S \cdot \mathbf{v}_j'$，proximity $e_j = \text{Prox}(\mathbf{C}_{j \to S}, \mathbf{Y}_S^{mid})$
  4. Residual importance：$e_{res} = \text{Prox}(\sum_{i \in S} w_i \cdot \mathbf{X}_i^{in}, \mathbf{Y}_S^{mid})$
  5. MLP importance：$e_{mlp} = \text{Prox}(\sum_{i \in S} w_i \cdot \text{MLP}(\mathbf{X}_i^{mid}), \mathbf{Y}_S^{out})$
  6. Normalize：token scores / (token scores + residual + MLP)，保证各层贡献归一化

累加所有 layer 的 normalized scores 得到 $\mathbf{w}^{(k)}$。

Normalization linearization：RMSNorm/LayerNorm 被近似为 $\text{Norm}(\mathbf{x}) \approx \mathbf{x} \odot \mathbf{s}(\mathbf{x})$（Eq 13），$\mathbf{s}$ 固定为 forward pass 时的 scaling vector。这使得归因可以线性穿透 normalization layer。推测 RMSNorm 的 scaling：$\mathbf{s} = \frac{1}{\text{RMS}(\mathbf{x})} \cdot \gamma$ [?]，论文没有给出 $\mathbf{s}(\mathbf{x})$ 的具体公式。

MLP 的处理：被整体当作一个 contribution component，没有进一步分解 MLP 内部 token-to-token 的贡献（因为 MLP 不做 token 间信息交换，这是 ALTI/IFR 的传统做法）。

核心模块 2：Recursive Attribution

Hop 0：target = output span O，weight = 1 for all tokens in O。跑 Span-wise Aggregation 得到 $\mathbf{w}^{(0)}$，拆成 $\mathbf{w}_\mathbf{I}^{(0)}$ 和 $\mathbf{w}_\mathbf{T}^{(0)}$。

Hop 1：target = reasoning span T，weight = $w_t^{(0)}$（从 Hop 0 的 T 分数取出来）。跑 Span-wise Aggregation 得到 $\mathbf{w}^{(1)}$。

Flow ratio（完整定义见 Appendix Eq 23）：

$$\rho_{k} = \frac{\sum_{t \in S_{think}} w_t^{(k)}}{\sum_{\text{all } j} w_j^{(k)}} \quad \text{(Eq 23)}$$

主文 Eq 11 只写了分子 $\rho_k = \sum_{t \in \mathbf{T}} w_t^{(k)}$，Appendix 给了完整比例形式。

Final aggregation：

$$\mathbf{w}_{final} = \mathbf{w}_\mathbf{I}^{(0)} + \sum_{k=1}^{K} \left(\prod_{j=0}^{k-1} \rho_j\right) \cdot \mathbf{w}_\mathbf{I}^{(k)} \quad \text{(Eq 12)}$$

直觉：每 hop 有部分 mass 流入 I（被解释了），剩余 mass 流入 T（等待下一 hop 解释）。Hop 1 分给 I 的权重要乘 $\rho_0$，因为只有 $\rho_0$ 这么多的权重"还需要解释"。

递归 hop 数量：实验中 K=1。Table 7（MoreHopQA）：0 Hop RISE=0.127, MAS=0.209；1 Hop RISE=0.128, MAS=0.205。RISE 微微恶化 0.001，MAS 改善 0.004——两个指标对递归效果不一致，差异都在 0.001-0.004 范围内 [?]。论文声称"even a single recursive hop improves faithfulness"，但 RISE 指标实际恶化了。

方法流程代码示例

以下 Python-style pseudocode 拆解 FlashTrace 的完整流程。输入是一段已经生成好的文本，分成三个 span：I（输入）、T（推理链）、O（答案）。

# ============================================================
# Step 0: 一次 forward pass，缓存所有中间量
# ============================================================
# 模型对完整序列 I∘T∘O 做一次 forward pass
# 缓存每层 l 的:
#   X_in[l]   — 进入 layer l 的 hidden states (N × D)
#   X_mid[l]  — layer l 中 attention 输出后、MLP 输入前的 hidden states (N × D)
#   X_out[l]  — layer l 最终输出的 hidden states (N × D)
#   A[l]      — layer l 的 attention maps (N × N per head, 共 H heads)
#   s[l]      — forward pass 时 RMSNorm 的 scaling vector (N × D)，固定下来不再变

# ============================================================
# Step 1: Span-wise Aggregation（核心效率模块）
# ============================================================
# 目标：对 span S 内所有 target token 一次算出每个 source token 的贡献
# 关键 trick: v_j 只依赖 source j，不依赖 target i
# 所以可以把 v_j 提出来，attention weights 先做 scalar sum

def spanwise_attribution(S, w, cached):
    """
    S: target span 的 token index 集合, e.g. {indices of O}
    w: 每个 target token 的权重向量 (len(S)), 
       Hop 0 时 w = [1, 1, ..., 1]（所有 O token 同等重要）
       Hop 1 时 w = Hop 0 中 T 上拿到的权重
    cached: forward pass 缓存的 X_in, X_mid, X_out, A, s
    """
    total_scores = np.zeros(N)  # N = 全序列 token 数

    for layer_l in range(L):
        # --- 1. 聚合 target representations（加权求和） ---
        Y_mid = sum(w[i] * cached.X_mid[l][S[i]] for i in range(len(S)))  # D-dim vector
        Y_out = sum(w[i] * cached.X_out[l][S[i]] for i in range(len(S)))  # D-dim vector

        # --- 2. 预聚合 attention weights（scalar sum，这是 O(M·N) → O(N) 的关键） ---
        # 之前（naive per-token）: 对每个 target i, 每个 source j, 都要算 α_{i,j} · v_j → O(M·N·D)
        # 现在: 先把所有 target i 的 attention weight 对同一个 source j 加起来
        #       α_j^S = sum(w[i] * A_{S[i], j}^{(l)}) for all heads h  → 只是一个 scalar per j
        alpha_preagg = np.zeros(N)  # scalar per source token
        for i in range(len(S)):
            for h in range(H):
                # A_{S[i], :}^{(l, h)} 是第 h 个 head 中 target token S[i] 对所有 source 的 attention
                alpha_preagg += w[i] * cached.A[l][h][S[i], :]  # 按行加权求和

        # --- 3. 对每个 source token j，算 attention contribution ---
        token_scores_l = np.zeros(N)
        for j in range(N):
            # v_j' = (x_j_in ⊙ s_j) * W_V * W_O   — 含 normalization linearization
            # ⊙ s_j 是把 RMSNorm 近似为 x ⊙ s(x)，s 在 forward 时已固定
            v_j = (cached.X_in[l][j] * cached.s[l][j]) @ W_V @ W_O  # D-dim vector, 只算一次!

            # span-level contribution: scalar α_j^S × vector v_j
            C_j_to_S = alpha_preagg[j] * v_j  # D-dim vector

            # Proximity metric: C_j 对 Y_mid 有多大贡献？
            # Prox(z, y) = max(0, -||y - z||_1 + ||y||_1)
            # 物理含义：如果把贡献 z 从 y 中去掉，y 的 L1 norm 减少多少
            e_j = proximity(C_j_to_S, Y_mid)
            token_scores_l[j] = e_j

        # --- 4. Residual 的重要性 ---
        # residual connection: x_out = x_in + attn_out + mlp_out
        # x_in 也直接流向 x_out，算 x_in 对 Y_mid 的 proximity
        X_in_agg = sum(w[i] * cached.X_in[l][S[i]] for i in range(len(S)))
        e_res = proximity(X_in_agg, Y_mid)

        # --- 5. MLP 的重要性 ---
        # MLP 不做 token 间通信，整体算一个 component
        MLP_agg = sum(w[i] * MLP(cached.X_mid[l][S[i]]) for i in range(len(S)))
        e_mlp = proximity(MLP_agg, Y_out)

        # --- 6. Normalize per layer（保证每层总贡献 = 1） ---
        total_raw = e_res + e_mlp + sum(token_scores_l)
        token_scores_l_norm = token_scores_l / total_raw  # 每个 source token 的 normalized score

        # 累加到全局
        total_scores += token_scores_l_norm

    return total_scores  # N-dim vector, 每个 input/reasoning/output token 的归因分数

# ============================================================
# Step 2: Recursive Attribution（核心 faithfulness 模块）
# ============================================================
# 问题: Hop 0 的结果里 T（推理链）占了 ~90% 权重，I（输入）只占 ~10%
# 解决: 把 T 上的权重当作"待解释的 mass"，递归追问"T 上的权重来自哪些 I token"

def flashtrace_full(I_indices, T_indices, O_indices, cached):
    # --- Hop 0: 归因 output span O ---
    w_0 = np.ones(len(O_indices))  # O 的每个 token 权重 = 1
    scores_0 = spanwise_attribution(O_indices, w_0, cached)
    # scores_0 是一个 N-dim vector，拆成 I 和 T 两部分
    w_I_0 = scores_0[I_indices]   # 输入 token 在 Hop 0 的分数
    w_T_0 = scores_0[T_indices]   # 推理 token 在 Hop 0 的分数

    # flow ratio: T 在 Hop 0 中占多少比例？
    rho_0 = sum(w_T_0) / sum(scores_0)  # ≈ 0.9（推理链吸走了 90% 的 mass）

    # --- Hop 1: 归因 reasoning span T（用 Hop 0 的 T 权重作为 target weight） ---
    w_1 = w_T_0  # 关键：不再是均匀权重，而是 Hop 0 里 T 拿到的权重
    scores_1 = spanwise_attribution(T_indices, w_1, cached)
    w_I_1 = scores_1[I_indices]   # 输入 token 在 Hop 1 的分数

    # --- Final aggregation ---
    # 直觉：
    #   w_I_0 是 Hop 0 直接分给 I 的（约 10%）
    #   rho_0 * w_I_1 是 Hop 0 流入 T 的部分（约 90%），经递归后重新分配到 I
    #   两部分加起来才是 I 的真实贡献
    w_final_I = w_I_0 + rho_0 * w_I_1

    # 推理链越长，rho_0 越大，递归纠正的幅度越大
    # 没有 T 时（direct answering），rho_0 ≈ 0，递归无用
    return w_final_I

# ============================================================
# 为什么 span-wise 比 per-token 快？
# ============================================================
# Per-token (naive IFR extension):
#   对 M 个 target token, 每个 target 独立跑一遍:
#   for i in O_indices:       # M iterations
#     for j in range(N):      # N iterations per target
#       C_j_to_i = alpha_{i,j} * v_j   # D-dim multiply
#   总复杂度: O(M · N · D)
#
# Span-wise (FlashTrace):
#   alpha_preagg[j] = sum(alpha_{i,j} for i in S)  # scalar sum, O(M) per j → O(M·N) scalar ops
#   C_j_to_S = alpha_preagg[j] * v_j               # 一次 D-dim multiply per j
#   总复杂度: O(M·N) scalar ops + O(N·D) vector ops = O(N·D)
#   v_j 只算一次，不随 span length M 增长！

# ============================================================
# 为什么递归能修复 faithfulness？
# ============================================================
# 自回归模型里 token i 几乎完全依赖 token i-1（adjacent dependency）
# 所以 per-token 归因时，推理链内部的邻近 token 把权重全吸走
#
# Hop 0: O 的归因 → T 占 90%, I 占 10%
# Hop 1: 把 T 的 90% 拿出来，问"T 的权重来自哪里？" → 权重穿透回了 I
# 最终: I 的贡献 = 10% (直接) + 90% × (递归后分配到 I 的比例)
#
# 类比：
#   你问"谁的工资最高？" → CEO (Hop 0)
#   再问"CEO 的工资来自哪个部门？" → 市场部 (Hop 1)
#   市场部的贡献 = 市场部直接工资 + CEO工资 × 市场部对CEO的贡献

  • Ground truth：RULER 有显式 ground-truth token 标注，MATH/MoreHopQA 没有 token-level label，用 perturbation metrics 评估。

5. 关键结果：130x 加速 + faithfulness 优势，但统计严谨性堪忧

主实验结果

效率（Figure 4）：5k target span，FlashTrace < 20s，IFR > 38min → 130x+ speedup。Gradient-based methods（IG, IG-Attn）在长上下文直接 OOM。FlashTrace memory 不随 target span length 增长（working memory O(N+D)）。

注意：130x 是跟 naive IFR extension 比。没有跟优化过的 sentence-level perturbation 比——后者只做 ~20-50 forward passes（Appendix D.2），比 IFR 的 M*N pass 快得多。如果把 sentence-level perturbation 也纳入时间对比，加速倍数可能只有 5-10x。

另外，gradient methods 在最有意义的场景（长上下文 + 长推理链）里直接 OOM 退出比赛了。论文只在短上下文比较了 gradient 方法的 faithfulness，但在短上下文上推理链也短，faithfulness drop 本身就不严重——这是一个 confounding variable [?]。

统计严谨性问题

  • 涨幅可能不显著：MATH 上 RISE 差距仅 0.006，在 100 样本（HotpotQA 仅 66 个）上极可能不显著
  • Baseline 的 post-processing 偏帮 baseline：所有 baseline 的 reasoning token scores 被丢弃后 renormalize 到 input 上（Eq 31）。这实际上是在帮 baseline "聚焦"到 input——如果不做 renormalization，baseline 在多步推理场景可能更惨 [?]
  • Perturbation metric 定义被改了：RISE/MAS 标准实现是逐 token mask（step size = 1），这里改成 top 5% per step（20 steps，Appendix F.2）。这不是微调，是 metric 定义的变更，所有 faithfulness 比较的基础被替换了 [?]

缺失的 ablation

  • 没有 span-wise aggregation vs per-token then average 的直接对比

6. Insights

6.1 对论文本身的 Comments

span-wise 的核心 trick 不反直觉，但前提条件决定了可行性。把 $\mathbf{v}_j$ 提出来本质上就是"矩阵乘法里把不依赖循环变量的部分提出来"。但这个 trick 的前提是 attention contribution 有 factorization 结构（$\alpha \cdot \mathbf{v}$），gradient-based 方法没有这个结构，所以 IG 根本没法做类似优化。选择什么基础框架决定了你能不能做 span-wise。

reasoning token 吸权重的比例增长比线性预期更陡。Figure 1a 显示从 ~80% 到 >90%，这个增长速度比"每多一步就多吸收一点"的线性预期更快 [?]——意味着推理链越长，input 的归因衰减越严重。

K=1 就够了——证据很弱。Table 7 上 MAS 只改善 0.004，RISE 反而恶化 0.001——这些差异都在噪声量级。但 Figure 7 的 mass shift 可视化直观可信——问题在于 mass shift ≠ 最终 metric 改善。一个可能的解释是：span-wise 聚合本身有"模糊化"效果——把整个推理链当成一个 span，一次递归就能把大部分权重穿透回去，不需要逐步穿透每个推理 step。但这也意味着精度有损（Table 3 里 FlashTrace 确实比 Exhaustive Rollout 略差）。

Normalization linearization 处理有点粗糙。固定 forward pass 的 $\mathbf{s}(\mathbf{x})$ 忽略了 normalization 的动态反馈效应。在短上下文可能无所谓，但在长推理链里 normalization 的 scaling 会随上下文显著变化——固定 $\mathbf{s}$ 可能引入累积误差 [?]。

Recovery Rate 和 perturbation metrics 之间的一致性没有验证。论文提出了 Recovery Rate 作为 metric（只在有 ground-truth 的合成数据上能用），在真实推理任务上只有 RISE/MAS。论文从未验证这两个 metric family 是否一致——如果 Recovery Rate 高但 RISE/MAS 也高，整个评估框架的可信度就崩了。

只筛选正确回答样本做归因偏离了 interpretability 的核心场景。归因的目的恰恰是理解模型为什么出错——如果你只能归因模型回答正确的情况，那归因对你的帮助在哪？

所有实验只在 8B 模型上做。8B 模型的推理链质量远不如 production 模型，推理链也更短。方法在大模型上可能完全失效。

Aider 实验 apples-to-oranges。不同 target scope 的 metric 不可直接比较。

gradient methods OOM 导致只在问题不严重的场景比较了最强对手。

6.3 研究品味

Span-wise aggregation 的核心 trick（factor out $\mathbf{v}_j$，预聚合 attention weights 做 scalar sum）和 FlashAttention 有相似之处——都是通过 algebraic reordering 把 vector op 降成 scalar op。"找到线性结构、把 vector op 降成 scalar op"这种思路在 interpretability 里之前没人用过。
