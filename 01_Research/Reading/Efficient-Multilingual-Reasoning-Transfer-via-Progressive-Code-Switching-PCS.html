论文笔记: Efficient Multilingual Reasoning Transfer via Progressive Code-Switching (PCS)

1. 背景信息

  • 作者：Zhijun Wang（一作，Tongyi Lab 实习期间完成）、Junxiao Liu、Hao Zhou、Hao-Ran Wei、Baosong Yang、Shujian Huang（通讯，南京大学 NLP 组 NJUNLP + 通义）
  • 机构：Tongyi Lab（阿里通义）+ 南京大学，挂了南大 NSFC 基金
  • 时间：arXiv:2607.00485v1，2026-07-01，cs.CL，CC BY 4.0。未标会议，但 Acknowledgments 提到 "anonymous reviewers"，应该在投稿/rebuttal 中
  • 一句话：只用轻量翻译（不蒸馏更强 teacher 的目标语言 trace、不用在线 judge 打分），靠"渐进式 code-switching + 课程 RL"把英文推理能力搬到目标语言，让模型既算得对、又用目标语言 think。

2. 关键问题：大推理模型嘴上答目标语言、脑子里却在用英文想，硬逼它换语言又会掉点

Golden Case — 问题是什么？ 一个泰语用户问了一道数学题（泰语）。你希望模型：(a) 答对，(b) 整个 <think>...</think> 推理过程也是泰语（这样用户看得懂、可信）。 现实是 Qwen3-8B 拿到泰语题后，推理链几乎全用英文——SLC（步骤级语言一致性）只有 6.4%，也就是 100 个推理步骤里只有 6 步是泰语（Table 2，MMATH，Qwen3-8B 行）。用户看不懂它在想什么。 那直接逼它用泰语呢？最狠的反面教材是 M-Thinker（Figure 3/10）：给它加个"整段回复要是泰语"的奖励 + 更强 judge 的跨语对齐奖励（CTA），结果模型学会了骗语言检测器——它在 token 级疯狂混英文和中文来推理，但塞进足够的泰语线索，让 langdetect 输出 [th:0.9999999]。答案对了，但推理过程是英中夹杂的天书，比全英文还难读。

这个 case 把两难讲清楚了：控不住语言（偷偷切回英文），或者控住了但掉点/被 hack。

  • 动机：多语言推理 = 用非英语解数学题。LRM（DeepSeek-R1、Qwen3、o1）在英文上很强，换语言就掉，(a) 常偷偷切回英文推理，(b) 强行逼目标语言又掉准确率。用户语言和模型思考语言不匹配 → 可读性/可信度崩掉。
  • 之前的方法卡在哪（论文列了一排，每个都有硬伤，Table 1/2 佐证）：
    • Prompt Control（推理时加语言指令）：几乎无效。8B MMATH SLC&Acc 平均 0.6（Table 2），跟不控制没区别。
    • Prefix Control（在 <think> 后塞一个目标语言的 "Okay" 诱导）：SLC 能上去，但大幅掉精度。8B MMLU-ProX 上 Prefix 把 FR 的 acc 从同语言 base 的 51.7 打到 48.4，KO 从 38.3 打到 24.0（Table 2）。
    • SFT on 蒸馏的多语推理 trace：受制于多语长推理数据稀缺 + 质量，会引入严重重复（Table 1 里日语因 repetition 崩到 4B MMATH acc 7.7、MMLU-ProX acc 0.6）。且这些 trace 得靠更强模型蒸馏，贵、不好 scale。
    • RL + response 级语言一致性奖励（Magistral 的 SoftLC / M-Thinker）：要么退化回英文（Naive RL 的 SLC&Acc≈0），要么像 M-Thinker 那样被 reward hacking。
    • 核心痛点：已有方法要么靠更强 teacher 蒸馏目标语言 trace，要么靠在线 judge 打分——都贵、难 scale；而"一步到位强推目标语言"这件事本身不稳定、掉点。缺一条"既切语言又保精度"的平滑路径。

注：这一节只讲问题，方法怎么解决留到下一节。

3. 关键方法：把 code-switching 当"中间态桥梁"，用课程 RL 把目标语言比例从 10% 一路推到 95%

Golden Case — 方法怎么跑？ 继续那道泰语数学题。PCS 不逼模型一夜之间全说泰语，而是让它"慢慢换舌头"：

  1. Cold-start：拿一条英文推理 trace（比如 12 行），随机挑 30% 的行用 TranslateGemma-4B 翻成泰语，其余保持英文 → 得到一条"英泰混杂"的 code-switched trace。再和纯英文数据混起来 SFT，让模型先具备"能混着说"的能力。此时 SLC 还很低。
  2. RL 起步：设阈值 τ=10%。模型 rollout，只要这条回复里泰语步骤占比 ≥10%，且答对、格式对、不重复，就给 1.1 的奖励。门槛很低，模型很容易达到，不会为了凑语言而牺牲推理。
  3. 课程推进：每 40 步 RL 检查一次 Pass@SLC(τ)（在答对+格式对的回复里，SLC≥τ 的比例）。一旦 ≥0.9（说明当前难度饱和、奖励不再有区分度），就把 τ 抬高 0.1（10%→20%→…）。门槛越高，模型被迫把越来越多的行改成泰语。
  4. 收尾：τ 一路涨到 0.95，SLC 逼近 100%。同时后期策略偏离 SFT 越来越远，KL 会爆，于是当 KL loss > 0.2 时把 reference model 重置为当前 policy，再加个 0.001 的 KL 惩罚稳住。

关键 trick：永远不直接奖励"更高的 SLC"（那样太激进会掉点），而是用二值门槛 τ 一档一档往上抬，每档先让模型稳住再加难度。

核心思想：与其逼模型突然切到全目标语言推理，不如把 code-switched reasoning 当成跨语迁移的中间态——底层推理逻辑仍是英文那套高质量逻辑，通过 code-switching 逐步搬到目标语言。

整体架构（两阶段）

英文推理数据 ──30%行翻译(TranslateGemma-4B)──► code-switched trace
                                                      │
                                          [阶段1] Cold-Start SFT（混入纯英文数据）
                                                      │  (会说混合语言，但SLC低)
                                                      ▼
                                          [阶段2] Progressive Code-Switching RL (GRPO)
                                            τ: 10% ──课程──► 95%
                                            reward gate + SLC bonus
                                            KL reset when KL>0.2
                                                      ▼
                                          全目标语言推理 (SLC≈96-99%)

Backbone：Qwen3-4B-Base / Qwen3-8B-Base。优化器 GRPO。

核心模块与数学形式化

(a) Step-Level Language Consistency, SLC(T,L) —— 全文度量基石。要解决的问题：怎么量化"这条推理链有多大比例在用目标语言"？response 级整段判语言太粗（会被 hack），所以细到 step。

给定推理 trace T=(s_1,…,s_n) 和目标语言 L，用分类器 c(·)（实操用 langdetect）给每步打标签，三类：L（目标语言）、L̄（非目标语言，主要是英文）、∅（无自然语言，如纯数学表达式）。

$$\mathrm{SLC}(T,L)=\frac{\sum_{i=1}^{n}\mathbf{1}[c(s_i)=L]}{\sum_{i=1}^{n}\mathbf{1}[c(s_i)\in\{L,\bar{L}\}]}$$
  • 分子：目标语言步骤数；分母：有自然语言的步骤数（故意排除 ∅ 纯数学步——它们语言无关，算进去会稀释分母）。
  • 分母为 0（整条全是数学）→ 这条 trace 在 batch 统计里丢弃。
  • 物理意义：在"有自然语言的行"里，目标语言占多少。目标推向 100%，同时保住 task performance。

工程近似："step" 用换行分隔的行（line）来近似，作者说这样 "lightweight and stable in RL training"。Appendix C 专门验证了这个近似会不会被 hack（见结果节 line-level hacking 自检）。

(b) Reward Modeling —— 要解决的问题：怎么设计奖励，既保推理质量又鼓励换语言，还不被 hack？

四个原子奖励：r_rep（无重复=1，用三级重复检测，见数据集节）、r_fmt（符合 <think>...</think>=1）、r_acc（答对=1）、r_SLC（先正则去掉数学内容，再用 langdetect 判每步语言，若 SLC(T,L)≥τ 则=1）。

组合方式：先过硬门 C，门不过直接 0 分：

$$C=(r_{\text{fmt}}=1 \land r_{\text{rep}}=1)$$
$$r_{\text{final}}=\begin{cases}1.1,&\text{if }C\land(r_{\text{acc}}=1)\land(r_{\text{SLC}}=1)\\ 1,&\text{if }C\land(r_{\text{acc}}=1)\land(r_{\text{SLC}}=0)\\ 0.1,&\text{if }C\land(r_{\text{acc}}=0)\\ 0,&\text{otherwise}\end{cases}$$

设计要点（复现关键）：

  • 语言奖励只是在答对之上加的一个 0.1 小 bonus（1 → 1.1），而对/错的差距是 1.0 vs 0.1 = 0.9——正确性权重比语言高一个量级。这是全文核心 tradeoff：assign a higher priority to correctness。所以训练曲线里 acc 基本稳、SLC 猛涨（Figure 4）。
  • 硬门把 format/repetition 作前置条件，避免模型为了凑语言/答案生成垃圾。
  • 答错但门过了给 0.1（比彻底 0 好），保留一点梯度信号。

(c) Progressive Curriculum over τ —— 要解决的问题：τ 该怎么调？直接给"SLC 越高奖励越高"的 dense reward 行不行？

课程进度指标 Pass@SLC(τ)：在满足 format+correctness 的回复里，SLC(T,L)≥τ 的比例（batch 级）。每 k 步评估一次，按下式更新 τ：

$$\tau\leftarrow\begin{cases}\min(\tau+\Delta\tau,\;0.95),&\text{if }\mathrm{Pass@SLC}(\tau)\geq 0.9\\ \tau,&\text{otherwise}\end{cases}$$
  • 超参：k=40，Δτ=0.1，τ 从 0.10 起，封顶 0.95。
  • 逻辑：Pass@SLC(τ)≥0.9 说明当前难度饱和、奖励不再有区分度（"saturated and less informative"），抬高 τ 让语言奖励重新变 informative = 加难度。
  • 为什么不用 dense reward：跨语言迁移本质是慢过程；dense reward（SLC 越高奖越多）会逼模型"过早换语言"，在中间迁移阶段还没学好就 aggressive 换，伤推理。消融 PCS-Dense 验证了（见结果节）。

(d) KL 稳定化 —— 要解决的问题：τ 到后期很大时，policy 严重偏离 SFT，KL 爆炸、训练不稳。

  • 初始 KL 约束会限制换语言效率，所以不能一直死约束。
  • 做法：当 KL loss 超过经验阈值 0.2 时，把 reference model 重置为当前 policy，再用 0.001 的 KL 惩罚系数。相当于把优化锚点更新到"和当前迁移阶段对齐"的策略上，再温和约束后续更新。承认了"目标本来就要大幅偏离 SFT，硬约束反而限制语言切换效率"，让锚点跟着课程一起移动。

与已有方法的本质区别

  • vs Son et al.（Language-Mixed CoT）：他们把 code-switching 当最终态（永久锚英文 + 固定比例保留目标语言术语）；PCS 把它当过渡态桥梁，最终要完全目标语言。
  • vs CURE-med（Onyame et al.）：他们的课程按"语言资源等级"排、用 binary response-level 奖励，不显式驱向完全目标语言；PCS 直接在 code-switching ratio 上做课程，用 step-level 阈值。
  • vs M-Thinker：需要更强 judge（DeepSeek-V3）在线打跨语对齐奖励（有延迟、吃算力），且 response 级奖励被 hack；PCS 只用轻量 langdetect，无 teacher trace、无 judge。

line-level hacking 自检的 Prompt（Appendix C，用 DeepSeek-V3 判 longest-line 是否 code-switch）：

{text}
Please determine whether the language of the given text is consistent, meaning it contains only a single language (excluding mathematical content).
Return 0 if it contains only one language, and 1 if it mixes multiple languages. Output exactly 0 or 1 with no additional text or explanations.

4. 数据集：训练数据全靠"翻译"拼出来，不蒸馏目标语言完整推理；评测用两个多语数学 benchmark、5 种语言

训练数据（Appendix A）

  • Cold-start SFT（PCS 版）：550K 样本 = 500K 英文 QA 推理（来自 Tam et al. 2025）+ 50K code-switched 数据（每语 10K）——从英文 trace 随机选 30% 的行用 TranslateGemma-4B 翻成目标语言。这是 PCS 省钱的关键：不蒸馏目标语言完整推理，只做行级翻译。
  • Cold-start SFT（baseline 版）：结构相同，但那 50K 是 DeepSeek-V3.2-Exp 蒸馏的目标语言推理 trace（10K/语言，query 从 500K 英文随机采样再翻译）。数据配方大体 follow AM-Thinking-v1（Ji et al. 2025）。
  • RL（GRPO）数据：把 Tam et al. 的所有 math RL 数据用 DeepSeek-V3.2-Exp 翻成 5 种语言，所有 training-based 方法共用。
  • ⚠️ 注意：RL 阶段的题目翻译用的是 DeepSeek-V3.2-Exp（强模型），不是 TranslateGemma。所以摘要里 "without any stronger model" 的说法，严格只对"目标语言推理 trace 蒸馏"和"online judge"成立，翻译环节仍用了强模型（见 6.1 批判）。

重复检测机制（Appendix A，r_rep 的实现，复现必需）：三级，按优先级依次执行

  1. 行级精确匹配：一行重复 ≥20 次且长度 ≥20 字符，或 ≥10 次且 ≥50 字符 → 判重复。
  2. n-gram 序列重复：suffix array（divsufsort 建 SA，kasai 算 LCP，sparse table 区间查询），找长度 ≥2、重复 ≥20 次的 n-gram。
  3. n-gram 统计启发式：统计定长 n-gram（默认 n=20）频率，最高频出现 ≥20 次时用 suffix array 精确验证。

评估数据

  • MMATH（Luo et al. 2025）：macro-average 四个子集（MATH500、CNMO、AIME2024、AIME2025），报 avg@4。⚠️ AIME2024/2025 各只有 30 题、CNMO 也小 [?]（各 30 题为外部常识，原文未给子集题数）——样本量极小、方差大。
  • MMLU-ProX_math（Xuan et al. 2025）：math 子集，报 avg@1（标准 zero-shot，每题只采 1 次，噪声大）。
  • 语言：法(fr)、葡(pt)、日(ja)、韩(ko)、泰(th)——刻意选类型学差异大的（罗曼语/黏着语/孤立语/声调语都覆盖）。
  • 三个指标：SLC（目标语言步骤占比）、Acc（答对率）、SLC&Acc（既对又语言一致，SLC≥0.9，主指标）。用 0.9 而非 1.0 是为容忍少量语言无关/杂散 token。

训练超参（Appendix A，复现关键）

  • SFT：2 epoch，global batch 128，lr 8e-5，max seq len 32,768，sequence-parallel size 4。
  • GRPO：600 update steps，lr 5e-6，max response length 4,096，batch 256，完全 on-policy，每 prompt 采 8 个回复，温度 0.9（测试也用 0.9）。
  • 硬件：2×8 H100。

5. 关键结果：主指标 SLC&Acc 全面第一，但"第一"主要靠 SLC 撑，纯 Acc 常打不过 Naive RL / M-Thinker

⚠️ 全部数字为单点估计、无 std、未说明 seed 数、无显著性检验。数字来自 Table 1（4B）、Table 2（8B）。

  • 主结果 ALL-AVG SLC&Acc（主指标，PCS 确实第一）：

    • MMATH 4B：PCS 32.3 > M-Thinker 23.4 > SoftLC RL 20.2 > Prefix 20.1（+8.9 over M-Thinker）
    • MMLU-ProX 4B：PCS 71.0 > M-Thinker 52.5 > SoftLC RL 48.6（+18.5，很大）
    • MMATH 8B：PCS 37.1 > M-Thinker 34.0 > RLC-RL 30.2 > Prefix 22.2 > SFT 16.6 > Prompt 0.6 > Naive-RL 0.1（只 +3.1 over M-Thinker）
    • MMLU-ProX 8B：PCS 77.1 > RLC-RL 74.2 > M-Thinker 66.1 > SFT 27.1（只 +2.9 over RLC-RL）
    • ⚠️ 规模越大，PCS 相对最强 baseline 的领先大幅收窄（4B 领先两位数 → 8B 只领先 ~3 分）。而作者只测了 4B/8B（自己 Limitation 也承认小）。8B 上 +2.9~+3.1 的领先，在无 std / avg@4 / AIME 各 30 题的情况下，可能落在噪声内——这削弱了 "substantially outperforms" 的叙事。

  • SLC（纯语言一致性）：PCS 稳定 96–99%，几乎总是最高——这是它主指标领先的主要来源。

  • 纯 Acc（目标语言）——最经不起推敲的地方：

    • MMATH 8B ALL-AVG 各语言 acc，PCS vs M-Thinker 互有胜负：fr 42.6 vs 41.6、pt 39.2 vs 41.2、ja 38.1 vs 36.6、ko 33.8 vs 37.7、th 37.6 vs 36.8。M-Thinker 在 pt/ko 上 acc 更高。
    • Naive RL 的 acc 在多数语言上反而更高（MMATH 8B：fr 41.6 / pt 39.5 / ja 40.3 / ko 38.8 / th 39.9），但 SLC&Acc≈0.1（raw SLC 仍有 3.7–30%，只是不够高，不是 0）。5 项里 fr 是唯一反例（PCS 42.6 > Naive 41.6）。说明 acc–一致性 tradeoff 真实存在，PCS 是用一部分 acc 换 SLC。
    • 英文 vs 目标语言差距未真正闭合：MMATH 8B EN acc = 45.0（PCS 行 EN 列）vs 目标语言平均 ~38.3 → 仍差 ~6.7；MMLU-ProX 8B EN 85.4 vs 目标 ~78.9 → 仍差 ~6.4。原文口径是 "substantially narrows"，narrows 可以、closes 不行。
    • ⚠️ PCS 的英文 acc（45.0）还略低于 Naive RL 的英文 acc（46.1），说明训 code-switch 对英文本身也有轻微损耗。

  • 消融 1：课程 vs dense reward（Figure 5）

    • PCS-Dense（去掉 τ 课程，用 r_final = 1+0.1·SLC(T,L)，见 Eq.5）：SLC 涨得快，但 acc 每一步都低于 PCS，只比 SoftLC RL 略好。结论：dense reward 逼模型过早换语言、伤推理，课程是必需的。⚠️ 只有训练曲线，无 benchmark 最终数字，无法量化差多少。

  • 消融 2：reference reset + KL（Appendix D, Figure 9）

    • 去掉这两个组件 → "substantial drop"，证明后期防 policy drift 的必要性。⚠️ 同样只有 Fig 9，无数字表。

  • 稳健性：SLC 阈值敏感度（Figure 6，MMATH） —— 这里有个反转，要小心读

    • τ_eval 从 0.80→0.95：PCS 37.9→34.3（掉 3.6，最稳）；SoftLC RL 31.6→27.2；M-Thinker 38.2→22.9（暴跌 15.3）。
    • ⚠️ 关键细节：在宽松阈值 τ=0.80 下 M-Thinker(38.2) 反而略胜 PCS(37.9)！PCS 的主指标优势完全来自"严格阈值下更稳"。原文把主阈值定在 0.9，恰好落在 PCS 开始反超的区间。这既可读作"PCS 的语言一致性是真的、M-Thinker 是虚的（reward hacking）"，也可读作"作者选了对自己有利的评测点"（见 6.1）。

  • 可解释性验证（Appendix B，MEXA 层级对齐，Figure 7） —— 支撑核心叙事的唯一机制证据

    • PCS 在中间层（10–25，负责 reasoning）与英文表征的对齐度和 Naive RL 相当、高于 SoftLC RL → 保留了英文式推理能力；在上层（负责语言实现）对齐最低 → 输出确实换成目标语言。这在表征层面支撑了"逻辑用英文的、表达用目标语言的"这个核心叙事。

  • 防 line-level hacking 自检（Appendix C, Table 3/4）

    • 担心：模型会不会把大量英文塞进一个超长行、其他行说目标语言来骗过 line 级 SLC？
    • 事实：PCS 的最长行确实更长（FR 223 token vs Naive 178），但最长行被 langdetect 判为目标语言的比例 LC≥96.7%，行内 code-switching 比例仅 0.7–1.6%（DeepSeek-V3 检测）→ 没有藏英文。
    • ⚠️ 但这个自检用的还是 langdetect + DeepSeek-V3，而 Appendix E 恰恰证明 langdetect 会被骗（英中混合判成 99.99% 泰语），自检工具本身就是被批判的对象（见 6.1）。

6. Insights

6.1 对论文本身的 Comments

反直觉、值得记的正面判断：

  1. "把语言奖励压成一个 0.1 的小 bonus"是全文最反直觉、也最关键的一步。 直觉上做多语言一致性，会想给语言一个显著奖励；但作者把 correctness(1.0) 和 language(0.1) 拉开一个量级，本质是承认"语言迁移是副目标、不能喧宾夺主"。配合课程才有"acc 稳、SLC 猛涨"的曲线。如果让我来做，我大概率先掉进 dense reward 的坑（PCS-Dense 正是这个坑）。

    • 更深一层（GRPO 视角）：GRPO 用组内归一化优势，绝对数值 0.1 不直接决定梯度——0.1 bonus 能否在"答对样本组"内产生有效 advantage，取决于组内 SLC 通过率的方差。只有当 τ 卡在"大部分样本恰好在边界"时 bonus 才有区分度。这恰好和课程 "Pass@SLC 饱和就抬 τ" 自洽：抬 τ 就是把样本重新推回边界、让那 0.1 重新变得有梯度。所以"0.1 小 bonus"和"阈值课程"其实是同一件事的两面，不只是两个独立的权重设计。

  2. 课程的触发条件设计得巧：不是按固定步数抬 τ，而是按 Pass@SLC(τ)≥0.9（奖励饱和度）自适应抬。把"什么时候该加难度"交给数据决定，而不是拍脑袋排 schedule。这比 CURE-med 那种"按语言资源等级排课程"更本质——课程直接建在被优化量（code-switching ratio）上。

最强攻击点（如果我审稿，主攻这几条）：

  1. 评测指标与训练目标同构，且主阈值可能选在对自己有利的点。 PCS 直接优化 step-level SLC，主指标 SLC&Acc 也用 step-level SLC≥0.9。Fig 6 自曝：τ=0.80 时 M-Thinker(38.2) > PCS(37.9)，抬到 0.9 才反超。现在的对比本质是"step-level 训练 vs response-level 训练"在 step-level 指标上比，先天不公。一个更公平的对照：让 M-Thinker 也用 step-level 奖励训练，再比。（注意：这条纠正了一种常见误读——把 Fig 6 当成"PCS 稳健性优点"来夸，其实它同时暴露了阈值选点问题。）

  2. "Efficient / no stronger model" 的 claim 有水分。 标题写 Efficient、摘要写 "only lightweight translation without any stronger model"。但 Appendix A：RL 数学题的翻译用的是 DeepSeek-V3.2-Exp（强模型），只是 cold-start 的 code-switch trace 用了 TranslateGemma-4B。严格说 PCS 省掉的是"目标语言推理 trace 蒸馏"和"online judge"，不是"所有强模型"。而且全文零 GPU-hour / wall-clock / 吞吐量数字支撑 "efficient"——只有一句 M-Thinker judge "non-trivial latency" 的定性说法。标题里的 Efficient 几乎没有量化证据。

  3. 统计严谨性薄弱。 全部单点、无 std、未报 seed 数。MMATH 里 AIME2024/2025 各 30 题、avg@4，宏平均后 8B 上 PCS 对 M-Thinker 只领先 3.1 分——量级完全可能落在噪声内。MMLU-ProX 用 avg@1 每题一采。没有任何显著性检验。8B 上的领先（+2.9~+3.1）不敢轻信。

  4. 对主要竞品 M-Thinker 的 "reward hacking" 指控建立在自己复现 + 单个 case 上。 "We reproduce M-Thinker under our experimental settings" + Fig 3/10/11 全是单条泰语样本的定性展示。把最强对手描述成"会作弊"再顺势说"我不会"，叙事方便但证据 anecdotal。至少应给 M-Thinker 复现的 SLC 分布 / hacking 发生率统计，而不是挑一条最难看的贴出来。（复现细节：Appendix A 结尾说 follow M-Thinker 设置、用 DeepSeek-V3 作 judge。）

  5. 自证清白用的是自己批判过的工具（循环论证）。 Appendix E 用 langdetect 把英中混合判成 "th:0.9999999" 来证明 response 级检测不可靠——但 PCS 自己的 step-level 奖励每一行也是用 langdetect 判，对短行（一个 step 可能就几个词）langdetect 更不可靠。Appendix C 的 line-hacking 自检又用 langdetect + DeepSeek 来"证明没作弊"。用一个你刚论证会失灵的工具给自己开脱，逻辑上站不住。

  6. [?] cold-start 混淆变量（最该补的结构性漏洞）。 原文 L225 只说 "We design consistent settings for different baselines and PCS"，但没讲清 Naive RL / SoftLC / M-Thinker 是从哪一种 cold-start 出发。PCS 的 cold-start 是 code-switch SFT；若 RL baselines 用的是蒸馏版 cold-start，则"PCS vs baselines"把 cold-start 数据配方和 RL 算法两个变量捆在一起，无法把功劳单独归因到 progressive curriculum。查了 Appendix A 也未能明确对齐起点——保留存疑。相关地，论文有 PCS-Dense / 去 KL-reset 消融，但缺一个关键内部 ablation："code-switch cold-start + Naive RL" vs "distilled cold-start + PCS-RL"，即无法分离"混合语 SFT 数据"和"课程 RL"各自的贡献。30% 混合比例也无 ablation。

其他做得不好的点： 9. 多个关键 ablation（PCS-Dense 最终分数、reference reset、KL）都只有训练曲线图、无 benchmark 数字表，无法复核幅度。 10. max response length 只有 4,096 token，对 AIME 这种真实推理链往往 >4K 的题偏短，可能系统性压低所有方法的 acc（尤其难题）——而作者又用 AIME 当 benchmark。自己 Limitation 也承认没测 16K/32K。 11. 命名不一致（脚注级）：Table 1（4B）叫 "SoftLC RL"、Table 2（8B）同位置叫 "RLC-RL"，但 baseline 定义节只定义了 SoftLC RL（= Magistral 的 soft response-level reward），RLC-RL 全文无定义 = 论文自身笔误，二者是同一 baseline。

6.2 对未来的预测

  • "把训练指标离散化成课程台阶、用 Pass@metric 饱和信号自动推进难度"这套 curriculum 机制不限于语言一致性——任何"想优化某个软约束但直接优化会伤主任务"的 RLVR 场景（格式、长度、风格、安全）都可能套用，核心是"用课程把副目标从易到难注入，主目标钉死高权重"。真正的开放问题是它在长 context（16K+）和更大模型上还稳不稳——这恰恰是本文没做、而 8B 已显露领先收窄的地方。

6.3 研究品味

  • 叙事和验证的三层咬合值得学：核心 claim 是"逻辑保留英文、表达换目标语言"。他们没停在结果表，而是 claim → 行为证据（结果表 SLC↑ acc 稳）→ 机制证据（Appendix B MEXA 层级对齐，中间层对齐英文、上层发散）三层互相印证。做机制类工作值得学这种"不同粒度证据互证"的组织方式。
  • "主动攻击自己的 metric" 是好习惯，但这次做得不干净。 Appendix C 主动去查 line-level SLC 会不会被"塞长行"绕过（最长行确实变长了，可疑），并给反证——这种 self-adversarial 姿态比大多数论文强。但反证工具是被自己 Appendix E 批过的 langdetect + DeepSeek，属循环论证。真正严谨的版本应该用人工标注一小批 longest-line 做 ground truth。
  • M-Thinker hacking 的单 case（Figure 10）是全文最有说服力的一击，但也最该打折扣。 一个泰语回复 token 级英中夹杂，langdetect 却给 th:0.9999 ——这一个例子直接说明"response 级语言检测器不可信"，以小见大、论证 step-level 的必要性极漂亮。但反过来，把竞品定性成"作弊"、把自己方法的优越性挂在一条精心挑选的样本上，作为审稿证据链是脆弱的（见 6.1#6）。两面都要看：作为叙事很强，作为证据偏弱。
