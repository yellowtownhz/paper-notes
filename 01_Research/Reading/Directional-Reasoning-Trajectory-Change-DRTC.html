论文笔记: Directional Reasoning Trajectory Change (DRTC): Identifying Critical Trace Segments in Reasoning Models

1. 背景信息

  • 论文: Directional Reasoning Trajectory Change (DRTC): Identifying Critical Trace Segments in Reasoning Models
  • 作者: Waldemar Chang
  • 团队: Johns Hopkins University
  • 版本 / 时间: arXiv:2602.15332v2, 2026-02-17
  • 类别: cs.LG
  • 代码: 论文元数据里没有给出 GitHub 链接
  • 一句话定位: 一个解释长 CoT 推理 trace 的方法。它不问“最后答案是谁导致的”，而是问：在模型推理中那些不稳定的转折点上，前面哪些 chunk 的信息流真正把轨迹往当前这条 rollout 的方向推了。

2. 关键问题：长 CoT 里，真正改变推理方向的片段很难从文本表面看出来

Golden Case — 问题是什么？

论文 Appendix B 的一个例子是：

一个有理系数非零多项式，把 $1+\sqrt{2}, 2+\sqrt{3}, \dots, 1000+\sqrt{1001}$ 都作为根。问这个多项式最小可能次数是多少？

模型的 trace 会先重述题目、试探思路，然后某个地方突然抓到关键约束：有理系数多项式如果有某个无理根，通常也必须包含它的共轭根。这个片段在 case study 里是 chunk 6，DRTC 分数是 +3.4020，是最大正向贡献。早期的泛泛 preamble（“Okay, let me try...”）反而是 -1.9895，也就是说它在 DRTC 的方向意义上不是支持最终推理轨迹的核心信息。

直觉上这很合理：真正让模型走向正确解法的不是“我要解这道题”这种开场白，而是“有理系数 ⇒ 共轭根约束”这个结构性承诺。

这篇论文要解决的是一个很具体的 interpretability gap：长程推理不是单个 forward pass 的问题，而是一条有路径依赖的生成轨迹。

为什么普通 attribution 不够用？

  1. 最后答案 forward pass 不代表整个推理过程
    长 CoT 里，中间 token 会改变后续上下文。模型可能先走错路，再说 “wait”，再换策略。只解释最后一个答案 token，很容易错过前面真正改变路线的 pivot。

  2. 直接编辑 trace 很容易 off-policy
    如果你把 trace 中间某句话删掉，却强行保留后续文本，这个上下文可能已经不是模型自然会生成的状态。解释结果会变得很怪：你不是在解释模型真实 rollout，而是在解释一个被人为拼接过的输入。

  3. 重新采样 continuation 又难比较
    另一种做法是改了中间内容以后重新 rollout。但新 trace 可能完全换了路径，长度、语义、答案都不一样。这样很难说变化来自哪个局部因素。

所以 DRTC 的目标不是 outcome-level causality，而是更窄的 process-causal attribution：在一条已经生成的 on-policy rollout 里，找到那些关键决策点，然后测试“前面哪个 chunk 的信息流会在这个决策点改变 log-probability 轨迹方向”。

3. 关键方法：先找 pivot，再做 receiver-side masking，最后看轨迹方向怎么变

Golden Case — 方法怎么跑？

还是上面的多项式例子。模型已经生成了一条完整 CoT。DRTC 不改写这条 CoT，也不重新生成后半段，而是：

  1. 把 rollout 切成固定 16-token chunks。
  2. 在每个生成位置计算不确定性和分布变化，挑出 $K=8$ 个最像“转折点”的 pivots。
  3. 对每个 pivot，逐个遮掉它对前面某个 chunk 的 attention edge：也就是让这个 pivot 位置“看不到”那个 earlier chunk，但保持整条真实 prefix 不变。
  4. 看 pivot 处的 log-probability vector 怎么变。
  5. 如果遮掉 chunk 以后，轨迹变化方向说明原 chunk 原本在支持真实 rollout 的方向，这个 chunk 就拿正分；如果原 chunk 反而在 counter-steer，就拿负分。

对 polynomial case 来说，“有理系数 ⇒ 共轭根”那个 chunk 被遮掉时，会强烈改变关键 pivot 的分布，而且方向上支持真实解题路线，所以它的 DRTC 是大正数。

3.1 Problem setup：把推理看成 log-probability space 里的轨迹

给定 prompt，模型生成一条 on-policy rollout：

$$ \{y_t\}_{t=1}^{T} $$

每个位置 $t$ 有 logits $z_t \in \mathbb{R}^{|\mathcal{V}|}$，对应概率分布 $p_t$。DRTC 在 log-probability 空间里做方向比较：

$$ s_t = \log p_t(\cdot) = \log \operatorname{softmax}(z_t) \in \mathbb{R}^{|\mathcal{V}|} \tag{1} $$
  • $z_t$: 第 $t$ 个生成位置的 raw logits
  • $p_t$: softmax 后的 next-token distribution
  • $s_t$: 对每个词表 token 的 log probability

直观说，$s_t$ 是模型在第 $t$ 步“对所有下一个 token 的偏好画像”。一条 CoT 就是一串这样的画像在高维空间里移动。

3.2 Pivot discovery：找“不稳定、可能转向”的位置

DRTC 给每个位置一个 pivot score：

$$ \tilde{u}_t = \gamma_H H_t + \gamma_M(1-\mathrm{margin}_t) + \gamma_S S_t \tag{2} $$

其中：

  • $H_t$: entropy。越高说明模型越不确定。
  • $\mathrm{margin}_t$: top-1 和 top-2 token probability 的差距。越小越像“两个选择打架”。
  • $S_t$: 前后 token window 的 Jensen-Shannon divergence，表示局部分布是否突然变了。
  • 论文使用 $(\gamma_H, \gamma_M, \gamma_S)=(1.0,1.0,0.5)$。

直觉：这像在 CoT 里找“拐弯处”。如果模型很确定地继续写公式，那未必是 pivot；如果它开始犹豫、top choices 接近、前后分布明显切换，那更可能是策略转折点。

挑出 top $K$ 个 pivot 后，用 softmax 得到 pivot importance：

$$ u_k = \frac{\exp(\tilde{u}_{\tau_k})}{\sum_{j=1}^{K}\exp(\tilde{u}_{\tau_j})},\qquad \sum_{k=1}^{K}u_k=1 \tag{3} $$

这里 $\tau_k$ 是第 $k$ 个 pivot 的 token 位置。$u_k$ 可以理解为“这个转折点在整条 trace 里的权重”。

3.3 Receiver-side intervention：只在 pivot 处切断某个 earlier chunk 的信息流

关键设计是 receiver-side attention masking。对 pivot $\tau_k$ 和 earlier chunk $c_i$，DRTC 不删除 chunk，也不重写后续文本，而是只在 pivot 的预测位置阻断从 $c_i$ 到 $\tau_k$ 的 attention 信息流。

先看 baseline top token $y_{\tau_k}^{\star}$ 的 logit 下降多少：

$$ a_{k,i}=\ell_{\tau_k}(y_{\tau_k}^{\star})-\ell_{\tau_k}^{(-i,k)}(y_{\tau_k}^{\star}) \tag{4} $$
  • $\ell_{\tau_k}$: baseline logits
  • $\ell_{\tau_k}^{(-i,k)}$: 在 pivot $k$ 处 mask 掉 chunk $i$ 后的 logits
  • $y_{\tau_k}^{\star}$: baseline 下 pivot 处的 top token
  • $a_{k,i}$: 遮掉 chunk $i$ 后，baseline top token 的 logit 被削弱多少

如果 $a_{k,i}$ 很大，说明这个 chunk 对 pivot 的原始选择确实有影响。然后把它变成 relevance gate：

$$ w_{k,i}=\sigma\left(\beta_k \hat{a}_{k,i}\right)\in[0,1] \tag{5} $$
  • $\hat{a}_{k,i}$: robust scaling 后的 screening effect
  • $\beta_k$: pivot-specific calibration parameter
  • $w_{k,i}$: 这个 chunk-pivot pair 的可信 relevance 权重

这一步像一个“先验过滤器”：如果遮不遮 chunk 对 pivot top token 基本没影响，那后面就别给它太大 attribution。

3.4 Directional trajectory change：不是看 likelihood 变大变小，而是看方向

DRTC 定义整条 pivot sequence 的全局 rollout direction：

$$ g=\frac{s_{\tau_K}-s_{\tau_1}}{\lVert s_{\tau_K}-s_{\tau_1}\rVert} \tag{6} $$

这个 $g$ 是从第一个 pivot 到最后一个 pivot 的单位方向向量。可以粗略理解为：“这条真实推理轨迹总体往哪里走”。

对每个 chunk-pivot pair，先看 intervention 造成的 log-probability vector 改变量：

$$ e_{k,i}=s_{\tau_k}-s_{\tau_k}^{(-i,k)} \tag{7} $$

再投影到全局方向 $g$ 上：

$$ \delta_{k,i}=\langle e_{k,i},g\rangle \tag{8} $$
  • $\delta_{k,i}>0$: chunk $i$ 原本在 pivot $k$ 支持真实 rollout 方向。
  • $\delta_{k,i}<0$: chunk $i$ 原本对真实 rollout 方向有反向张力；mask 掉它反而让变化更贴近 $g$。

一个简单类比：把推理轨迹想成一辆车的路线。某个 chunk 可能不是“油门大小”，而是“方向盘往哪个方向打”。DRTC 关心的是它在 pivot 处把方向盘往真实路线方向推，还是往相反方向推。

最终聚合：

$$ \mathrm{DRTC}(i)=\sum_{k=1}^{K}u_k\,w_{k,i}\,\delta_{k,i} \tag{9} $$

也就是：pivot 重要性 $u_k$ × chunk-pivot relevance $w_{k,i}$ × 方向性效果 $\delta_{k,i}$。

3.5 Curvature diagnostics：看几何转弯强度，但不参与 attribution

论文还算一个 curvature diagnostic。对连续 logits：

$$ v_{\mathrm{prev}}=z_t-z_{t-1},\qquad v_{\mathrm{next}}=z_{t+1}-z_t $$
$$ \kappa(z_{t-1},z_t,z_{t+1})=\arccos\left(\frac{\langle v_{\mathrm{prev}},v_{\mathrm{next}}\rangle}{\lVert v_{\mathrm{prev}}\rVert\,\lVert v_{\mathrm{next}}\rVert}\right) \tag{10} $$

这就是相邻两段 logit movement 的夹角。夹角大，说明轨迹在这个点“拐弯”明显。

Intervention 后的 curvature change：

$$ \Delta\kappa_{k,i}=\kappa(z_{\tau_k-1},z_{\tau_k}^{(-i,k)},z_{\tau_k+1})-\kappa(z_{\tau_k-1},z_{\tau_k},z_{\tau_k+1}) $$
$$ \mathrm{CurvImpact}(i)=\sum_{k=1}^{K}u_k\,\Delta\kappa_{k,i} \tag{11} $$

重点：CurvImpact 不是 causal attribution score。它只说明“遮掉这个 chunk 会不会让轨迹几何形状明显转弯”。论文反复强调 curvature 不用于 pivot discovery、gating 或 DRTC score。

3.6 和已有方法的区别

  • 相比普通 saliency / attribution：DRTC 不只标相关 token，而是在 pivot 处做局部 causal intervention。
  • 相比 final-answer flip：DRTC 不需要答案翻转，也适用于 open-ended 或 unfinished reasoning。
  • 相比 trace editing + resampling：DRTC 保留 realized rollout，不重新采样 continuation，避免不同 rollout 难以比较。
  • 相比 Towards-Long-Horizon-Interpretability-FlashTrace-Multi-Token-Attribution：FlashTrace 更像高效追踪多 token attribution；DRTC 更强调 pivot-local receiver-side intervention 和 directional trajectory target。
  • 相比 Thought-Anchors-Which-LLM-Reasoning-Steps-Matter：Thought-Anchors 找哪些 reasoning steps 重要；DRTC 把“重要”进一步定义成在关键 pivot 上对 log-probability trajectory 方向的支持/反向支持。

4. 数据集：数学推理 rollout，小样本跨模型 + 500 题扩展验证

  • 主要评估数据: math-rollouts problems 的固定 24-example slice，只使用 problem statements。
  • 扩展验证: 500 个 MATH problems。
  • 模型:
    • LFM2.5-1.2B-Thinking
    • Ministral-3B-Reasoning
    • Phi-4-Mini-Reasoning
    • R1-Distill-Qwen-1.5B
  • 生成设置: on-policy autoregressive reasoning rollout，greedy decoding，fixed seeds。
  • 分块: 固定 stride 的 16-token chunks。prompt 和 ground-truth solutions 保留用于 audit，但不参与 pivot discovery、intervention、scoring。
  • 默认 pivot 数: $K=8$。
  • 配置对比:
    • C0: DRTC only
    • C8: DRTC + curvature diagnostics
    • C9: matched random-span control，同样 masking 和 scoring 逻辑，但 pivot 换成 random spans

这里的数据规模不大，尤其跨模型主实验只有 24 examples。论文主要证明的是方法信号不是完全随机、不是 curvature logging artifact、不是 trivially proximity-driven；不是在证明某个 benchmark 上的泛化性能。

5. 关键结果：DRTC attribution 很集中，learned pivots 比 random spans 更有干预强度

5.1 Curvature logging 不影响 DRTC 分数

C0 和 C8 唯一区别是是否计算 curvature diagnostics。论文报告所有四个模型、每个 24 examples 上，C0 vs C8 的 per-chunk DRTC Spearman rank correlation 都是：

$$ \rho=1.000 $$

median $1.000$，95% CI $[1.000,1.000]$。这说明 curvature 确实只是旁路 diagnostic，没有偷偷影响 attribution。

5.2 Attribution 是集中而不是均匀铺开的

用 per-example normalized $|\mathrm{DRTC}|$ mass shares 看：

  • median Gini: 0.50–0.58
  • top 5% chunks 占总 influence mass: 0.23–0.28

这点很重要：如果 DRTC 最后只是给每个 chunk 差不多的分数，它对人类 audit 没用。集中性意味着它能把长 trace 压缩成一个 shortlist。

5.3 Pivot weighting 不是纯装饰

把 learned pivot weights $u_k$ 换成 uniform weights 后，weighted vs uniform 的 Spearman correlation 仍然很高：

$$ \rho \approx 0.97-0.99 $$

但严格小于 1。解释是：主结构来自 pivot-local effects 和 relevance gates；pivot weighting 不会完全重写排序，但会产生非平凡 reshuffling。这个结果比“权重完全改变一切”更可信，也比“权重没影响”更有用。

5.4 Learned pivots 比 random spans 产生更强 intervention

在四个模型上，C8 learned pivots 的 median per-example mean absolute pivot-local intervention magnitude 都高于 C9 random spans：

  • median gaps (C8 - C9): +0.039 到 +0.178

扩展到 500 个 MATH problems + R1-Distill-Qwen-1.5B：

  • median $\Delta = 0.409$
  • 95% CI: $[0.354,0.453]$
  • $\Delta>0$: 355/500 examples
  • sign test: $p=2.3\times10^{-21}$
  • median trace length: 2694 tokens, IQR [2131, 3068]
  • attribution concentration: median Gini 0.586, median top-1 mass 0.089, median top-5% mass 0.209

这个是论文最硬的 falsification evidence：DRTC 找到的 pivot 不是随便挑的位置；在相同 masking/scoring 下，learned pivots 的确更能引发 directional intervention。

5.5 Curvature 是 reorientation intensity，不是 directional steering

C8 中：

  • $|\mathrm{CurvImpact}|$ 和 $|\mathrm{DRTC}|$ 正相关。
  • signed $\mathrm{CurvImpact}$ 和 signed $\mathrm{DRTC}$ 接近零相关。
  • 500 MATH scaling 中，median Spearman $\rho(|\mathrm{CurvImpact}|,|\mathrm{DRTC}|)=0.080$，signed $\rho=-0.039$。

我的理解：curvature 能告诉你“这里几何上转弯很猛”，但不能告诉你“这个转弯是在支持还是反对最终方向”。这也是为什么论文把它定位成 diagnostic，而不是 attribution。

5.6 Adjacency 解释不了全部信号

相邻 chunks（距离 pivot-containing chunk $|\Delta i|\leq1$）的 mean $|\mathrm{DRTC}|$ 比远处 chunks（$|\Delta i|\geq5$）高，比例大概 2–3×。这说明局部邻近性确实有影响。

但远处 chunks 仍然有 non-zero influence，所以 DRTC 不是简单“离 pivot 越近越重要”。这点对长程推理尤其关键：早期 problem constraint 或 strategy commitment 可能隔很远仍然影响后续 pivot。

6. Insights

6.1 对论文本身的 Comments

  1. 我喜欢它把“解释答案”降级成“解释轨迹方向”
    很多 CoT interpretability 工作容易被 final answer 绑架：解释这个 token 为什么是 42。DRTC 换了目标：解释一条 rollout 在关键 pivot 上为什么继续沿这个方向走。这个目标更弱，但更可操作。尤其对 open-ended / truncated reasoning，最后答案可能不存在，但过程中的 steering 已经可以分析。

  2. receiver-side masking 是全篇最关键的工程取舍
    它避免了两个烂选择：删 trace 导致 off-policy，或者 resample 后无法比较。只在 pivot 位置切 attention edge，有点像问：“如果这个决策点当时没看到前面那段话，它的下一步分布会怎么变？”这个问题足够局部，也足够因果。

  3. 方向性分数比纯 magnitude 更有信息，但也更难直觉化
    正分好讲：支持 realized rollout。负分不等于“坏”或“错误”，而是“mask 掉它会让变化更 aligned with $g$”。这对人类读者会比较绕。论文 case study 里把 negative chunks 解释成 orientation text、exploratory detours、provisional reasoning，这个说法合理，但有一点 post-hoc flavor。

  4. 全局方向 $g$ 可能是最值得追问的假设
    用 $s_{\tau_K}-s_{\tau_1}$ 定义全局 rollout direction 很简洁，但长 CoT 可能不是单一方向：它可能先探索、再纠错、再收敛。一个全局 $g$ 会不会把多阶段结构压扁？论文用 curvature roles 补了一点结构诊断，但 primary DRTC 仍依赖这个方向定义。

  5. 实验更像 method validation，不是应用 benchmark
    结果证明 learned pivots > random spans、curvature 不污染 attribution、分数有集中性。但还没有回答一个更工程的问题：如果开发者拿 DRTC shortlist 去 debug reasoning model，能不能更快找到问题、修 prompt / data / model？这需要人类审计实验或 downstream debugging loop。

6.2 对未来的预测

  • 这类方法很可能会和 Towards-Long-Horizon-Interpretability-FlashTrace-Multi-Token-Attribution 这类高效 attribution 系统合流：先用便宜方法扫长 trace，再对少数 pivot/chunk 做更重的 causal probe。
  • 对 agent trace 也有潜在迁移空间，但不能直接套。agent 的 pivot 不只是 token uncertainty，还包括 tool-call boundary、environment observation、commitment point；这更接近 Causal-Agent-Replay-Counterfactual-Attribution 的 point-of-commitment 设定。

6.3 研究品味

这篇的好处是把方法的“因果声明边界”画得很清楚：DRTC 是 process-causal，不声称 chunk 导致答案正确；CurvImpact 是 diagnostic，不声称 causal direction。很多 interpretability 论文会把 saliency、causality、geometry 混在一个故事里讲，这篇反而一直在拆边界。

7. 我的疑问

  1. 全局方向 $g$ 是否太粗？
    当前理解：$g$ 是从第一个 pivot 到最后一个 pivot 的 log-probability displacement。它给 DRTC 一个统一参照系。疑问是，如果 trace 中存在多次 strategy switch，一个 single global direction 可能把“先远离后靠近”的局部结构压平。或许可以有 segment-wise $g$、piecewise trajectory direction，或者用 pivot-to-pivot local direction。

  2. receiver-side attention masking 在不同架构上是否完全等价？
    当前理解：论文在 open-weight transformer reasoning models 上实现 attention-edge masking。但不同模型的 attention implementation、KV cache、GQA/MQA 结构可能影响 mask 的精确语义。论文主文没有把这些实现差异展开到我完全放心的程度。[?]

  3. 负 DRTC 的语义能否被更严格验证？
    当前理解：负分表示 directional tension，不一定是错误。case study 里常解释成 preamble、detour、uncertainty。但这类解释需要更多人工标注或可控合成任务来验证，不然容易变成“看到负分再找一个合理故事”。[?]

  4. 固定 16-token chunk 会不会错过语义边界？
    当前理解：固定 chunk 的好处是长度可控、tokenization reproducible、干预强度不被句子长度混淆。代价是一个语义步骤可能被切开，或者多个小步骤被合并。论文选择更偏工程可控，而不是语义自然。

8. 连接与发现
