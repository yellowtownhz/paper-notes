2. 关键问题：把英语强模型扩出新语言（hu/sr/bn）又不想花钱跑 SFT+RL，但 dense merge 里"留旧"和"学新"互相打架

Golden Case — 问题为什么难

你拿到 Qwen2.5-7B-Instruct，想让它会匈牙利语（Hungarian）。 用户问："Kérlek, írj egy haikut a tavaszról."（请写一首关于春天的俳句。） 原版 Qwen 在 hu 上挺烂：MGSM-hu 61.2、Flores En-Hu 34.04、MIFEval-hu 58.91。

你只有两条 data-free 捷径，因为根本搞不到百万级匈语指令数据：

  • Dense-FT-Avg（ElChat-style）：拿 Instruct 跑 hu CPT，再跟原 Instruct 做权重平均。MGSM-hu 涨到 64.4，但等于把刚学到的 hu 知识稀释一半，新东西吃不饱（Table 5）。
  • Dense-FT-Delta（PARAM-Δ）：拿 base 跑 hu CPT，再加上 "Instruct − Base" 这个对齐 delta。Flores En-Hu 拉到 88.31 看着很漂亮（Table 9），但 MGSM-hu 反而只有 56.80，比 Avg 还差（Table 5）——翻译涨了，数学推理崩了；原语言代价更惨：MGSM-en 80.8→78.0、Es 67.2、Fr 54.0，等于把英语推理打飞。

一句话：dense 权重空间里你只有"稀释新知识"或"打飞旧知识"两个选项。

为什么 dense merge 必然 trade-off？ CPT 把权重从 θ_base 推到 θ_cpt，post-training 把 θ_base 推到 θ_post。把两个偏移塞回同一组 dense 参数里：averaging 就是把两个方向加权平均（稀释 CPT），delta merge 就是叠加两个不相关方向（θ 飘离原 Instruct，catastrophic forgetting）。这是参数空间冲突，不是数据量不够——2× CPT 数据的 Dense-FT-Avg-2FLOPs 在 hu MGSM 上从 64.4 退到 56.8，2× 数据反而更糟（Table 5）。

要解决的是架构层面的冲突：能不能开一块新的参数子空间专门装新语言、再让 alignment delta 干净地嫁接过来。

3. 关键方法：把 dense FFN 复制成 4 experts，CPT 阶段冻住 expert-0 装原语言、剩下 3 个 trainable expert 装新语言；Merging 阶段把 dense alignment delta 广播给所有 experts

Golden Case 续 — 一个 hu token 在 DeltaMoE 里的完整生命周期

输入："Hogyan készítsünk teát?"

Stage 1（CPT 完成之后）：

  1. embedding（共享、冻结）映射 token
  2. attention（共享、冻结）算上下文 hidden state x ∈ ℝ^d
  3. router 给出 4 个 logits，softmax → top-2 选中 experts，例如 {1, 3}
  4. expert 1（trainable，CPT 后已在 hu 上特化）和 expert 3 各算 SwiGLU FFN
  5. 归一化后线性组合 + 残差：y = Σ w_i E_i(x) + x

Stage 2（Merging 完成之后，每个 expert 都被加 Δ_FFN_post）： 6. expert 1 的 W_gate 现在等于「CPT 训完的 W_gate^1 + Δ_gate^post」（Δ = Qwen2.5-7B-Instruct − Qwen2.5-7B-Base 的 FFN 部分），相当于"hu 特化的 FFN 也获得了 Instruct 对齐的指令跟随能力" 7. attention/embed 也被加上对应 Δ_shared

对比英语输入 "How do I brew tea?"：Figure 3 显示 router 几乎把 token 全送到 expert-0，所以英语前向 ≈ base FFN + Δ_FFN_post ≈ 原 Instruct FFN，几乎不被新 experts 干扰。

3.1 整体架构

两阶段串联，全程跳过 SFT、跳过 RL、不需要任何指令数据：

  • Stage 1: CPT via Sparse Upcycling — 把 dense 升级成 4-expert MoE，只训新加的 3 个 expert + router
  • Stage 2: MoE Model Merging — 拿同 base 的公开 dense Instruct，算 Δ_post = θ_post − θ_base，按组件 graft 到 Stage 1 产物上

3.2 Stage 1 — Sparse Upcycling

Why upcycle 而非从头训 MoE？ 想复用英语上的预训练知识。Komatsuzaki 2023 sparse upcycling 的入口：N 个 expert 都用原 dense FFN 的 deep copy 初始化。

MoE 层定义（SwiGLU FFN）：

$$ E_i(x) = \big(\mathrm{SiLU}(x W_\text{gate}^i) \odot x W_\text{up}^i\big) W_\text{down}^i $$
  • x ∈ ℝ^d，W_gate^i / W_up^i ∈ ℝ^{d×f}，W_down^i ∈ ℝ^{f×d}
  • 4 experts，全部用 expert-0 的 FFN deep copy 初始化（gate/up/down 三组矩阵）
  • 注：原文 Eq.1 SiLU 括号位置有 typo（写成 SiLU 作用于 gate⊙up），按 SwiGLU 标准实现纠正 [?]

Top-k 路由（k=2, N=4）：

$$ p = \mathrm{softmax}(x W_\text{router}),\quad \mathcal{T} = \mathrm{TopK}(p, k),\quad w_i = \frac{p_i}{\sum_{j\in\mathcal{T}} p_j}\cdot \mathbb{1}[i\in\mathcal{T}] $$
$$ y = \sum_{i=1}^N w_i\, E_i(x) + x $$

Frozen anchor 设计 — 全文最核心的工程决策：

"we freeze all parameters of the dense base model, including the 0-th expert, which serves as a knowledge anchor"

可训练参数：

$$ \theta_\text{tr} = \{\theta_\text{exp}^{(k)}\}_{k=1}^{N-1} \cup \{\theta_\text{router}\} $$

（原文 Eq. 写 k=1..N 与文字"only expansion experts trained / N=4、3 trainable"矛盾，按文字描述写为 k=1..N−1）[?]

也就是 attention、embedding、LM head、layer norm、expert-0 的 FFN 全部冻结，只有 expert 1..3 的 SwiGLU 三矩阵 + 每层 router 在更新。这样 router 可以学会在英语上把 token 全部送到 expert-0，英语前向几乎等价于原 dense 模型 + 残差。

损失 — NTP + load-balancing：

$$ \mathcal{L}_\text{LB} = N\cdot \sum_{i=1}^N f_i P_i,\quad \mathcal{L} = \mathcal{L}_\text{NTP} + \alpha\,\mathcal{L}_\text{LB},\ \alpha = 0.01 $$

f_i = batch 内被路由到 expert i 的 token 比例；P_i = batch 内 expert i 的平均 router 概率（标准 ST-MoE 设定）。

训练超参：LLaMA-Factory + DeepSpeed ZeRO-3、BF16、LR 5e-5 cosine、global batch 512、seq len 2048、1 epoch；每种扩展语言 3B tokens × 3 = 9B tokens；未披露 GPU 数 / 总步数 / wallclock / seed 数。

3.3 Stage 2 — MoE Delta Merging

Why 不直接 dense delta merge 再 upcycle？ 那样 expert-0 就也被 delta 冲掉了，等于回到 Dense-FT-Delta 的 forgetting。

Component-wise merging：

1) Shared params（attention / embedding / norm）—直接相加：

$$ \hat\theta^\text{MoE}_\text{shared} = \theta^\text{MoE}_\text{shared} + \Delta^\text{shared}_\text{post},\quad \Delta^\text{shared}_\text{post} = \theta^\text{shared}_\text{post-trained} - \theta^\text{shared}_\text{base} $$

Stage 1 这些参数被冻结所以等于 base，加 Δ 后等价于 dense post-trained 模型的对应位置。

2) Expert FFN — 同一个 FFN delta broadcast 到所有 i ∈ {0, 1, ..., N−1}（注意包括 frozen expert-0）：

$$ \hat W^i_\text{gate} = W^i_\text{gate} + \Delta^\text{gate}_\text{post},\quad \hat W^i_\text{up} = W^i_\text{up} + \Delta^\text{up}_\text{post},\quad \hat W^i_\text{down} = W^i_\text{down} + \Delta^\text{down}_\text{post} $$

重要细节：所谓 "frozen expert-0" 严格说只在 CPT 阶段成立——Merging 阶段 expert-0 也被加上了 Δ_FFN_post，结果等于 base FFN + Δ_FFN_post ≈ post-trained FFN。真正的"anchor"机制不是冻结，而是 routing-aware 的 Δ application：router 把 en 大量路由到 expert-0，等价于把 en 路由到"dense post-trained FFN 的近似"。

Router 不被 merge（dense 模型没有 router），Stage 1 训出的 router 原样保留。

能力转移结果：

  • expert-0：base FFN + Δ ≈ post-trained FFN → en 几乎恢复 dense Instruct
  • expert 1..3：base FFN + ΔCPT_i + Δ_post → 在 hu/sr/bn 特化的 FFN 上叠加 alignment 偏移
  • attention/embed 直接等价 dense Instruct
  • Stage 1 训出的 router 决定 token 分流

3.4 与已有方法的本质区别

方法 新语言子空间 原能力保留机制 Alignment 转移
Dense-FT-Avg 无（同一 θ） 与 Instruct 平均（稀释 CPT） 同上
Dense-FT-Delta 无 无 → forget 直接加 Δ
LLaMA-Pro 新 Transformer blocks（深度扩） 冻原 blocks Δ 只加到原 dense 参数
MoLA LoRA experts（rank=1120, 各层 2/4/6/8 个） 冻原参数 Δ 加到原 dense；LoRA 接不上 Δ
DeltaMoE trainable experts（宽度扩） frozen expert-0 + 路由隔离 Δ broadcast 到所有 experts，FFN 同形可 graft

跟 MoLA 的本质差别：MoLA 用低秩 adapter 学新语言，但 dense Δ 没法投回 LoRA 子空间，只能加到原 dense 参数上 → 新语言 FFN 完全没被 alignment 更新过。DeltaMoE 的 full-rank expert 跟 dense FFN 同形，Δ 直接 graft——这是 +1.76 主表 gap 的机制来源。但反过来说，这个对比也意味着 MoLA 是一个被精心挑选的、设计上就接不到 dense delta 的对手，详见 §6.1.

3.5 复现可能卡的点

  • 论文未披露 router 初始化方式（按 sparse upcycling 惯例应该是 random init，但 1 frozen + 3 trainable 的设定下，random init 会让 expert-0 在 Stage 1 早期被路由概率分散——en 会受损。也没说有没有 router-only warmup）[?]
  • baseline LR 不一致：Dense-FT 系列 2e-5、LLaMA-Pro 2e-4（高 10×）、MoLA 5e-5、DeltaMoE 5e-5（Table 11）——LLaMA-Pro 的 LR 高一个数量级，加上 +28 层时崩到 24.60，公平性受影响
  • top-2 引入约 1.8× dense FLOPs，作者用 2× CPT data 的 dense baseline 来过补偿对比公平性
  • Total 24.7B / Active 13.3B vs dense 7.6B
  • Stage 2 之后是否还要再 fine-tune？论文看是 zero-shot 直接评估
  • §4.2 的 router-tuning 是 optional：0.15B token（原:新 = 1:2），只训 router，进一步提升原语言保留——不属于主表 pipeline

4. 数据集：扩展语言用 FineWeb2/CulturaX 抓的纯语言 monolingual 文本，eval 覆盖数学/指令/阅读/常识/翻译五大类

CPT 训练数据：

  • 扩展语言：Hungarian (hu)、Serbian (sr)、Bengali (bn)，每种 3B tokens 共 9B
  • hu/bn 来自 FineWeb2；sr 因 FineWeb2 数据量不足改用 CulturaX
  • 无指令数据、无平行语料
  • 2FLOPs baseline 把数据翻倍到 18B 以匹配 top-2 MoE FLOPs

原语言（仅评估，不在 CPT 里 replay）：en, zh, es, fr。§4.2 可选 replay 用 0.15B：en 来自 DCLM、es 来自 FineWeb2、zh 来自 SkyPile-150B（每语言 50k docs），French 留作 OOD。

Routing 分析（Figure 3）放在数据/分析侧讨论：

作者解读对应 Wendler 2024 的 latent language 工作："模型在中层用英语思考、在上层做语言特化输出"。意味着 language-specific experts 实际上更像 "output formatter" 而非 "language understander"——深层语义理解还在英语 FFN 里做。这个分析只在 ifeval 上做了一次，MGSM / Flores 的路由分布会不会完全不同，论文没扫。

评估 benchmark（全 zero-shot）：

  • MGSM（数学推理，BenchMAX 子集）：accuracy，zero-shot CoT；样本量论文未明说 [?]
  • MIFEval（指令跟随，BenchMAX 子集）：prompt/instruction × strict/loose 四子指标平均
  • BELEBELE（阅读理解，122 语言）：MCQ accuracy + zero-shot CoT
  • M_MMLU：每个 subject category 各抽 10% 的分层子集（绝对题数未给）
  • Flores-200：用 XCOMET-XXL（reference-free）打分；En-XX 和 XX-En 双向

评估细节（Appendix C）：

  • MCQ prompt 用 OpenAI simple-evals 模板，用 DeepSeek-V3 翻译到目标语言——对 hu/sr/bn 这种低资源语言 prompt 本身质量是个未控变量
  • 答案抽取两段式：先 regex Answer: [A-D]，失败 fallback 到 Qwen3-4B-Instruct 做抽取——对 Qwen2.5 系基线可能有 model-family 偏好
  • Flores 用 custom prompt（Figure 5）；XCOMET-XXL 是 LLM-as-judge，对低资源语言的可信度本身是公开问题

5.3 Replay 知识保留（Figure 4）

  • DeltaMoE + 0.15B router-tuning > Dense-FT-Avg 在 in-domain
  • Dense-FT-Delta 即便 60×（约 9B）replay 仍打不过 DeltaMoE 的 0.15B
  • 法语作为 OOD（router-tuning 没见过法语）接近 Dense-FT-Avg —— 解耦设计对未见原语言有泛化保护
  • 公平性注意（B 抓到）：DeltaMoE 是 post-CPT router-only fine-tune，Dense-FT-Delta 是 CPT-time data mixing，两者 replay 时机和粒度不同；论文没给"Dense-FT-Delta + 事后 fine-tune-on-replay"的对照

5.4 泛化（Table 3、4）

  • 换 alignment delta（Tulu3 SFT 自己做）：DeltaMoE Expand 65.77（vs LLaMA-Pro+7L 64.97 = +0.80），Original 76.14 —— 但 Dense-FT-Avg 在该 setting 下 Original = 76.46，DeltaMoE 反而输了 0.32。原文 "competitive results that rival the top-performing baseline" 软化了这个事实。
  • 换 base 到 LLaMA-3.1-8B：DeltaMoE 69.37 / 77.32 双 SOTA。
  • LLaMA-Pro 在 LLaMA-3.1 上极不稳：+8L 58.92、+16L 44.44、+24L 崩到 14.80 / 13.87（Appendix G Table 14）；同方法在三种 setting 下最优层数都不同（Qwen2.5+14L / Tulu+7L / LLaMA3.1+8L），说明 LLaMA-Pro 极度依赖 hyperparameter，作为 baseline 公平性受损。

5.5 Scalability（Appendix H）

  • 5 种扩展语言（hu/bn/sr/te/is 各 1B）：3 trainable expert 75.67 vs 5 trainable 75.84 ≈ 持平 → 3 个 trainable 容量够
  • 从 3 种扩到 8 种（19B 总 token）：原 3 种 Expand 从 74.97 → 74.43（−0.54），Original 81.17 → 81.04；同条件 Dense-FT-Delta 退化到 70.00 → MoE 抗干扰强。自我吐槽：论文用宽尺度量正向收益（+1.76 算大）但用紧尺度量这里的 −0.54（算"几乎不退化"），其实跟 BELEBELE +0.52 同量级，双标。

5.6 作者自陈 Limitations（原文 §Limitations）

  1. 评估语言/benchmark 不足以覆盖全球语种多样性
  2. MoE 架构在训练/推理上带来 non-trivial computational overhead

6. Insights

6.1 对论文本身的 Comments

A. 单 seed、零方差、提升幅度在噪声内 — 全篇所有表格都没有 std / CI / seed 数，每个 benchmark 只跑一次。关键 gap：BELEBELE +0.52、M_MMLU +1.10、Flores En-XX +0.77，都在 0.5–1 个点。M_MMLU 还是 10% stratified subsample（每个 subject 抽 10%，绝对题数未给），方差进一步放大。论文措辞"resolves the trade-off"、"SOTA"、"effectively preserving"跟数字差距严重不对位——reviewer 容易被措辞带偏，但只看数字会发现 claim 站不太稳。最可执行的 reviewer ask：跑 3 个 seed 给 std。同时 DeltaMoE 自己 Original 81.17 vs base 82.33 = −1.16 净损失，按这个量级，所谓"preservation"不是真的无损。

B. 参数预算的"公平"对比有诡辩感 — DeltaMoE：13.3B active / 24.7B total（3.25× dense 7.6B）。论文用"matched FLOPs"表头偷换"matched capacity"——MoE 总参数是真的占显存、占存储的成本。真正公平的设置应该是让 dense baseline 也用 ~20B 总参数（比如 Qwen2.5-14B 跑同 9B CPT + delta），论文没做。"matched FLOPs" 这一组里 dense baseline 只是数据翻倍但参数没变。

C. MoLA 是被精挑细选的 strawman，缺关键 multilingual-MoE 直接对位 baseline — 论文核心论点"MoLA 的 LoRA expert 接不到 dense delta"在设计上就让 MoLA 先天处于劣势。可以给 MoLA 也设计适配的 delta 注入策略（把 dense FFN delta 投影到 LoRA 空间，或在 LoRA 上做 ElChat-style averaging），论文没尝试。真正缺位的对手是 MoE-LPR / DMoE / LayerMoE 等 multilingual-MoE 工作——§Related Work 只一句"它们没做 alignment 传递"打发，但这些才是直接对位的方法。

D. "frozen anchor" framing 不准确，真实机制是 routing-aware Δ application — Stage 2 时 expert-0 也被加 Δ_FFN_post，已经不再 frozen。anchor 的真实机制不是"冻结"，而是 router 把 en 大量路由给 expert-0，等价于把 en 路由到"dense post-trained FFN 的近似"。论文（和我自己读第一遍）都把"frozen"当 framing 卖，但实际上 Stage 1 的冻结只是为了让 Stage 2 的 graft 有干净参照系。如果让我来做，我大概率会让所有 expert 都训，反而踩进 dense merging 的同一个坑。

E. Δ_post broadcast 到 trainable expert 能 work 暗示一个反直觉假设：dense post-training 方向与新语言知识方向接近正交 — trainable expert 在 CPT 阶段已经偏移了（设偏移 ΔCPT_i），最终权重 = θ_base + ΔCPT_i + Δ_post。这跟 Dense-FT-Delta 在某种意义上是同构的（只是被限制在某些 token 路径上），但前者不 forget 后者 forget。作者论证是"experts 都源自同一 FFN"，但这其实是空话——真正能 work 的原因更像是：dense Instruct 的 post-training 在权重空间里方向比较"通用"（指令格式 + 推理结构），跟具体语言知识方向接近正交，所以加上去不打架。可证伪预测：在更激进的 post-training delta（比如长 CoT 推理专门强化的 R1 系模型）上，这个广播策略可能会崩。同样未解的：‖Δ_post‖ 跟 ‖ΔCPT_i‖ 的相对大小？如果前者远大于后者，所有 expert grafting 后都会塌缩到 base + Δ_post 邻域，等于稀释 CPT——论文没报这个 norm 比例。

F. 缺 Stage 1 中间产物 M_MoE-base 在扩展语言上的单独数字 — 现在所有结果都是 "CPT + Merging" 的 final pipeline，没法分开看 CPT 学了多少、Merging graft 了多少。这是审稿人会问的第一刀。

G. 为什么 original 会掉 1.16 点？三个互斥假设论文没 disentangle — Figure 3 显示 English token 几乎全压回 expert-0，理论上应该零损失。三种猜测：(a) shared param（attention/embed）上的 grafted Δ 与原 instruct 仍有微小数值差；(b) router 偶尔路由错把 en 送到 trainable expert；(c) expert-0 在 merging 阶段加了 Δ_FFN，跟原 Instruct FFN 不完全一致。可执行 ablation：把 Stage 2 的 Δ_FFN_post 只加给 expert-0、不加给 expert 1..3，看 en 上还掉不掉。

H. top-2 强制激活第二个 expert，但论文只给了 routing 的边缘分布、没给联合分布 — en token 上 expert-0 是第一选择，那第二个是哪个？如果第二激活的是 trainable expert，理论上会污染 en，但 en 性能仅掉 1.16 点——反过来暗示 trainable expert 在 en 上几乎学成了 identity-like 映射，这是个有 mechanistic 价值的发现，论文跳过了。

I. Router-tuning replay 跟主表不一致 setting，比较时还跨 replay 范式 — 主表 Table 1 是 no replay；Figure 4 才加 router-tuning。给 Dense-FT-Delta 也加一个"事后 fine-tune-on-replay"阶段才公平，但论文没做，仍然把 0.15B vs 9B 的差距当 60× 数据效率秀。

J. 路由分析只在 ifeval 上做了一次 — 推理（MGSM）和翻译（Flores）的路由分布很可能完全不同，"模型在中层用英语思考"的故事只有一张图支撑，generalization 待验证。

K. LLaMA-Pro 在不同 setting 下最优层数都不同（Qwen+14 / Tulu+7 / LLaMA3.1+8），且 +28 层时崩到 24.60 / 8.66（Appendix E/F/G） — 加上 LR 比其他 baseline 高 10×（2e-4 vs 2e-5/5e-5，Table 11），LLaMA-Pro 这个 baseline 调优本身就极度不稳。论文选 best variant 没错，但这个崩盘幅度本身就是 LLaMA-Pro 作为 fair baseline 的硬伤。反过来 DeltaMoE 自己只扫了 expert 个数（Appendix H），没扫 top-k、N、CPT epoch 等 — 自身有没有 hyperparameter cherry-picking 不可证。

6.2 对未来的预测

  • post-training delta 作为可移植"能力包"会越来越流行：DeltaMoE 的真正贡献是给了一个"如何把 dense delta 嫁接到 sparse 架构"的模板。可以预期：reasoning-MoE-graft、tool-use-MoE-graft、safety-alignment-MoE-graft 系列工作。但 §6.1.E 的反直觉假设是个 caveat——长 CoT 推理这种"强方向性"的 delta 上广播策略可能会崩，这是值得跟踪的第一批验证目标。

6.3 研究品味

  • trade-off 可视化的杀伤力：Figure 1 二维 Pareto plot 把 dense baseline 全压在前沿、DeltaMoE 单点跳到右上角。这种写法让 reviewer 没法用"你只是稍微更好"reject。做"两个互斥目标同时优化"类工作必备。
  • baseline 分组"same data / matched FLOPs / matched parameters"层次清晰，但要警惕双标：论文把这三组拆开来打，看起来非常严谨。但 B 抓到的是——"matched parameters"那组都是参数扩张架构（LLaMA-Pro / MoLA / DeltaMoE 自己），没有同样 ~20B 总参数的 dense baseline。所以"参数公平"那一维其实没真打。这个手法的两面：拆维度是好习惯，但每一维都得有真正同等的 dense 对手，否则就是"每一组都赢但每一组都缺真正的对照"。
  • claim 措辞 vs 实际数字差距的 lesson：这篇所有 SOTA claim 都在 1-2 个点内（含 net forgetting −1.16），且无 std。作为 reader / reviewer 训练，永远先把 abstract 措辞按到桌面再去看数字——"effectively preserving" 在数字上是 −1.16；"resolves the trade-off" 在数字上是从 trade-off 前沿"挪动"到一个稍好的点，没真正"resolve"。
